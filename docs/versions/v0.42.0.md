# v0.42.0：Model Viewer 架构与跨平台收敛

## 状态

**实施中。** Model Viewer 架构收敛已经完成，正在处理跨平台加载界面和生命周期可靠性。

## 版本目标

重新划分 Model Viewer、Example Common、Asset Manager 和任务执行器之间的职责，让 Desktop 与 Web
只保留入口和执行策略差异。加载、场景准备、GPU 上传、Viewer 状态、渲染和 ImGui 界面由共享代码
驱动，同时解决 v0.41.0 遗留的 Linux 托管 Emscripten 浏览器 WebGPU 波动。

## 固定范围

| 任务 | 本版本交付 | 公共 SDK 影响 |
|---|---|---|
| [S-77 Model Viewer 架构收敛](../plans/S-77-0.42.0-model-viewer-convergence.md) | 拆分 glTF 渲染支持，统一加载操作、Viewer Document、Renderer 与调度边界，删除重叠层次 | 默认不改公共 API；Example 私有接口可直接使用最新设计 |
| [S-78 Linux 与 Emscripten 可靠性](../plans/S-78-0.42.0-model-viewer-platform-reliability.md) | 统一 ImGui 加载体验，修复浏览器 WebGPU 生命周期波动，完成 Linux XCB/Wayland 与浏览器验收 | 不新增平台专用公共 API |
| [S-79 ImGui Integration 教程与验收归位](../plans/S-79-0.42.0-imgui-integration-layout.md) | 删除重叠综合 Sample，以 `08_sdl_imgui` 讲解外部 SDL Window 集成，并将视觉与性能入口归位 | 不改变安装 Integration 组件或公共 API |

## 不进入本版本

- 不把示例的 glTF Loader、GPU Scene、任务系统或 Model Viewer 状态机提升为公共 SDK；
- 不建立通用公共应用框架、Scene Graph 或 Editor 框架；
- 不借目录调整重构 RenderPipeline、资产格式或 PBR 行为；
- 不为历史 Example 私有接口保留兼容转发；
- 不处理缺少复现、范围和验收条件的附带问题。

## 任务依赖

S-77 先建立稳定职责边界和共享状态机。S-78 可以先补充故障诊断，但最终 UI、生命周期和平台验收
必须基于 S-77 的新结构完成。S-79 在共享 ImGui 使用路径稳定后整理示例和验收归属。三个任务在
同一特性分支连续推进。

## 阶段出口

1. `examples/common/model_viewer` 被语义明确的 glTF 渲染支持取代，Viewer 专属状态回到 Sample。
2. 加载与渲染分别只有一个状态来源，不再由多层 Session、Service 和 Observer 重复转发。
3. Desktop 与 Web 共用 Model Viewer Application、Document、Renderer、UI 和阶段转换。
4. 浏览器从首个可渲染帧开始使用 ImGui 呈现加载、取消和失败，不再显示 DOM 加载界面。
5. Linux 原生和 Linux 托管 Emscripten 验收分别给出确定结果，浏览器 WebGPU 不依赖重跑通过。

## 发布门槛

- Example Common 与 Model Viewer 目标形成单向依赖，不存在循环依赖和重复运行时状态；
- Asset Manager 负责资产请求、依赖、缓存、取消和进度，Model Viewer 不重建第二套资产系统；
- Desktop 专用线程与 Web 协作执行消费同一状态机，只通过执行策略组合；
- 资源获取、解析、GPU 上传和 Pipeline 准备期间均能持续产生 ImGui 加载帧；
- 正常、取消、失败、Resize、Surface 恢复和 Shutdown 路径均完成资源回收；
- Linux XCB/Wayland Model Viewer、Emscripten Node 和真实 Chrome WebGPU 验收通过；
- Dawn Instance/Device 生命周期波动有根因、修复和稳定回归，不以测试重试掩盖；
- Windows、Linux、Emscripten、安装 SDK、文档检查和共享 SDK 工作流通过。

## 待纳入问题

新增 Model Viewer 问题须记录触发条件、预期行为、平台范围和验收方式。与本版本架构或平台收敛
直接相关的问题可以加入 S-77/S-78；独立渲染功能和公共 API 扩展另建任务。
