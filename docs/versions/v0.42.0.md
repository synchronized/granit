# v0.42.0：Model Viewer 加载体验与浏览器稳定性

## 状态

**规划中。** 本版本先完成 [S-77](../plans/S-77-0.42.0-model-viewer-convergence.md)，再进入实现。
除已经确认的 Model Viewer 加载流程和浏览器稳定性外，其余问题须有复现证据后才能加入固定范围。

## 版本目标

让桌面与浏览器 Model Viewer 从加载开始到模型可交互都使用同一套 C++ Application、状态模型和
ImGui 界面。浏览器 HTML 只承担 Canvas、启动和自动化观测，不再提供另一套可见加载界面。

## 固定范围

| 任务 | 本版本交付 | 公共 SDK 影响 |
|---|---|---|
| [S-77 Model Viewer 收敛](../plans/S-77-0.42.0-model-viewer-convergence.md) | 统一 ImGui 加载面板、可观测进度、取消与失败状态、浏览器协作式加载和 WebGPU 生命周期验收 | 默认不改公共 API；只有实现证据证明现有接口不足时才调整 |

## 不进入本版本

- 不建立通用公共加载界面或应用框架；
- 不把 Model Viewer 私有任务调度提升为公共 Granit 执行器；
- 不借本任务重构 RenderPipeline、资产格式或 glTF 公共 API；
- 不保留可见 DOM 加载界面作为浏览器备用路径；
- 不处理没有复现、范围和验收条件的附带问题。

## 阶段出口

1. 固定共享加载状态、阶段、进度和取消契约，并建立行为测试。
2. 浏览器删除可见 DOM 加载界面；桌面与浏览器均由 ImGui 呈现加载、失败和取消状态。
3. 资产获取、解析、GPU 上传和 Pipeline 准备均可在加载期间持续产生可见帧与进度。
4. Model Viewer 完成后进入同一套模型、相机、面板和渲染路径。
5. 浏览器 WebGPU 生命周期问题有明确根因和稳定回归，不依赖重跑掩盖失败。

## 发布门槛

- 浏览器首个可渲染帧显示 ImGui 加载面板，HTML 页面不存在可见进度条或重复控制界面；
- 加载进度覆盖资源获取、场景准备、GPU 上传和 Pipeline 准备，且阶段切换单调、可测试；
- 正常、取消、资源失败和设备丢失路径均给出明确状态并完成资源回收；
- Desktop 与 Web 的完成态使用相同 Model Viewer UI 和交互行为；
- Model Viewer 浏览器测试能证明加载期间至少提交一个 ImGui 帧，随后成功显示模型；
- Windows、Linux、Emscripten Node、浏览器 WebGPU、安装 SDK 和文档检查通过；
- 浏览器验收不依赖手工重跑，Validation 和生命周期诊断无错误。

## 待纳入问题

用户发现的其他 Model Viewer 问题将在提供复现现象后逐项评估。只有与本版本目标一致、能够给出
验收条件的问题才加入 S-77；独立渲染功能或公共 API 扩展另建后续任务。
