# ADR-003：Renderer 内部多后端边界

- 状态：提议
- 日期：2026-08-26

## 背景

公共 C ABI 已使用后端无关的句柄和描述结构，但内部 `renderer_state` 与 `renderer_registry`
直接保存 Vulkan 资源、命令和同步类型。直接加入 WebGPU 条件分支会复制生命周期、句柄校验和
错误处理，并使公共前端继续依赖 Vulkan 执行模型。

## 决策

- 保留 `renderer_registry` 作为公共句柄、所有权、生命周期和线程安全的唯一前端。
- 在 Registry 下增加单个内部 `renderer_backend` 契约，按设备、资源、Pipeline、命令、Queue、
  Surface 和能力查询提供粗粒度操作；后端原生类型只出现在各自实现目录。
- Registry 记录保存后端无关描述与拥有型内部资源对象，不保存 `Vk*`、WebGPU 句柄或后端同步状态。
- 命令继续批量记录；不为每次 Draw 或资源访问增加额外动态库调用，也不要求使用虚函数表示每条命令。
- 能力在 Renderer 创建后形成不可变快照。公共请求先按共同语义验证，再由后端验证格式、限制和
  可选能力；不支持的能力返回现有结果码并产生可操作诊断。
- Vulkan 首先迁移为该契约的唯一实现，迁移阶段不得改变公共行为。WebGPU 仅在契约通过 Vulkan
  回归和测试替身验证后接入。
- 后端选择、能力查询和多种 Shader 输入属于后续公共 ABI 设计；内部边界不提前锁定 Dawn、
  wgpu-native 或公共枚举布局。

## 影响

- 句柄表、资源父子关系、延迟销毁和 C/C++ 包装可在后端之间复用。
- Vulkan 的资源状态与提交细节移入 Vulkan 实现，WebGPU 可以使用自身的隐式状态和异步模型。
- 初期会增加一层内部适配和迁移工作，但调用粒度保持在资源或命令批次级，性能风险可测量。
- SPIR-V 专用 Shader 描述暂时保留；WebGPU Shader 契约必须在 S-10C 单独扩展。

## 替代方案

- **复制完整 Renderer 实现并用编译开关选择**：落地快，但会复制句柄、验证和生命周期逻辑，拒绝。
- **让 Registry 保存联合体形式的原生句柄**：改动较小，但前端仍持续理解每个后端，拒绝。
- **先公开后端枚举再重构内部实现**：会形成没有能力模型支撑的 ABI 承诺，推迟到内部原型之后。
