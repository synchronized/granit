# 0.24.0 句柄类型安全本地验收

## 触发问题

AssetTools 的 Shader、Material、Texture、Environment 结果原本由各自从 1 起步的整数计数器分配。
不同领域同时存在数值相同的句柄时，误传句柄可能命中另一个领域的结果。Pipeline 的 Environment
Map 与 Debug Draw List 也重复使用 `0x45` 类型标记。

## 实施结果

- Core 内部集中登记 Renderer、Pipeline 与 AssetTools 的句柄类型，编译期检查类型值唯一。
- AssetTools 六类句柄使用共享对象句柄表，编码类型、generation 和槽位；销毁后旧句柄失效，槽位
  复用不会让旧句柄命中新对象。
- Environment Map 改用独立类型标记；公共 typedef、函数签名、资产字节和内容 ID 均未改变。
- C11 行为测试验证四个资产领域的跨类型传递、跨类型销毁、重复销毁和槽位复用；Core 单元测试
  验证查询对象保活；Pipeline 测试验证 Environment Map 与 Debug Draw List 的双向交叉调用。

## 本地验证

- Windows Clang 共享库 Debug 完整构建、91/91 测试通过。
- Windows MSVC 共享库 Release 完整构建、87/87 测试通过，包含 ABI 导出测试。
- Windows Clang 静态库 Release 完整构建、81/81 测试通过。
- 干净 MSVC 安装目录的导出审计通过；Core、RenderPipeline、Window、Input、AssetTools 的独立
  安装 Consumer 及版本、component 选择矩阵通过。

远端 Linux、Emscripten 与发布候选验收仍按 0.24.0 的统一分支执行。
