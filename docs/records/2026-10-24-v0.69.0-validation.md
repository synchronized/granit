## 验收发现与修复

- 最小 CPU 探针证实 generation 完整回绕后旧句柄与新句柄相等并重新可查找；
  资源表与共享表改为耗尽后退役槽位，两个真实完整 generation 空间回归在 Clang 18 下通过。
  GPU 长测同时保留最早销毁的 Buffer 身份，防止只检查上一代句柄遗漏历史复活。


- Shader 逻辑名称的十六进制缓存文件名会随名称长度翻倍，在静态构建目录触发 Windows 路径限制；
  改为固定 SHA-256 文件名，新增长名称构建和缓存命中回归。

  Frame Context、Resource Table 和 Sampler。优化构建调试栈定位后，两个原有 Smoke 均通过。
- MSVC 严格警告发现 Bindless 测试局部变量遮蔽，重命名局部变量，保留警告级别。
- Unlit 精确像素测试的 0.5 输入落在 UNORM 舍入边界；改用目标码值除以 255，保留精确相等断言。
- Windows Clang 资源重编译时，当前工具链把 GNU 行标记交给 SDK rc.exe 而失败并阻塞输出；
  同一预处理文件由 llvm-rc 成功编译，最小 CMake DLL 资源构建通过。preset 显式选择 llvm-rc，
  完整项目的 RC 步骤与 Clang 22 共享库构建已通过，最终完整回归待执行。
- 普通 test preset 默认排除 `stress`；显式长测入口覆盖排除规则，防止启用后误跑长测。

查询 32 字节、导出返回 20 字节，而头部长度仍为 32；不依赖 Granit 即可复现。
[对应 Mesa 上游代码](https://chromium.googlesource.com/external/gitlab.freedesktop.org/mesa/mesa/+/ec071eb25d7fd923e836569277da6c5e81030444/src/gallium/frontends/lavapipe/lvp_pipeline_cache.c)

对照验收使用 Arch 官方归档的 Mesa 26.2.3 与 LLVM 22.1.8，均已校验软件包签名，
只解包到虚拟机的 `build/driver-probe/`。通过进程级 `VK_DRIVER_FILES` 与
`LD_LIBRARY_PATH` 选择，不降级系统软件、不修改第三方源码。对照驱动正确返回 32 字节，
上述 Linux 原生完整与安装验收均在该环境通过。26.2.4 的失败报告仍保留。

### 2026-10-25 泄漏分配模块定位

在原有 ASan 构建上重跑全部八个失败用例及独立 `vkcube --c 3`，九个进程继续报告泄漏。
使用仅记录 `/proc/self/maps` 后调用原始 `dlclose` 的临时诊断探针，保持正常模块卸载，
没有 `RTLD_NODELETE`、预载驻留 ICD 或泄漏抑制。`detect_leaks=1`、`halt_on_error=1`，
另用 `fast_unwind_on_malloc=0` 保存分配调用栈。

卸载前映射与报告地址逐项匹配：九个进程的所有原未知模块栈帧均位于同一份
`libvulkan_lvp.so`，每个泄漏分配的首个调用点均落在文件偏移 `0x4cf563` 或 `0x4cf57b`。
独立 `vkcube` 与八个 Granit 用例的分配位置一致；分配由该 Lavapipe 驱动路径发起，
不再只是根据泄漏字节数相似推测。测试进程的泄漏检查仍失败，不能写成已修复。
