# S-67：0.34.0 公共 SDK 与 AssetTools 契约收敛

## 状态

**已完成，P1。** 0.34.0 已统一 AssetTools 构建结果的查询模型，补齐 component 级跨版本 ABI
兼容检查，并完成普通 C++ 用户路径与安装 SDK 验收收口。

## 背景与目标

0.33.0 已让 Shader Library 源构建返回可拥有的结构化结果，并统一 Shader 工具链的 CI 与安装 SDK
入口。当前剩余问题集中在公共契约：Texture、Material、Environment 仍通过多个 getter 查询结果，
Shader Library 使用单个 `get_info`；ABI 快照只检查当前导出集合，不能区分稳定候选 component 的
兼容新增与实验性 component 的显式破坏性变化；Model Viewer 浏览器验证仍有一处普通 C++ 调用路径
向下传递裸 Renderer 句柄。

0.34.0 完成以下工作：

- 为四类 AssetTools 构建结果统一 `result_info` 与单次 `result_get_info` 查询形式。
- 删除被统一查询取代的实验性 getter，不为尚未稳定的 0.x API 保留重复入口。
- 以 0.33.0 为跨版本基线，检查稳定候选 component 不删除旧符号，实验性破坏必须显式登记。
- 明确 Core、Renderer、Window、RenderPipeline 与 AssetTools 的稳定等级和进入稳定版本的门槛。
- 清理普通示例中的裸 C 句柄传递，并继续验证安装 SDK 的 C/C++ 与图形工作流。

## 非目标

- 不承诺 0.34.0 已提供稳定 ABI，也不改变 0.x 兼容策略。
- 不改变 `.grshlib`、`.grmat`、Texture Asset 或 GRENV 格式。
- 不新增 Bindless、透明 PBR、Clustered Forward、公共 glTF SDK 或线程池。
- 不把 AssetTools 的领域输出强行合并成无类型通用字节接口。

## 已确认决策

- 每个领域保留强类型结果句柄和领域专用 `result_info`；字段名称反映 archive、package、manifest 等
  实际含义，查询、生命周期和失败语义保持一致。
- `result_info` 中的指针均由结果句柄持有，在句柄销毁前有效；无对应输出时返回空视图。
- C++ 包装提供一次 `info()` 查询和原有语义化便利访问器，便利访问器不产生第二套运行时状态。
- Core、RenderPipeline 与 Window 作为稳定候选，跨版本检查禁止删除已有公开符号；AssetTools 继续
  实验性，破坏性变化必须列入显式清单和 Changelog。
- 当前版本的精确导出快照统一保存到 `0.34.0`，历史快照继续作为兼容基线保留。

## 实施顺序

1. **S-67A AssetTools 结果查询**：统一 C ABI、C++ RAII、实现、CLI 和测试。
2. **S-67B C++ 用户路径**：清理示例中非互操作场景的裸句柄传递并复查公共包装。
3. **S-67C 跨版本 ABI 门禁**：统一当前快照，增加兼容子集和显式破坏清单检查。
4. **S-67D 稳定等级与安装验收**：更新兼容参考并扩展安装 Consumer 契约验证。
5. **S-67E 0.34.0 收口**：完成 Changelog、本地与远端矩阵并正式发布。

## 测试与验收

- C 与 C++ 测试覆盖四类结果的成功、失败、空视图、错误类型、销毁和重复销毁。
- AssetTools CLI 与现有资产生成流程继续输出相同格式和确定性字节。
- 稳定候选 component 相对历史基线不存在未登记删除；AssetTools 的移除符号与新增符号可审计。
- 普通示例不通过 `native_handle()` 绕过已有 C++ 包装；原生互操作和 C ABI 专项测试不受限制。
- Windows/Linux shared 与 static、Emscripten、安装 Consumer、Documentation 和
  `git diff --check` 通过。

## 最终结果

- 四类 AssetTools 结果已统一为强类型 `result_info` 和单次 `result_get_info` 查询；0.33.0 的十个
  分散实验性 getter 已删除，并提供迁移指南。
- Core、RenderPipeline、Window 和 AssetTools 已建立 0.34.0 精确快照及跨版本兼容门禁；稳定候选
  禁止删除历史导出，实验性破坏必须与独立清单完全一致。
- 安装 SDK Consumer 已覆盖新的 C11/C++20 结果查询，普通示例中的 Renderer/Window 传递使用
  强类型引用。
- 本地 shared、static、Emscripten 和文档检查，以及 PR 的 Windows、Linux、Emscripten、浏览器与
  Documentation 矩阵全部通过；`v0.34.0` 已发布并完成公开附件摘要复验。

## 风险与未决问题

- AssetTools getter 删除会破坏 0.33.0 源码与 ABI；该 component 仍为实验性，迁移只需改为一次
  `get_info` 查询，必须在 Changelog 中明确列出。
- 稳定候选只表示准备接受兼容约束，不代表已经发布稳定承诺；结构布局和行为门槛仍需后续验证。
- `result_info` 会扩大栈上值结构，但只发生在工具构建与检查路径，不属于逐帧性能热点。
