# S-72：0.39.0 Asset Manager 与任务系统

## 状态

**已完成，P1。** 本任务以 `examples/common` 为验证边界，把现有资产读取零件收敛为单一
`asset_manager`，并提取可注入的示例任务系统。版本目标为 `v0.39.0`，不新增 Granit 公共 C ABI，
也不把示例实现提前声明为稳定 SDK。

## 背景与目标

现有 Example Asset System 已经隐藏 Desktop 与 Web 的读取差异，但调用方仍需理解
`asset_system`、`asset_request`、`asset_batch`、`resource_resolver` 和 `document_loader`。资产来源、
格式解析、复合资产依赖和任务推进分散在多个入口中，教程与 Model Viewer 仍需手工组合这些零件。

本版本完成以下收敛：

- 普通调用方只通过 `asset_manager::load<T>()` 加载资产；
- `load<T>()` 只有异步语义，立即返回强类型 `asset_handle<T>`，不阻塞调用线程；
- Source 与 Loader 使用显式注册进入 Manager，平台和格式扩展不修改 Manager 核心；
- Source 只读取字节，Loader 只解析格式、发现依赖并生成 CPU 资产；
- 单个句柄可查询状态、阶段、字节和依赖进度，`asset_group` 汇总一次加载流程；
- 提取独立 `task_system`，由应用拥有并注入 Manager，Manager 不私自创建线程池；
- Application Host 自动推进任务和发布完成结果，Tutorial 不再手工 `poll()`；
- 删除已被取代的 Example Asset System 入口，不保留兼容转发。

## 非目标

- 不在本版本发布公共 VFS、公共 Asset Manager 或公共 Executor ABI；
- 不让 Asset Manager 接管 Renderer、GPU 资源创建、Window 循环或 Render Graph；
- 不把 Model Viewer 的帧替换、GPU 线程归属和控制任务顺序降级为普通后台任务；
- 不增加目录枚举、资产写入、热重载、分布式缓存或内容数据库；
- 不要求 Web 使用 pthread；Fetch 和浏览器回调继续采用浏览器原生异步机制；
- 不为旧 `asset_system`、`asset_batch` 或 Resolver 调用方式保留适配层。

## 已确认设计

### 单一应用入口

应用只观察 Manager、强类型句柄和可选 Group：

```cpp
auto group = assets().create_group();
auto model = group.load<gltf::scene>(
    asset_location::bundled("models/Suzanne.gltf"));
auto environment = group.load<environment>(
    asset_location::external(environment_location));
```

`asset_location` 表达 bundled 或 external 等稳定意图。普通调用方不创建 Mount，不拼接平台文件路径，
也不选择文件系统、MEMFS 或 Fetch Source。Manager 内部可以继续使用规范逻辑路径和私有 Mount 表，
但这些类型不进入业务接口。

`load<T>()` 返回后句柄至少处于 queued 状态。即使内存 Source 或 inline executor 可立即完成工作，
结果也只能在后续完成发布阶段变为 ready 或 failed，保证 Desktop、Web 和测试具有相同可观察语义。

### Source 注册

`asset_source` 只负责把位置异步读取为自有字节和读取元数据，不解析 PNG、glTF 或 Granit 资产格式。
Source 由平台组合入口显式注册：

```text
examples/common/platform/
├─ desktop/
│  ├─ register_asset_sources.cpp
│  └─ filesystem_asset_source.cpp
└─ emscripten/
   ├─ register_asset_sources.cpp
   ├─ memfs_asset_source.cpp
   └─ fetch_asset_source.cpp
```

不同平台分别编译同名 `register_platform_asset_sources(asset_manager&)`，公共资产代码不使用平台宏。
重复 Scheme、缺少必需 Source 或注册发生在首次加载之后均返回明确错误。禁止全局静态自注册，避免
初始化顺序、链接裁剪和测试间共享状态。

### Loader 注册

`asset_loader` 接收字节、元数据和 `asset_load_context`，负责解析目标类型并通过 Context 请求相对
依赖。Loader 由 `register_standard_asset_loaders()` 显式注册，测试可以只注册目标 Loader。

Loader 选择首先依据 `load<T>()` 的目标类型，再结合媒体类型、扩展名和文件头；不能只相信扩展名。
glTF Loader 负责解析主文档、发现 Buffer 与图片依赖，并让 Manager 把依赖纳入同一请求图和 Group。
Importer 不再要求调用方预先构造 `memory_resource_resolver`。

### 异步句柄与缓存

`asset_handle<T>` 提供 queued、reading、discovering_dependencies、loading_dependencies、decoding、
ready、failed 和 cancelled 状态，以及只读结果、诊断与进度快照。句柄复制共享观察权，不暴露
Source、Loader 或任务对象。

同一规范位置、目标类型和加载选项的并发请求合并到底层同一任务。取消一个句柄只取消该观察者；
仅在没有其他句柄、Group 或缓存策略需要结果时，Manager 才取消底层任务。失败不会把部分解析结果
发布为 ready。

### 进度模型

单个句柄报告当前阶段、已读取字节、可选总字节、已完成依赖和可选依赖总数。只有 Loader 能提供
可信工作总量时才报告 `fraction`；未知长度和动态发现依赖时不伪造百分比。

`asset_group` 统计由该 Group 发起的根请求及其递归依赖，提供完成数量、失败数量、字节与可选总
进度。Manager 的全局 `stats()` 只用于诊断活动请求、缓存命中和失败，不作为加载界面的稳定总进度。

### Task System

示例私有 `task_system` 独立于资产模块，提供 worker、main completion 和 inline 三种 Executor 视图：

- Desktop 使用 worker 执行阻塞文件读取和 CPU 解码；
- Web Source 使用 Fetch 等平台异步入口，CPU 工作可先以内联任务推进；
- 测试使用 inline executor，但完成结果仍延迟到显式发布阶段；
- Application Host 每个 Tick 推进 main completion，Tutorial 不直接调用 Manager 的内部泵。

Task System 由 Application Host 或上层应用拥有，通过描述传给 Asset Manager。Manager 析构前停止
接收新请求并取消自身任务，但不销毁外部 Task System。回调捕获的数据必须由任务拥有，完成回调只在
声明的 completion executor 上运行。

Model Viewer 的 `render_task_executor` 保留专用语义。它可以复用 Task System 的队列或线程设施，
但帧替换、GPU 所属线程、控制任务顺序、flush 和停止协议仍由 Render Executor 负责。

## 测试与验收

- `load<T>()` 从不阻塞，结果不会在返回前对调用方变成终态；
- inline、Desktop worker 与 Web Fetch 对相同请求产生一致状态顺序和错误分类；
- Source/Loader 重复注册、缺失注册、错误格式和不匹配目标类型均返回确定错误；
- 请求合并、缓存命中、单观察者取消、最后观察者取消和 Manager 析构没有悬空任务；
- glTF 外部 Buffer、图片、Data URI、缺失依赖、路径逃逸和循环依赖具有覆盖；
- 单资源与 Group 在未知长度、动态发现依赖、失败和取消时报告一致进度；
- Tutorial 和 Model Viewer 业务代码不出现 Mount、Batch、Resolver、Source、Loader 或手工轮询；
- Desktop Vulkan 与浏览器 WebGPU 示例加载相同 bundled 资产并获得相同内容；
- `render_task_executor` 的帧替换、顺序、flush 和停止测试继续通过；
- Windows/Linux shared、Emscripten 编译、Chrome 行为与文档检查通过。

## 风险与未决问题

- 通用类型擦除不能跨动态库边界依赖 `std::type_index`；当前示例私有实现可使用模板门面，但内部
  Type ID 应预留迁移到显式稳定标识的路径。
- 动态发现依赖会改变总数量；UI 应优先展示阶段和原始计数，只在总量可信时展示百分比。
- 缓存必须限制所有权和失效策略，首版只做进程内读取/解析结果缓存，不实现磁盘缓存。
- 大型解码任务若在 Web 主线程产生明显卡顿，再以测量结果决定引入 Web Worker；本版本不提前要求。
- 只有至少第二个仓库外使用者需要相同 Manager/Executor 契约时，才另行规划公共 SDK 与 C ABI。
