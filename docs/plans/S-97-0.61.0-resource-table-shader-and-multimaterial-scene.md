# S-97：0.61.0 Resource Table 实际 Shader 采样与多材质场景

## 状态

**已确认，实施中（2026-10-13；S-97A 部分完成）。** 承接 v0.60.0 已完成的 Resource Table 材质契约、生命周期保护
和回退路径。本版本的判断标准从“资源表可以创建和更新”提升为“Vulkan Shader 实际通过资源表索引
并采样纹理”。

## 背景与目标

v0.60.0 的 Tutorial 12 已加载 Suzanne 的 BaseColor 和 MetallicRoughness 纹理，也填充了 Resource
Table，但最终绘制仍使用传统 Bind Group。因此它验证了资源持有和回退契约，没有验证 Resource Table
对实际纹理采样和多材质绘制的价值。

本版本目标是：

- 增加真正读取 Resource Table 纹理/采样器数组的 Vulkan Shader 变体；
- 让 Material、Pipeline Layout、Shader 反射和绘制绑定保持一致；
- 将 Tutorial 12 升级为多材质、多纹理、多 Draw 的可见场景；
- 使用 Bind Group 作为对照路径，记录绑定次数、CPU 开销、GPU 时间和变体数量；
- WebGPU 无原生 Resource Table 时继续使用合法的 Bind Group 回退。

## 非目标

- 不把 Resource Table 设为默认绑定路径；
- 不把 WebGPU Bind Group 回退描述为 bindless；
- 不实现 SVT、纹理驻留、预算管理、虚拟地址或自动流送；
- 不迁移 Model Viewer 或 Tutorial 01～11；
- 不按 alpha、skinning、lighting 等功能继续增加独立绑定模型维度；
- 不为了三角形数量引入难以复现、体积过大的外部模型依赖。

## 已确认决策

| 项目 | 决策 |
|---|---|
| Vulkan | 实现真正的 Resource Table Shader 纹理/采样器索引和采样 |
| WebGPU | 继续使用 Bind Group 回退，保持结果和错误语义合法 |
| 默认路径 | Bind Group 仍是默认路径，Resource Table 必须显式选择 |
| Shader 来源 | HLSL-first，由 AssetTools 生成后端代码和布局反射 |
| Tutorial 12 | 保留名称，升级为真实模型 + 可控材质网格的双层验证场景 |
| 真实模型 | 使用中等复杂、可审计的轻量多材质 glTF，不直接引入大型外部场景 |
| 压力规模 | 16～32 材质、16～32 张纹理、16～64 个 Draw 作为首轮固定规模 |
| 资源生成 | 优先使用仓库内生成的确定性纹理和 glTF，避免下载依赖与版权不确定性 |
| 材质包格式 | 不新增公开扩展名；扩展现有 `.grmat`，由一个包承载公共材质数据和多个后端 implementation |
| Vulkan 专用载荷 | Resource Table implementation 只要求 Vulkan SPIR-V，可不生成 WGSL |
| 应用层体验 | Material 层按 Renderer 能力选择 implementation，应用不重复维护模型、纹理和参数 |

## 实施顺序

1. **S-97A：Shader 绑定模型与反射**
   - 定义 Resource Table 的纹理/采样器数组布局；
   - 扩展 AssetTools 支持 `vulkan_native` 专用 Shader profile/Library，不强制生成 WGSL；
   - 用反射结果检查 Shader、Pipeline Layout 和 Material 描述的一致性；
   - 保持绑定模型选择与其他材质功能正交。

2. **S-97B：Material 与 Pipeline 实际接线**
   - 将现有 `.grmat` 归档升级为 v6 implementation 列表；implementation 列表是唯一绑定来源，
     不保留 v6 之前布局的运行时兼容分支；
   - 公共材质参数和资源声明只保留一份，后端实现分别保存绑定模型和 Shader 载荷；
   - 根据 Renderer 能力选择 Vulkan Resource Table 或 Bind Group implementation；
   - 让 Resource Table Material 变体在 Vulkan 绘制中真正绑定资源表；
   - 传递材质纹理索引，而不是只更新 Resource Table slot；
   - 保留 Bind Group 对照和 WebGPU 回退；
   - 补充不支持能力、索引越界、缺失资源和布局不匹配的负向测试。

3. **S-97C：Tutorial 12 多材质场景**
   - 新增轻量多材质 glTF；
   - 增加 4×4 可控材质网格；
   - 使用 16～32 张确定性纹理覆盖 BaseColor、Normal、MetallicRoughness 等组合；
   - 提供 Resource Table、Bind Group 和压力模式切换；
   - UI 显示材质索引、纹理槽位、Draw 数量和实际绑定模式。

4. **S-97D：压力对照**
   - 固定 4/16/32 材质和 8/32/64 Draw 档位；
   - 记录 Bind Group 创建/更新次数、Resource Table 更新次数、CPU 提交时间、GPU 时间、
     Descriptor 写入数量、构建时间和 Shader 变体数量；
   - 形成可重复的本地和 CI smoke/压力命令。

5. **S-97E：跨平台收口**
   - Windows Vulkan 验证真实 Resource Table Shader；
   - Linux Lavapipe 验证校验层、能力查询和回退；
   - Chrome WebGPU 验证 Bind Group 结果一致；
   - 不支持设备验证明确回退或失败，不生成非法能力声明。

### 阶段边界

S-97A/S-97B 先允许构建系统生成独立的 Vulkan Resource Table 实验载荷，以降低工具链改造风险；
最终交付仍必须合并到同一个 `.grmat` 多 implementation 归档中。独立载荷只能作为构建中间产物，
不作为新的公开材质文件类型。

当前已完成的 S-97A 子项：源 JSON 支持 implementation 列表和逐 Shader implementation 选择；
Material Builder 的 C/C++ 输入支持为每个 Shader Library 指定 implementation ID；`.grmat v6`
归档继续使用 implementation 列表。已增加一个 Vulkan-only 的最小 Resource Table Shader Library
源清单，确认 descriptor array 可在 `vulkan_native` profile 下生成 SPIR-V 且不生成 WGSL；它目前
仍是独立验证载荷，并已通过最小材质探针生成 `.grmat v6`；它尚未接入标准 PBR `.grmat`，真正的纹理索引参数和绘制接线仍属于后续
S-97A/S-97B 工作，尚未宣称完成。Material GPU 实例已明确把传统绑定号转换为按资源类型从 0
开始的 Resource Table 数组槽位，避免把 Bind Group binding 当作 descriptor array index。

## 测试与验收

- Vulkan Tutorial 12 至少显示 16 个不同纹理材质；
- 改变纹理槽位或材质索引后，画面发生确定性变化；
- Resource Table Shader 实际读取纹理数组，不能只验证 slot 已填充；
- Bind Group 和 Resource Table 输出一致；
- WebGPU 不出现未支持的 bindless 声明或布局错误；
- Vulkan 校验层无 descriptor、layout、stage visibility 和数组索引错误；
- 资源缺失、索引越界、能力不足、重复更新和跨 Renderer 句柄均有负向测试；
- 变体数量、构建时间、资产大小、CPU/GPU 数据和已知限制写入验收记录；
- Tutorial 01～11、Model Viewer 和默认 Bind Group 路径继续通过回归测试。

## 风险与未决问题

- **已验证的工具链边界**：当前跨后端 Shader Toolchain 要求 Vulkan SPIR-V 与 WebGPU WGSL
  使用同一 portable 反射契约；descriptor array 会被 portable 目标拒绝。因此 Resource Table
  Shader 不能直接追加到 `pbr_standard` 跨后端库，下一子阶段需要增加 Vulkan 专用 Shader
  profile/Library，并在能力不支持时选择现有 Bind Group implementation，而不是生成非法 WGSL。
- `.grmat` 格式升级会要求重新生成已安装材质包；由于当前仍处于 0.x，不保留旧布局的运行时
  兼容分支，AssetTools 负责在构建期完成转换或重新打包。
- 不同后端对纹理/采样器数组的限制可能要求缩小第一版资源类型；
- 如果真实压力下 Resource Table 没有稳定收益，只保留实验 API，不升级为默认路径；
- 若大型真实模型导致资产、加载或测试不稳定，以可控材质网格作为权威验收负载；
- 若 Shader 变体数量增长失控，回退到运行时绑定模型选择，不增加功能笛卡尔积。
