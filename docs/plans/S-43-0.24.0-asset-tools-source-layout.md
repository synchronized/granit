# S-43：0.24.0 AssetTools 源码布局收敛

## 状态

**实施中。** S-43A 至 S-43D 已经完成，下一步整理 AssetTools 测试布局。本任务统一 AssetTools
的公共路径、内部命名空间、源码目录、格式复用和测试归属。项目仍处于 0.x 阶段，迁移直接删除
旧 include 路径，不保留转发头或名称兼容层。

## 背景与目标

当前 `tools/` 同时保存可安装的 `granit_asset_tools` SDK、`granit_asset_tool` CLI、Shader Library
构建核心、通用进程辅助代码和测试专用 Fixture 工具。公共头位于 `include/granit/tools`，C++ API
却位于 `granit::asset_tools`；内部实现又使用含义过宽的 `granit::tools`。

`tools/CMakeLists.txt` 还直接列出 `src/material` 与 `src/asset_formats` 的实现文件。它让 CLI 目录
反向管理 Runtime 源文件，并在多个目标中重复声明共享格式实现。S-38 确定的 AssetTools 产品边界
已经成立，但源码布局和 S-41 的共享格式层尚未完整收敛。

目标布局为：

```text
include/granit/asset_tools/       # 可安装 C11 API 与 C++20 包装
src/asset_formats/                # Runtime 与 AssetTools 共用的私有格式
├─ shader/
├─ material/
├─ texture/
└─ environment/
src/asset_tools/                  # 可安装 AssetTools SDK 实现
├─ common/
├─ shader/
├─ material/
├─ texture/
└─ environment/
tools/granit_asset_tool/          # CLI 薄适配层
tests/asset_tools/                # AssetTools API 与内部行为测试
tests/support/shader_fixture_tool/# 测试专用资产生成程序
```

## 非目标

- 不改变 `granit_asset_tools_*` C ABI 函数名、句柄语义或结果码。
- 不改变 `.grshlib`、`.grshaderobj`、`.grmat`、`.grtex`、`.grenv` 或索引格式字节。
- 不让 AssetTools 链接 Renderer、RenderPipeline 或 GPU 后端。
- 不把 CLI 文件 I/O、命令行参数或测试 Fixture 功能加入 AssetTools SDK。
- 不增加新的资产领域、图片编解码、纹理压缩或环境光卷积能力。
- 不为 `<granit/tools/...>`、`granit::tools` 或旧源码路径保留兼容入口。

## 已确认决策

### 公共身份统一为 AssetTools

公共头迁至 `include/granit/asset_tools`，CMake target 保持 `granit::asset_tools`，C++ API 保持
`granit::asset_tools::{shader,material,texture,environment}`。导出头改为领域内的 `export.h`。

C API 继续使用 `granit_asset_tools_` 前缀；`.h` 保持 C11 可独立包含，`.hpp` 继续作为调用 C API
的轻量 RAII 包装。迁移同步更新安装 FILE_SET、包审计、C/C++ Consumer、测试和文档。

### 格式代码由格式目录拥有

`src/asset_formats` 按领域建立内部 Object Library：

```text
granit_asset_format_shader
granit_asset_format_material
granit_asset_format_texture
granit_asset_format_environment
```

共享格式不得使用 `granit::tools`：仅供格式实现使用的类型放在 `granit::detail`，与 Runtime
材质模型共同使用的 Package、Metadata 等类型保留 `granit::material`。目标启用 PIC。Runtime 与
AssetTools 只消费所需 Object，不能再从其他目录的 CMakeLists 手工列出格式 `.cpp`。

Material 的 Archive、Metadata、Package 和 Package Archive 属于共享格式；GPU Instance、Hot
Reload、Pipeline Schema 和 Draw Inputs 继续属于 Runtime Material。Material 源 JSON 与调试 JSON
只服务离线构建，迁入 `src/asset_tools/material`。

Shader Library/Object 二进制编解码属于共享格式；HLSL 编译、反射、Source Manifest、Object
Cache、Library Builder 和 Object Storage 属于 AssetTools SDK。

### SDK、CLI 和测试工具分别拥有源码

`src/asset_tools` 构建 `granit_asset_tools`。公开 C ABI 的实现以领域内 `*_api.cpp` 表达，私有类型
使用 `granit::asset_tools::detail`，不再使用 `granit::tools`。

`tools/granit_asset_tool` 只构建命令行程序。它负责参数、文件 I/O、原子替换和退出码，资产语义、
格式编码、反射和缓存全部通过公开 AssetTools API 完成。若现有命令缺少公开能力，应先补足一个
领域明确的 SDK 接口，不能继续直接包含 AssetTools 私有头。

`granit_shader_fixture_tool` 迁至 `tests/support/shader_fixture_tool`，继续允许直接调用测试所需的
私有格式辅助代码，但不安装、不进入正式工具目录。

### 测试按被测边界组织

`tests/tools` 改为 `tests/asset_tools`，并按 shader、material、texture、environment 分目录。C 与
C++ API 测试并列放置；格式 Codec 测试靠近对应资产格式测试；CLI 行为仍由 CMake 脚本驱动。

## 实施顺序

1. **S-43A 契约与构建图**：建立计划和目标依赖图，记录当前文件到目标目录的映射。
2. **S-43B 格式层（已完成）**：按领域迁移 Shader、Material、Texture 和 Environment 格式代码，
   建立内部 Object Library，消除跨目录重复源文件声明。
3. **S-43C AssetTools SDK（已完成）**：迁移公共头和 SDK 实现，统一内部命名空间与安装导出，
   直接删除旧 `<granit/tools/...>` 路径。
4. **S-43D CLI 与测试工具（已完成）**：迁移正式 CLI 和 Fixture Tool，确保正式 CLI 只依赖
   公开 SDK。
5. **S-43E 测试布局**：迁移 `tests/tools`，按领域更新 CTest target、标签、Fixture 路径和文档检查。
6. **S-43F 验收**：验证共享/静态库、C11/C++20 头、构建树与安装 Consumer、AssetTools CLI、
   无完整 Shader Toolchain 的固定快照路径和文档。

每个阶段形成一个独立提交。S-43 使用独立特性分支，待 S-42 合入后再以 `main` 为基线整理提交。

## 测试与验收

- 仓库中不存在 `include/granit/tools`、顶层 AssetTools SDK `.cpp` 或 `granit::tools`。
- `tools/` 只保存可执行程序；`src/asset_tools` 只保存 SDK 实现。
- Runtime 与 AssetTools 共用格式 Object Library，不在多个目标中重复列出同一 `.cpp`。
- `granit_asset_tool` 不包含 `src/asset_tools` 私有头，也不直接实现资产格式算法。
- C11 与 C++20 公共头测试均从 `<granit/asset_tools/...>` 包含成功。
- AssetTools 共享/静态库、CLI、API 测试、安装包审计和独立 Consumer 通过。
- 有完整 DXC/Tint 时 HLSL-first 构建通过；缺少完整工具链时固定 SPIR-V/WGSL 测试路径通过。
- 生成的正式资产与已提交参考快照逐字节一致。

## 风险

- Object Library 同时进入多个共享库时必须保持 PIC，并避免导出私有符号。
- Material 格式与 Runtime 状态当前同目录，移动时必须按职责选择文件，不能移动 GPU 生命周期代码。
- CLI 仍有少量命令直接调用 Source Manifest 私有实现；迁移前需要确认其公开 SDK 等价入口。
- 公共 include 路径是破坏性源码迁移，必须一次同步全部 Consumer 和安装审计，不能留下混合状态。
