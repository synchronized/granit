# S-74：0.39.0 Marching Cubes 教程

## 状态

**已确认，P1。** 本任务新增 `06_marching_cubes`，以 CPU 密度场、网格提取和动态 Vertex Buffer
展示显式 Metaballs 表面，并与 `05_metaballs` 的 SDF Raymarch 路径形成可运行对照。版本目标为
`v0.39.0`，不新增 Granit 公共 ABI。

## 背景与目标

现有 `05_metaballs` 在 Fragment Shader 中执行 SDF Raymarch，不生成真实三角形。它适合验证全屏
程序化渲染，却不能展示密度场采样、等值面提取、动态网格上传和普通 Mesh Pipeline。

本教程参考 bgfx Metaballs 的教学方向，但使用 Granit 当前公共接口重新实现：

- 在 CPU 更新三维标量场和梯度；
- 使用 Marching Cubes 查表提取指定 ISO 的三角形；
- 将实际生成的顶点范围上传到预分配 GPU Vertex Buffer；
- 使用普通 Graphics Pipeline 绘制动态网格；
- 复用 S-73 的 ImGui 主题、性能面板和 Orbit Camera；
- 提供 ISO、Grid Size、动画与表面参数，并显示网格与阶段统计；
- Desktop Vulkan 与浏览器 WebGPU 编译同一主体源码；
- 通过确定性算法测试和跨后端 Smoke 验证结果。

## 非目标

- 不删除或改写 `05_metaballs`；两章分别展示隐式像素求交和显式网格提取；
- 不在首版使用 Compute Shader、GPU Marching Cubes、3D Texture 或 Storage Atomic；
- 不在缺少 Indirect Draw 契约时通过 GPU 回读顶点计数驱动每帧绘制；
- 不新增通用 Geometry Processing、Transient Buffer 或 Mesh Asset 公共 API；
- 不以逐帧最高性能为目标，首版优先保证算法清晰、容量安全和跨后端一致；
- 不复制来源不明或许可证不兼容的查找表。

## 已确认设计

### 教程定位

两种 Metaballs 路径同时保留：

| 教程 | 表面表示 | 主要能力 |
|---|---|---|
| `05_metaballs` | Fragment SDF Raymarch | 全屏三角形、Shader 循环、SDF、程序化法线 |
| `06_marching_cubes` | CPU 提取三角形网格 | 密度场、动态顶点、Buffer 上传、Mesh Pipeline |

`06_marching_cubes` 不隐藏算法核心。密度更新、梯度计算、Cell Case、边插值和三角形输出保留为可读
的教程本地代码；仅复用 Application、Tutorial Runtime、Orbit Camera 和通用数学函数。

### 数据流程

```text
动画球参数
  → 采样 Grid 密度
  → 计算 Grid 梯度
  → 遍历 Cell 并查表
  → 插值 Position / Normal
  → 写入 CPU Vertex Array
  → 上传实际字节范围
  → draw(vertex_count)
```

首版生成非索引三角形，避免在教程中同时引入顶点去重和动态 Index Buffer。顶点包含 Position、Normal
和 Color；法线来自密度场梯度插值，不按三角形重复计算硬边法线。

### 容量与更新

Grid Size 限制为 8～32。按最大 Grid 的理论最坏情况预先计算并验证顶点容量，使用带
`vertex | transfer_destination` Usage 的持久 Buffer。每帧只上传 `[0, vertex_count)` 的有效范围，
不创建或销毁 GPU Buffer。

算法在写入每个三角形前检查剩余容量。任何尺寸乘法、字节数和偏移计算均使用 64 位并检查溢出；
容量不足返回明确错误，不截断为可能破损的网格。

Grid Size 或影响密度场的参数变化时重新计算；动画开启时逐帧更新。暂停且参数未变化时复用上一帧
网格，不重复执行 CPU 提取和上传。

### 面板与统计

章节面板至少提供：

- `ISO`：等值面阈值；
- `Grid Size`：每个轴的采样数量；
- `Ball Count`：参与密度场的球数量；
- `Animation` 与 `Animation Speed`；
- `Wireframe` 仅在后端能力矩阵支持时启用，否则显示不可用原因；
- 当前 Cell、Triangle、Vertex 数量和 Buffer 使用率；
- Density、Gradient、Triangulate 和 Upload 的 CPU 时间。

公共区域继续显示 S-73 的平滑 FPS、CPU Frame、Framebuffer 和帧号。相机复用 Common Orbit
Camera，根据网格边界设置初始 Focus，并支持 Reset 与 Auto Orbit。

### Shader 与 Pipeline

Vertex Shader 接收 Position、Normal 与 Color，使用 Orbit Camera 的 View Projection；Fragment
Shader 提供简单方向光、环境项和基于法线的颜色。Shader 继续通过 HLSL-first Library 生成 SPIR-V
与 WGSL，不提交独立后端源码。

Pipeline 使用普通 Triangle List 和 Depth Test。Wireframe 只在能力查询明确支持 Line Polygon Mode
时切换 Pipeline；WebGPU 不模拟不存在的 Polygon Mode。

### 查表来源

Marching Cubes Edge/Triangle Table 必须满足以下之一：

1. 根据公开算法在仓库内生成，并提交生成器及确定性结果测试；
2. 采用许可证与 Granit 兼容的固定来源，保留许可证、上游版本、链接和修改说明。

不能只复制网络片段。查表数据是教程实现的一部分，需检查索引范围、终止标志和最大三角形数量。

## 实施顺序

1. **S-74A 算法基线**：实现标量场、梯度、Cell Case、边插值、查表和容量检查；通过小型固定场景
   验证三角形数量、范围、法线有限性和确定性摘要。
2. **S-74B GPU 动态网格**：创建最大容量 Vertex Buffer、Depth Target、Shader Library 和普通 Mesh
   Pipeline，只上传有效顶点范围并按实际数量绘制。
3. **S-74C Tutorial Runtime**：接入 S-73 的统一主题、性能面板与 Orbit Camera，增加 ISO、Grid、
   Ball、动画和能力受限的 Wireframe 控制。
4. **S-74D 指标与稳态更新**：记录 Density、Gradient、Triangulate、Upload 时间；暂停时跳过未变化
   工作，Resize 只更新相机与呈现资源。
5. **S-74E 文档与对照**：说明 Marching Cubes 数据流、ISO/Grid 含义、与 SDF Raymarch 的区别及
   CPU 首版边界，不把 GPU 版本描述为已实现。
6. **S-74F 跨平台验收**：加入 Desktop CTest、Emscripten 页面与浏览器任务，纳入 `v0.39.0` 发布
   检查。

## 测试与验收

- 空密度场、全内/全外 Cell 不生成三角形，单 Cell 已知 Case 生成确定拓扑；
- 所有查表边索引有效，每个 Cell 不超过理论最大三角形数；
- 插值顶点、法线、颜色均为有限值，法线在误差范围内归一化；
- Grid Size 8～32 的容量计算不溢出且不越界，非法尺寸被拒绝；
- 固定球参数、ISO 和时间产生确定的 Triangle/Vertex 数量及数据摘要；
- 暂停且参数不变时不重复生成或上传，参数变化后只执行一次必要更新；
- Vulkan 与 WebGPU 绘制同一生成网格，Resize 后继续渲染；
- WebGPU 明确禁用 Wireframe，不返回含糊的 Pipeline 创建失败；
- Smoke 固定 Grid、ISO、球参数和时间，验证非零网格、非空 UI Canvas 和资源完整释放；
- Tutorial 文档解释显式网格与 SDF Raymarch 的差异，并准确标出 CPU/GPU 边界；
- Windows/Linux、Emscripten 编译、Chrome 行为和文档检查通过。

## 后续 GPU 版本的进入条件

GPU Marching Cubes 另立任务，至少需要先确认：

- Compute 写 Storage Buffer 与计数器的跨后端布局和同步；
- 动态输出容量、溢出诊断和资源屏障；
- `draw_indirect` 或等价的不回读顶点计数绘制路径；
- Vulkan 与 WebGPU 对 Atomic、Buffer Usage 和限制查询的共同契约；
- 相对 CPU 版本存在可复现的性能收益。

条件未满足时不在本教程中加入每帧同步回读或后端特例。
