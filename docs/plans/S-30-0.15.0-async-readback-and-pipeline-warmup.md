# S-30：0.15.0 异步回读与管线预热

## 状态

- 路线图任务：S-30
- 目标版本：0.15.0
- 优先级：P1
- 状态：已确认
- 前置依赖：S-28、S-29

## 背景与目标

0.13.0～0.14.0 已建立统一异步操作、Timestamp 异步读取和有界异步上传，但截图、拾取、离屏结果
导出等 GPU 到 CPU 路径仍需调用方自行组织拷贝、等待和映射。Shader 与 Pipeline 创建也仍可能在
首次使用时产生明显卡顿。

0.15.0 建立后端无关的异步 Readback，复用现有 `granit_async_operation` 状态、取消和生命周期语义；
同时提供可批量预热且可缓存的 Pipeline 准备路径，把不可避免的编译成本移出交互帧。两项能力都
服务上游调度，不引入公共线程池。

## 非目标

- 不把文件写入、图片编码、网络传输、资产缓存或任务线程交给 Granit。
- 不承诺取消已经提交给 GPU 的拷贝或驱动已经开始的 Pipeline 编译。
- 不让异步 API 接受调用方短生命周期的裸输出指针。
- 不在本版本异步化 Renderer/Device 创建、普通句柄销毁或所有轻量查询。
- 不增加桌面 Dawn、Android、公共 glTF SDK、TAA、Bindless 或新的渲染后端。

## 已确认决策

### 异步 Readback

- Buffer 与 Texture 回读共用一种有界 Readback Batch；一次批次可记录多个区域，减少动态库调用、
  后端提交和异步句柄数量。
- 提交返回 `granit_async_operation`。结果只在操作成功后通过显式查询大小和复制接口读取，不把
  调用方内存跨帧交给后端持有。
- Texture 结果携带格式、宽高、层级以及实际 `row_pitch`/`slice_pitch`，不假设 Vulkan 与 WebGPU
  具有相同对齐规则；复制接口可选择保留原始布局或紧密重排。
- 批次具有最大暂存字节数和操作数，并在分配或复制前返回 `NOT_READY`；单项永远无法容纳时返回
  `INVALID_ARGUMENT`。
- 销毁公开异步句柄后，内部工作和源资源仍保持到安全完成；Renderer 关闭前可请求取消并排空内部
  状态，但不在浏览器主线程同步等待。

### Pipeline 预热

- 第一阶段提供批量预热入口，而不是复制一套异步 Pipeline 创建 API；输入继续使用现有图形/计算
  Pipeline 描述，输出按条目记录成功、失败和诊断。
- 预热返回统一异步操作；已创建 Pipeline 进入现有缓存/Registry，后续相同描述应复用结果或显著
  降低创建成本。
- Vulkan 优先复用现有 Pipeline Cache 导入/导出；WebGPU 使用设备实际提供的异步管线创建能力，
  若平台只能同步创建，则必须通过能力查询明确报告，不伪装为非阻塞。
- Pipeline 身份必须由规范化描述、Shader 内容 ID、后端、设备能力和缓存格式共同决定；不得使用
  进程内句柄值作为可持久化缓存键。
- 预热失败不使整个 Renderer 失效；调用方可以读取逐项结果，并决定降级 Shader 变体或功能路径。

## 实施顺序

1. **S-30A Readback 契约**：确定批次描述、结果布局、大小查询、结果复制、容量背压及 C/C++ API。
2. **S-30B 双后端 Readback**：实现 Vulkan Fence/Staging 与 WebGPU Copy/Map Async，在相同状态机上
   覆盖完成、失败、取消、提前销毁和 Device Lost。
3. **S-30C Readback Consumer**：迁移截图、像素探针和拾取 Fixture，证明主线程不需要同步等待 GPU。
4. **S-30D Pipeline 预热**：实现批量描述、能力查询、逐项结果和稳定缓存键，并接入 Vulkan Cache
   与浏览器 WebGPU 异步创建路径。
5. **S-30E 性能与发布验收**：记录冷启动/预热后首帧、回读延迟和主线程最长停顿，完成跨后端、
   安装 Consumer、浏览器和 Release 矩阵。

## 测试与验收

- Buffer/Texture 多区域回读在 Vulkan 和 WebGPU 返回一致内容；行距差异通过结果元数据正确表达。
- 提交、轮询、复制结果的全过程不阻塞浏览器主线程；未完成时稳定返回 `NOT_READY`。
- 覆盖空批次、越界区域、容量不足、取消竞态、提前销毁句柄、源资源提前销毁和 Renderer 关闭。
- 公共资源统计包含仍由调用方持有的 Readback Batch 与异步操作，安全完成后全部归零。
- Pipeline 预热覆盖图形/计算、部分失败、重复条目、缓存导入/导出、能力不支持和 Device Lost。
- 预热后的正式 Model Viewer 首次交互帧不再触发已知 Pipeline 冷编译；性能记录给出可复现数据，
  不使用没有基线依据的固定百分比门槛。
- Windows、Linux、Emscripten、共享/静态、C/C++ Consumer、文档和 Release 预验证全部通过后才
  提升并发布 0.15.0。

## 风险与未决问题

- WebGPU 回读的 Map 回调依赖浏览器事件循环；自动化必须验证真正让出主线程，而非忙轮询。
- Pipeline Cache 数据通常绑定驱动和设备；公共契约必须允许拒绝不兼容缓存，不能承诺跨设备复用。
- 若真实性能数据表明 Pipeline 预热无法在无公共执行器的条件下保持非阻塞，应先收窄为能力查询与
  显式预热阶段，不在本版本扩张线程模型。
- Readback Batch 是否允许提交后立即复用，应以结果对象所有权实现验证为准；不得让后续 reset
  覆盖尚未复制的结果。
