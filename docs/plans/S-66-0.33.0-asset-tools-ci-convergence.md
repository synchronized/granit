# S-66：0.33.0 AssetTools 诊断与 CI 收敛

## 状态

**实施中，P1。** 0.33.0 将补齐 Shader Library 源构建诊断，统一锁定 Shader 工具链在 CI 和
安装 SDK 中的使用入口，并减少文档与版本准备变更触发的重复平台构建。

## 背景与目标

0.32.0 已让安装后的 shared SDK 能从 HLSL 清单生成 `.grshlib` 并完成首个 Draw，但当前工作流仍有
四处割裂：Library Builder 只返回结果码和缓存命中状态，CLI 会丢失 DXC/Tint 的具体诊断；各平台
Workflow 重复恢复工具链并硬编码版本目录；文档与版本身份变更会启动完整平台矩阵；独立 Consumer
还需要手写 AssetTools CLI 命令。

0.33.0 完成以下工作：

- 为 Shader Library 源构建提供可拥有的结果对象，暴露缓存状态和稳定诊断文本。
- 用仓库内统一入口下载、校验并输出锁定 Shader 工具链根目录，Workflow 不依赖版本目录名称。
- 根据变更范围保留必要门禁，避免纯文档与版本准备重复运行完整平台矩阵。
- 安装并验证公共 Shader Asset CMake helper，让源码树和安装 SDK 共享同一构建声明。

## 非目标

- 不改变 `.grshlib`、`.grshaderobj` 或其他资产格式。
- 不把 DXC/Tint 并入 Granit 基础运行时库，也不引入网络运行时依赖。
- 不新增公共 VFS、异步任务系统或 Shader 源语言。
- 不降低代码、ABI、安装 Consumer 和正式 Release 的现有门禁。

## 已确认决策

- Shader Library 构建结果遵循 Material、Texture 与 Environment Builder 的句柄所有权模式。
- 参数结构错误可以不产生结果句柄；已开始的清单解析、工具发现和编译失败应尽量保留诊断。
- C++ 包装以移动式 RAII 结果对象表达缓存命中与诊断，不要求调用方管理原生句柄。
- CI 通过单一本地 Action 获得已验证的工具链根目录，后续步骤只消费 Action 输出。
- Pull Request 的纯文档和版本身份变化由 Quick Check 验证；平台 Workflow 仍可手动完整运行，
  正式 Release 始终执行完整 Windows、Linux 和安装 SDK 矩阵。
- 安装 SDK 的 Shader helper 复用 `granit_add_hlsl_shader_library`，自动选择源码目标或安装后的 CLI。

## 实施顺序

1. **S-66A 结构化 Library Builder 结果**：补齐 C ABI、C++ RAII、CLI 诊断与失败测试。
2. **S-66B Shader 工具链 CI 入口**：增加本地 Action，删除 Workflow 中的版本目录硬编码。
3. **S-66C 变更范围门禁**：让纯文档和版本准备只运行适合其风险的检查。
4. **S-66D 安装 SDK Shader helper**：安装 CMake 模块并让独立 Triangle 从源码复用它。
5. **S-66E 0.33.0 收口**：完成文档、Changelog、本地与远端矩阵并正式发布。

## 测试与验收

- C 与 C++ 测试覆盖结果句柄成功、失败诊断、错误类型、销毁和重复销毁。
- CLI 在 Shader 编译失败时输出来自 DXC/Tint 的具体诊断和对应 Shader 逻辑名称。
- Workflow 不再出现 `granit-shader-toolchain-v...` 目录硬编码，并统一消费工具链入口输出。
- 纯文档或版本身份 Pull Request 不启动完整 Windows、Linux、Emscripten 矩阵；手动触发不受影响。
- 安装目录包含 Shader Asset CMake helper，独立源码 Triangle 仅通过安装 package 构建。
- Windows/Linux shared SDK、源码 static、Emscripten、Documentation 与 `git diff --check` 通过。

## 风险与未决问题

- 新结果句柄会扩大实验性 AssetTools ABI；项目仍处于 0.x，本版本直接替换旧签名并同步所有调用方。
- GitHub Workflow 路径过滤可能影响分支保护的必需检查设置；合并前需验证实际 PR 检查状态。
- 首次恢复工具链仍依赖 GitHub Release 下载；统一入口只消除目录知识和重复脚本，不改变供应链来源。
