# S-73：0.39.0 统一交互式 Tutorial

## 状态

**实施中，P1；S-73A 已完成。** 本任务统一当前五个 Tutorial 的 ImGui 生命周期、主题、性能面板、
相机和章节参数，
让每个示例既能展示渲染结果，也能交互验证对应能力。版本目标为 `v0.39.0`，主要实现位于
`examples/common` 与 `examples/tutorials`；Instancing 会对实验性的 Mesh Draw 接口做一次聚焦调整，
使实例数量成为逐次 Draw 参数，而不是只能在 Mesh 创建时固定。

## 背景与目标

当前 Cube 与 PBR Assets 已接入 ImGui，但没有统一使用现有 Granit 主题；Instancing、Raymarch 和
Metaballs 没有面板，新增 Marching Cubes 也需要相同交互基础。六个 Tutorial 若分别管理 ImGui
Context、字体、输入、Canvas、帧指标和相机，继续在每个 `main.cpp` 中复制会掩盖教程真正要展示的
渲染能力。

本版本完成以下收敛：

- 五个现有 Tutorial 使用同一个 Granit ImGui 主题、字体、输入和 Canvas 捕获流程；
- 五个现有 Tutorial 至少显示平滑 FPS、CPU 帧时间、Framebuffer 尺寸和帧号；
- 建立 Tutorial 专用运行时，章节只实现内容初始化、参数面板与内容渲染；
- 将 Model Viewer 的轨道相机泛化到 `examples/common`，供全部 3D Tutorial 与 Viewer 复用；
- 相机输入尊重 ImGui 捕获状态，支持旋转、缩放、重置和可选自动环绕；
- 每章提供能直接验证本章主题的参数，并保持 Desktop 与 Web 相同行为；
- 自动 Smoke 继续使用确定参数，不依赖真实时间或人工输入。

## 非目标

- 不把 ImGui、Tutorial Runtime 或 Orbit Camera 安装为 Granit SDK 公共组件；
- 不把完整 Model Viewer 面板、材质编辑器或调试工具迁入 Tutorial；
- 不强制未来的纯 2D 或计算型 Tutorial 使用 3D Orbit Camera；
- 不让 UI 层接管 Renderer、Frame Context、Render Pipeline 或资源生命周期；
- 不把当前 SDF Raymarch Metaballs 改写为 bgfx 的 Marching Cubes 实现；显式网格版本由
  [S-74](S-74-0.39.0-gpu-marching-cubes.md) 作为独立教程规划；
- 不在每个 Tutorial 中重复 ImGui 初始化和主题代码。

## 现状结论

- Cube 调用 `ImGui::StyleColorsDark()`，没有使用 `apply_imgui_theme()`；
- PBR Assets 创建 ImGui Context，但没有应用任何统一主题；
- Instancing、Raymarch 与 Metaballs 未链接 `granit_example_imgui`，也没有面板；
- Instancing 的 `9 x 5` 实例数量是编译期固定数组，不能交互修改；
- Raymarch 与 Metaballs 只上传 resolution/time，Shader 内相机固定；
- Orbit Camera 与输入累积器位于 Model Viewer 私有目录，Tutorial 无法合理复用；
- 当前主题会把色板从显示空间转换到线性空间，因此每个 Context 只能应用一次。

## 已确认设计

### Tutorial Runtime

新增组合式 `tutorial_runtime`，由 Tutorial Application 持有：

```cpp
class tutorial_runtime {
public:
  result initialize(renderer& renderer);
  void process(const window_event& event);
  void process(const input_event& event);
  result begin_frame(const window_state& window, float delta_seconds);
  void draw_common_panel(const tutorial_info& info);
  result end_frame();
  canvas_draw_list_ref canvas() const noexcept;
  void shutdown() noexcept;
};
```

Runtime 统一拥有 ImGui Context、字体 GPU 资源、Texture Registry、Canvas Draw List、主题应用、输入
桥接和帧指标。初始化后应用一次 `apply_imgui_theme()`，并禁用持久化 `imgui.ini`。业务代码通过
虚拟 Hook 或回调添加章节面板，不接触字体上传和 DrawData 转换。

Runtime 只生成 Canvas Draw List。RenderPipeline 教程把该列表传给 Pipeline；低层 Renderer 教程在
内容 Pass 后渲染同一列表。两条内部消费路径产生相同面板，不要求所有教程改用 RenderPipeline。

### 统一面板

所有面板使用一致布局：

```text
Tutorial 名称
功能说明
FPS / CPU frame ms
Framebuffer / Frame
Camera
Chapter Settings
```

FPS 使用稳定的指数平滑值，原始 `delta_seconds` 仍保留给章节逻辑。窗口首次出现位置和宽度一致，
用户可以移动或折叠。Smoke 模式固定动画时间与参数，面板仍生成 DrawData，便于验证 UI 合成路径。

### 通用 Orbit Camera

把 Orbit Camera、Bounds 和通用输入状态从 Model Viewer 私有目录移入：

```text
examples/common/camera/
├─ orbit_camera.h/.cpp
├─ orbit_camera_input.h/.cpp
└─ orbit_camera_test.cpp
```

Model Viewer 和五个当前 Tutorial 复用同一实现。每章只设置 Focus Bounds、默认距离、Yaw/Pitch 和
裁剪面。公共交互为：主按钮拖动旋转、滚轮缩放、Home/面板按钮重置、可选 Auto Orbit。ImGui 要求
捕获鼠标或键盘时，相机不能消费对应输入。

当前六章均为 3D 内容，因此全部启用 Orbit Camera。该约定不扩大为“所有未来 Tutorial 必须使用
轨道相机”；纯 2D、UI 或计算章节可以禁用 Camera 区域。

### 章节参数

| Tutorial | 章节面板 | 相机与动画 |
|---|---|---|
| 01 Cube | 纹理预览、模型旋转开关、旋转速度 | Orbit、Reset、可选 Auto Orbit |
| 02 PBR Assets | Base Color、Metallic、Roughness、纹理预览 | 根据模型 Bounds 聚焦，默认 Auto Orbit |
| 03 Instancing | Rows、Columns、Spacing、动画开关/速度、实例总数 | 参数变化后重新计算 Bounds 并聚焦 |
| 04 Raymarch | Max Steps、Surface Epsilon、动画开关/速度 | Shader 接收相机 Origin/Basis/FOV，支持 Orbit |
| 05 Metaballs | Ball Count、Radius、Smooth Radius、动画开关/速度 | Shader 接收相机数据，支持 Orbit |
| 06 Marching Cubes（S-74） | ISO、Grid Size、Ball Count、容量与 GPU 阶段统计 | 根据密度场 Bounds 聚焦 |

bgfx Metaballs 的 ISO 与网格 Size 控制 Marching Cubes 网格。本项目当前章节使用 SDF Raymarch，
因此不复制不对应的参数；如果未来增加 Marching Cubes 教程，再提供 ISO、Grid Resolution、顶点数
和各阶段耗时。

### 动态资源

Instancing 使用带最大容量的动态数组和 GPU Buffer，Rows/Columns 决定实际 `instance_count`。参数
改变时仅更新实例数据；超过容量时明确拒绝，不在每帧重建 Buffer。首版建议每维限制为 1～32。

Mesh 继续保存拓扑、Vertex/Index Buffer binding 和默认几何范围，实际实例范围改由 Draw 时提供。
C API 使用可扩展的 `granit_mesh_draw_desc`，C++ 包装提供对应 `mesh::draw(recorder, desc)`；描述至少包含
`instance_count` 与 `first_instance`。无参数重载使用 Mesh 创建时的默认值，动态重载不得超过实例
Vertex Buffer 能覆盖的范围。该调整让调用方修改实例数时不必重新创建 Mesh，也不必绕过 Mesh 重复
录制 Vertex/Index Buffer binding。

`03_instancing` 初始创建可容纳上限数量的 Instance Buffer。Rows、Columns、Spacing 或动画结果变化时，
CPU 循环只负责生成并写入实例记录；绘制阶段只绑定一次 Mesh，并以 `rows * columns` 作为
`instance_count` 提交一次 indexed instanced draw。如果只是减少数量且前缀实例数据仍然有效，则只
更新 Draw 参数，不重新上传。首版复用现有 `buffer::write()`；帧级 Transient Buffer 由
[S-74](S-74-0.39.0-gpu-marching-cubes.md) 统一设计，S-73 不提前建立第二套临时分配器。

### bgfx 对照与取舍

bgfx `05-instancing` 每帧根据面板中的网格边长计算实例数，查询帧级 Instance Data Buffer 可用容量，
分配临时实例数据并循环填写矩阵和颜色，最后通过一次 `setInstanceDataBuffer()` 与一次 `submit()`
绘制全部实例。它还保留逐对象 `submit()` 的非 Instancing 路径，用 Draw Call 数直接展示差异。

Granit 教程采用相同的“一次实例化 Draw”与可选对照路径，但当前阶段复用持久动态 Buffer：

- Instancing 开启时，CPU 可循环生成实例数据，GPU 只接收一次 Draw；
- Instancing 关闭时，按实例循环 Draw，作为教学和指标对照，不作为推荐渲染路径；
- 面板同时显示请求实例数、实际实例数和本章 Draw Call 数；
- Buffer 容量不足时限制实际数量并明确显示，不静默越界；
- S-74 落地统一 Transient Buffer 后，再评估教程是否迁移到逐帧临时切片。

Raymarch/Metaballs 的可调参数进入 Uniform，循环最大上限仍由 Shader 固定，运行时参数只降低实际
工作量。这样 Vulkan 与 WebGPU 的控制流一致，也避免 UI 输入触发 Pipeline 重建。

## 实施顺序

1. **S-73A Runtime 与主题（已完成）**：已建立统一 ImGui 生命周期、主题、字体、输入、Canvas 与
   公共性能面板；Cube 和 PBR Assets 已迁移并验证低层 Canvas 与 Render Pipeline 两类消费路径。
2. **S-73B 通用相机**：把 Orbit Camera 与输入从 Model Viewer 私有目录迁入 Common，统一 ImGui
   捕获、Bounds 聚焦、Reset、Auto Orbit 和测试。
3. **S-73C Instancing**：调整 Mesh Draw 的动态实例范围，接入 Runtime，把固定实例数组改为最大容量
   动态数据，增加 Rows、Columns、Spacing、动画和 Instancing 对照开关；面板显示实例数、容量与
   Draw Call 数。
4. **S-73D Raymarch**：接入 Runtime 和 Orbit Camera，扩展相机 Uniform，增加步数、命中阈值和动画
   控制。
5. **S-73E Metaballs**：接入 Runtime 和 Orbit Camera，增加球数量、半径、平滑半径和动画控制。
6. **S-73F PBR 与 Cube 收口**：统一默认位置、面板层次、Auto Orbit、材质/纹理参数和资源释放顺序。
7. **S-73G 阶段验收**：五个现有 Tutorial 统一依赖 ImGui 集成，更新桌面 Smoke、浏览器导出和文档，
   为 S-74 提供稳定 Tutorial Runtime；本阶段不修改版本号、不创建标签或 Release。

## 测试与验收

- 五个现有 Tutorial 均应用一次 Granit ImGui 主题并显示公共性能区；
- 五个现有 Tutorial 的面板在 Vulkan 与浏览器 WebGPU 可见且可交互；
- ImGui 捕获鼠标时相机不旋转或缩放，释放后立即恢复；
- Orbit Camera 的 Focus、Resize、Reset、Auto Orbit、极角限制和缩放范围具有单元测试；
- Instancing 参数改变实例数、布局和 Draw 参数，不越过 Buffer 容量；
- Instancing 路径无论实例数量多少都只录制一次几何 Draw，非 Instancing 对照路径录制相同数量的
  Draw，并能从面板指标观察差异；
- `mesh::draw()` 保留创建时默认实例范围，动态 Draw 描述能覆盖 `instance_count` 与
  `first_instance`，C/C++ 测试覆盖零数量、越界范围和错误 Renderer/Recorder；
- Raymarch 的相机、步数与阈值确实进入 Shader，结果不依赖固定相机；
- Metaballs 的球数量、半径和平滑半径改变画面，参数保持在安全范围；
- Smoke 使用固定时间和参数，仍验证非空 ImGui DrawData 与 Canvas 合成；
- Tutorial 源码不再直接创建/销毁 ImGui Context、上传字体或调用默认主题；
- Model Viewer 迁移到 Common Orbit Camera 后行为测试继续通过；
- Windows/Linux、Emscripten 编译、Chrome 行为和文档检查通过。

## 风险与未决问题

- ImGui 成为整个 Tutorial 集合的构建前置；CMake 应在依赖缺失时整体禁用 Tutorial 并给出明确说明，
  不再只构建没有面板的子集。
- UI Canvas 与低层内容 Pass 的 Load/Store 和资源状态必须保持明确，不能为统一外观引入双重 Present。
- FPS 是 CPU Tick 指标，不应标成 GPU FPS；GPU 时间仅在已有可靠 Timestamp 数据时单独显示。
- Common Orbit Camera 仍是 Example 辅助实现，不能因为目录提升而进入安装 SDK。
