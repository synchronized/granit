# S-94：0.58.0 后端诊断闭环与硬件捕获

## 状态

**已确认，待实施。** 本计划承接 v0.57.0 尚未完成的后端诊断回归，把 Vulkan、WebGPU 和
RenderDoc 的开发期验证收敛为可重复的自动化与操作证据。不新增公共诊断、RenderDoc、Vulkan、
Dawn 或 Bindless ABI。

## 背景与目标

v0.57.0 已固化 Frame Trace schema、失败附件和 RenderDoc 使用边界。剩余风险集中在后端诊断
本身：WebGPU 命令调试组和 Pass 生命周期缺少完整回归，Vulkan Debug Utils 缺失路径缺少
明确门禁，RenderDoc CLI 捕获虽然已在 Windows Intel Vulkan 主机成功，但还需要固定为可复现
的验收入口。

目标：

1. 补齐 WebGPU debug group、重复 Pipeline 绑定、异常结束和销毁路径回归；
2. 固化 WebGPU Timestamp 当前“不支持”契约，防止误报为已实现能力；
3. 补齐 Vulkan Debug Utils 缺失、Validation 回调和对象命名 no-op 覆盖；
4. 固化 Windows Vulkan 硬件的 RenderDoc CLI `.rdc` 捕获命令，并保留 Linux/no-op 证据；
5. 保持 Frame Trace 默认关闭、公共 ABI 不变、Bind Group 仍为默认资源绑定模型。

## 非目标

- 不新增公共 GPU Profiler、Frame Trace、RenderDoc、Vulkan、WebGPU 或 Dawn 接口；
- 不实现 RenderDoc 替代品、浏览器 GPU 捕获器或跨版本持久化 Trace 格式；
- 不进入 Bindless 公共 ABI、Descriptor Buffer、SVT、纹理驻留、预算管理或 VFS；
- 不把 RenderDoc、Vulkan SDK 或显卡驱动打包进 Granit SDK。

## 已确认决策

- 诊断验证继续优先使用现有 CTest、Frame Trace validator 和 Model Viewer smoke，不创建第二套
  日志系统；
- RenderDoc 作为外部可选工具，Granit 只负责动态探测、触发和 no-op；`.rdc` 文件属于本地
  验收产物，不进入仓库和发布包；
- Vulkan 硬件证据使用当前 Intel UHD 630 作为基线，同时保留无驱动、无 Layer 和无 RenderDoc
  环境的明确失败/no-op 分类；
- WebGPU 诊断只验证现有 Emscripten 后端语义，不为了诊断引入 WebGPU 原生对象到公共接口。

## 实施顺序

  JavaScript 异常；Vulkan Timestamp 支持保持不变；
- [ ] 确认 tutorial-06、Frame Trace validator 和浏览器 smoke 的失败信息可关联到同一帧。

- [ ] 生成 v0.58.0 验收记录，确认没有公共 ABI、SDK 依赖或默认路径回归。

## 测试与验收

- WebGPU tutorial-06、Frame Trace、Model Viewer 浏览器 smoke 通过；Timestamp 不支持契约通过；
- Vulkan Validation、资源/命令回归和当前 Intel UHD 630 Model Viewer smoke 通过；
- RenderDoc CLI 能生成至少一个 `.rdc`，并且关闭或缺失 RenderDoc 时仍能运行；
- 公共头文件、安装 SDK、Runtime Bundle 和 CMake package 不出现 RenderDoc/Vulkan/Dawn 传递依赖；
- `git diff --check`、Documentation、shared/static Consumer 和现有像素测试通过。

## 风险与未决问题

- 浏览器 Dawn 错误回调受浏览器与 Emscripten 版本影响，失败时必须区分环境缺失与 Granit
  回归；WebGPU Timestamp 维持明确不支持，不因浏览器偶然暴露 feature 而启用。
- RenderDoc `.rdc` 是驱动和工具版本相关的诊断证据，不作为性能基准或稳定测试快照；
- 只有新的真实材质绑定压力证明 Bind Group 成为瓶颈时，才另立计划恢复 Bindless/Resource Table。
