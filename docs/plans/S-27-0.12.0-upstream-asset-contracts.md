# S-27：0.12.0 上游资产与标准材质契约

## 状态

- 路线图任务：S-27
- 目标版本：0.12.0
- 优先级：P1
- 状态：进行中（S-27A 已完成）
- 前置依赖：S-20、S-23、S-24、S-26

## 背景与目标

Gneiss 应拥有面向产品的材质语义、资产身份与热重载策略，Granit 只拥有 GPU 材质实例和渲染管线。
当前边界仍有三个缺口：上游只能按私有二进制偏移读取 `.grshader` 内容 ID；稳定 PBR Schema 位于
`src/`；构建树没有与安装包一致的 RenderPipeline 资产目录变量。0.12.0 公共化这些通用消费契约，
使上游无需复制 Granit 私有格式、Binding 或源码路径。

## 非目标

- 不把 Gneiss 的材质语义、资产数据库、热重载或文件系统接入 Granit。
- 不公开示例私有 glTF Loader、Model Viewer 执行器或完整内部 Material 模块。
- 不增加异步 Timestamp、Web Worker、Android、TAA、Bindless 或新的渲染后端。
- 不让 Core API 直接读取文件路径；公共资产接口继续消费调用方拥有的内存字节。

## 已确认决策

### Shader Asset 检查

- Core 提供 C11 `granit_shader_asset_inspect` 和轻量 C++20 包装，复用现有私有解码与摘要校验。
- 返回内容 ID、缓存键、Stage、Entry Point，以及每个变体的 Backend、Profile、代码格式、
  Required Features、Payload 大小和摘要；入口点使用调用方容量，当前格式的两个变体使用固定上限，
  不跨动态库分配内存。
- 损坏摘要、未知格式、容量不足和过小结构返回稳定结果码；检查不创建 Shader 或持有输入内存。

### 标准 PBR Material

- 将已经由标准 PBR Shader 验证的参数名称、常量布局、纹理槽位和顶点布局要求迁移到公开
  RenderPipeline 头文件，内部实现改为消费同一权威定义。
- 安装确定性的 `materials/pbr_standard.grmat`，其 Shader Asset ID 必须引用同一版本安装的公共 PBR
  Shader；公开模板版本和内容 ID，方便上游建立映射与缓存身份。
- 不新增与通用 `granit_material` 重叠的有状态 `granit_pbr_material_create`。

### 构建树资产目录

- 请求或构建 RenderPipeline 时，安装包、FetchContent 和 `add_subdirectory` 都提供同名
  `granit_RENDER_PIPELINE_ASSET_DIR`，指向包含 `shaders/`、`materials/` 和 `environments/` 的根目录。
- 构建树使用生成资产目录，不要求消费者访问 Granit 源码树；变量只在对应 component 可用时定义。

## 实施顺序

1. **S-27A Shader Asset 检查（已完成）**：设计 C ABI、C++ 包装、错误语义和格式复用，补齐损坏及
   容量测试。
2. **S-27B 公共 PBR Schema**：迁移稳定值类型和常量，内部实现与测试改用公开头文件。
3. **S-27C 标准 PBR 模板**：生成、安装并校验 `pbr_standard.grmat` 及其 Shader 引用。
4. **S-27D 统一资产目录**：统一安装树和两种构建树消费方式，增加子项目 Consumer Fixture。
5. **S-27E 发布验收**：完成共享/静态、C/C++ Consumer、Windows/Linux、浏览器、文档、迁移说明和
   0.12.0 发布验证。

## 测试与验收

- C11 与 C++20 Consumer 只包含安装头即可解析标准 `.grshader` 元数据，不读取固定偏移。
- Shader Asset 检查覆盖所有 Stage、多个变体、无效摘要、截断输入、未知枚举和容量不足。
- 标准 PBR Schema、`.grmat`、SPIR-V/WGSL 反射和实际 Pipeline Binding 保持同一权威布局。
- Package、FetchContent、`add_subdirectory` 三种模式得到同名有效资产目录，目录内容一致。
- 独立 Consumer 能从该目录检查 Shader、加载标准材质与环境资产，不包含 `src/` 头文件。
- Windows/Linux 共享与静态安装 SDK、Emscripten Model Viewer 和发布包验证全部通过。

## 风险与未决问题

- 当前 `.grshader` 格式固定最多两个后端变体；未来格式若扩展该上限，需要同步扩展公共结构，不能
  静默截断或返回内部数组指针。
- `.grmat` 当前由内部 Material 工具生成；若安装模板会让私有模块泄漏到公共契约，应只公开格式稳定
  的数据结构和产物，不导出内部运行时对象。
- 构建树资产由生成步骤产生，目录变量必须配套目标依赖，避免消费者配置成功但构建时资产尚不存在。
