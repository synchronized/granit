# S-88：0.52.0 真实绑定压力与 Resource Table 闸门

## 状态

**实施中。** S-88A 已完成，Windows Vulkan 的 S-88B 基线已记录；v0.51.0 已完成 RenderPipeline Consumer 和生命周期验收。当前没有新的 Gneiss
上游 Granit PR；本版本承接 H-09E，补齐真实 Shader 采样的绑定压力证据，再决定是否进入 D-09
Resource Table 原型，不凭理论复杂度直接冻结 Bindless 公共 API。

## 目标

1. 建立固定种子的真实压力纹理与材质 Consumer，Shader 必须实际采样绑定资源；
2. 对传统 Bind Group 与资源缓存测量创建、更新、切换、缓存命中、Descriptor Pool 占用和帧成本；
3. 在 Vulkan 硬件、Lavapipe 和 WebGPU 编译路径验证资源语义、回退和容量边界；
4. 根据 P50/P95、设备覆盖率和产品负载决定：继续传统路径、建立纯 CPU Resource Table 原型，
   或进入可选 Bindless 后端实现。

## 固定边界

- 不把 Bindless 设为默认路径，也不删除或改变传统 Bind Group 回退；
- 不公开 Vulkan Descriptor、扩展常量或原生句柄；
- 不实现 SVT、纹理驻留预算、VFS、任务调度或 Gneiss 资源生命周期；
- 不把 Descriptor Buffer、Ray Tracing、Mesh Shader、Clustered Forward 与本版本捆绑；
- 只有测量满足 D-09 开始条件，才在本版本后半段建立独立 Resource Table 原型任务。

## 实施顺序

1. **S-88A 压力 Consumer**：已完成。benchmark 生成 8/64/512 纹理组和固定材质，片元 Shader
   实际采样五类材质纹理，并输出真实 Draw、纹理组、绑定更新和缓存计数。
2. **S-88B 传统路径基线**：进行中。已测量 Windows Vulkan 的 CPU P50/P95/P99 和 GPU timestamp；
   同时覆盖 Vulkan 硬件、Lavapipe 和 WebGPU 编译/行为门禁。
3. **S-88C 闸门决策**：初步结论为保持传统路径；待跨平台门禁完成后固化最终结论。
4. **S-88D 可选原型**：仅在闸门通过后建立内部 CPU Resource Table 和最小 Renderer 能力查询，
   不自动接入材质或改变默认路径。
5. **S-88E 发布验收**：完成 shared/static、Windows/Linux/Emscripten 编译、公开 Consumer 和
   benchmark 结果记录后发布 v0.52.0。

## 验收门槛

- 压力 Shader 对每个测试纹理组执行可验证采样，结果不会被编译器消除；
- 输出包含真实资源计数和绑定操作计数，不仅记录请求规模；
- 传统 Bind Group 在不支持高级能力的设备上仍完整可用；
- 所有性能结论包含设备、驱动、分辨率、样本、预热和 Validation 状态；
- 若进入原型，资源索引具备 generation、类型、Renderer 归属和延迟复用校验；
- 公共头文件不包含 Vulkan SDK，未满足闸门时不新增公共 ABI。
