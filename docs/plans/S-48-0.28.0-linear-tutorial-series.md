# S-48：0.28.0 线性入门教程与配套示例

## 状态

**实施中，P1。** 0.28.0 聚焦从空项目到完整可交互渲染程序的连续学习路径，不新增与教程无关的
公共能力。

## 背景与目标

现有教程按 Renderer、资源、Pipeline、窗口和 Model Viewer 主题排列，章节之间虽然互相引用，但
读者不能从第一章持续扩展同一个程序并在每一步得到可见结果。部分教程还以内部测试代替使用者示例，
模糊了 Tutorial、Example 和 Test 的职责。

本版本建立一条以窗口应用为起点的 C++20 教程系列。每章只引入一个主要概念，以上一章为前置，
并对应一份可编译、可运行、可验证的完整源码快照。教程同时作为公共 C++ 包装的易用性验收入口：
普通资源关系应由 RAII 对象或明确的非拥有引用表达，不要求读者用裸 C 句柄补齐包装缺口。

```text
Window → Triangle → Texture → Depth/Camera → Mesh
       → Material/Lighting → Render Pipeline → ImGui
```

## 非目标

- 不同时维护旧教程和新教程两套学习路径。
- 不把单元测试、错误路径或平台探测程序包装成示例。
- 不复制 Model Viewer 的完整实现到教程源码。
- 不为教程暴露 Vulkan、WebGPU、Win32、XCB 或 Wayland 原生类型。
- 不在 0.28.0 承诺 C11 与 C++20 双轨教程；教程使用 C++20 包装。
- 不为了教程方便创建与现有公共抽象重叠的第二套运行时接口。
- 不删除或弱化 C ABI、C11 Header、ABI 布局、C consumer 与 C API 行为测试。
- 不要求所有 `native_handle()` 消失；它继续作为明确的 C/C++ 互操作出口。

### 教程顺序

1. **Window**：安装包接入、Renderer、Window System、Window、Surface、Swapchain、清屏和退出。
2. **Triangle**：HLSL-first Shader Library、Graphics Pipeline 与第一个 Draw。
3. **Texture**：Texture、View、Sampler、上传、Bind Group 和纹理采样。
4. **Depth and Camera**：Vertex/Index Buffer、深度附件、Uniform、变换和相机。
5. **Mesh**：把几何资源收敛为 Mesh，并加载一个仓库内可再分发的最小模型。
6. **Material and Lighting**：`.grmat`、材质参数、方向光和基础 PBR。
7. **Render Pipeline**：Scene Snapshot、Draw Binding、Shadow、HDR 与 Tone Mapping。
8. **ImGui**：输入事件、Canvas、Texture ID、Resize 和调试面板。

### 平台与 Shader

- 教程只使用 `granit::window` 创建窗口和 Surface，不暴露原生平台 API。
- Shader 源统一使用 HLSL，由 AssetTools 在构建期生成跨后端 Shader Library。
- 01～07 首先保证 Windows/Linux Vulkan；08 复用相同内容验证 Emscripten WebGPU。
- 平台差异只留在构建和事件循环壳层，不复制渲染业务逻辑。

### C++ 主路径与测试边界

- Tutorial、Example 和面向使用者场景的 C++ 测试优先使用 `.hpp` 包装、RAII 对象、C++ 枚举和
  C++ 描述结构，不直接调用 `granit_*` 函数管理资源生命周期。
- C ABI 行为、错误码、句柄安全、结构布局、C11 可包含性、导出符号和 C consumer 继续直接使用
  C API；这些覆盖不能用 C++ 测试替代。
- C++ Header 编译测试只验证头文件独立可用；C++ 包装的成功、失败、移动和借用生命周期由对应
  行为测试覆盖，不在每个底层 C API 测试中机械复制一份 C++ 版本。
- 回调签名、第三方库桥接和显式互操作可以使用 C 结构或 `native_handle()`，但应把转换限制在适配
  边界，不能向教程主循环扩散。

### 拥有对象与非拥有引用

现有 `texture`、`texture_view` 等类型表示拥有资源，析构时调用对应销毁函数。Swapchain Backbuffer
由 Swapchain 拥有，当前 C++ `backbuffer` 却输出裸 `granit_texture` 和 `granit_texture_view`，无法
在类型上表达借用关系。0.28.0 增加轻量、不可销毁的强类型引用，并统一以下规则：

```cpp
texture owned_texture;                 // 拥有；析构时销毁
texture_ref texture_reference;         // 借用；没有 reset/destroy
texture_view_ref view_reference;       // 借用；没有 reset/destroy
swapchain_backbuffer backbuffer;       // 一组由 Swapchain 拥有的借用引用
```

- `texture::ref()` 和 `texture_view::ref()` 返回对应非拥有引用；引用不延长拥有对象生命周期。
- C++ `swapchain::backbuffer` 接受 `acquired_frame` 而不是独立图像索引，并输出
  `swapchain_backbuffer`，从而同时校验 Frame 与 Swapchain 归属。
- Backbuffer 引用的保证使用期截止到 Frame present/cancel；Swapchain recreate/destroy 或 Renderer
  销毁会使底层句柄失效。某个后端即使暂时仍接受过期引用，也不延长公共契约；使用者不能通过
  引用请求销毁。
- Rendering Attachment、Recorder、Bind Group、Pipeline 和需要借用 GPU 资源的高层组件逐步接受
  强类型引用。拥有对象通过 `ref()` 进入相同调用路径，Backbuffer 不需要特殊重载。
- C API 保持输出非拥有整数句柄，并继续拒绝公开销毁 Backbuffer；所有权增强只发生在零状态的
  C++ 包装层，不建立第二套 Registry。

### C++ 包装缺口审计

按教程实际经过的调用链分级处理，不在本版本一次重写全部包装：

1. **必须在 01 Window 前完成**：Backbuffer 借用引用、Frame 归属校验、Rendering Attachment 接受
   `texture_view_ref`，以及对应生命周期测试。
2. **随 02～04 完成**：Shader、Pipeline Layout、Buffer、Texture、Sampler、Bind Group 在 Pipeline
   描述与 Recorder 命令中的强类型引用；教程不手工声明裸资源句柄数组。
3. **随 05～08 完成**：Mesh、Material、Render Pipeline、Canvas 与 ImGui 适配边界使用 C++ 描述和
   引用；必须保留的 C 回调数据集中在 adapter/helper 内部。
4. **父资源参数（已完成基础层）**：Renderer、Window System、Surface、Texture 等父资源以 C++
   包装引用传入常规 `initialize`/`create` 路径；原始句柄仅保留给显式互操作。高层组件统一描述和
   工厂式创建仍按后续教程经过的调用链评审。

审计时区分“C++ 包装缺口”和“合理互操作”。只因实现内部最终调用 C ABI，不要求公共 C++ 类型复制
运行时状态，也不为了消除文本中的 `granit_` 前缀包装回调 ABI 或常量。

## 测试与验收

- 八章按顺序阅读时不要求读者预先理解后续章节概念。
- 每章包含目标、相对上一章的增量、关键代码、完整源码入口、运行命令、预期结果、排错和下一章。
- 每个 `examples/tutorials/<step>` 目标能独立构建，源码不包含 Granit 私有头或后端原生类型。
- 教程源码不直接调用 Granit C 资源创建/销毁函数；Backbuffer 和其他借用资源不以拥有型 RAII
  对象承载，也不由教程保存为无生命周期说明的裸句柄。
- C++ 包装测试覆盖拥有对象转引用、Backbuffer Frame 归属、保证使用期和 Recreate 后失效，以及
  对借用类型不存在公开销毁操作；WebGPU 额外覆盖 Present/Cancel 后动态 Backbuffer 失效，原有
  C API 测试继续覆盖销毁 Backbuffer 返回 Unsupported。
- C++ Example 和行为测试中的 `native_handle()` 只出现在当前包装尚未提供对象重载的初始化调用、
  C 回调或第三方适配边界；不用于手工管理资源所有权。
- 每章至少有一个自动验证：进程退出、中心像素、固定区域颜色、资源状态或浏览器帧推进。
- Windows/Linux 覆盖桌面教程；最终 ImGui 内容同时覆盖 Vulkan 与浏览器 WebGPU。
- 文档链接检查禁止重新引用已删除的旧教程文件。
- 运行 Documentation、相关 Example Smoke、Windows/Linux 完整矩阵和 Emscripten 浏览器验证。

## 风险与未决问题

- 当前 Triangle 示例尚未进入顶层构建，需要先确认其资产生成与跨平台构建状态。
- 逐章完整快照会产生少量代码重复；只有遮蔽教学目标的稳定代码才抽入 `common`。
- 教程所需 Bind Group、顶点布局或动态 Uniform 若暴露公共 API 缺口，应先记录并评审最小补充，
  不能在示例中绕过公共边界。
- 强类型引用会影响多个 C++ 描述和 Recorder 重载。实施时先完成 Texture/View/Backbuffer 的纵向
  闭环，再按教程顺序扩展，避免提前制造覆盖全部资源类型的抽象模板。
- WebGPU Backbuffer 的有效期短于 Vulkan 静态 Swapchain 图像；公共借用引用按较短的跨后端生命
  周期定义，不能根据 Vulkan 行为放宽。
- Model Viewer 原教程包含仍有价值的运行说明，删除前应迁移到独立 Guide，而不是丢失内容。
