# S-22：0.7.0 SDK 稳定化与上游集成

## 状态

- 目标版本：0.7.0
- 优先级：P1
- 设计状态：已确认
- 实现状态：已完成；S-22A～S-22E 均已验收
- 前置依赖：S-06、S-18、S-20、S-21

## 背景与目标

0.6.0 已完成跨后端 Shader 资产变体和可复现工具链。0.7.0 不继续横向增加平台或高级渲染功能，
而是收敛 Granit 作为可安装 SDK 的公共边界，并用 Gneiss 等真实宿主的集成路径验证这些契约。

本阶段需要明确各 CMake component 的职责、依赖和成熟度，减少上游对内部模块、示例代码和构建树
布局的依赖。真实上游暴露的问题只有在能够归纳为后端无关契约并由 Granit 独立测试复现后，才进入
公共 SDK。

## 非目标

- 不在 0.7.0 宣布稳定 ABI，也不执行 S-06D 的最终稳定版本验收。
- 不修改 Gneiss 源码；Gneiss 只作为只读需求和验证依据。
- 不接入 Android、桌面 Dawn 或新的图形后端。
- 不因 Model Viewer 已使用 glTF 就公开示例私有加载器；S-14 仍需满足双 Consumer 门槛。
- 不接管上游 ECS、场景、资产数据库、任务系统或渲染线程。
- 不启动透明 PBR、CSM、Clustered Forward 或 Bindless 等需求门控能力。

## 已确认决策

- Core、RenderPipeline、Window、Input、ShaderTools 和第三方 Integration 独立评估成熟度，不能用
  整体版本号代替 component 契约。
- 0.7.0 的目标是形成“稳定候选”边界，而不是承诺旧二进制可直接加载新动态库。
- Core 保持最小后端无关入口；可选 component 不得向 Core Consumer 传播额外依赖。
- Shader 资产清单、后端 sidecar 和材质包继续使用独立格式版本，不从 Granit 包版本推导兼容性。
- 0.x CMake 包只接受相同次版本，避免旧 Consumer 在未迁移时静默接受含破坏性变化的新 SDK。
- 上游集成优先复用安装 SDK、能力查询、批量上传和显式生命周期接口；便利性封装留在上游。
- 新公共能力必须同时具备真实问题、最小复现、C/C++ 契约、安装 Consumer 和失败路径测试。

## 实施顺序

1. **S-22A component 契约清单（已完成）**：在兼容性参考中列出所有可安装 component 的目标、
   依赖、当前稳定等级和 0.7.0 处理方向，消除“整个 Granit 一起稳定”的歧义。
2. **S-22B 安装 SDK 门禁（已完成）**：Core-only 隔离、RenderPipeline、Window、Input 与
   ShaderTools 的独立请求、依赖闭包、缺失 component 和 0.x 次版本选择均已形成自动化检查。
3. **S-22C 公共边界收敛（已完成）**：公共头未泄漏后端或内部类型；Core 底层 Pipeline 与可选
   RenderPipeline 高层入口职责不同，不做无依据合并。结果见
   [SDK 边界审计](../records/2026-09-05-s22cd-sdk-boundary-audit.md)。
4. **S-22D 上游集成回归（已完成）**：只读检查 Gneiss 的公开使用路径，未发现构建树内部头依赖
   或应提升到 Granit 的上游专用类型；审计结论已固化为 Granit 自有选包与 Consumer 门禁。
5. **S-22E 0.7.0 验收（已完成）**：Windows/Linux 共享与静态矩阵、C11/C++20 安装 Consumer、
   浏览器 WebGPU、Shader Toolchain 和 Release 预验证均已通过，并已提供 0.6 到 0.7 迁移说明。

各阶段在同一特性分支和 Pull Request 中推进。若 S-22B 或 S-22D 发现破坏性调整，先记录迁移影响，
待范围收敛后统一提升 0.7.0 版本号和 ABI 快照，不在每个子提交中重复提升。

## 测试与验收

- 每个可安装 component 都有明确目标名、直接依赖、稳定等级和缺失依赖行为。
- Core-only Consumer 不加载 RenderPipeline、Window、Input、ShaderTools 或第三方 Integration。
- 可选 component 能被单独请求；共享和静态 SDK 的依赖闭包一致且不泄漏内部 Vulkan/WebGPU 类型。
- Gneiss 的核心接入路径只依赖安装后的公共头、CMake 目标和运行时资产，不依赖 Granit 构建树。
- 新发现的通用缺陷在 Granit 仓库内具有最小回归测试，不依赖 Gneiss 源码或私有资产。
- 0.7.0 发布前完成 ABI 差异、迁移指南、变更记录、许可证和发布产物校验。

## 风险与未决问题

- 目前明确的真实上游仍以 Gneiss 为主，单一 Consumer 的便利需求不能自动升级为公共 API。
- “稳定候选”只表示边界趋于收敛，不构成 SemVer 稳定承诺；最终稳定范围仍由 S-06D 决定。
- RenderPipeline 的高层便利性与 Core 的长期稳定节奏可能不同，应保留独立 component 等级。
- ShaderTools 是构建期 SDK，其工具版本与缓存身份契约不能直接套用运行时 C ABI 规则。
