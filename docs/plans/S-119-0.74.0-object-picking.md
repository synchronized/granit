# S-119：对象 ID 输出与异步像素拾取

## 状态

**已完成，目标版本为 `v0.74.0`。**

## 背景与目标

为 Gneiss 等外部引擎提供可选的对象 ID 输出和异步像素拾取能力。调用方继续负责场景、材质和
自定义 Pass；Granit 只负责在参考 RenderPipeline 中生成 ID attachment，并复用 Renderer 的
异步回读与资源生命周期管理。

首期必须能在不启用拾取时保持现有渲染路径和开销；启用后可从离屏输出或窗口对应的视图中读取
一个精确的 `R32_UINT` 对象 ID。背景像素和没有对象 ID 的像素返回 0。

## 非目标

- 不在本版本提供通用 GPU picking 算法、射线相交或场景对象查找。
- 不把 Vulkan 类型、RenderPass 或 Subpass 暴露到公共 API。
- 不支持 MSAA ID resolve、透明物体 ID 规则定制、UI/debug 绘制写入 ID。
- 不要求外部 `record` 回调自动获得 ID 输出；首期仅保证 Granit 内置标准 PBR 路径，其他路径明确返回不支持。

## 已确认决策

- `granit_render_pipeline_output` 增加可选 `object_id_view`，由调用方创建和销毁，RenderPipeline 只借用。
- ID attachment 使用单采样 `R32_UINT`，每视图清零；Opaque 和 MASK 实例写入 `object_id`，BLEND、UI 和 debug 不写入。
- `object_id == 0` 仍参与深度测试和遮挡，只表示该像素没有可拾取对象。
- 首期增加按 Texture View 回读的异步接口，返回原始整数布局，不做颜色转换、不翻转 Y。
- 回读提交后由异步操作持有资源引用；调用方可以在操作完成或销毁后再释放输出资源。
- RenderPipeline 不保存调用方的输出描述、回调用户数据或临时图资源；单次 render 返回后只保留 GPU 使用所需的内部引用。

## 实施顺序

1. **API 契约**：补充 output 字段、初始化宏、C++ 包装和生命周期/线程约束文档。自定义 `record`
   路径在首期明确返回 `unsupported`，不能静默忽略。
2. **View 回读**：让 `ReadbackBatch` 能从 Texture View 读取指定的 1x1 区域，并覆盖格式、范围、无效句柄和跨设备校验。
3. **ID attachment**：在 RenderPipeline 图中导入 ID 输出，使用独立整数 shader 接入标准 Opaque/MASK 绘制；关闭时不创建、不绑定、不增加 ID Pass。
4. **多视图与尺寸**：为每个输出视图独立处理 ID attachment，覆盖输出尺寸变化、离屏路径和窗口 Frame 路径。
5. **测试与示例**：增加 C/C++ API、回读生命周期、渲染结果和失败诊断测试；提供不依赖内部头文件的最小 picking 示例。
6. **Gneiss 对接准备**：整理外部引擎调用契约和迁移说明，待 `v0.74.0` 发布后由 Gneiss 映射 ID 到 `instance_key`。

## 测试与验收

- 不设置 `object_id_view` 的现有 RenderPipeline 测试结果不变，且无额外 ID 资源或回读操作。
- 设置 ID 输出后，Opaque/MASK 命中返回对应 `object_id`，背景返回 0，深度遮挡关系正确。
- BLEND、UI 和 debug 不写入 ID；自定义 record 路径在不具备能力时返回明确的 `unsupported`。
- 1x1 `R32_UINT` 异步回读返回精确 32 位值，坐标原点为左上角，越界和非单采样输入失败。
- 连续执行、输出尺寸变化、回读尚未完成时销毁/重建 RenderPipeline 均不会提前释放 GPU 资源。
- 覆盖离屏和交换链输出；共享库、静态库、C consumer 和 C++ consumer 均通过相关构建与测试。

## 风险与未决问题

- 当前 Render Graph 的 attachment 能力可能要求 ID 作为独立 Pass，而不是与颜色输出组成 MRT；实现阶段按后端能力选择，并保持公共语义不变。
- WebGPU 对 `R32_UINT` 渲染附件和回读的支持矩阵需要实际验证；不支持时应返回 `unsupported`，不能静默改为颜色格式。
- MSAA、透明排序和自定义材质的 ID 语义留到后续版本，不在首期扩大公共 ABI。
