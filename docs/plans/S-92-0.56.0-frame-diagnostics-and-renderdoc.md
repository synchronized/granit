# S-92：0.56.0 帧诊断与 RenderDoc 协作

## 状态

**实施中（S-92A 已完成首版基线）。** 本计划承接 v0.55.0 的 Bindless 排查经验，目标是降低 Vulkan、WebGPU 和 Model Viewer
问题的定位成本，不改变公共渲染模型，也不把 RenderDoc 变成 Granit 的运行时依赖。

## 背景与目标

当前 Granit 已有 Validation、诊断回调、对象命名、Renderer 资源统计和 Timestamp Query，但这些
信息尚未形成统一的“某一帧发生了什么”视图。RenderDoc 适合分析 Vulkan 单帧的 API、资源、Pipeline、
Shader 和 GPU 事件；WebGPU 浏览器提供 Debug Group、错误作用域和可选 Timestamp Query，但没有
一个所有浏览器都提供的 RenderDoc 等价物。因此 Granit 自己仍需要提供跨后端、可自动化、可在 CI
保存的结构化帧 Trace。

目标：

1. 提供可选的 RenderDoc 运行时桥接和按帧捕获触发；
2. 统一 Vulkan Command Buffer、Pass、Pipeline、Draw/Dispatch、Barrier 和 Descriptor 的命名/标记；
3. 输出可被 Chrome Trace/Perfetto 等工具读取的 JSON Lines 帧 Trace；
4. 关联 CPU 录制、Submit/Fence、GPU Timestamp、资源创建/销毁和延迟回收；
5. 在 Model Viewer、PBR 压测和 CI 失败路径中形成最小可复现诊断附件；
6. 保持公共 C ABI 不出现 RenderDoc、Vulkan 或平台句柄。

## 非目标

- 不把 RenderDoc 头文件、库、Layer 或安装包作为 Granit 构建/运行时依赖；
- 不在公共头文件暴露 `renderdoc_app.h`、`Vk*` 或 RenderDoc 类型；
- 不实现 RenderDoc 的替代品，不复制其资源检查、Shader 调试或回放能力；
- 不默认每帧输出大量日志，不让诊断模式改变正常渲染时序；
- 不要求 WebGPU/Emscripten 模拟 RenderDoc 捕获；WebGPU 只输出 Granit Trace；
- 不把 Chrome DevTools、Dawn 调试开关或第三方 WebGPU Inspector 变成运行时依赖；
- 不在本版本新增公共 GPU Profiler ABI 或绑定 Bindless/SVT 功能。

## 已确认决策

### RenderDoc 桥接

- 仅在开发诊断组件中通过运行时动态加载访问 RenderDoc In-Application API；
- Windows 探测 `renderdoc.dll`，Linux 探测已加载的 `librenderdoc.so`；找不到时返回“不可用”而不是失败；
- 通过环境变量、命令行或内部诊断命令选择 `off`、`trigger`、`frame:N` 和 `sampled` 模式；
- 捕获使用 RenderDoc 支持的 Vulkan Device/Queue/Window 指针，但这些类型只存在于 Vulkan 内部实现；
- Granit 不主动注册或分发 RenderDoc Layer，用户负责安装和启用 RenderDoc。

### WebGPU 调试协作

- 在 WebGPU 后端使用对象 `label`、`pushDebugGroup/popDebugGroup` 和 `insertDebugMarker`，能力不可用时
  自动降级；
- 通过错误作用域、`uncapturederror`、Shader 编译信息和 `device.lost` 事件写入统一 diagnostic 事件；
- 仅在设备支持 `timestamp-query` 且应用允许时写入 GPU 时间，否则记录 `unavailable`；
- Chrome DevTools Performance、Dawn backend validation 和第三方 WebGPU Inspector 只作为外部调试手段，
  不纳入 Granit 构建和发布依赖；
- 如果使用原生 Dawn 调试环境，可记录其 backend validation 或 wire trace，但不把 Dawn 私有接口提升为
  Granit 公共契约。

### Granit Frame Trace

首版采用开发期内部 JSONL 文件格式，每条记录包含 `frame_id`、`thread_id`、`timestamp_ns`、`kind` 和
结构化 payload。事件最少覆盖：

| 事件 | 关键字段 |
|---|---|
| frame | frame id、开始/结束、present 状态 |
| pass | 名称、所属 frame、开始/结束 |
| command | recorder、queue、draw/dispatch、pipeline |
| resource | 类型、句柄、创建/销毁、generation、大小 |
| sync | barrier、submit、fence、retirement point |
| gpu_timestamp | query、stage、纳秒结果或 unavailable |
| diagnostic | severity、backend、message、source location |

输出默认关闭；开启后支持固定大小 ring buffer、采样帧和失败时保留最近 N 帧，避免诊断本身造成
不可控的内存增长。

## 实施顺序

### S-92A：诊断配置与事件模型

- [x] 在内部 diagnostics 模块定义事件写入器和固定容量事件缓冲区；
- [x] 明确线程安全、丢事件计数和进程退出时 flush 行为；
- [x] 接入现有 diagnostic sink、resource stats 和 Timestamp registry 结果；
- [x] 使用 `GRANIT_FRAME_TRACE` 和 `GRANIT_FRAME_TRACE_MAX_EVENTS` 控制，默认关闭，不改变公共 ABI。

首版基线记录见 [S-92A Frame Trace 基础设施](../records/2026-10-08-s92a-frame-trace-baseline.md)。当前格式是
开发期 JSONL，后续 S-92C 再补充 frame/pass/resource/sync/timestamp 的关联字段。

### S-92B：Vulkan Debug Label 与 RenderDoc 桥接

- [x] 统一 Vulkan Command Buffer 和 dynamic rendering label；缺少 Debug Utils 函数时自动 no-op；
- [ ] 统一 Vulkan 对象名称、Pass label 和 Pipeline 名称；
- 动态加载 RenderDoc API，增加手动/帧号/采样触发；
- 在 RenderDoc 不存在、API 版本不匹配或捕获失败时保持正常渲染；
- 通过测试替身验证探测、版本协商和 no-op 路径，不在 CI 强依赖 RenderDoc 安装。

当前 Vulkan label 基线见 [S-92B Vulkan Debug Label 基线](../records/2026-10-08-s92b-vulkan-debug-label-baseline.md)。

同时实现 WebGPU 的 Label/Debug Group/Marker 适配和 no-op 能力探测，确保 Vulkan 与 WebGPU 的事件
命名规则保持一致。

### S-92C：帧级 CPU/GPU/资源关联

- 将 Frame Context、Command Recorder、Submit、Fence 和 Timestamp Query 关联到同一 frame id；
- 记录 Pipeline/Descriptor/Barrier 统计、资源创建销毁和延迟回收队列；
- Vulkan 和 WebGPU 分别输出可用字段，缺失能力显式标记 `unavailable`；WebGPU 错误、设备丢失和
  Shader 编译信息也关联到 frame id。

### S-92D：应用与 CI 接入

- Model Viewer 增加诊断模式和捕获帧选择；
- PBR/压力测试输出固定格式 Trace；
- CI 失败时保留小型 Trace 作为 artifact，正常构建不上传空诊断文件；
- 增加 Trace schema、解析器和最小回归样例。

## 测试与验收

- Windows Vulkan Validation 下，手动触发一帧 RenderDoc capture，能在 RenderDoc 中看到稳定的 Frame、
  Pass、Pipeline、Resource 和 Command Label；没有 RenderDoc 时程序正常运行；
- Linux Vulkan 下验证动态探测和 no-op 路径，不要求 CI 安装 RenderDoc；
- Emscripten/WebGPU 输出一帧 Trace，包含 Debug Group/错误事件；缺少 GPU Timestamp 时明确记录
  `unavailable`；
- 浏览器 Performance 记录、Dawn backend validation 和可选 WebGPU Inspector 验证不改变 Granit 的
  默认运行路径；
- Model Viewer 能按 frame id 关联 CPU 录制、Submit、GPU 时间和资源生命周期；
- Trace 文件可被 JSONL 解析器读取，损坏、截断和磁盘写入失败不会破坏渲染；
- 默认关闭诊断时现有像素、性能和 ABI 测试不改变；
- 公共头文件、安装 SDK 和 C11/C++20 Consumer 不出现 RenderDoc/Vulkan 依赖。

## 风险与未决问题

- RenderDoc 捕获依赖外部 Layer 和驱动支持，不能作为所有机器上的自动化性能基准；
- Debug Label 会增加命令录制成本，需由模式开关控制；
- GPU Timestamp 只能说明设备执行时间，不能替代 RenderDoc 的资源/Shader 检查；
- Trace schema 在 0.x 阶段只作为开发诊断格式，不承诺跨版本持久化兼容；
- 是否需要将 Frame Trace 提升为公共 API，留待后续版本根据 Model Viewer 和 CI 使用结果决定。
