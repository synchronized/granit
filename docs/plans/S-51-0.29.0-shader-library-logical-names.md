# S-51：0.29.0 Shader Library 逻辑名称

- 目标版本：0.29.0
- 实现状态：已完成

## 问题

`.grshlib.json` 已定义稳定的 Library 名称和 Shader 逻辑名称，但旧工具链只把名称写入额外的
`.grshidx.json`。运行时代码必须包含构建后生成的内容 ID，Material Builder 也必须读取与 Library
重复的索引文件。这让源码依赖构建目录，并允许 Library、索引和 Material 彼此失配。

## 目标设计

- `.grshlib` 自身保存 Library 名称和按名称排序的“逻辑名称 → Shader 记录”表。
- 内容 ID 继续标识 Shader 内容，用于去重、缓存、Material 包引用和高级接口；修改逻辑名称不改变
  Shader 内容身份。
- 普通运行时代码通过 `shader_library::create_shader("name", shader)` 创建 Shader。
- C API 分为明确的按名称入口和按内容 ID 高级入口，不保留含义模糊的旧函数名。
- Material Builder 直接读取一个或多个 `.grshlib`，不再生成或消费 `.grshidx.json`。
- CMake、教程和内建 Shader 不再生成或包含 `*_shader_ids.inc`。

## 阶段

1. **S-51A 格式与查找**：升级 `.grshlib` schema，加入 Library 名称和独立名称表，覆盖确定性、
   去重、损坏归档和名称查找测试。
2. **S-51B 运行时 API**：增加 C/C++ 按名称创建接口，保留名称明确的内容 ID 高级入口，迁移内建
   Tone Mapping、Shadow、Debug Draw 和教程 02–05。
3. **S-51C 工具链收口**：Material Builder 改为读取 `.grshlib`；删除 `.grshidx.json`、`index-ids`
   命令、索引 API、生成 ID 规则和对应快照。
4. **S-51D 文档与验收**：更新 Reference、教程、工具说明和资产布局；验证共享库、静态库、
   Consumer、教程和浏览器 WebGPU。

## 验收条件

- 用户源码只需使用清单内稳定名称，不包含由构建生成的内容 ID。
- 同一内容允许多个逻辑名称，重复名称指向不同内容时构建失败。
- Material 源中的 Library/Shader 名称只从 `.grshlib` 解析，缺失或重复名称产生明确失败。
- 安装包和仓库生成资产不包含 `.grshidx.json` 或运行时 `*_shader_ids.inc`。
- Windows Clang、MSVC、静态构建、Emscripten 和相关 Consumer/教程测试通过。

## 最终结果

- `.grshlib` schema 2 已内嵌 Library 名称和逻辑名称表，名称与内容身份相互独立。
- C/C++ Runtime 提供按逻辑名称的常规入口，以及名称明确的按 Content ID 高级入口。
- Material Builder、内建渲染资源、教程、测试和基准测试均直接消费 `.grshlib`；旧索引、生成 ID
  include 及其工具命令已经删除。
- Windows Clang 全量 99 项测试、MSVC 动态相关 15 项测试、Emscripten 13 项测试及 Chrome WebGPU
  平台与 Tutorial 08 验证通过。MSVC 静态相关 Library、Material 和 Renderer 测试通过；仓库位于
  当前深层目录时，完整 Visual Studio 构建和 Build Tree Consumer 受 Windows 260 字符路径限制，
  未发现代码或接口错误。
