# S-41：0.23.0 资产目录收敛

## 状态

**已确认，开始实施。** 本任务只调整 Granit 仓库内部文件布局和构建引用，不改变安装后的资产
目录、公共 API、ABI、资产格式或内容字节。

## 背景与目标

当前根 `assets/` 同时保存 HLSL/JSON 作者输入和 `.grshlib`、`.grmat`、`.grenv` 最终产物；
`src/pipeline/assets` 与 `src/pipeline/shaders` 又保存内建 Shader 的输入和快照；`src/assets` 实际
保存资产格式编解码代码。相同名称表达三种不同职责，构建脚本也需要了解多组特殊路径。

本任务按生命周期收敛目录，使文件位置直接表达以下身份：

```text
assets/
├─ sources/                      # AssetTools 作者输入
│  ├─ shaders/{pbr,unlit,debug,pipeline}/
│  └─ materials/
└─ generated/                    # 提交到仓库的确定性生成快照
   ├─ installed/                 # 安装到 SDK 的运行时资产
   │  ├─ libraries/
   │  ├─ materials/
   │  └─ environments/
   └─ embedded/pipeline/         # 编译进 RenderPipeline 的私有资产

src/asset_formats/               # Runtime 与 AssetTools 共用的格式实现
tests/fixtures/                  # 测试输入与测试专用后端快照
build/generated/                 # 不提交的本次构建输出
```

## 非目标

- 不修改 `${granit_RENDER_PIPELINE_ASSET_DIR}` 下的安装目录结构。
- 不改变 HLSL-first 作者入口、Shader Library、Material、Texture 或 Environment 格式。
- 不删除缺少 DXC/Tint 时需要的已提交快照。
- 不把 AssetTools 文件 I/O、缓存或资产数据库引入 Runtime。
- 不借目录迁移重写 CMake 资产生成逻辑或公共资产接口。

## 已确认决策

- `assets/sources` 只保存手写或维护的作者输入；构建不得把输出写回该目录。
- `assets/generated` 只保存由锁定工具链生成并由测试逐字节验证的权威快照。
- `generated/installed` 与 SDK 安装后的 `share/granit/assets` 一一对应；索引等构建伴随文件可以与
  对应产物同目录保存，但安装规则必须显式选择公开文件。
- `generated/embedded/pipeline` 保存 RenderPipeline 私有 Library、Material、索引和内容 ID；这些
  文件不安装，并在构建时转换为 Build Tree 中的 `.inc`。
- `src/asset_formats` 保存可由 Runtime 与 AssetTools 复用的格式代码，继续使用
  `granit::detail`，不形成新的公共模块。
- `tests/fixtures` 保存测试输入；`tests/fixtures/generated` 继续保存不安装的 SPIR-V/WGSL 快照。
- 新增 `assets/README.md` 作为资产目录职责和生成规则的权威说明。

## 实施顺序

1. **S-41A 目录契约**：新增资产目录说明，建立 `sources`、`generated/installed` 和
   `generated/embedded`，迁移根资产并集中 CMake 路径。
2. **S-41B 内建 Pipeline 资产**：迁移 `src/pipeline/shaders` 与 `src/pipeline/assets`，更新嵌入、
   内容 ID 生成和快照比较。
3. **S-41C 格式实现**：将 `src/assets` 改为 `src/asset_formats`，同步内部 include 和目标源文件。
4. **S-41D 测试 Fixture**：将 `tests/assets` 按 Shader 与 Material 迁入 `tests/fixtures`，保留
   `tests/fixtures/generated` 的明确快照身份。
5. **S-41E 验收**：验证有/无锁定 Shader Toolchain、共享/静态、Emscripten、安装审计、独立
   Consumer 和文档检查，并记录迁移结果。

每个阶段形成一个聚焦提交。纯路径迁移优先使用 `git mv`，避免改变资产字节或无关格式。

## 测试与验收

- 仓库中不再存在 `src/pipeline/assets`、`src/pipeline/shaders`、`src/assets` 或 `tests/assets`。
- 作者输入、已提交生成快照、Build Tree 输出和测试 Fixture 不互相混放。
- 锁定工具链生成的 Library、索引、内容 ID 和 Material 与迁移后的快照逐字节一致。
- Toolchain `off` 模式可以只依赖提交快照完成 Runtime、RenderPipeline 和测试构建。
- 安装目录仍只包含公开 `.grshlib`、`.grmat`、`.grenv` 和 Environment Manifest，不包含 HLSL、
  `.grshidx.json`、`.inc`、SPIR-V、WGSL 或测试 Fixture。
- Windows 共享/静态与 Emscripten 构建、相关测试、安装 Consumer 和文档检查通过。

## 风险与未决问题

- CMake 中散落的路径必须一次迁移并由无工具链构建覆盖，否则本机有工具链时可能掩盖快照遗漏。
- `.grshidx.json` 是生成伴随文件而非运行时资产；允许与对应快照同目录保存，但不能被宽泛安装。
- 文件移动不应触发资产重新编码；如内容变化，必须独立说明工具链身份和摘要差异。
