# S-06：版本与兼容承诺

## 状态

- 设计状态：已确认
- 实现状态：S-06A～S-06C 及 S-06D 验收准备已完成；稳定发布时执行最终验收
- 路线图任务：S-06
- 优先级：P2
- 前置依赖：S-01、S-03、H-09

## 背景与目标

项目已有导出符号、结构布局、共享/静态和安装 Consumer 回归，但“能够发现变化”不等于“承诺不
发生变化”。本计划明确核心 C ABI、高层 component、C++ 包装、CMake 包和原生互操作的稳定等级，
让 S-01E 的正式快照具有清晰的版本语义。

## 非目标

- 不在 0.x 阶段提前宣布稳定 ABI。
- 不承诺 C++ 对象布局、STL 类型或编译器之间的二进制兼容。
- 不把 Vulkan 原生互操作加入基础公共接口。
- 不因创建快照就禁止 0.x 的有记录架构调整。

## 已确认决策

- 当前 0.x 允许在次版本中进行有记录的破坏性变更；修订版本只用于兼容修复。
- 核心 `.h` 是未来 ABI 承诺主体；`.hpp` 以源码兼容为目标，不承诺 C++ 二进制 ABI。
- 可选 component 独立宣布稳定等级，但共享同一 Granit 包版本。
- 持久化格式使用自己的格式版本和兼容规则，不从库版本隐式推导。
- 原生 Vulkan 互操作始终为显式不稳定高级接口，内部和 benchmark 入口无兼容承诺。

当前行为的权威说明见[版本与兼容策略](../reference/compatibility.md)。

## 实施顺序

1. **S-06A（已完成）**：记录 0.x 接口等级、版本规则、破坏性变更流程和稳定门槛。
2. **S-06B（已完成）**：S-01E 已生成 Granit 0.1.0 核心 C ABI 快照，并由 CI 比较
   导出符号、布局和关键常量。
3. **S-06C（已完成）**：Core、RenderPipeline、Window 与 Input 已完成所有权、线程安全、错误、
   扩展语义和 component 边界审计。
4. **S-06D（准备已完成）**：变更记录和发布验收清单已建立；首个稳定版本确定后更新 README、
   参考文档、版本号和发布说明，并执行最终验收。

## 测试与验收

- README 不再只给模糊的“不稳定”提示，而是链接唯一兼容策略来源。
- 文档明确区分 C ABI、C++ 源码、CMake component、持久化格式和不稳定互操作。
- S-01E 前不把当前回归基线描述为正式兼容承诺。
- 稳定发布前，CI 必须能对正式快照报告新增、删除和布局变化。

## 风险与未决问题

- 首个稳定版本号和发布日期尚未确定，不在本计划中承诺。
- 可选 component 是否与核心同时稳定，仍需在稳定发布前逐项决定并建立独立 ABI 快照。
- 未来若支持 32 位平台，需要独立 ABI 快照，不能复用当前 64 位布局基线。
