# H-09B：透明 PBR 正确性草案

## 状态

- 文档状态：已确认评估契约
- 实现状态：暂缓；当前没有足够需求或性能依据进入原型
- 所属任务：H-09B
- 基线：[透明覆盖层 GPU 性能基线](../../benchmarks/results/2026-08-18-windows-clang-transparent-b4b0396.md)

## 背景与目标

现有 Unlit Canvas 已验证预乘 Alpha、稳定调用顺序、相邻兼容合批和透明 overdraw。透明 PBR 会
额外引入 HDR 光照、深度关系、View 排序、材质变体和阴影语义，不能只给现有不透明 PBR Pipeline
打开混合。本草案定义未来原型必须保持的正确性边界，但不新增公共 API，也不承诺实现时间。

## 非目标

- 不在本阶段实现透明 PBR Shader、Pipeline、Scene 分类或公共 ABI。
- 不把 Alpha Cutoff 材质归入透明队列；它仍属于写深度的不透明/镂空路径。
- 不处理折射、透射、体积吸收、双层玻璃、顺序无关透明或深度剥离。
- 不承诺透明材质接收或投射方向光阴影；这些能力必须分别验证视觉与性能需求。

## 正确性契约

### 合成阶段

首个原型如被批准，应在不透明 PBR 之后、Tone Mapping 之前写入同一线性 HDR 颜色目标：

```text
Shadow -> Opaque PBR -> Transparent PBR -> Tone Mapping -> UI Overlay
```

透明 PBR 参与场景曝光和 Tone Mapping。显示空间 UI 仍在 Tone Mapping 后合成，不能复用透明 PBR
队列。透明阶段读取不透明阶段的深度，不清除 HDR 颜色或深度。

### 深度与排序

- 深度测试使用与当前 PBR 一致的 `less_equal`，深度写入关闭。
- 透明对象按当前 View 的相机空间深度从远到近稳定排序。
- 深度相同时依次使用调用方显式排序键、对象 ID 和原始提交序号作为稳定决胜字段。
- 多 View 分别计算深度和顺序，不能复用另一个 View 的排序结果。
- 相交几何和单个 Mesh 内部三角形无法由对象级排序完全解决，必须作为已知限制记录。

任何合批都只能合并排序后相邻且 Pipeline、材质资源、Mesh 状态兼容的项，不得跨项重排来减少
Draw。Bindless 只能降低绑定成本，不能改变透明合成顺序。

### Alpha 与混合

- Shader 输出必须是线性 HDR 的预乘 Alpha：`rgb = lit_color * alpha`。
- 颜色和 Alpha 均使用 `one / one_minus_source_alpha` 混合，操作为 `add`。
- `alpha <= 0` 的片元不影响目标；`alpha >= 1` 的结果应与同参数不透明着色在容差内一致。
- 材质基础色、顶点色和基础色纹理的 Alpha 只组合一次，不能重复预乘。
- Alpha 模式必须由资产或材质语义显式选择，不能根据某一帧参数值自动切换队列。

### 光照与材质

首个原型应复用当前不透明 PBR 的金属度、粗糙度、法线、IBL 和直接光公式，保持相同输入得到相同
表面光照，再于输出阶段应用 Alpha。首轮仅评估表面透明混合，不模拟介质内部传输。

透明材质与不透明材质可以共享参数 Schema，但必须使用不同 Pass/变体；不得在一次 Draw 中动态
切换深度写入或混合状态。缺失纹理继续使用现有默认资源，资源所有权与生命周期规则不变。

## 原型前测试矩阵

未来原型至少需要以下自动验证：

| 类别 | 必测场景 | 验证内容 |
|---|---|---|
| 混合 | 两层、八层固定颜色 | 预乘 Alpha 数值与稳定顺序 |
| 深度 | 不透明遮挡透明、透明前后交错 | 深度测试开启且透明不写深度 |
| 排序 | 等深度、显式排序键、多 View | 决胜字段确定且每 View 独立 |
| 材质 | 常量、纹理、Alpha 0/1 | 只组合一次 Alpha，端点行为正确 |
| 光照 | 方向光、点光、IBL 开关 | 与不透明 PBR 表面光照一致 |
| 生命周期 | 销毁材质、纹理、Scene | 旧句柄失效且不跨帧悬空 |
| GPU | 0、2、8、32 覆盖层 | Transparent 阶段 timestamp 独立报告 |

像素回归使用线性目标读取，允许由格式量化产生的小范围误差。Validation 正确性运行必须无
warning/error；性能采样关闭 Validation，并与 Unlit 透明基线使用相同分辨率和覆盖分布。

## 当前结论

当前 64×64 基线显示，32 层兼容合批的 GPU P50 约为 26.3 µs，明显成本主要来自逐层 Draw 和
绑定切换，而不是单纯 overdraw。仓库也没有已确认的透明受光材质产品需求。因此 H-09B 的结论是
保留现有 Unlit 透明路径，并暂缓透明 PBR 原型。

出现以下任一情况时重新评估：

- 实际项目需要受光玻璃、粒子、植被或其他无法由 Unlit/Alpha Cutoff 表达的材质。
- 目标分辨率和设备上透明 overdraw 在 P50、P95 均成为主要 GPU 瓶颈。
- 已有资产能明确 Alpha、排序、阴影和双面语义，并可形成像素回归样例。

重新评估仍需建立独立实现 Plan；本正确性草案不直接授权公共 API 或后端改动。
