# S-93：0.57.0 诊断硬化与跨后端回归

## 状态

**已确认，待实施。** 本计划承接 v0.56.0 的 Frame Trace、RenderDoc 桥接和 WebGPU 调试协作，
目标是把诊断能力从“能输出”推进到“能稳定用于回归和定位”。不新增公共 GPU Profiler、RenderDoc、
Vulkan、Dawn 或 Bindless ABI。

## 背景与目标

v0.56.0 已解决 tutorial-06 在 Dawn 中因调试组栈不平衡和时间戳提交范围错误导致的命令缓冲失效，
并完成 Frame Trace 的首版接入。下一步应固化这些边界，避免诊断代码本身改变录制语义或掩盖第一条错误。

目标：

1. 固化内部 Frame Trace 的事件顺序、截断和写入失败语义；
2. 为 Vulkan/WebGPU 的调试标记、错误回调、Timestamp 和命令结束路径增加回归覆盖；
3. 让 Model Viewer、Tutorial 和 CI 失败附件使用同一套最小诊断配置；
4. 提供 RenderDoc 手动验收指南和跨平台 no-op 证据，不把 RenderDoc 变成构建依赖；
5. 继续以传统 Bind Group 为默认，不将 Bindless、SVT 或纹理驻留职责移入 Granit。

## 非目标

- 不新增公共诊断、GPU Profiler、Frame Trace 或 RenderDoc API；
- 不实现 RenderDoc 替代品、浏览器专用 GPU 捕获器或 Dawn 私有接口；
- 不进入 Descriptor Buffer、Bindless 公共 ABI、SVT、预算管理、VFS 或资源驻留调度；
- 不以关闭校验、过滤错误或延长浏览器超时掩盖命令录制错误。

## 已确认决策

- Frame Trace 继续作为内部开发期 JSONL，默认关闭；格式演进通过校验器和记录文件管理，暂不承诺持久化兼容；
- 诊断路径必须先保留第一条后端错误，再生成汇总状态；异步回调无法安全关联帧时使用 `frame_id=0`；
- Debug Group 必须由 pass 生命周期成对管理，Pipeline/Draw/Dispatch 标记不得隐式改变栈深度；
- Timestamp resolve、readback 和多帧在途缓冲必须分别验证范围、对齐和生命周期；
- RenderDoc 仍由用户安装和启用，Granit 只做动态探测、触发和 no-op 诊断。

## 实施顺序

### S-93A：Frame Trace 语义硬化

- [ ] 增加 schema 版本、丢事件/截断计数和 flush 失败诊断；
- [ ] 明确 frame、command、resource、timestamp、diagnostic 事件的最小字段和顺序约束；
- [ ] 扩展 JSONL 校验器，覆盖截断文件、重复 frame、未知事件和磁盘写入失败；
- [ ] 保持固定容量和默认关闭，不改变正常渲染路径。

### S-93B：后端命令/诊断回归

- [ ] 增加 WebGPU pass/debug group 平衡测试，覆盖重复绑定 Pipeline、异常结束和销毁路径；
- [ ] 增加 WebGPU Timestamp 范围、256 字节 resolve 偏移、多帧在途和 `NOT_READY` 回归；
- [ ] 增加 Vulkan Debug Utils 缺失、Validation 回调和对象命名 no-op 覆盖；
- [ ] 保留浏览器 tutorial-06 作为 Dawn 命令缓冲有效性门禁。

### S-93C：应用与 CI 诊断统一

- [ ] Model Viewer、Tutorial 和 PBR/压力测试统一诊断环境变量与附件命名；
- [ ] CI 失败时上传第一条后端诊断、最近帧 Trace 和最小运行状态，不上传空文件；
- [ ] 增加 Trace 与测试结果的关联元数据，但不把 CI 日志复制进计划文档。

### S-93D：RenderDoc 手动验收与发布边界

- [ ] 增加 Windows Vulkan 硬件上的一帧 capture 操作指南和验收清单；
- [ ] 在 Linux/无 RenderDoc 环境验证动态探测、路径选择和 no-op；
- [ ] 检查 SDK、Runtime Bundle、公共头和安装 Consumer 不包含 RenderDoc 依赖；
- [ ] 形成发布记录，决定 Frame Trace 是否继续保持内部格式。

## 测试与验收

- Windows Vulkan Validation、Linux Vulkan/Lavapipe 和 Emscripten/WebGPU 的相关构建与测试通过；
- 浏览器 tutorial-06、Model Viewer、PBR/压力测试和现有像素测试继续通过；
- 开启 Frame Trace 时 JSONL 可完整校验，截断/丢事件/写入失败可诊断且不破坏渲染；
- 关闭诊断时公共 ABI、安装 Consumer、性能基线和默认渲染路径无变化；
- 公共头文件和安装 SDK 不出现 Vulkan、RenderDoc、Dawn 或 WebGPU 类型依赖。

## 风险与未决问题

- Trace 仍是内部格式，若多个应用需要消费，再单独评估稳定化或公共导出接口；
- RenderDoc 手动验收依赖具体驱动和外部 Layer，不能作为跨机器性能基准；
- Bindless/SVT/纹理驻留继续等待真实跨平台负载和 Gneiss 明确边界，不作为本版本隐含目标。
