# S-103：0.66.0 发布收口与 Runtime 缓存验证

## 状态

**已确认，待实施。**

## 背景与目标

`v0.65.0` 已正式发布，但部分版本、路线图和验收文档仍保留候选状态。与此同时，Release 每次都会
重新编译固定提交的 Vulkan-Headers、Vulkan-Loader 和 Vulkan-ValidationLayers，Runtime 构建占据了
主要远端耗时。

本任务收口发布文档，并验证按平台和锁定提交哈希缓存 Runtime 制品的 CI 行为；同时为已完成的 ImGui
Window/Input 适配补齐真实 Consumer 验收证据。

## 非目标

- 不修改公共 C ABI、Renderer、Window 或 ImGui 的接口语义；
- 不重新发布 `v0.65.0`，不修改已发布制品；
- 不把 Runtime 缓存改为跨平台共享，也不缓存未锁定的源码或编译结果；
- 不恢复 Bindless、Resource Table 或 Render Graph 的新公共能力。

## 已确认决策

- Runtime 缓存键至少包含平台、架构、Headers、Loader 和 ValidationLayers 的提交哈希；
- 缓存命中只复用最终 Runtime 归档，缓存未命中仍执行完整源码构建和现有打包校验；
- Runtime 归档继续经过 `vulkan-runtime.json`、SHA-256、公开下载和内容清单复核；
- 文档状态以 `docs/versions`、`docs/roadmap.md` 和 `docs/records` 的职责分工维护，不在 Plan 中追加
  逐次实施日志。

## 实施顺序

1. 收口 `v0.65.0` Version、Acceptance Record、Roadmap、Plan Index、Version Index 和 Changelog；
2. 在 Release workflow 中验证 Runtime 缓存恢复、缓存未命中构建和缓存写入；
3. 使用相同依赖提交重复运行 Release，记录两个平台的缓存命中和耗时；
4. 修改任一 Vulkan 依赖提交进行隔离验证，确认对应平台缓存失效并重新构建；
5. 补充 ImGui Window、外部 SDL Window 和浏览器 Consumer 的跨平台验收结果；
6. 更新版本验收记录，完成 v0.66.0 发布门槛审计。

## 测试与验收

- `granit.documentation.links` 通过，且不再报告 v0.65.0 的候选状态；
- Release workflow 的首次运行中两个 Runtime Job 完整构建并上传成功；
- 相同依赖提交的第二次运行命中两个 Runtime 缓存，并跳过 Khronos 源码构建；
- 任一锁定提交变化后，只有对应 Runtime 缓存失效并重新构建；
- Windows/Linux shared/static 和 Emscripten 的 ImGui Consumer 验收结果有明确记录；
- Release 继续通过安装 Consumer、Runtime manifest、SHA-256 和公开下载复核。

## 风险与未决问题

- GitHub Actions 缓存受分支、缓存额度和保留策略影响，缓存未命中必须始终保持可接受的完整构建路径；
- Release workflow 的缓存优化需要至少一次远端命中运行才能形成有效证据，本地不能替代该验证；
- 如果 Emscripten 只有构建证据而没有稳定的输入 Smoke，需明确记录边界，不把编译通过描述为完整行为验收。
