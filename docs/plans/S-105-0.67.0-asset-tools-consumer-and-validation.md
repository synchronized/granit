# S-105：0.67.0 AssetTools Consumer 与资产验证闭环

## 状态

**实施中。**

## 背景与目标

AssetTools 已提供 Shader Library、Material、Texture 和 Environment 的实验性构建接口，但当前主要
由单元测试和内部示例覆盖。下一版本建立一个不依赖源码树私有状态的安装 SDK Consumer，验证资产归档
从构建、检查到 Renderer/RenderPipeline 使用的完整边界。

## 非目标

- 不把 AssetTools 提升为稳定 ABI；
- 不引入新的纹理压缩格式、材质模型或公共 glTF 加载器；
- 不恢复公共 Bindless、Render Graph 或线程池设计；
- 不让 AssetTools 成为核心 Renderer 的传递依赖。

## 计划范围

1. 建立最小 Shader Library、Material、Texture、Environment 资产样例和固定输入；
2. 增加安装 SDK C++ Consumer，覆盖构建、inspect、失败诊断、归档替换和运行时加载；
3. 验证 shared/static、Windows/Linux 和 Emscripten 可表达的构建边界；
4. 补齐资产格式、版本、路径、校验和、生命周期与错误语义文档；
5. 记录构建耗时和资产大小基线，确认没有把源码树路径或 Vulkan 类型泄漏给 Consumer。

## 已完成阶段

- 安装 SDK 的 C++ Consumer 已接入 AssetTools component selection；
- Consumer 已实际执行 Texture 和 Environment 的 build、inspect、损坏归档与失败诊断路径；
- Consumer 已实际执行 Material 的 build、inspect、无效 Shader Library 失败诊断路径；
- 测试 fixture 在 packaging 测试配置阶段复制到测试目录，Consumer 不读取源码树路径。

## 下一阶段

- 将 Material 与 Shader Library 的安装 Consumer 验证接入可复用的已安装 fixture；
- 在 packaging CTest 中统一执行 Consumer，并补充 shared/static 配置结果；
- 补充资产格式、路径和生命周期的文档与验收记录。

## 验收门槛

- 安装 SDK Consumer 不包含源码树路径、Vulkan 头文件或私有头依赖；
- Shader Library、Material、Texture、Environment 的成功和失败路径均有测试；
- shared/static、Windows/Linux 和可用的 Emscripten 构建矩阵通过；
- AssetTools 仍保持实验性，公共 ABI 稳定等级不被自动提升；
- 文档、安装导出、SHA-256 和版本验收记录完整。

## 需要先确认的资源

- 优先使用仓库现有程序化纹理、环境像素和 CC0 Suzanne 资产；
- 若需要新外部资产，必须先记录来源、许可证、尺寸和是否进入发布包；
- 复用现有 AssetTools fixture，不重复引入 stb_image 或新的模型加载库。
