# S-37：0.21.0 Shader Library 与后端无关材质

## 状态

**实现中。** S-37A～S-37F 已完成确定性 `.grshlib` v1、公共 Library 句柄、Renderer 内部选择与
缓存、Material 的后端无关 Library 接入、`.grmat` v5、变体边界、最终资产构建、安装和迁移。
S-37G 已完成 Windows 共享/静态、Vulkan、Emscripten、浏览器 WebGPU、ABI 和独立 Consumer 的
本地验收；S-37H 已完成 WebGPU 内部 Provider 边界收敛及本地回归。推送后还需完成 Linux、远端
SDK 和不可变 Release Candidate 验收。S-37I 已统一 Surface 创建边界；S-37J 已将 Render
Pipeline 内建 Shader 收敛到 Shader Library 路径；S-37K 已完成共享类型、Compiler、Compilation、
Reflection、Shader Object 与 Library Builder 边界，并拆分 CLI；S-37L 已确认采用 HLSL-first 作者
入口并准备实施；发布验收待实施。

## 背景与目标

0.20.0 的 `.grmat` 已使用稳定内容 ID 引用 `.grshader`，但
`granit_material_shader_resolver` 仍接收 backend/profile，并要求调用方返回已经选好的 SPIR-V 或
WGSL sidecar。这让应用、内建材质和示例重复实现后端选择，也使
`granit_shader_create_from_asset` 的自动选择职责不完整。

本版本以 [ADR-006](../decisions/ADR-006-shader-library-runtime-asset.md) 为依据，引入确定性的
`.grshlib` 运行时容器。应用只提交材质归档和 Shader Library，Renderer 负责变体选择、完整性校验、
GPU Shader 创建及缓存。材质功能继续表达 PBR、Unlit、纹理、透明和阴影等渲染语义，不表达后端。

## 非目标

- 不接管文件系统、网络、资产数据库、线程池、异步加载或热更新调度。
- 不在运行时编译 HLSL 或 WGSL；源码转换继续属于离线 ShaderTools。
- 不把 Shader 直接复制进每个 `.grmat`，也不要求整个应用只有一个全局 Library。
- 不增加 Android、新 Renderer 后端、Bindless、材质节点图或新的 PBR 特性。
- 不稳定原生后端互操作；底层 `granit_shader_create` 继续作为显式高级入口。

## 已确认决策

- `.grshlib` v1 保存版本、内容哈希、Shader 记录、入口与阶段、反射契约、变体要求、载荷索引和
  去重后的载荷字节；所有范围、对齐、摘要和重复 ID 都必须严格校验。
- Library 可包含 Vulkan、WebGPU 或两者载荷。构建目标决定收集范围，运行时 API 与目标无关。
- `.grshader` 和 sidecar 不再安装或作为运行时资产交付；单 Shader 中间结果进入工具私有缓存，
  可改名为 `.grshaderobj`，不承诺跨版本格式兼容。
- 新增属于 Renderer 的 64 位 `granit_shader_library` 句柄。创建描述借用 Library 字节直到销毁，
  避免复制大型包；调用方必须保持字节地址和内容稳定。
- Material 创建描述改为接收 Library 句柄，删除 shader resolver 及其 user data。Material 借用
  Library；仍有 Material 引用时销毁 Library 返回明确的资源占用错误。
- `granit_shader_create()` 的直接代码描述统一为单一 `code_format + code`；该底层入口不再同时携带
  SPIR-V 与 WGSL，跨后端选择只由 Library 路径承担。
- `.grmat` 升级到 v5，在归档中明确 Frame、Material、Object 与 Lighting 绑定组要求，禁止根据
  Pass 名称猜测 Pipeline Layout。
- 编译期功能只包含会改变 Shader、绑定布局或固定 Pipeline 状态的选项；颜色、粗糙度、纹理和
  Sampler 等运行时参数不产生变体。`textured/untextured` 使用纹理功能位和默认资源表达。
- Granit 定义统一的 View、正面绕序和渲染目标 UV 语义；Renderer 后端保持正面绕序，Canvas
  在内部处理左上原点像素投影。Material、场景和应用不得按 Renderer backend 修正坐标。
- Library 内以 Shader 内容 ID 去重。相同 ID 必须具有完全相同的阶段、入口、反射和变体记录，
  冲突直接导致离线链接或运行时检查失败。
- Surface 创建收敛为 `granit_surface_desc` 带标签联合体和唯一的 `granit_surface_create`；C++ 使用
  `surface_desc` 来源工厂与唯一的 `surface::initialize`。0.21 直接删除旧平台创建入口。

## 公共接口方向

S-37B 已按 ABI 规则确定以下所有权和调用方向；完整接口见
[Shader Library 参考](../reference/shader-library.md)：

```c
typedef granit_handle granit_shader_library;

typedef struct granit_shader_library_desc {
  uint32_t struct_size;
  uint32_t reserved;
  const void* archive_data;
  uint64_t archive_size;
} granit_shader_library_desc;

granit_result granit_shader_library_create(
    granit_renderer renderer,
    const granit_shader_library_desc* desc,
    granit_shader_library* library);

granit_result granit_shader_library_destroy(
    granit_renderer renderer,
    granit_shader_library library);
```

`granit_material_desc` 已在保持结构尺寸不变的前提下，以 `shader_library` 和保留字段替换 resolver
函数指针及 user data。
不建立与 C API 平行的 C++ 状态，C++ 包装只提供移动与 RAII。

## 实施顺序

1. **S-37A Library 格式与链接器（已完成）**：定义 `.grshlib` v1，复用现有内容 ID、反射和
   变体记录；实现确定性编码、载荷去重、冲突检查及 `all/vulkan/webgpu` 裁剪。
2. **S-37B 公共 Library API（已完成）**：增加 C11 句柄、描述、创建/销毁、检查与 C++20 RAII；完成类型、
   generation、所属 Renderer、重复销毁和借用字节生命周期验证。
3. **S-37C Renderer 内部选择（已完成）**：由 Renderer 根据真实能力选择 Library 载荷、验证
   SHA-256 并缓存 Shader；Material、Canvas、Model Viewer、测试和基准统一传入 Library，删除
   Material 对 backend/profile 的查询与 resolver。
4. **S-37D Material v5（已完成）**：`.grmat` 显式引用 Library 中的 Shader ID，并按 Frame、
   Material、Object、Lighting 顺序声明连续绑定组；删除 `uses_unlit_pipeline_layout()` 及基于
   Pass 名称的布局推断。
5. **S-37E 变体与坐标收敛（已完成）**：静态功能由 Pass 和 Feature 选择，参数更新只替换常量
   或资源绑定；PBR 纹理掩码归并为有限 Shader 结构类别。View 与 Material 不再包含后端渲染
   特判；Renderer 后端保持正面绕序，Canvas 在自身实现内转换左上原点像素投影。
6. **S-37F 构建、安装与迁移（已完成）**：构建目标确定性生成并校验公共 PBR 与内建 Canvas
   Library；Canvas、Model Viewer 和公共资产测试直接消费最终 Library。安装包只发布 `.grmat`、
   `.grshlib` 与环境资产，并提供 0.20 到 0.21 迁移指南。
7. **S-37G 双后端与发布验收（本地部分已完成）**：已完成 ABI 快照、独立 Consumer、
   Windows 共享/静态、Vulkan、Emscripten 和浏览器 WebGPU 像素回归；推送后继续完成 Linux、
   远端 SDK 和不可变 Release Candidate 验收。
8. **[S-37H WebGPU Provider 边界收敛](S-37H-webgpu-provider-boundary-collapse.md)（本地完成）**：
   已删除浏览器静态后端中遗留的 Provider ABI、函数表、dispatch、domain adapter 和冗余 owner，
   按领域拆分后端私有设备实现，并保持公共 HAL 与 API/ABI 不变。
9. **S-37I Surface 创建收敛（本地完成）**：统一 C/C++ 创建描述和入口，Registry 与私有 HAL 只传递
   一份带来源标签的描述，由 Vulkan 和 WebGPU 在后端内部分派平台实现；删除四个旧公共入口。
10. **S-37J 内建 Shader Library 收敛（本地完成）**：Tone Mapping、Shadow 和 Debug Draw 由构建
    过程生成 `.grshaderobj` 中间结果并链接内建 `.grshlib`，运行时只通过 Library 内容 ID 创建 Shader。
    Tone Mapping 资源只保留 Library 初始化入口，不再接受直接 SPIR-V/WGSL 或单个 `.grshaderobj`。
    本机构建同时校验归档与 ID 快照；Emscripten 交叉构建直接嵌入已校验快照。
11. **[S-37K Shader 工具接口与组织收敛](S-37K-shader-tooling-api-structure.md)（本地完成）**：统一
    Core 与工具的 Shader 类型，以单一 Compiler API 覆盖 WGSL/HLSL，将 Compilation、
    Reflection、私有 Shader Object、Library Builder、CLI 和 CMake 适配拆成明确边界；源码中间
    快照和旧 Core 单 Object API 已删除。
12. **[S-37L HLSL-first Shader 作者入口](S-37L-hlsl-first-shader-authoring.md)（已确认）**：将离线
    作者输入收敛为 HLSL 与 Library 源清单，由工具统一生成 SPIR-V、WGSL、私有 Object、Library
    和名称索引；Material 源清单使用逻辑名称，运行时格式与内容 ID 边界保持不变。

## 测试与验收

- 相同输入和目标产生逐字节一致的 `.grshlib`；输入顺序不影响输出。
- 检查器覆盖截断、越界、重叠、错误对齐、摘要不匹配、重复 ID 冲突、未知版本和未知必需段。
- 全后端、Vulkan-only 与 WebGPU-only Library 均由同一 Material API 消费；缺少兼容载荷时返回
  `GRANIT_ERROR_UNSUPPORTED`，不回退到含义不同的 Shader。
- Library 句柄测试覆盖零值、类型错误、generation 失效、跨 Renderer、重复销毁和被引用时销毁。
- 多个 Material 共享同一 Shader 时只创建并缓存一个后端 Shader；并发获取不产生重复对象。
- 静态功能组合覆盖纹理掩码、Alpha 模式、阴影 Pass 与 Unlit；动态参数更新不增加 Pipeline 数量。
- Vulkan 与浏览器 WebGPU 使用同一材质、Library 和固定画面完成像素回归，业务层不存在后端分支。
- C11/C++20、共享/静态、构建树/安装 Consumer、Quick Check、Windows、Linux、Emscripten 和
  Documentation 全部通过。

## 风险与未决问题

- 首版借用完整 Library 字节会要求调用方长期保留映射；若真实大型资产证明内存压力明显，再设计
  分页读取源，不能提前把文件系统或异步 I/O 引入 Core。
- Library 缓存键必须同时覆盖格式版本、Shader 内容、反射、目标能力和工具身份，避免混用旧载荷。
- 多 Library 的跨包引用、覆盖优先级和 DLC 查找属于上游资产组织；首版由每个 Material 显式指定
  一个 Library，避免隐式全局搜索。
- `.grshader` 退出公开资产是破坏性变化；0.21.0 不保留旧 resolver 或双路径兼容，工具和资产应
  整体重建。
