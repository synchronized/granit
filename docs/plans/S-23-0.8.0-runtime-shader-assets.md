# S-23：0.8.0 运行时 Shader 与材质资产契约

## 状态

- 目标版本：0.8.0
- 优先级：P1
- 设计状态：已确认
- 实现状态：S-23A～S-23E 已完成；S-23F 验收中
- 前置依赖：S-20、S-21、S-22、H-02E3

## 背景与目标

0.6.0 已建立后端无关 `.grshader` 清单和 WGSL/SPIR-V sidecar，0.7.0 已收敛安装 SDK 与
component 边界，但运行时仍主要由调用方拆解 Shader 载荷，`.grmat` 也继续内嵌一份独立的
SPIR-V/WGSL 数据。工具输出、Renderer 输入与材质包之间因此存在重复表示和重复校验。

0.8.0 将建立一条可安装、后端无关且不负责文件 I/O 的运行时资产路径：调用方提供已经读取的
清单及 sidecar 字节，Granit 根据 Renderer 能力选择变体、验证摘要并创建 Shader；材质包改为引用
同一 Shader Asset 身份，不再维护平行的 Shader 容器语义。目标是让 ShaderTools 的产物能够被
Core 和 RenderPipeline 直接消费，同时保留上游对资产存储、异步 I/O 和缓存策略的控制权。

## 非目标

- 不在 Granit 中加入虚拟文件系统、资产数据库、路径搜索、热更新监视器或后台 I/O 线程。
- 不接管 Gneiss 的资源 ID、依赖图、缓存目录或任务系统。
- 不公开 Vulkan、WebGPU、SPIR-V 工具链或 Dawn 类型。
- 不增加新的图形后端、Android、桌面 Dawn、Bindless 或高级 PBR 功能。
- 不为尚未发布的旧 `.grmat` 格式保留运行时兼容分支；迁移通过离线重新构建完成。
- 不在子阶段反复提升项目版本；完成全部契约和迁移后统一更新到 0.8.0。

## 已确认决策

- `.grshader` 是 Shader 变体、能力要求和载荷摘要的唯一资产级权威；WGSL/SPIR-V sidecar 仍是
  可裁剪的后端执行代码。
- Core 只接受“字节视图 + 明确长度”，不打开路径；输入内存只在调用期间借用，成功后由
  Renderer 拥有创建出的 Shader。
- 运行时选择依据是实际 Renderer 后端、portable 档位和 Shader feature bits，不能根据版本号或
  平台宏猜测能力。
- 缺少目标 sidecar、摘要不匹配、清单不支持、能力不足和 Shader 编译失败必须返回可区分结果并
  产生结构化诊断，不允许静默回退到不匹配变体。
- `.grmat` 保存 Shader Asset 的稳定内容 ID、阶段、入口和变体约束；实际字节由调用方通过受限
  resolver 回调提供。回调契约必须明确线程、重入、所有权和有效期。
- Material 创建保持事务性：任一依赖解析、校验或 GPU 创建失败时，不留下部分 Material、Shader
  或 Pipeline 资源。
- ShaderTools 负责构建、检查和依赖清单；Core 与 RenderPipeline 共享只读格式解析和校验实现，
  不链接编译器前端。

## 实施顺序

1. **S-23A 契约与重复实现审计（已完成）**：已固定 `.grshader` 当前布局、sidecar 命名和错误
   分类，并确认 schema 3 缺少 stage、entry point 和独立内容 ID；结果见
   [S-23A 审计记录](../records/2026-09-05-s23a-shader-asset-contract-audit.md)。
2. **S-23B Core 运行时 Shader Asset（已完成）**：增加 C11 字节视图描述、能力匹配和 Shader 创建入口，补齐
   C++20 轻量包装；不得新增文件路径 API 或第二套 Renderer 状态。
3. **S-23C 共享只读资产解析（已完成）**：把格式解码、边界检查、摘要验证和变体选择整理为工具与运行时
   共用的私有实现；编译器、文件写入和缓存仍只属于 ShaderTools。
4. **S-23D Material 外部 Shader 引用（已完成）**：提升 `.grmat` 格式，使用稳定 Shader Asset ID 和 resolver
   解析依赖；删除包内平行双载荷，更新构建器、检查器和 RenderPipeline 加载路径。
5. **S-23E 迁移与集成验证（已完成）**：迁移仓库测试资产、Model Viewer 和 Smoke Fixture；验证 Vulkan 与
   浏览器 WebGPU 使用同一清单并分别只携带所需 sidecar。
6. **S-23F 0.8.0 验收（进行中）**：完成公共参考、0.7 到 0.8 迁移指南、ABI 快照、安装 Consumer、共享/静态
   SDK、Shader Toolchain、Windows/Linux/Emscripten 和 Release 预验证，最后统一提升版本号。

## 测试与验收

- C11 与 C++20 Consumer 能从内存中的清单和目标 sidecar 创建 Shader，不依赖 ShaderTools。
- Vulkan 只需要 SPIR-V sidecar，浏览器 WebGPU 只需要 WGSL sidecar；全量包仍可由同一接口选择。
- 覆盖清单损坏、未知必需区段、越界、摘要不匹配、缺失 sidecar、后端不匹配、档位不足、特性
  不足、错误阶段、错误入口和跨 Renderer 句柄。
- Material resolver 覆盖同步成功、缺失依赖、错误资产 ID、回调失败、重入拒绝和失败回滚；资源
  统计在失败和销毁后归零。
- ShaderTools 构建结果保持确定性；`inspect` 能报告资产 ID、变体、能力和材质依赖闭包。
- Model Viewer 的 Vulkan 与浏览器 WebGPU 路径不再包含独立的 Shader 容器或手写后端选择。
- Windows/Linux 共享与静态安装 SDK、C/C++ Consumer、Emscripten 浏览器测试及发布包校验通过。

## 风险与未决问题

- resolver 回调若直接暴露通用资产系统语义，会把上游架构固化进 RenderPipeline；首版只解析
  Shader Asset，并限制为 Material 创建期间的同步借用。
- 共享解析实现必须保持私有，不能把工具内部 C++ 类型泄漏到 C ABI 或安装头中。
- `.grmat` 去除内嵌 Shader 会增加部署文件数量；ShaderTools 应提供依赖清单和可选目录打包辅助，
  但运行时不隐式搜索文件。
- Shader Asset 的格式兼容性独立于 Granit 包版本；若审计发现当前格式缺少可扩展区段，应先形成
  ADR，再冻结新的格式版本。
