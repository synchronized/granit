# S-95：0.59.0 Resource Table 实验性 API

## 状态

**已完成（S-95A/C/D/E；S-95B 与真实压力验证转入 v0.60.0）。** 本计划为 Resource Table
建立可删除、可回退、可测量的实验性公共 API，复用已有 Vulkan Bindless 原型，不把 Bindless
设为默认资源绑定路径。

## 背景与目标

Granit 已在 v0.54.0/v0.55.0 完成 Vulkan Descriptor Indexing、Shader/Pipeline 变体、延迟回收和
真实压力初步验证，但 Bindless 仍是 Vulkan 内部实验。现有 Shader Library 和 Material 已支持后端
载荷及逻辑变体，原 Tutorial 12 已能验证能力探针和传统路径回退。

本版本目标：

1. 增加后端无关、明确标记为实验性的 Resource Table C/C++ API；
2. Vulkan 使用现有 Bindless 原型，WebGPU 提供能力分级和合法回退；
3. 为后续版本保留 `explicit_bindings` 与 `resource_table` Shader/Pipeline 变体扩展点；
4. 保持 Bind Group 为默认路径，不修改现有 Material、Tutorial 和 Consumer 的默认行为；
5. 将原能力探针改造为 Tutorial 12 Resource Table，验证公共实验 API，而不是改写基础教程；
6. 将 Shader/Material 变体和真实多材质、多纹理压力作为 v0.60.0 的继续/收缩闸门。

## 非目标

- 不公开 Vulkan Descriptor、Vk 类型或原生 Vulkan 互操作接口；
- 不把 Resource Table 宣称为所有 WebGPU 设备都支持的真正 Bindless；
- 不实现 SVT、纹理驻留、资源预算、VFS、RID 或任务调度；
- 不让 Resource Table 替换现有 Bind Group 默认路径；
- 不修改已有 01～12 Tutorial 使其依赖实验性 API；
- 不为每个材质功能无条件增加新的变体维度；
- 不承诺实验性 API 的跨 0.x 版本兼容。

## 待确认决策（本计划采用的结论）

| 项目 | 决定 |
|---|---|
| 公共名称 | `resource_table`，不使用公共 `bindless` 命名 |
| 稳定等级 | Experimental/Unstable，可在后续 0.x 删除或重设计 |
| 首期资源 | Sampled Texture View、Sampler、Storage Buffer |
| 索引 | `uint32_t` 槽位索引，越界和无效句柄明确报错 |
| 更新 | 单项更新与批量更新；提交后资源表状态不可变 |
| 生命周期 | 受 GPU 完成点保护，旧句柄和跨 Renderer 使用必须失效 |
| Vulkan | 使用现有 Descriptor Indexing 内部实现 |
| WebGPU | 能力分级；支持时使用受限实现，不支持时回退 Bind Group 或 Buffer Table |
| 显式选择 | 显式 Resource Table 不静默回退；`auto` 才允许选择 Bind Group |
| Shader | 绑定模型进入 Shader/Pipeline 变体，布局不能运行时混用 |
| Tutorial | 将 `12_bindless_probe` 重命名为 `12_resource_table`；不迁移旧基础教程 |

## 公共 API 边界

计划中的核心对象为 `granit_resource_table` 64 位句柄，描述结构包含 `struct_size`、各类资源容量
和能力/绑定模型标志。首期 API 至少覆盖：

- 创建、销毁和能力查询；
- Texture View、Sampler、Storage Buffer 的槽位更新；
- 批量更新；
- Command Recorder 或 Material/Draw Binding 的显式 Resource Table 绑定；
- 不支持、容量不足、越界、类型错误、跨 Renderer 和在途销毁错误。

API 不得暴露 Vulkan 类型，不得让 C ABI 跨边界传递 STL、异常或后端句柄。C++ 包装保持 move-only
RAII，并调用同一套 C ABI，不建立第二套资源状态。

## Shader 与 Material 变体策略

现有 HLSL-first Shader Library 已支持逻辑变体，计划新增类似以下逻辑名称：

```text
pbr.fragment/explicit_bindings
pbr.fragment/resource_table
```

两种变体共享 PBR 计算逻辑，只替换资源声明、索引访问和 Pipeline Layout。绑定模型作为独立变体
家族，不与每个纹理、Alpha 或 Pass 功能盲目形成新的布尔维度。只生成实际使用的组合，并在
AssetTools 构建阶段统计和限制变体数量。

Material Variant Key 必须能表达绑定模型，但动态材质值、逐贴图 UV 选择和资源句柄更新不得因此
重新创建 Pipeline。

## 验收门槛

- 公共 C/C++ API、安装 SDK、ABI 和句柄负向测试通过；
- Vulkan Resource Table 与传统 Bind Group 画面一致，Validation 无新增错误；
- WebGPU 不支持时不崩溃、不产生非法绑定，并能维护自动模式逻辑回退；
- Pipeline Layout 与 Resource Table 的 descriptor set 位置不混用；Shader 变体验收转入 v0.60.0；
- Tutorial 12 在当前 Windows Vulkan smoke 路径完成验证；Chrome WebGPU 路径转入 v0.60.0；
- Tutorial 01～11 和现有 Model Viewer 默认路径无变化，Tutorial 12 仅验证实验 API；
- 真实压力结果可复现，且记录是否存在稳定收益；
- 变体数量、构建时间和发布资产大小未超过预设上限；
- 不新增 Vulkan 类型、Descriptor 类型、SVT、纹理驻留或预算依赖到公共 ABI。

## 发布出口

v0.59.0 只承诺 Resource Table 为实验性、可选、可回退能力：公共 C/C++ 契约、Vulkan descriptor
更新、Pipeline Layout/Command Recorder 绑定和 Tutorial 12 已完成。Bind Group 仍是默认路径；
Shader/Material 变体、真实跨平台压力和 GPU 在途更新安全性不进入本版本发布承诺，统一由 v0.60.0
继续验证。
