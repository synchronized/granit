# S-29：0.14.0 异步管线指标与资源流送

## 状态

- 路线图任务：S-29
- 目标版本：0.14.0
- 优先级：P1
- 状态：已完成
- 前置依赖：S-28

## 背景与目标

0.13.0 已提供后端无关的异步操作与异步 Timestamp API，但参考 Render Pipeline 的内部 GPU
指标仍调用同步结果读取。这会让支持 Timestamp 的浏览器 WebGPU 无法启用同一套指标，并可能在
桌面端引入不必要的等待。Gneiss 的真实接入需求证明该能力应由 Granit 在 Render Pipeline 内部
统一实现，上游继续只读取最近一个完整指标快照。

0.14.0 首先让 Render Pipeline 使用 0.13.0 的异步 Timestamp 契约；随后补齐有界资源上传、失败
回滚和跨后端生命周期验证，为 Gneiss 等上游提供可组合的资源流送基础，而不接管其任务系统。

## 非目标

- 不向公共 API 暴露 Render Pipeline 内部 Query Pool 或异步操作句柄。
- 不改变 `granit_render_pipeline_get_metrics` 的调用方式，也不承诺把指标精确映射到上游帧序号。
- 不在销毁或帧循环中阻塞等待 GPU；取消已经提交的操作仍只是一项请求。
- 不提供公共线程池、作业系统、文件系统、网络、glTF 解析器或场景管理。
- 不增加桌面 Dawn、Android、TAA、Bindless 或新的渲染后端。

## 已确认决策

### Render Pipeline 异步 GPU 指标

- 每个活动帧槽拥有独立的 Timestamp Query Pool、异步读取操作和提交序号；存在未完成读取时不得
  重置或复用对应 Query Pool。
- 每帧非阻塞轮询全部待处理槽，而不只轮询当前即将复用的槽；完成后复制结果、销毁操作句柄并
  发布快照。
- 仅发布比当前快照更新的提交结果，避免多个帧槽乱序完成导致指标倒退；公共
  `sample_sequence` 仍表示成功发布的样本序列，不伪装为应用帧编号。
- `NOT_READY` 只表示暂时没有新样本，不影响渲染；失败或取消会清理对应操作并允许槽位恢复使用，
  同时保留稳定诊断，不用 CPU 时间伪装 GPU 指标。
- 禁用指标或销毁管线时，请求取消并立即销毁操作句柄，再销毁 Query Pool；依赖 0.13.0 的内部
  持有语义让已提交工作安全完成，不在浏览器主线程排空等待。
- 不支持 Timestamp 的设备继续稳定返回 `GRANIT_ERROR_UNSUPPORTED`。

### 资源流送边界

- 在现有异步操作之上评估并补齐上传完成状态，使调用方能够非阻塞地轮询、取消尚未提交的阶段、
  查询失败，并在完成后安全切换资源。
- 上传以有界批次和每帧预算提交，避免为每个细粒度资源创建一次动态库调用或异步句柄。
- CPU 解码、资产缓存、优先级和任务线程由上游拥有；Granit 只管理 GPU 操作、资源生命周期和
  后端一致的结果语义。
- 显存预算先提供能力与统计依据；没有跨后端可靠依据前，不承诺由 Granit 自动驱逐上游资产。

## 实施顺序

1. **S-29A 异步管线指标**：改造 Render Pipeline 指标槽、轮询、乱序发布、失败恢复和非阻塞销毁，
   保持公共指标 ABI 不变。
2. **S-29B 指标契约测试**：使用确定性测试替身覆盖 `NOT_READY`、乱序完成、失败、取消、禁用和销毁；
   以 Vulkan 与浏览器 WebGPU Smoke 验证真实 Timestamp 支持及降级路径。
3. **S-29C 异步上传完成语义**：根据 Model Viewer 与 Gneiss 的真实上传路径确定最小公共入口，优先
   扩展现有 Upload Batch，不建立平行传输系统。
4. **S-29D 有界流送与回滚**：覆盖批量提交、进度、取消、部分失败、Device Lost、资源替换和延迟
   回收，保证关闭前公共资源统计归零。
5. **S-29E 跨后端与发布验收**：以同一公共用例验证 Vulkan/WebGPU 的结果码和生命周期，在大型
   Model Viewer 资产上记录主线程响应性、峰值内存和上传吞吐，再完成 0.14.0 发布矩阵。

## 测试与验收

- 开启 GPU 指标后，Render Pipeline 的帧提交和 `get_metrics` 均不调用同步 Timestamp 读取。
- 多帧槽乱序完成时只发布更新结果；暂未完成、失败或取消不会阻塞或破坏后续渲染。
- 管线禁用指标、销毁以及 Renderer 关闭均不泄漏 Query Pool 或异步操作，也不访问失效回调状态。
- Vulkan 与支持 `timestamp-query` 的浏览器 WebGPU 能取得有效纳秒指标；不支持设备稳定报告
  `UNSUPPORTED`。
- 资源流送测试覆盖背压、批次边界、取消竞态、部分失败、Device Lost 和安全资源切换。
- Windows、Linux、Emscripten、共享/静态、C/C++ Consumer、文档和 Release 预验证通过后才提升
  并发布 0.14.0。

## 风险与未决问题

- 当前公共指标结构没有原始提交帧编号；若 Gneiss 需要精确关联帧，必须以真实需求单独设计字段，
  不能把 `sample_sequence` 解释为应用帧序号。
- 异步操作销毁后调用方无法继续查询终态；内部诊断必须在销毁句柄前保存必要结果。
- WebGPU Timestamp 支持依赖实际 Adapter 能力，自动化需同时覆盖支持与不支持分支。
- 只有在现有 Upload Batch 无法表达完成边界时才新增公共上传入口，避免扩大 0.14.0 API 面积。

## 完成记录

- Render Pipeline 已按活动帧槽持有异步 Timestamp 操作，非阻塞轮询并按提交序号避免旧结果覆盖
  新快照；失败、取消、禁用和销毁均释放内部状态。
- Upload Batch 已增加可选字节/操作数上限、占用查询和异步提交。超过单项上限返回
  `INVALID_ARGUMENT`，批次暂时满载返回 `NOT_READY`，失败提交保留原暂存数据供重试。
- Vulkan 使用 fence 查询真实 GPU 完成；浏览器 WebGPU 在队列复制输入后完成。提前销毁公共异步
  句柄不会释放后端仍使用的上传数据和目标资源。
- Model Viewer 已复用公共异步上传入口；Windows 动态/静态构建、78 项本地测试、Emscripten
  Debug/Release 构建及 Chrome 浏览器渲染、取消回滚、缺失资源诊断均通过。
