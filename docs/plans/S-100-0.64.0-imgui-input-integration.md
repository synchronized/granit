# S-100：0.64.0 ImGui 输入适配与 Window 解耦

## 状态

**已完成本地实施，待跨平台与发布收口。** 本计划承接当前 ImGui Integration 只有 Draw Data 转换、示例自行维护
Window/Input 到 ImGuiIO 输入桥接的问题。目标是提供可复用的输入适配，同时不让只使用 ImGui
Draw Data 的应用被迫依赖 `granit::window`。

## 背景与目标

当前公共 `granit::integration::imgui` 只负责把 `ImDrawData` 追加到 Canvas。Tutorial Runtime
在 `examples/common/imgui/imgui_input.*` 中重复维护以下逻辑：

- Granit Window/Input 事件到 ImGui 键盘、修饰键、文本输入、鼠标和焦点事件的转换；
- 每帧显示尺寸、Framebuffer Scale、Delta Time 和 `ImGui::NewFrame()`；
- ImGui 捕获状态与示例相机输入之间的边界。

本版本将这部分能力提升为明确的可选公共适配层，并保持两个使用方向独立：

1. 只拥有自己的事件循环或 SDL Window 的应用，继续使用核心 ImGui Integration 和自己的 ImGui
   Platform Backend；
2. 使用 `granit::window` 的应用，可以直接把 `window_event`、`input_event` 和每帧窗口状态交给
   Granit 的 Window→ImGui 适配层。

## 非目标

- 不接管 ImGui Context、字体 Atlas、Texture ID 或 ImGui Platform/Renderer Backend 的所有权；
- 不把 SDL3、GLFW 或其他平台事件类型加入 Granit ImGui 公共接口；
- 不要求不使用 `granit::window` 的应用链接 Window 组件；
- 不改变现有 `append_draw_data` 的绘制、纹理解析和 Canvas 生命周期语义；
- 不新增 C ABI；输入适配首版只提供 C++20 接口；
- 不在 Granit 内部创建全局事件订阅器，也不自动消费应用事件队列。

## 已确认决策

### S-100A：核心 ImGui 帧接口保持 Window 无关

在现有 `granit::integration_imgui` 组件中增加不依赖 Window 类型的帧描述和新帧入口，实际形态为：

```cpp
namespace granit::integration::imgui {

struct frame_desc {
  float display_width = 0.0F;
  float display_height = 0.0F;
  float framebuffer_scale_x = 1.0F;
  float framebuffer_scale_y = 1.0F;
  float delta_seconds = 1.0F / 60.0F;
};

inline void begin_frame(const frame_desc& frame) noexcept;

}
```

实现只更新当前 ImGui Context 的 IO 并开始新帧，不创建或销毁 Context。调用方不需要链接
`granit::window`，也可以继续只使用 `append_draw_data`。

### S-100B：Window 输入适配作为可选组件

新增独立的 `granit::integration_imgui_window` 组件及对应头文件，拟定入口为：

```cpp
namespace granit::integration::imgui::window {

void process_window_event(const granit::window_event& event) noexcept;
void process_input_event(const granit::input_event& event) noexcept;

}
```

该组件依赖 `granit::window`，但核心 `granit::integration_imgui` 不依赖它。适配层以 header-only
目标发布，函数在调用方内联执行，只转换事件，
不持有 Window，不改变事件所有权，也不决定事件循环顺序。使用 Window 的应用按“处理事件 →
`begin_frame` → 构建界面 → `ImGui::Render` → `append_draw_data`”顺序调用。

### S-100C：示例统一复用公共适配

将 `examples/common/imgui/imgui_input.*` 的转换逻辑迁移到公共适配层，示例保留 Runtime 编排，
不再维护第二份键位、鼠标按钮、滚轮、文本和焦点映射。`08_sdl_imgui` 继续使用 SDL3 官方
ImGui Backend，因为它验证的是外部 SDL Window 所有权边界，不使用 Granit Window。

## 预定文件与目标

```text
include/granit/integrations/imgui/input.hpp
include/granit/integrations/imgui/window_input.hpp
```

同步调整：

- `src/integrations/imgui/CMakeLists.txt`：拆分核心和 header-only Window 适配目标，维护安装 FILE_SET、导出
  目标和静态/共享链接属性；
- `examples/common/imgui/imgui_input.*`：改为薄封装或删除重复实现；
- Tutorial Runtime 及使用 Window 的教程：迁移到公共入口；
- ImGui Integration Reference、Window/Input Reference 和第三方集成说明：补充当前真实接口及
  生命周期限制。

## 实施顺序

1. **S-100A 接口确认（已完成）**：核对 ImGui Context、帧尺寸、DPI、Delta Time 和线程调用约束，确定
   `frame_desc` 字段和错误语义；
2. **S-100B 核心帧实现（已完成）**：实现 Window 无关的 `begin_frame`，补充公共头安装和组件 Consumer；
3. **S-100C Window 适配实现（已完成）**：迁移现有键盘、文本、鼠标、滚轮、焦点和修饰键映射，保持
   `window_event`/`input_event` 当前语义；
4. **S-100D CMake 与示例迁移（已完成）**：建立可选 `integration_imgui_window` 目标，迁移 Tutorial Runtime，
   保留 `08_sdl_imgui` 的独立 SDL 路径；
5. **S-100E 测试与诊断（已完成）**：增加输入事件单元测试、无 Window 核心 Consumer、Window 适配 Consumer
   和 ImGui Draw Data 回归；
6. **S-100F 文档收口（已完成）**：更新 Reference、兼容性、README、版本计划、验收记录和路线图，
   形成版本验收记录；
7. **S-100G 跨平台验收（本地部分完成）**：完成 Windows Vulkan、Linux Vulkan、Emscripten/WebGPU、共享/静态
   安装 Consumer 和文档检查后，再进入发布收口。

## 测试与验收

- 仅链接 `granit::integration_imgui` 的 Consumer 不需要包含或链接 `granit::window`；
- 使用 `granit::integration_imgui_window` 的 Consumer 能正确转换键盘、修饰键、UTF-8 文本、
  鼠标移动/按键/滚轮、指针离开和窗口焦点事件；
- `begin_frame` 正确设置显示尺寸、Framebuffer Scale 和 Delta Time，并且不创建 ImGui Context；
- 输入和帧接口在共享构建中不从 Granit DLL 访问 ImGui Context，避免调用方与动态库各自持有 Context；
- Tutorial Runtime 的输入行为与迁移前一致，ImGui 捕获鼠标时相机控制仍遵守现有边界；
- `08_sdl_imgui` 不引入 Granit Window 依赖，SDL3 外部宿主路径继续通过官方 Backend 工作；
- 核心组件和可选 Window 适配分别通过 Windows/Linux 共享与静态安装 Consumer；
- Emscripten/WebGPU 至少完成多帧输入、Resize、DPI 和文本输入 Smoke；
- CMake 导出、公共头 C++20 编译、文档链接、`git diff --check` 和现有 ImGui 视觉回归通过；
- 不新增 Vulkan 类型、C ABI 或公共资源所有权；若事件模型不足以表达触控/手柄输入，单独记录为
  后续计划，不在本版本隐式扩大范围。

## 风险与未决问题

- ImGui Context 仍由调用方拥有；多 Context、多线程和事件跨线程转发首版不提供自动同步；
- 需要确认 `window_state` 的 DPI/Framebuffer 尺寸字段是否足以填充 `frame_desc`，不足时只扩展
  Window 状态查询，不把平台类型泄漏到 ImGui 组件；
- 是否保留 `examples/common/imgui/imgui_input.*` 的兼容转发，取决于示例外部使用者是否依赖该
  非公共路径；默认优先删除重复逻辑；
- 触控、手柄和 IME 组合输入不属于首版验收范围，需先建立 Granit Input 的稳定公共语义。

## 版本出口

只有核心 ImGui 路径与 Window 适配路径均有独立 Consumer、示例迁移、跨平台输入 Smoke、安装导出
和文档收口证据后，才允许创建 `v0.64.0` tag 和 GitHub Release。
