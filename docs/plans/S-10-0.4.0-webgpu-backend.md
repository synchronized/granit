# S-10：0.4.0 多后端与 WebGPU

## 状态

- 实现状态：进行中；S-10A 至 S-10D、S-10E1 至 S-10E3 已完成，正在实施 S-10E4 公共 Renderer
- 目标版本：0.4.0
- 前置依赖：S-09E
- 优先级：P2

## 背景与目标

Granit 公共 C ABI 已隔离 Vulkan 类型，但内部 Renderer、资源和命令实现仍以 Vulkan 为唯一后端。
0.4.0 计划先建立可验证的内部多后端边界，再增加 WebGPU MVP，并最终验证 Emscripten 浏览器路径。

目标包括：

- 保持现有公共句柄、所有权和错误语义，不把 WebGPU 或 Vulkan 原生类型加入基础 API。
- 抽出设备、资源、绑定、Pipeline、命令、Queue、同步、Surface 和能力查询的内部后端契约。
- 在桌面环境跑通 WebGPU Buffer、Texture、Sampler、Bind Group、Pipeline 和离屏三角形。
- 建立 WGSL 输入或经过验证的 Shader 转换链，不要求浏览器直接消费 Vulkan 专用 SPIR-V 路径。
- 接入 Emscripten WebGPU、浏览器 Canvas、非阻塞主循环和基础输入，形成可自动验证的 Web 示例。

## 非目标

- 不要求首个 WebGPU 后端与 Vulkan 的全部格式、查询、同步和高级渲染能力完全对等。
- 不在后端边界明确前用大范围条件编译复制 Vulkan 实现。
- 不在 0.4.0 MVP 中承诺 Bindless、原生后端互操作或浏览器多线程渲染。
- 不在 0.4.0 中交付 Android NDK、移动 Surface、触控输入或应用生命周期集成；当前只保证内部
  插件和 WebGPU 实现边界不会阻碍后续 S-11。
- 不因 Web 平台限制降低 Vulkan 后端现有能力；差异通过能力查询和明确降级表达。

## 已确认决策

- 0.3.0 只完成 SDK 与发布验收，多后端工作使用新的 0.4.0 特性分支。
- 先做桌面 WebGPU 离屏 MVP，再接入 Emscripten，避免同时调试后端抽象和浏览器平台边界。
- Vulkan 继续作为完整主后端；WebGPU 首阶段只实现共同最小能力集。
- WebGPU 原型采用 Dawn Native 与浏览器 Emdawnwebgpu，私有锁定匹配的 `webgpu.h`。桌面插件内部
  静态链接 Dawn，Android 和 Emscripten 默认编译期接入；核心只加载 Granit 自有插件 ABI，具体
  约束见[ADR-004](../decisions/ADR-004-webgpu-provider-loading.md)。
- Registry 继续统一管理公共句柄、生命周期和线程安全；后端通过粗粒度内部契约提供资源、命令、
  Queue、Surface 与能力实现，详见[ADR-003](../decisions/ADR-003-internal-renderer-backend-boundary.md)。
- 首轮迁移不增加公共后端枚举，也不改变 SPIR-V 创建接口；这些 ABI 在内部边界和 WebGPU 原型验证
  后分别设计。

## 实施顺序

1. **S-10A 后端边界与能力模型**：耦合审计与接口分层已形成；先定义 Granit 后端插件 ABI，验证
   Dawn 静态插件、无窗口设备与 Emdawnwebgpu 编译路径，再实现资源契约并按资源类别迁移 Vulkan。
2. **S-10B 桌面 WebGPU MVP**：完成无窗口设备、基础资源、绑定、Pipeline、命令提交和离屏回读。
3. **[S-10C Shader 工具链](S-10C-wgsl-toolchain.md)**：已完成；以 WGSL 为跨后端源码权威，建立
   Tint 离线编译、反射清单、确定性资产、错误诊断和缓存测试。
4. **S-10D Emscripten 平台层**：接入浏览器设备请求、Canvas Surface、事件循环和资源加载。
5. **S-10E 高层路径与 CI**：迁移 Frame Context、Canvas 和最小 RenderPipeline 示例，加入浏览器测试。

## S-10D 已确认决策

- **依赖接入**：使用锁定 Emscripten 工具链提供的 `--use-port=emdawnwebgpu`，继续以私有
  `<webgpu/webgpu.h>` 作为实现接口；不直接集成 Emdawnwebgpu 的 C++/JavaScript 源码，也不在
  浏览器运行时加载 Dawn 动态库。
- **阶段边界**：S-10D 只建立 Emscripten 构建目标、浏览器 Adapter/Device 初始化、Canvas
  Surface、非阻塞主循环、基础键盘/鼠标事件适配和启动 smoke test。RenderPipeline、Canvas
  绘制闭环和三角形像素验证属于 S-10E。
- **异步模型**：Adapter/Device 请求使用显式状态机和回调推进；帧循环使用
  `emscripten_set_main_loop_arg()` 并由浏览器 `requestAnimationFrame` 调度。首阶段保持单线程，
  不启用 Asyncify，也不通过同步等待阻塞浏览器主线程。
- **平台接口**：扩展未稳定的内部 WebGPU 后端契约以表达 Surface 创建、配置、帧获取和 Present；
  Canvas 通过调用期间复制的 UTF-8 CSS selector 指定，默认使用 `#canvas`。公共 C ABI 和内部插件
  ABI 均不传递 `EM_VAL`、JavaScript 对象或 Emscripten/WebGPU 原生句柄。
- **资源加载**：首阶段通过 Emscripten 虚拟文件系统预加载确定性测试资源，不在 S-10D 新增通用
  Fetch API。浏览器按异步启动状态进入主循环，不假定资源可以通过桌面文件路径直接访问。
- **自动验证**：CI 锁定 Emscripten 与 Emdawnwebgpu 组合，至少验证 Wasm 编译、链接、页面启动和
  WebGPU 初始化状态；错误必须转为可读取的失败状态，不得静默跳过。Canvas 三角形和像素结果在
  S-10E 统一验证。

以上能力保持在内部平台层，不新增公共后端枚举、浏览器专用公共 API 或第二套 Renderer 状态。

S-10D 按以下子阶段实施：

1. **S-10D1 构建骨架**：增加锁定 emsdk 5.0.6 的 Debug/Release preset，以 Emdawnwebgpu port
   编译独立浏览器平台验证目标；当前 Vulkan `granit` 核心不伪装为可用的 Web SDK。
2. **S-10D2 异步启动**：验证预加载资源、Instance、Canvas Surface、Adapter/Device 回调状态机、
   Surface 配置、`requestAnimationFrame` 主循环和基础键鼠事件计数。
3. **S-10D3 自动验证**：手动 Emscripten Actions 缓存锁定工具链，审计 HTML、JavaScript、Wasm
   和数据包产物，并通过无头 Chrome 验证 WebGPU 启动状态及键鼠输入转发；本阶段不验证三角形
   像素。浏览器驱动锁定 `playwright-core` 1.62.1（Apache-2.0），仅用于 CI 测试且复用 Runner
   自带 Chrome，不进入 Granit SDK、运行时依赖或安装导出；备选的浏览器原生命令行缺少可靠的
   异步状态读取能力，完整 Playwright 浏览器包则会增加不必要的下载与缓存成本。

S-10D1 至 S-10D3 已通过锁定 Emscripten 工具链的远端构建、HTML、JavaScript、Wasm、数据包
产物审计，以及无头 Chrome 的 WebGPU 启动与输入转发验证。完整 Granit 公共 Renderer 接入、
Canvas 帧获取和绘制闭环仍属于后续子阶段及 S-10E。

## S-10E 已确认决策

- **先清理核心边界**：先移除 `renderer_state`、Registry Bind Group 访问记录和 Timestamp Query
  对 Vulkan 原生类型的直接依赖，再接入 WebGPU Canvas。公共句柄表、所有权、资源保留和延迟销毁
  继续只保留一份，不在 Emscripten 下复制 Renderer Registry。
- **异步初始化语义**：Renderer 句柄允许处于 `initializing`、`ready`、`failed` 或 `device_lost`
  状态。浏览器创建 Renderer 后由主循环推进 Adapter/Device 回调；依赖设备的操作在就绪前返回
  `GRANIT_ERROR_NOT_READY`，不启用 Asyncify、不阻塞浏览器主线程，也不把 JavaScript Promise 穿过
  C ABI。桌面 Vulkan 创建后仍立即处于 `ready`，保持现有调用路径。
- **状态查询**：增加可扩展的 Renderer 状态查询结构和 C/C++ 轻量包装；失败状态保留稳定结果码，
  详细文本继续通过 Diagnostic Callback 输出。状态查询不得隐式等待或执行用户回调。
- **后端选择**：Emscripten 构建只静态接入 WebGPU Provider，由内部工厂直接查询插件 ABI，不使用
  `dlopen`。桌面默认仍创建 Vulkan Renderer；0.4.0 不增加公共后端选择枚举，桌面显式选择 WebGPU
  延后到共同能力和错误语义稳定后。
- **Canvas Surface**：公共 Surface API 增加 CSS selector 的“指针 + 字节长度”描述，调用期间复制，
  默认 selector 为 `#canvas`；不公开 `EM_VAL`、JavaScript 对象、`WGPU*` 或其他原生句柄。该入口仅在
  支持 Canvas 的 Renderer 上成功，其他后端返回 `GRANIT_ERROR_UNSUPPORTED`。
- **呈现模型**：插件 ABI 增加 Surface、Swapchain、获取帧和 Present 的粗粒度操作。获取帧返回由
  Swapchain 拥有的借用 Texture/View，Frame 结束或重建后失效；Registry 继续生成并校验公共 Frame
  令牌。浏览器由 `requestAnimationFrame` 决定节奏，Mailbox/Immediate 不可用时明确降级到 FIFO，
  并在查询信息中返回实际模式。
- **插件 ABI 演进**：实验性插件 ABI 从版本 3 直接升级，不保留旧版本兼容分支。异步状态推进、
  Surface/Swapchain 和借用 Backbuffer 在同一版本中一次定义，桌面 Dawn Mock 与真实插件测试同步
  更新。
- **首个绘制闭环**：沿用已完成的 WGSL Shader 工具链和现有公共 RenderPipeline/Command Recorder
  语义，首个浏览器示例只绘制一个确定性三角形；不为示例增加专用 Shader、Mesh 或第二套 Canvas
  API。
- **跨后端 Shader 输入**：S-10C 资产同时保存 WGSL 与 SPIR-V；S-10E 在 `granit_shader_desc` 尾部
  增加可选 WGSL 视图，Vulkan 继续读取 SPIR-V，WebGPU 读取 WGSL。核心不在浏览器运行 Tint，
  C++ 通过独立 `shader_asset_desc` 保持既有 `shader_desc` 源码兼容。

S-10E 按以下子阶段实施：

1. **S-10E1 核心去 Vulkan 化（已完成）**：补齐后端状态、资源访问和 Timestamp Query 契约，使
   Registry 记录不再保存 `Vk*`；以 Vulkan 全量回归和测试替身验证行为不变。
2. **S-10E2 异步 Provider 生命周期（已完成）**：升级插件 ABI，增加状态查询与事件推进；桌面
   保持同步就绪，Emscripten 使用回调状态机，覆盖初始化中、成功、失败、Device Lost 和销毁期间
   回调失效。
3. **S-10E3 Canvas 与呈现（已完成）**：增加 Canvas Surface、Swapchain、借用 Backbuffer、
   Acquire/Present，复用公共 Frame 令牌和资源生命周期校验。插件呈现 ABI、状态机、Registry
   动态 Backbuffer、内部资源适配器和 Emscripten 静态 Provider 入口已完成；Debug/Release 浏览器
   验证覆盖异步初始化、Canvas/Swapchain、Acquire、借用 Backbuffer、Cancel、状态和输入转发。
4. **S-10E4 公共 Renderer 接入（进行中）**：Emscripten 静态链接核心和 WebGPU Provider，接通
   状态查询、限制、Shader、Pipeline、命令提交及 Canvas 帧路径；普通用户仍只包含 Granit 公共
   头文件。WebGPU Renderer 状态对象已集中管理静态 Provider、实例、诊断、异步生命周期、能力
   快照和呈现适配器，并通过 Mock 与 Emscripten Debug/Release 浏览器验证。Vulkan 与 WebGPU
   状态现已共同实现最小 `backend_renderer` 接口，Registry 根 Renderer 记录也已通过该接口统一
   生命周期推进、状态和能力查询。Registry 已增加 WebGPU 静态 Provider 工厂和不依赖 Vulkan
   资源状态的通用销毁路径。Emscripten Smoke 已改由公共 `granit_renderer_create`、状态、限制和事件
   API 驱动 WebGPU Renderer，并复用公共描述校验与 generation 句柄表。Canvas Surface、Swapchain、
   Frame、动态 Backbuffer 及 Cancel/Present 也已接入公共 C API，覆盖资源所有权、Renderer 级联
   销毁和帧结束后的句柄失效。公共 Shader 描述现可同时携带 SPIR-V 与 WGSL，WebGPU Shader
   创建、所有权、销毁及失效句柄已通过浏览器验证。空 Pipeline Layout 与无顶点输入、单颜色附件的
   基础 Graphics Pipeline 已接入公共 API，支持 RGBA8/BGRA8，并验证 Shader、Layout 与 Pipeline
   的依赖生命周期。最小 Command Recorder 状态机现已接通单颜色附件、空 Bind Group 三角形 Draw、
   Finish、帧关联 Queue Submit 和 Canvas Present；下一步补中心像素验收并收敛 S-10E5 示例。
5. **S-10E5 示例与验收**：浏览器绘制确定性三角形，无头 Chrome 验证状态、输入和中心像素；同时
   验证原生 Vulkan 构建、C/C++ Consumer、安装导出及 Emscripten 产物不回退。

## 测试与验收

- Vulkan 后端现有 Windows/Linux、共享/静态、安装 Consumer 和性能基线不得无解释退化。
- 同一公共资源与命令测试可对 Vulkan 和 WebGPU 后端复用，后端差异必须显式标记。
- 桌面 WebGPU 至少完成确定性离屏像素回归；浏览器至少完成 Canvas 三角形和基础输入 smoke test。
- Emscripten 构建不得要求使用者包含 WebGPU 实现头，也不得把 JavaScript 对象穿过稳定 C ABI。
- CI 锁定第三方版本并缓存工具链；浏览器测试失败不得通过跳过或降级检查掩盖。

## 风险与未决问题

- WebGPU 设备创建采用可查询状态且不阻塞的 Renderer 生命周期；剩余风险是映射、回读和提交完成
  如何在不扩大首轮公共异步 API 的前提下保持可预测进度。
- WGSL 已确定为新增跨后端 Shader 的源码权威，SPIR-V 和反射为可重建产物；后续风险集中在
  Emscripten 资源加载和浏览器诊断接入。
- Timestamp Query、纹理格式、动态偏移和 Surface 能力可能无法与 Vulkan 一一对应。
- Emscripten 的主循环、文件系统、线程和异常设置会影响现有示例及第三方 Integration 组织方式。

   移动所有权及不兼容 ABI 测试；Host 诊断、成对分配器、实例创建/销毁和卸载前清理契约也已通过
   测试。实验性 WebGPU 插件目标已经建立，并通过 Mock WebGPU 编译与生命周期测试；匹配工具链
   的 Windows/Linux Dawn 静态包、真实插件加载、Instance/Adapter/Device 生命周期、有限 Future
   等待和无 GPU runner 的软件适配器路径已经验证。详见
   [Dawn 发布包评估](../records/2026-08-26-s10a-dawn-package-evaluation.md)。
3. 建立后端资源基类和测试替身，迁移 Buffer、Texture、Texture View 与 Sampler 资源记录。已完成；
   四类 Registry 记录均只持有后端资源抽象，Vulkan 原生资源对象负责具体句柄和销毁语义。
4. 迁移 Shader、Bind Group 与 Pipeline；Shader 公共输入仍保持 SPIR-V。已完成；对应 Registry 记录
   均只持有后端资源抽象，Vulkan 对象负责原生句柄与销毁。
5. 迁移 Recorder、Queue、Frame Context 与 Upload Batch。已完成；Queue 契约统一普通与批量命令

   Release 全量测试以及 Release 帧循环性能回归已通过；Linux GCC/Clang 共享与静态、Integration
   Runtime、C/C++ Consumer 以及 Windows MSVC 共享与静态安装 Consumer 均已通过手动 Actions。

## S-10B 桌面 WebGPU MVP

S-10B 只验证内部插件契约和桌面离屏闭环，不新增公共后端枚举，也不把 Dawn 对象加入 Registry 或
公共 ABI。实验性插件 ABI 尚未发布，本阶段直接演进当前版本，不保留旧版兼容分支。

按以下顺序实施：

1. **S-10B1 设备与能力契约**：已实现插件实例操作表与固定能力快照，覆盖 Buffer 对齐/容量、
   Texture、Bind Group 和颜色附件限制；Mock 插件已通过 ABI 布局、`struct_size`、实例归属、错误
   语义和生命周期测试，并已通过 Windows D3D12 与 Linux Vulkan 真实 Dawn 验证。
2. **S-10B2 Buffer 与传输**：已实现实例所属的 64 位 Buffer 句柄、创建、销毁、Queue 写入和
   Map Read；已覆盖 Usage、对齐、越界、跨实例、重复销毁与级联清理。Dawn Future 最多等待十秒，
   超时返回 `GRANIT_ERROR_NOT_READY`；Mock、本地回归与真实 Dawn 回读均已通过。
3. **S-10B3 Texture 与 Sampler**：已实现实例所属的二维 RGBA8 Texture、默认 Texture View 和
   Sampler，覆盖 Usage、尺寸、过滤模式、跨实例、父子销毁顺序、重复销毁与实例级联清理。首轮
   固定单层、单 mip、单采样；Mock、本地回归与真实 Dawn 验证均已通过。
4. **S-10B4 Bind Group 与 Pipeline**：已实现固定 Texture View/Sampler Bind Group Layout、
   Bind Group、Pipeline Layout 和 RGBA8 Render Pipeline，测试内部使用固定 WGSL。已覆盖跨实例、
   重复销毁、依赖销毁顺序与实例级联清理；Mock、本地回归与真实 Dawn 验证均已通过。
