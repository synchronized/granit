# S-102：0.65.0 第三方依赖清单与缓存层收敛

## 状态

**实施中。**

## 背景与目标

S-101 已将 cgltf 和 stb_image 接入共享源码缓存，但不同依赖的版本、URL、SHA-256 和标记文件仍
分散在集成模块与示例 CMake 文件中。本任务集中维护下载型源码依赖的身份信息，并把缓存下载逻辑
独立为可复用的 CMake 模块。

## 非目标

- 不改变 SDL3、ImGui、cgltf 或 stb_image 的 target 类型和链接边界；
- 不把不同依赖强行包装成相同的构建目标；
- 不合并 Shader Toolchain 的二进制下载逻辑；
- 不引入 CPM.cmake、vcpkg、Conan 等新的包管理器。

## 已确认决策

- `cmake/granit_dependency_catalog.cmake` 是锁定版本、commit、URL、SHA-256 和 marker 的唯一来源；
- `cmake/granit_dependency_cache.cmake` 只负责源码归档下载、校验、解压和共享缓存；
- 集成模块继续按依赖类型创建 CMake 项目目标、手动源文件目标或头文件 `INTERFACE` 目标；
- Shader Toolchain 继续保留独立的工具版本、二进制归档和能力探测流程。

## 实施顺序

1. 建立依赖清单和通用源码缓存模块；
2. 迁移 SDL3、ImGui、cgltf、stb_image 的元数据引用；
3. 更新 CMake 文件索引、构建指南、版本规划和第三方通知；
4. 验证缓存命中、配置生成、共享/静态构建和文档检查；
5. 在 S-101 的基础上完成 v0.65.0 版本收口。

## 测试与验收

- 已有缓存时，四项源码依赖均不重复下载；
- SDL3 和 ImGui 仍能通过 `FetchContent` 使用缓存源码；
- cgltf 和 stb_image 仍能通过头文件目标编译 glTF 支持；
- 相关构建、文档检查和 `git diff --check` 通过；
- 版本、下载地址和 SHA-256 不再在多个 CMake 文件中重复定义。

## 风险与未决问题

- 新增依赖时仍需手动登记许可证和第三方通知；
- Shader Toolchain 的二进制缓存与源码缓存保持两套流程，后续若出现更多工具依赖再单独评估。
