# S-39：0.23.0 空帧与覆盖层可靠性

## 状态

**实现中。** S-39A～S-39C 已完成空可见集合契约、空 Opaque submission 与 clear-only 录制；
S-39D～S-39E 待完成跨后端覆盖层、Gneiss 和发布验收。版本不增加公共 API 或 ABI。

## 背景与目标

Gneiss 编辑器启动后会先显示工程选择界面。此时应用已经提供默认 View、Canvas 和交换链 Frame，
但场景没有相机实体或 3D 物体。Render Pipeline 应当清除场景目标、执行 Tone Mapping、绘制 Canvas
与用户 Overlay，并提交传入的 Frame。

当前实现把“没有可见物体”误判为渲染尚未准备：

- `build_render_view_submission` 对空可见集合返回 `GRANIT_ERROR_NOT_READY`；
- PBR Render Graph adapter 拒绝空对象数组；
- 内建 Opaque recorder 只在逐物体循环中开启 Rendering，零物体时不会清色、清深度或完成
  MSAA resolve；
- 因此后续 Tone Mapping、Debug Draw、Canvas、Overlay 和 `submit_frame` 都不会发生。

本任务建立“输出驱动”的帧语义：只要 Render 描述包含有效 View 和输出，零个可见物体就是合法帧，
仍然产生确定的背景与覆盖层结果，并按调用方提供的离屏或交换链目标完成提交。

## 非目标

- 不允许 Scene Snapshot 缺少 View；调用方仍须提供至少一个有效 View。
- 不增加 UI-only 专用入口、清屏专用入口或新的公开句柄。
- 不改变 Canvas、Debug Draw、Text、Scene Snapshot 或 Render Pipeline 的公共结构布局。
- 不把透明 PBR、天空盒、CSM、Clustered Forward、Bindless 或 Android 纳入本版本。
- 不借修复重新设计通用 Render Graph 或公开其私有 pass 类型。
- 不改变成功提交后由调用方 Present 的既有 Frame 所有权契约。

## 已确认决策

### 空可见集合是合法渲染输入

Scene Snapshot 仍必须包含被选择的 View；Renderable、方向光、点光和聚光可以全部为空。可见集合为空
不表示资源未准备，也不返回 `GRANIT_ERROR_NOT_READY`。Draw Binding 只要求覆盖实际可见的
Renderable，不要求为已被裁剪或不存在的物体提供占位绑定。

自定义 Opaque 回调仍会被调用一次，并接收 `payload_count == 0`、空 Renderable 和空 Draw Binding，
从而与内建录制路径保持相同的阶段顺序。Overlay 回调不依赖 Opaque 对象数量。

### Opaque pass 始终建立输出

PBR adapter 允许空对象数组，并继续建立具有 Color、Depth 和可选 Resolve 写访问的 Opaque pass。
内建 recorder 在零 Draw 时执行一次 clear-only Rendering：

- 使用 `clear_color` 清除 HDR Color；
- 清除 Depth；
- 启用 MSAA 时在同一次 begin/end 中完成 Resolve；
- 不创建 Material、Binding、Mesh 或 Draw 命令。

非空 Draw 的现有绘制顺序和结果保持不变。是否将非空对象收敛到单个 Rendering scope，只有在独立
测试证明资源准备失败不会留下部分录制、且 Vulkan/WebGPU 结果一致时才实施；它不是空帧修复的
前置条件。

### 后处理和覆盖层不依赖场景几何

Tone Mapping 始终消费已经初始化的 HDR 目标。世界 Debug Draw、Canvas 和用户 Overlay 继续按固定
顺序执行。Canvas 本身为空时仍允许帧成功，但不产生几何命令。

传入 `granit_frame` 时，成功路径必须通过 `execute_frame` 提交到该 Frame；离屏输出继续使用普通
Recorder 提交。任何 pass 录制失败都保留既有失败返回和 Frame 取消责任，不伪装成成功提交。

### 以行为矩阵代替单一路径回归

0.23.0 同时覆盖以下容易退化为“没有工作”的输入：

| Scene | 覆盖层 | 输出 | 预期结果 |
|---|---|---|---|
| 零 Renderable | 无 | 离屏 Texture | 背景色经过 Tone Mapping 后可回读 |
| Renderable 全部被裁剪 | Canvas | 离屏 Texture | 背景与 Canvas 都可回读 |
| 零 Renderable | Canvas/Text | Swapchain Frame | Frame 成功提交并可 Present |
| 零 Renderable | 自定义 Overlay | 离屏 Texture | Opaque 与 Overlay 回调各执行一次 |
| 零 Renderable、零 Light | Canvas | Vulkan/WebGPU | 两个后端阶段和像素语义一致 |

## 实施顺序

1. **S-39A 契约与回归基线（已完成）**：已增加空可见集合、全裁剪集合和回调阶段测试，并补充
   Render Pipeline、Scene Snapshot 与 C API 的空帧语义。
2. **S-39B 空 Opaque submission（已完成）**：submission 与 PBR adapter 已允许空对象，让空数组沿
   现有 Render Graph 数据流进入 Opaque callback。
3. **S-39C clear-only 录制（已完成）**：内建 Opaque recorder 已在零 Draw 时清除 Color 与 Depth，
   处理 1x/4x MSAA resolve，且不访问材质、绑定或 Mesh。
4. **S-39D 覆盖层与 Frame 验收**：验证 Debug Draw、Canvas、Text 和用户 Overlay 在空场景中保持
   顺序；桌面窗口覆盖 acquire、提交和 Present，浏览器 Canvas 覆盖 WebGPU 多帧结果。
5. **S-39E Gneiss 与发布验收**：使用安装后的 0.23 SDK 构建 Gneiss，验证工程选择界面只有 UI、
   切换到有物体场景及返回空场景；随后完成共享/静态、跨平台、文档和 Release Candidate 验收。

每个子阶段形成一个聚焦提交，全部阶段在同一个 0.23.0 特性分支和 Pull Request 中连续完成。

## 测试与验收

- 空可见集合不再返回 `GRANIT_ERROR_NOT_READY` 或 `GRANIT_ERROR_INVALID_ARGUMENT`。
- clear-only 离屏像素回读与 `clear_color` 经 Tone Mapping 后的预期值一致。
- 空场景加 Canvas/Text 的背景像素和 UI 像素均可区分，Canvas 不会被清屏覆盖。
- 自定义回调按 Opaque、Overlay 顺序各执行一次，Opaque 的数组计数与指针符合空输入契约。
- MSAA 1x/4x、UNORM/sRGB 输出、无 Light 与默认 Environment 组合通过。
- Vulkan 窗口 Smoke 至少完成多帧 acquire、Render Pipeline submit 和 Present。
- Emscripten Chrome WebGPU Smoke 验证相同的空场景、Canvas、Resize 和多帧路径。
- Gneiss 工程选择界面无需虚构 3D Renderable 即可稳定显示，进入工程后的普通 PBR 场景无回归。
- Windows/Linux 共享与静态测试、安装 Consumer、Emscripten 构建及文档检查通过。

## 风险与未决问题

- clear-only Rendering 必须在 Vulkan 与 WebGPU 上产生相同的 MSAA Resolve 结果，不能依赖某一后端
  对无 Draw render pass 的偶然行为。
- 自定义 Opaque callback 需要自行初始化其输出；Reference 必须明确该责任，避免空数组被误解为
  可以跳过回调。
- Swapchain Frame 的失败路径由调用方 Cancel 的现有契约不能改变；测试需要区分“成功提交”和
  “失败后仍可取消”。
- Gneiss 当前锁定的 Granit 版本与 0.23 候选包必须由安装 Consumer 显式更新，不能依赖开发树路径。
