# S-77：0.42.0 Model Viewer 加载与运行时收敛

## 状态

- 文档状态：草案
- 实现状态：未开始
- 目标版本：v0.42.0
- 已有证据：浏览器仍显示 DOM 进度层；加载完成后才稳定显示共享 ImGui；浏览器 WebGPU 验收
  偶发 Dawn Instance/Device 丢失

## 背景与目标

Model Viewer 的 Desktop 与 Web 已共用 `viewer_application`、Render Service 和最终 ImGui 面板，
但浏览器 Shell 仍维护一套可见 DOM 加载界面，并从控制台文本重建进度。共享 Application 虽已有
ImGui 加载窗口，场景解析、GPU 上传和 Pipeline 准备等同步阶段不能持续产生加载帧，导致 Web 的
实际体验仍依赖 DOM 覆盖层。

本任务把加载生命周期收回共享 C++ Application。平台入口只负责启动和驱动 Tick；加载状态、进度、
取消、错误和 UI 均由同一套代码管理。浏览器在 GPU 呈现尚未可用的启动瞬间只显示 Canvas 背景，
首个可渲染帧开始显示 ImGui 加载面板，完成后进入与 Desktop 相同的 Model Viewer。

## 非目标

- 不要求在 Renderer、Surface、Swapchain 或 ImGui Font Atlas 建立之前绘制 GPU UI。
- 不将 Model Viewer 私有状态机、资产加载器或执行器直接提升为公共 SDK API。
- 不新增 DOM 可见备用界面，也不让 JavaScript 负责业务进度或错误呈现。
- 不用测试重试、串行矩阵或吞掉设备丢失错误代替生命周期修复。
- 不处理缺少稳定复现和验收标准的其他 Model Viewer 问题。

## 已确认设计

### 单一状态来源

共享 Application 维护只读加载快照，至少包含：

- 当前阶段、阶段说明和整体进度；
- 已完成量、总量以及总量未知状态；
- 是否可取消、是否已取消和结构化失败结果；
- 加载完成并可切换到 Viewer 的明确状态。

进度由执行加载工作的 C++ 代码发布。Web Shell 可以读取隐藏的机器状态用于自动化，但不得解析
控制台文本来决定用户界面。控制台消息仅用于诊断。

### 统一可见界面

- Desktop 与 Web 使用同一个 ImGui 加载面板、主题和状态文本。
- 面板显示当前阶段、整体进度和取消入口；失败与取消也在同一窗口完成呈现。
- HTML Shell 只保留 Canvas、启动胶水和不可见的自动化观测点，删除标题、进度条、状态文本和
  DOM 取消按钮等可见元素。
- 完成态继续使用现有共享 Viewer 面板、相机、渲染服务和输入路径。

### 跨平台执行模型

加载按可轮询的阶段推进：

```text
platform bootstrap
  -> presentation ready
  -> asset fetch
  -> scene parse/decode
  -> GPU upload
  -> pipeline prepare
  -> viewer ready
```

每个 Tick 只推进有限工作，然后允许主循环绘制 ImGui 加载帧。Desktop 可以在后台执行 CPU 工作，
Web 使用协作式推进；两端消费同一个状态机。GPU 资源创建仍在满足 Renderer 线程约束的位置执行。
不得从任意资源进度回调中重入完整渲染流程。

若现有 glTF 解析或 GPU 上传只能整段同步执行，先把它拆成可测的准备、分批提交和完成步骤。只有
无法安全拆分的短操作允许作为单步执行，并须记录其最长阻塞时间。

### 浏览器遥测与测试

浏览器自动化通过隐藏状态或显式测试钩子读取阶段、结果和失败原因。该通道不参与视觉呈现，也不
成为正常应用逻辑的条件。测试须区分启动未具备呈现能力、加载中、完成、取消和失败。

### WebGPU 生命周期

独立审计 Emscripten 下 Instance、Adapter、Device、Surface 和异步回调的所有权，确保回调存活期
不超过其依赖对象，关闭和失败路径不会提前释放 Instance。浏览器测试启动器同时检查页面复用、
并行任务和退出清理，但只有生命周期证据证明相关时才调整矩阵并行度。

## 实施顺序

1. 为加载阶段、快照、进度单调性、取消和失败转换建立共享状态模型及单元测试。
2. 让共享 ImGui 面板完全消费该快照，并覆盖启动后首帧、加载、完成、取消和失败视图。
3. 删除 Web Shell 的可见加载层，把既有浏览器观测改为隐藏、结构化且不参与业务逻辑的通道。
4. 将资源获取、场景解析、GPU 上传和 Pipeline 准备接入可轮询状态机，使 Web 每阶段之间均可
   返回主循环并绘制；Desktop 复用同一转换规则。
5. 统一取消、失败、重试边界和资源回收，确认完成态只切换一次并使用共享 Viewer。
6. 定位并修复 Dawn Instance/Device 丢失，增加对象生命周期诊断与重复启动/退出回归。
7. 更新 Model Viewer Guide/Reference 和浏览器测试，完成 v0.42.0 跨平台验收。

各阶段在相关测试通过后创建聚焦提交。若实施证明必须修改公共 API，先回写本计划的所有权、线程和
兼容影响，再同步 C/C++ API、Reference、Consumer 与测试；当前 0.x 不保留被取代入口。

## 测试与验收

- 状态模型：阶段合法转换、整体进度单调、未知总量、重复完成、取消竞态和失败传播。
- UI：Desktop/Web 使用相同面板；加载、失败和取消文本来自同一快照；完成后不残留加载窗口。
- Web Shell：Canvas 外没有可见加载控件；隐藏遥测不改变应用行为。
- 执行：慢资源获取、慢解析、分批上传和 Pipeline 准备期间均能产生 ImGui 帧并响应取消。
- 渲染：加载完成后模型、相机、PBR、环境、调试面板和输入行为与 Desktop 一致。
- 生命周期：连续创建/退出、多页面或测试用例运行、失败中止和设备丢失均无悬空回调及资源泄漏。
- 平台：Windows Vulkan、Linux Vulkan、Emscripten Node 与浏览器 WebGPU 通过相关测试。
- 发布：浏览器正式/测试 Model Viewer 均稳定通过一次完整工作流，不以重跑作为成功条件。

## 风险与约束

- 场景解析和 GPU 上传的分步化可能暴露现有辅助类的隐式线程假设，应先保持在 Example 私有边界。
- 过细的每项进度会增加锁和回调开销，快照按阶段合并并限制发布频率。
- 浏览器在首个 GPU 帧之前无法显示 ImGui；Canvas 背景是明确的启动状态，不另建第二套 UI。
- Dawn 错误可能同时包含库生命周期和测试启动器因素，必须通过诊断证据分别处理。
