# S-40：0.23.0 Shader Toolchain 配置可靠性

## 状态

**已完成。** 配置顺序、旧缓存迁移、锁定工具链快照、Windows 完整构建和模式矩阵均已通过，
Linux 锁定包与 Release Candidate 也已完成远端验收。详细结果见
[S-39～S-41 远端发布验收](../records/2026-09-14-s39-s41-remote-release-acceptance.md)。

## 背景与目标

0.22.0 已把 DXC 与 Tint 作为一个锁定的 Shader Toolchain 根目录交付，但源码树在加入 `src/`
之后才探测工具链。旧构建缓存如果分别保存了 DXC 与 Tint 路径，Render Pipeline 会误以为能够从
HLSL 生成 Library，随后因缺少统一根目录而配置失败。

此外，仓库内 Shader Library 快照由旧的本机工具组合生成，与 0.22.0 发布的锁定工具链不一致。
清理对象缓存后，`download` 模式会生成不同内容 ID，并在快照比较阶段失败。

本任务让工具链发现先于所有 Shader 资产目标发生，并把同一根目录作为启用源码生成的原子条件。
锁定 Release 重新生成的 Library、索引、Shader ID 和 Material 成为仓库权威快照。

## 非目标

- 不改变 HLSL-first、`.grshaderobj`、`.grshlib` 或 `.grmat` 格式。
- 不让运行时目标依赖 DXC、Tint、网络或 AssetTools。
- 不接受来自不同目录的 DXC 与 Tint 组成一个隐式工具链。
- 不改变 Toolchain Release 的锁定版本、归档地址或 SHA-256。

## 已确认决策

- 顶层配置在加入 `src/` 前按构建选项执行一次工具链发现；`tools/` 不再重复发现。
- 只有根目录、DXC 与 Tint 同时有效时才生成并校验 HLSL Shader Library。
- 旧缓存中的两个工具路径仅在它们位于同一个名为 `bin` 的目录时推导根目录。
- 分离路径在 `system` 模式下清空并使用已提交快照；`auto` 模式随后获取锁定工具链。
- 快照及依赖它们的内容 ID 和 Material 必须由锁定工具链一起刷新。

## 实施顺序

1. **S-40A 配置顺序与能力条件（已完成）**：把发现移到顶层，并让 Library 生成检查完整根目录。
2. **S-40B 旧缓存迁移（已完成）**：接受共同 `bin` 目录，拒绝分离的 DXC/Tint 路径。
3. **S-40C 锁定快照（已完成）**：刷新 PBR、Canvas、Tone Mapping、Shadow 与 Debug Draw Library、
   索引、Shader ID 和 Material。
4. **S-40D 构建验收（已完成）**：已覆盖 `off`、`system`、`auto`、`download`，并执行干净缓存
   下的相关构建、测试和文档检查；Linux 锁定包已由远端矩阵验证。

## 测试与验收

- 0.22.0 遗留的分离工具路径不会导致 Render Pipeline 配置失败。
- 共同 `bin` 目录可恢复统一根目录，分离目录会被拒绝。
- `system` 缺少完整工具链时使用快照，且不访问网络。
- `download` 使用锁定归档，从空对象缓存生成与仓库逐字节一致的 Library 和索引。
- PBR 与 Canvas Material 引用刷新后的 Library 内容 ID。
- Windows 相关构建和测试、Shader Toolchain 模式测试及文档检查通过。

## 风险

- Toolchain 可执行文件是构建时输入；更新锁定 Release 时必须在同一变更中刷新全部权威快照。
