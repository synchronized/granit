# S-115：RenderPipeline 可选通道 GPU 计时收敛

## 状态

**本地实现与验证完成，待 v0.72.0 发布候选验收，2026-11-20。** 本任务修复 RenderPipeline 没有阴影通道时，
GPU Timestamp 指标槽位长期处于 `pending`，导致后续样本无法复用的问题。

## 背景与根因

RenderPipeline 的指标池固定使用 8 个查询，分别表示阴影、PBR、Tone Mapping 和总耗时的四组起止点。
没有方向光时，Render Graph 不创建阴影 Pass，因此查询 0/1 不会被录制；但回读路径仍固定请求全部 8
个查询。Vulkan 非等待回读遇到未写入查询会返回 `NOT_READY`，指标槽位保持 pending，后续帧无法取得
可复用槽位，表现为样本序号停止增长。

## 方案

- 保持内部 8 查询布局和现有指标 ABI 不变；
- 构建图时记录是否存在阴影 Pass；
- 缺省阴影通道在同一录制阶段写入查询 0/1，使阴影耗时明确为零并允许整组查询完成；
- 不修改通用 Timestamp 查询 API，不引入“动态查询数量”或多视图总耗时 API；
- 不改变有阴影场景、Renderer 提交、资源生命周期和公共 RenderPipeline 接口。

## 实施步骤

1. 在 RenderPipeline 指标录制逻辑中补齐缺省阴影通道的查询对。
2. 在离屏集成测试中创建无方向光场景，交替渲染有阴影和无阴影场景。
3. 验证指标样本序号继续增长，且无阴影样本的 `shadow_gpu_ns` 为零。
4. 更新版本文档、Changelog 和验收记录；完成 Windows Clang 构建、相关 CTest 和全量 CTest。

## 验收标准

- [x] 有方向光与无方向光场景交替渲染后，GPU 指标样本序号持续增长；
- [x] 无阴影场景不再长期返回 `GRANIT_ERROR_NOT_READY`；
- [x] 无阴影样本的阴影耗时为零；
- [x] 有阴影场景的原有四组计时仍可回读；
- [x] 离屏和窗口输出路径不改变；
- [x] 不新增公共 ABI，不暴露 Vulkan 类型；
- [x] Windows Clang 相关构建、回归测试和文档检查通过。

## 非目标与风险

本任务不处理 GPU 查询池容量扩展、设备丢失恢复、并行录制或多视图总耗时。若某些后端在同一阶段
写入的两个时间戳仍产生非零最小差值，应在后续后端能力契约中增加“不可用”状态；本任务先保持现有
指标结构，优先消除未写入查询造成的永久 pending。
