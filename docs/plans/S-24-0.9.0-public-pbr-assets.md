# S-24：0.9.0 公共 PBR 与渲染资产收敛

## 状态

- 路线图任务：S-24
- 目标版本：0.9.0
- 优先级：P1
- 状态：已确认，待实施
- 前置依赖：H-03、H-05、S-13、S-13H、S-13I、S-23

## 背景与目标

0.8.0 已让 Core 直接消费 `.grshader` 清单和目标后端 sidecar，并让 `.grmat` 通过稳定内容
ID 引用 Shader Asset。Model Viewer 也已验证纹理 PBR、方向光、IBL、Specular AA、质量选项以及
Vulkan/WebGPU 双端路径，但仍在 `examples/assets` 维护一套示例私有 PBR Shader。

0.9.0 的目标是把这些已经通过真实模型验证的能力收敛到公共 PBR 资产和唯一 Binding 契约，
使 Model Viewer 成为公共能力的 Consumer，而不是第二套 PBR 实现。版本完成后，公共 PBR Shader
应成为参考 Render Pipeline 和 Model Viewer 的共同实现。

## 非目标

- 不让 Core 负责文件 I/O、资产数据库、异步加载、缓存或热更新。
- 不把示例私有 glTF 加载器提升为公共 SDK；S-14 仍受两个非示例 Consumer 的复用条件约束。
- 不在本版本引入 Android、桌面 Dawn、TAA、Bindless、Clustered Forward、CSM 或透明 PBR。
- 不把 PBR 固化为底层 Renderer 唯一渲染模型；使用者仍可直接使用显式资源和 Pipeline API。
- 不以复制整份 Shader 的方式长期维护功能组合。

## 已确认决策

### 唯一公共 PBR 实现

- `assets/shaders/pbr` 是参考 PBR Shader 源码和发布资产的唯一归属位置。
- Model Viewer 不再拥有以 `model_viewer_pbr` 命名的 Shader 源码、清单或 sidecar。
- Model Viewer 的材质包引用公共 `.grshader` 的稳定内容 ID。
- 示例仍可拥有场景、相机、界面和环境选择逻辑，但不能复制 PBR BRDF 或 Binding 定义。

### Binding 契约

公共 PBR 固定以下职责分组，并以反射测试约束布局：

| Group | 内容 | 数据所有者 |
|---:|---|---|
| 0 | View、Projection、相机及逐帧渲染选项 | Render Pipeline/调用方 |
| 1 | 材质常量、五类纹理和 Sampler | Material |
| 2 | Model、Normal Matrix 和对象标识 | Scene/调用方 |
| 3 | 方向光、其他光源、阴影、IBL 和环境参数 | Lighting |

调试显示属于公共 PBR 渲染选项，不绑定 Model Viewer UI 状态；UI 只负责修改该选项。CPU 结构、
反射清单、WGSL 和 SPIR-V 必须表达同一套布局，不允许分别演化。

### Shader 变体

- 公共 Shader 覆盖无纹理和完整 glTF 金属度/粗糙度纹理路径。
- 可组合能力至少包含法线贴图、方向光、IBL、阴影、Debug Display 和 Specular AA。
- 变体由离线构建规则确定性生成，并继续输出 `.grshader`、`.grshader.spv` 和
  `.grshader.wgsl`。
- 变体清单只声明实际保留的后端与能力；缺少匹配变体或设备能力不足时明确失败。
- 公共源码片段或生成规则应消除 BRDF、输入结构和资源声明的重复，但不在运行时预处理 Shader。

### 安装与所有权

- 公共 PBR 发布资产随 RenderPipeline component 安装，不进入 Core component。
- 安装包提供稳定、可由 CMake Consumer 获得的资产目录契约；Core API 仍只接收内存字节。
- 嵌入、文件系统、包文件或上游资产数据库均通过同一 Shader resolver 接入。
- Gneiss 等上游决定加载线程、缓存和热更新策略，Granit 不接管其资源系统。

## 实施顺序

1. **S-24A 契约审计**：对比公共 PBR、Lighting、Material 与 Model Viewer 的常量、Binding、
   顶点输入、变体和质量选项，固定唯一布局并列出迁移映射。
2. **S-24B 公共 PBR 变体**：补齐完整纹理、方向光、IBL、Specular AA 和 Debug Display，建立
   无重复源码的离线组合与反射一致性检查。
3. **S-24C Consumer 迁移**：让参考 Render Pipeline 和 Model Viewer 使用公共资产及同一
   resolver，迁移 `.grmat` 后删除 `examples/assets/model_viewer_pbr.*`。
4. **S-24D 安装与验收**：安装公共 PBR 资产，增加独立 Consumer、双后端像素回归、Model Viewer
   基准截图和发布包审计。
5. **版本收尾**：更新当前行为的 Reference/Guide、迁移说明、变更记录和版本号，完成 0.9.0
   发布候选矩阵后再发布。

## 测试与验收

- 反射测试逐项比较四个 Group 的 Binding、类型、数组数量和最小 Buffer 尺寸。
- 公共 PBR 分别覆盖 Base Color、Metallic/Roughness、Normal、Occlusion、Emissive、方向光、
  IBL、Specular AA 和 Debug Display。
- Vulkan 与浏览器 WebGPU 使用相同 `.grmat` 和 Shader Asset ID，并产生容差内一致的结果。
- Model Viewer 中不存在私有 PBR Shader，且真实 Flight Helmet 能完成加载、绘制、质量切换和释放。
- 安装后的共享库与静态库 C/C++ Consumer 能定位并加载公共 PBR 资产。
- 缺失 sidecar、错误摘要、后端不匹配、能力不足和 Binding 漂移均有明确失败测试。
- Windows、Linux、Emscripten、文档检查及发布候选工作流全部通过。

## 风险与未决问题

- Shader 组合规则必须保持调试性和确定性，不能生成难以追踪的排列爆炸；S-24A 应先固定最小
  必需变体集合。
- 公共资产安装路径需要兼顾构建树、安装树和嵌入式 Consumer；具体 CMake 接口在 S-24A 中确认，
  但不得退化为 Core 内部文件 I/O。
- 现有公共 PBR 组合与 Model Viewer 布局可能存在迁移期差异；迁移必须一次完成并由反射测试守护，
  不长期保留兼容的第二套 Binding。
