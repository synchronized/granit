# S-87：0.51.0 RenderPipeline 契约与真实 Consumer

## 状态

**已完成。** S-87A Consumer 基线和 S-87B 契约验收已完成；v0.50.0 已完成 Core、Math、Renderer
和 Window 的稳定候选审计。当前没有新的 Gneiss 上游需求，本版本确认 RenderPipeline 的现有
观察候选边界，不提出新的公共 API 或 ABI 冻结承诺。

## 目标

1. 建立不依赖 Model Viewer 私有状态的 RenderPipeline Consumer；
2. 审计 Material、PBR Material、Scene、Mesh、Canvas、Text 和 Debug Draw 的所有权、生命周期、
   线程与错误契约；
3. 在 Vulkan/WebGPU 上验证多 Pass、Resize、资源重建和 Renderer 关闭行为；
4. 判断 RenderPipeline 是否可以从观察候选进入长期候选，或明确保留观察状态。

## 固定边界

- 不实现 Bindless、Clustered Forward、Cascaded Shadow Maps 或 GPU-driven 新公共 API；
- 不把 Model Viewer、Gneiss 或某个示例的状态机下沉到 RenderPipeline；
- 不新增第二套 Scene、Material 或资源生命周期系统；
- 不冻结 RenderPipeline 的 ABI，除非所有权、线程和跨后端证据完整；
- SVT、纹理驻留预算、VFS 和任务调度仍由 Gneiss 负责。

## 实施顺序

1. **S-87A Consumer**：建立独立 PBR/Scene/Canvas/Text Consumer，验证安装 SDK 使用路径和最小
   帧循环，不依赖 `examples/common` 私有状态。
2. **S-87B 契约审计**：覆盖 Material/Scene/Mesh/Canvas/Text/Debug Draw 的句柄、父资源、重复
   销毁、跨 Renderer、Resize 和失败清理。
3. **S-87C 跨后端验收**：固定 Vulkan/WebGPU 参数和像素/状态断言，覆盖多 Pass、透明、阴影、
   UI、Resize、最小化恢复和 Renderer 关闭。
4. **S-87D 稳定等级决策**：根据 Consumer 和上游证据，逐项提升或保留观察等级；任何 API 修改
   必须同步 C ABI、C++ 包装、测试、Reference 和 Changelog。
5. **S-87E 发布验收**：完成 Windows/Linux/Emscripten、shared/static、安装 Consumer 和公开
   制品复验后发布 v0.51.0。

## 验收门槛

- Consumer 不依赖 Model Viewer、Gneiss 或源码树私有状态；
- RenderPipeline 公开资源的所有权、线程、错误和生命周期契约有 Reference 与负向测试；
- Vulkan/WebGPU 的结果和失败边界明确，不通过后端特性静默改变公共语义；
- RenderPipeline 稳定等级有证据支持；证据不足时明确保持观察候选；
- 公共头文件仍不包含 Vulkan SDK，默认不新增公共 ABI。
