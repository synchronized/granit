# S-69：0.36.0 公共 API 稳定边界与最小数学库

## 状态

**计划中，P1。** 目标版本为 0.36.0。

## 背景与目标

0.35.0 已证明 Core 与 Window 具备稳定范围评审条件，RenderPipeline 保持稳定候选，AssetTools 与
第三方 Integration 保持实验性。但当前等级主要按 CMake component 描述，尚未逐公共头和功能域
明确哪些接口准备长期保留，平台原生逃生接口也没有与普通用户入口分级。

公共数学层目前只导出 ABI 值类型。Renderer 内部已有向量、矩阵、View 和投影运算，Model Viewer
直接包含私有 `src/math/math.h`，两个 Tutorial 又各自重复实现矩阵乘法和投影。这使安装 SDK 用户
无法复用 Granit 已经定义的坐标约定，也让示例与内部实现存在漂移风险。

0.36.0 的目标是：

- 为所有安装公共头建立唯一、可检查的稳定候选或实验性分类。
- 明确 Core 与 Window 准备长期保留的普通用户入口，以及原生互操作和平台 Backend 的支持边界。
- 将现有最小渲染数学运算提升为轻量公共 C++20 接口，并删除内部与 Tutorial 的平行实现。
- 让文档、安装 SDK Consumer 和 ABI/API 门禁共同验证上述边界。

## 非目标

- 不在 0.36.0 宣布整个 Granit ABI 冻结，也不发布 1.0。
- 不承诺 C++ 二进制 ABI；C++ 数学函数只提供源码兼容入口。
- 不建设 GLM 替代品，不增加 Quaternion、Transform 层级、SIMD、几何容器或相机控制器。
- 不把 GPU 对齐、资产解析或 Tutorial 组合逻辑归入数学库。
- 不提升 RenderPipeline、AssetTools、SDL3 Integration 或 ImGui Integration 的稳定等级。
- 不新增渲染特性、持久化资产格式或原生 Vulkan 公共接口。

## 已确认决策

### 稳定等级

- 以“稳定候选”“实验性”“内部”描述当前 0.x 等级；只有未来发布说明显式宣布后才形成稳定承诺。
- 分类粒度至少到安装公共头和功能域，不能仅从统一包版本或父 component 推导。
- Core 与 Window 的普通用户入口优先进入长期保留范围；原生句柄、平台逃生接口和第三方适配器
  单独评审，不随父 component 自动晋级。
- RenderPipeline 继续收集真实上游对 Material、Scene 和同步 Render 门面的演进证据。

### 公共数学接口

- `types.h` 继续只保存 C ABI 普通值类型，不增加导出数学函数或改变现有布局。
- 新增 `granit/math/functions.hpp`，提供 header-only、`noexcept` 的纯 C++20 运算；公共聚合头同步导出。
- 第一批包括向量加减、标量乘法、点积、叉积、长度、归一化、有限性检查、矩阵乘法、向量与点
  变换，以及 `look_at_rh`、`perspective_rh_zo`、`orthographic_rh_zo`。
- 增加基础平移、缩放和轴旋转矩阵构造；函数明确使用列主序、右手坐标和 `[0,1]` 深度范围。
- 可能失败的构造和透视除法继续使用 `bool + output`，非法输入不修改输出；归一化零向量或非有限
  向量返回零向量，与现有内部语义一致。
- `src/`、Sample 与 Tutorial 统一包含公共头，不保留含义相同的第二套运算。

## 实施顺序

1. **S-69A 公共数学面**：迁移现有内部实现到 `functions.hpp`，补齐矩阵构造和公共头安装声明。
2. **S-69B 使用路径收敛**：切换 Renderer、测试、Model Viewer 和 Tutorial，删除私有数学实现与
   重复矩阵代码，禁止示例依赖 `src/` 头。
3. **S-69C API 等级清单**：逐安装头标注稳定候选或实验性，形成单一 Reference，并由检查保证没有
   未分类公共头。
4. **S-69D Core/Window 边界**：确定长期候选功能集合、弃用策略、Backend 支持等级、宿主线程与
   生命周期限制，并单独说明 Native 接口等级。
5. **S-69E 契约基线**：保存 0.36.0 精确符号与布局快照，扩展安装 SDK 的数学、Window 多实例、
   Surface 重建和错误恢复 Consumer。
6. **S-69F 发布验收**：通过本地和远端矩阵，更新 Changelog、版本身份与发布记录，发布 0.36.0。

## 测试与验收

- `types.h` 继续由 C11 独立包含，现有数学值类型大小、对齐和字段偏移保持不变。
- `functions.hpp` 由 C++20 独立包含，正常与退化输入均有单元测试，坐标方向与深度结果符合
  `coordinates.md`。
- Tutorial 01/02、Model Viewer 和内部渲染代码不再定义重复矩阵运算，也不包含 `src/math/math.h`。
- 安装后的 C++ Consumer 能仅依赖 SDK 使用最小数学接口构造 View Projection，并完成编译运行。
- 每个安装公共头均出现在稳定等级清单中；新增未分类头会使自动检查失败。
- Core 与 Window 的长期候选范围、实验性边界、弃用策略和平台支持矩阵具有唯一权威文档。
- Windows MSVC/Clang、Linux GCC/Clang、Emscripten、shared/static、C11/C++20、浏览器与文档矩阵
  通过，发布附件摘要复验通过。

## 风险与退出条件

- header-only 数学函数的实现会参与使用者编译，必须避免依赖编译器特有 SIMD、隐式平台宏或
  后端类型，并以数值语义而非逐位浮点结果作为测试契约。
- 公开数学函数后只能兼容扩展或修复明确缺陷，因此第一批保持最小集合，不提前加入场景抽象。
- 若 Core 或 Window 某个功能域仍缺少所有权、线程或平台行为证据，应继续标为实验性，不能为了
  版本目标强行纳入长期候选范围。
- 完成本计划只确定稳定边界和候选基线；正式稳定版本号与 ABI 承诺仍需独立决策。
