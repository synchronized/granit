# S-38：0.22.0 ShaderTools 工具链交付与自动获取

## 状态

**已确认，待实施。** 0.22.0 将把 ShaderTools SDK 对 DXC 与 Tint 的独立路径依赖收敛为一个
Shader Toolchain 根目录，并为 CMake Consumer 提供显式、可校验的下载模式。DXC 与 Tint 继续
作为独立离线工具链发布，不重复进入每个 Granit SDK 或应用运行时包。

## 背景与目标

0.21.0 已将离线作者入口收敛为 HLSL-first，并发布了带许可证、归档摘要和包内完整性清单的
Windows/Linux Shader Toolchain。当前仍有三处使用体验没有闭合：

- C API、C++ 包装、CLI 和 CMake 分别传递 DXC 与 Tint 路径，向使用者暴露了内部转换流水线；
- 安装后的 ShaderTools SDK 没有统一的工具链解析入口，下游需要自行查找和拼接工具路径；
- 仓库已有下载及校验脚本，但缺少可安装的 opt-in 自动获取接口和稳定缓存契约。

本任务让使用者只选择工具链获取方式或提供一个根目录。Granit 负责定位工具、验证身份与能力，
并将同一工具链交给单 Shader 编译、Shader Library Builder、CLI 和 CMake 资产目标。已经构建的
`.grshlib` 继续不依赖 ShaderTools、DXC 或 Tint。

## 非目标

- 不把 DXC、Tint 或其运行库链接进 Granit Core、Renderer 或应用运行时。
- 不把工具链二进制重复放入每个共享/静态 Granit SDK 归档。
- 不在运行时下载或编译 Shader；下载只发生在明确启用的离线配置或资产构建阶段。
- 不依赖浮动的 `latest` URL，不接受未经摘要和清单验证的归档。
- 不增加新的 Shader 作者语言，也不恢复 WGSL、SPIR-V 或 GLSL 作者入口。
- 不为 0.21.0 的 ShaderTools ABI 保留过时字段、CLI 参数或平行兼容入口。
- 不在本任务增加 macOS、Linux ARM64 或 Windows ARM64 工具链；新增宿主包另行验证。

## 已确认决策

### SDK 与工具链独立发布

普通 Granit Release 继续交付 Runtime、开发头、库、CMake package 和 ShaderTools component。
Shader Toolchain 使用不可变的独立 Release 标签交付：

```text
granit-shader-toolchain-<toolchain-version>-windows-x64.zip
granit-shader-toolchain-<toolchain-version>-linux-x64.tar.gz
```

普通 Release 的机器可读清单记录所锁定的工具链标签和摘要，但不复制工具链归档。同一套经过验证
的 DXC/Tint 可以被多个 Granit 版本复用；只有工具版本、能力或再分发材料改变时才发布新工具链。

### 一个根目录代表完整工具链

ShaderTools 的公共 Compiler 描述改为只接收 `toolchain_root`。内部依据宿主平台从固定布局解析
DXC、Tint 和必要运行库，并首先验证 `shader-toolchain.json`：

```text
<root>/
├─ bin/dxc[.exe]
├─ bin/tint[.exe]
├─ lib/                         # 平台需要时存在
├─ licenses/
└─ shader-toolchain.json
```

CLI 的 `--dxc` 与 `--tint` 收敛为 `--toolchain <root>`。CMake Shader Library 函数接收解析后的
工具链根目录，不再把两个工具路径传播到每个资产命令。0.x API 尚未稳定，本次直接删除旧字段和
参数，不增加弃用层。

### 获取策略显式选择

CMake 增加 `GRANIT_SHADER_TOOLCHAIN_MODE`，取值及行为如下：

| 模式 | 行为 |
|---|---|
| `off` | 禁用 HLSL 资产生成；允许使用仓库或安装包中的 `.grshlib` 快照 |
| `system` | 默认值；只检查显式根目录、Vulkan SDK 和 `PATH`，不访问网络 |
| `auto` | 先查找本机完整工具链，找不到或不兼容时下载 Granit 锁定包 |
| `download` | 不采用本机偶然版本，下载或复用缓存中的 Granit 锁定包 |

显式设置 `GRANIT_SHADER_TOOLCHAIN_ROOT` 时始终优先使用该目录，不再下载替代品。`system` 找不到
完整工具链时，构建 ShaderTools SDK 本身仍然可用；要求生成 HLSL 资产的目标给出明确配置错误。
`auto` 与 `download` 是使用者对网络访问的明确授权，下载失败不得静默降级。

### 安装公开的解析模块

新增可安装的 `GranitShaderToolchain.cmake`，提供概念接口：

```cmake
granit_resolve_shader_toolchain(
  MODE "${GRANIT_SHADER_TOOLCHAIN_MODE}"
  CACHE_DIR "${CMAKE_BINARY_DIR}/_granit/toolchains"
  OUT_ROOT shader_toolchain_root
)
```

安装 Consumer 可以在 `find_package(granit COMPONENTS ShaderTools)` 后调用该函数，再把结果交给
Granit 提供的 Shader Library 构建函数。内部构建与安装 Consumer 复用同一解析实现，不维护两套
查找顺序、平台文件名或能力规则。

### 版本元数据只有一个来源

锁定版本、Release 标签、平台归档名、归档 SHA-256、DXC 版本和 Tint 修订集中到一个可安装的
CMake 版本文件。下载器、验证器、CI 和 Release 工作流读取同一份数据，避免脚本之间手工同步。
版本文件只引用不可变标签和精确摘要。

### 下载、缓存与验证

下载缓存默认位于构建树，不写入源码目录或用户全局目录。解析器按以下顺序处理下载包：

1. 使用 `file(LOCK)` 串行化同一工具链缓存的写入；
2. 下载到缓存目录内的临时归档，并以 `EXPECTED_HASH` 校验发布级 SHA-256；
3. 解压到目标目录旁的临时目录，拒绝越界路径；
4. 使用 `shader-toolchain.json` 校验完整文件集合、大小和 SHA-256；
5. 运行 DXC 版本、DXC SPIR-V 编译和 Tint SPIR-V 到 WGSL 能力探针；
6. 全部成功后原子重命名为版本化缓存目录；失败时清理临时文件；
7. 复用已有缓存前重新验证包内清单，不信任仅凭目录存在的结果。

工具链归档必须继续包含 DXC、Dawn/Tint 及其第三方依赖所要求的许可证和声明。发布流程保留人工
许可证复核，自动摘要校验不能替代再分发合规检查。

### 失败语义统一

- 工具链根目录为空、工具缺失或尚未准备：`GRANIT_ERROR_NOT_READY`；
- 描述结构、字符串、模式或路径表达非法：`GRANIT_ERROR_INVALID_ARGUMENT`；
- 包内清单或摘要不一致：使用现有最接近的损坏数据错误；若结果码不足，再单独评估新增错误；
- 工具存在但无法启动、能力不兼容或编译失败：`GRANIT_ERROR_INITIALIZATION_FAILED`；
- HLSL 诊断由 Compilation 保存，失败时删除不完整的 SPIR-V、WGSL、索引和 Library 输出。

Compiler 创建阶段验证根目录、清单和工具能力，使配置问题在首次编译前暴露。Library Builder、
CLI 和 CMake 只映射统一结果，不再自行定义另一套缺失工具语义。

## 实施顺序

1. **S-38A 根目录契约**：修改 ShaderTools C/C++ Compiler 描述、CLI 与内部编译调用，只传递一个
   Toolchain 根目录；删除 `dxc_path`、`tint_path`、`--dxc` 和 `--tint`。
2. **S-38B 统一解析模块**：增加可安装的 `GranitShaderToolchain.cmake` 和获取模式；内部构建、
   `add_subdirectory`、FetchContent 与安装 Consumer 共用相同查找顺序。
3. **S-38C 安全下载与缓存**：重构现有下载脚本，加入共享版本元数据、并发锁、临时目录、原子
   发布、归档摘要、包内清单和能力验证。
4. **S-38D 构建入口与诊断**：让 Shader Library CMake 函数、CLI 和 SDK Builder 使用解析结果；
   统一缺失、损坏、不兼容和源码编译失败的结果及诊断。
5. **S-38E 发布交付**：让独立 Toolchain 工作流生成不可变 Windows/Linux 归档；普通 Granit
   Release 记录锁定工具链身份并验证下载 Consumer，不重复附带二进制。
6. **S-38F 文档与发布验收**：更新 ShaderTools Reference、工具链包 Reference、构建 Guide、
   0.21 到 0.22 迁移说明、ABI 快照、安装清单和 Release Candidate 验收记录。

每个子阶段形成一个聚焦提交，全部阶段在同一 0.22.0 特性分支和 Pull Request 中连续完成。

## 测试与验收

- C11 与 C++20 安装 Consumer 只提供 Toolchain 根目录即可完成 HLSL 编译和 Library 构建。
- `off` 和缺少本机工具的 `system` 模式不访问网络，Runtime 与快照构建保持可用。
- `auto` 在已有兼容本机工具时不下载；缺失任一工具时下载并复用锁定缓存。
- `download` 忽略 PATH 中的偶然工具版本，始终使用经验证的版本化缓存。
- 错误摘要、损坏清单、缺失文件、额外文件、截断归档和能力探针失败均被拒绝。
- 两个并发 CMake 配置不会生成半成品缓存，也不会相互删除有效工具链。
- CLI、SDK 和 CMake 对缺失与不兼容工具返回一致类别，并保留 HLSL 编译诊断。
- Windows x64 与 Linux x64 的共享/静态 ShaderTools 安装 Consumer、真实 HLSL 双后端编译和
  Shader Library 确定性比较通过。
- Emscripten、Runtime-only 和禁用 ShaderTools 的构建不下载、不安装且不依赖宿主工具链。
- Release Candidate 能从公开的不可变工具链 URL 下载、校验并复现仓库内置 Shader Library。

## 风险与未决问题

- `shader-toolchain.json` 当前主要承担完整性验证；S-38A 需要确认其 schema 是否足以表达宿主平台、
  架构与能力，必要扩展必须保持严格版本检查。
- Linux DXC 运行库的加载方式需要在安装 Consumer 中验证，不能依赖开发机已有的动态库搜索路径。
- GitHub API 限流或网络不可用必须表现为可操作的下载错误；离线使用者始终可以预下载并设置
  `GRANIT_SHADER_TOOLCHAIN_ROOT`。
- 工具链包体积较大，CI 缓存键必须包含平台、架构、归档摘要和脚本契约版本，避免无效重复下载。
- 新增宿主平台前必须分别确认 DXC/Tint 可执行产物、运行库布局、许可证和真实双后端能力。
