# S-35：0.19.0 纹理资产变体与流式加载契约

## 状态

**已确认。** 0.19.0 在 0.18.0 压缩格式与上传能力之上，建立可检查、可选择、可分阶段上传的
纹理资产契约；版本号在全部功能完成并通过发布验收后统一提升。

## 背景与目标

0.18.0 已解决 BC、ETC2、ASTC 块数据如何查询能力和上传，但上游仍需自行定义纹理清单、解析
固定偏移、匹配设备格式并组织逐 mip 上传。0.19.0 让 Gneiss 等资产系统可以使用稳定公共接口描述
同一逻辑纹理的多个 GPU 变体，并按当前 Renderer 能力选择最佳变体。

Granit 负责资产元数据检查、确定性变体选择和 GPU 上传编排；上游继续负责资产身份、文件读取、
缓存、网络、热重载、容器格式与离线转码。

## 非目标

- 不解析 KTX2、DDS、PNG、JPEG 或 glTF，也不引入 KTX-Software、Basis Universal 等依赖。
- 不在运行时压缩或转码纹理，不隐藏 RGBA8 回退，也不替上游决定平台包内容。
- 不接管文件系统、网络请求、线程池、资产数据库或 Gneiss 的资源生命周期。
- 不支持压缩纹理运行时 Mipmap 生成或读回；完整 mip 链由离线资产管线提供。
- 不在本版本加入 Android、新渲染后端、Bindless 或虚拟纹理。

## 已确认决策

- 定义带版本和长度校验的 Texture Asset Manifest，包含逻辑尺寸、层数、mip 数、颜色空间、内容
  ID，以及每个变体的格式、profile、数据范围和逐子资源布局。
- Manifest 只描述元数据；像素块由调用方拥有并以指针加长度传入，不跨动态库边界分配内存。
- 公共检查接口必须拒绝越界、重叠、溢出、不完整 mip 链和与格式块布局不一致的数据。
- 公共选择接口综合 Renderer 格式能力、用途、过滤需求和调用方优先级，返回选中变体及明确失败
  原因；相同输入必须产生确定结果。
- 选择策略优先满足正确性，再遵循调用方顺序；Granit 不假设 BC、ETC2 或 ASTC 固定优于另一种
  格式，也不自动选择缺失的回退资产。
- 流式加载复用现有异步 Upload Batch、操作状态、取消和背压语义，支持逐 mip 提交与最终原子
  切换；取消不能撤销已经提交给 GPU 的工作。
- C API 提供稳定 ABI；C++20 包装只增加强类型视图和 RAII，不建立第二套资产状态。

## 实施顺序

1. **S-35A Manifest 契约**：定义公共结构、二进制布局、版本、内容 ID 和严格检查接口。
2. **S-35B 变体选择**：根据设备格式能力、用途和调用方优先级实现确定性选择与诊断。
3. **S-35C 流式上传**：将逐 mip 数据映射为有界异步 Upload Batch，覆盖进度、取消、背压、失败
   回滚和资源保活。
4. **S-35D 上游消费**：增加独立 Consumer Fixture，证明上游无需读取私有格式或复制选择规则。
5. **S-35E 双后端验收**：使用同一资产分别验证 Vulkan 与浏览器 WebGPU 的选择、上传、采样和
   无能力路径。
6. **S-35F 版本收尾**：更新 Reference、迁移指南、ABI 快照、Changelog、版本号和发布验收记录。

## 测试与验收

- C11/C++20 公共头、共享/静态库、构建树与安装 Consumer 全部通过。
- Manifest 检查覆盖截断、未知版本、重复或重叠范围、整数溢出、错误块布局、缺失 mip 和非法
  Cube/Array 层数。
- 变体选择覆盖 BC/ETC2/ASTC/RGBA8 组合、SRGB/UNORM、过滤与传输用途、调用方优先级，以及无
  可用变体时的稳定结果码和诊断。
- 流式上传覆盖逐 mip 进度、队列饱和重试、提交前取消、提交后取消、部分失败、Renderer 销毁和
  最终资源原子切换。
- Vulkan 与浏览器 WebGPU 使用相同公共测试语义；缺少压缩 feature 的设备必须选择显式提供的
  兼容变体或明确失败。
- 发布前通过 Quick Check、Documentation、Windows、Linux、Emscripten 和不可变 Release
  Candidate，并记录公开 SDK 验证结果。

## 风险与未决问题

- Manifest 是 Granit 资产契约，不应演化为通用容器；若元数据无法直接服务运行时选择，应由上游
  容器转换后再输入。
- 首版是否提供文件型 Resolver 取决于第二个真实 Consumer；没有复用证据时只提供内存检查与选择
  接口。
- 低分辨率 mip 优先上传会影响纹理完整性和采样状态；实现必须在后端一致的合法资源状态下才允许
  渐进可见，否则先完整上传再原子切换。
