# S-64：0.31.0 SDK-first 示例与资产入口

## 状态

**实施中，P1。** 目标版本为 0.31.0。本计划让仓库示例同时验证源码树开发体验和安装后 SDK
消费体验，并收敛教程、Sample、私有 Example Common 与资产加载的边界。

## 背景与目标

0.30.0 已交付带真实纹理的 Cube 教程、带 Suzanne 模型的 PBR Assets 教程、跨后端 Model Viewer，
以及 Desktop/Web 共用的 Example Asset System。现有安装 Consumer 能验证头文件、目标、链接和
基础运行时，但还不是普通使用者可以复制的完整 Window、Surface 与帧循环程序；示例私有资产系统
也缺少面向维护者的稳定职责说明和安装 SDK 边界测试。

0.31.0 完成以下工作：

- 增加只依赖安装后 Granit CMake package 的独立 C++ Quickstart，展示 Window、Surface、
  Swapchain、Frame Context、清屏、提交与 Present。
- 让独立 Quickstart 同时成为 shared SDK 的可构建、可运行消费端验收，不依赖仓库内部头文件、
  CMake 函数或源码目标。
- 明确教程使用随程序部署的稳定逻辑资产路径，Model Viewer 使用外部目录或 URL 挂载；平台文件
  路径、Fetch 和线程差异只存在于 Example Asset System 内部。
- 审计 Tutorials、Samples 和安装 Consumer 的 C++ API 使用，消除普通路径中的裸 C 句柄、原始
  枚举比较和不必要的 `native_handle()`。
- 保持真实资产的来源、许可证、固定提交和摘要可追溯，并验证桌面复制与浏览器部署的资产集合一致。

## 非目标

- 不把 `examples/common` 或 Example Asset System 提升为公共 SDK component。
- 不新增公共 VFS、网络客户端、模型格式或纹理解码 API；出现第二个独立下游需求后再单独设计。
- 不重复增加近似的 Cube、Triangle、Model Loading 或 Model Viewer 示例。
- 不改变 `.grshlib`、`.grmat`、`.grtex`、`.grenv` 或 glTF 的持久化格式。
- 不增加新的渲染特性，也不改变 Renderer、Window 或 RenderPipeline ABI。

## 已确认决策

### 示例分层

- `examples/tutorials` 保存聚焦单条学习路径的完整源码，目前以 Cube 和 PBR Assets 为主。
- `examples/samples` 保存 Model Viewer、ImGui 等综合应用。
- `examples/common` 只保存至少两个真实示例复用的仓库私有实现，不安装、不导出。
- 独立 SDK Quickstart 使用自己的顶层 `CMakeLists.txt` 和公共头文件，不能通过主工程目标获得隐式
  include、编译定义、资产或 DLL 搜索路径。

### 资产入口

- 业务代码只使用 `asset_mount + logical_path`；平台来源由 `asset_system` 解析。
- Bundled 资产使用 `asset:///` 诊断位置。Desktop 从可执行文件旁的 `assets` 读取，Web 从统一
  `/assets` 根读取；调用方不分支拼接平台路径。
- glTF 相对 URI 由文档加载器以文档目录为基准解析，调用方不重复维护资源前缀。
- Shader Library 是否内嵌或来自正式安装资产由目标用途决定，不和通用模型、纹理 Fetch 混为一层。

### 安装消费验收

- Quickstart 通过 `find_package(granit CONFIG REQUIRED COMPONENTS Window)` 和导出目标构建。
- 自动验收至少覆盖配置、构建、运行到首个成功提交或明确的无设备跳过结果，以及动态库定位。
- Release 继续只发布 Windows/Linux x64 shared SDK；静态构建保持源码和 CI 验证。

## 实施顺序

1. **S-64A 计划与现状审计**：登记 0.31.0，确认真实资产、示例分层、统一 Asset System 和安装
   Consumer 的现状，删除与 0.30.0 重复的工作。
2. **S-64B 独立 SDK Quickstart**：增加最小 Window 清屏程序、独立 CMake 工程和运行说明，只使用
   安装目标与公共 C++ API。
3. **S-64C 安装后端到端验收**：把 Quickstart 接入 Windows/Linux shared SDK 安装 Consumer，
   验证 DLL/SO 定位、Surface、帧提交和无设备跳过语义。
4. **S-64D Example Asset Contract（已完成）**：补充资产逻辑路径、Mount、Desktop/Web Source、
   glTF 相对 URI 与 Shader Library 的职责文档，并增加规范化路径和诊断位置测试。Desktop/Web 的
   部署集合继续由同一个 `granit_example_target_assets` 声明和现有浏览器 Smoke 验证。
5. **S-64E C++ 使用面审计（已完成）**：Tutorials 与独立 Quickstart 已只使用 C++ API；Model
   Viewer 的场景值和采样数改用 `granit::scene_*` 与 `granit::sample_count`。保留的裸句柄仅位于
   明确验证 C ABI 的浏览器测试钩子，以及直接比较句柄身份的单元测试。
6. **S-64F 0.31.0 验收与发布收口**：运行 shared/static、Emscripten、Documentation 和独立安装
   Consumer 矩阵，记录最终差异并准备版本。

## 测试与验收

- 独立 Quickstart 不依赖仓库源码路径，使用安装后的 shared SDK 可以配置、构建和运行。
- Window、Surface、Swapchain、Acquire、Frame Context、清屏、Submit 与 Present 使用公共 C++ API。
- 缺少可用 GPU 或显示环境时返回稳定跳过结果；真实 API 或生命周期错误必须失败。
- Tutorials 与 Model Viewer 的 Desktop/Web 业务代码不按平台拼接资产路径。
- 教程和 Sample 使用的第三方资产具有来源、固定版本、许可证和摘要记录。
- Windows/Linux shared SDK Consumer、源码 static CI、Emscripten 浏览器测试、Documentation 与
  `git diff --check` 通过。

## 风险与未决问题

- Window Quickstart 在无显示的 CI 中不能强制成功呈现；使用虚拟显示或明确跳过，不能把真实错误
  一律忽略。
- 独立示例可能复制少量应用循环代码；它的目标是展示公共 SDK，不能依赖仓库私有 Application
  Framework 来减少这些必要步骤。
- Example Asset System 目前只有仓库示例使用，继续保持私有；若上层引擎提出相同 URI、挂载和异步
  契约需求，再以独立公共设计评估。
