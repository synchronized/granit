# S-98：0.62.0 交互式图形特性教程

## 状态

**实施中。** 本计划承接 v0.61.0，目标是把 Tutorial 09～11 从最小能力探针升级为
可观察、可操作且仍可自动验收的完整特性教程。教程保留确定性 Smoke 配置，不新增粒子系统、
透明材质系统或能力查询的第二套公共 API。

## 背景与目标

当前 Tutorial 09～11 能验证底层路径，但画面和交互过于简陋：09 只有程序生成的二维粒子，
10 只有四个矩形，11 主要显示少量能力数字。它们适合 CI 探针，却不能让读者直观看到特性的
用途、限制和失败边界。

v0.62.0 将它们调整为三个相互独立的可运行示例：

- Tutorial 09：Particle Generator，展示不同粒子形状、运动参数、生命周期和透明混合；
- Tutorial 10：Transparency Gallery，展示不透明、镂空、半透明模型和对象级排序；
- Tutorial 11：Capabilities Inspector，实际执行资源能力探测并显示结果，而不是只打印常量。

## 非目标

- 不新增公共 Particle、Emitter、Material 或 Scene API；
- 不在 09 中引入 GPU 粒子模拟、Compute Shader、GPU culling 或 OIT；
- 不在 10 中实现逐三角形排序、OIT、折射、透明阴影或完整 Model Viewer；
- 不把 11 的教程探测结果包装成新的能力缓存系统；
- 不修改 `.grmat`、`.gltf` 或 Shader Library 持久化格式；
- 不为教程引入未审计许可证的外部模型或纹理资产。

## 已确认决策

### 09：Particle Generator

- 使用一个共享基础 Mesh，通过实例化绘制粒子；首批形状为低面数球体、正方体和长方体；
- 粒子状态继续放入 Storage Buffer，第一版由 CPU 更新，GPU 负责实例化绘制；
- 面板提供数量、形状、颜色、初始方向、速度、加速度、生命周期、淡入淡出、尺寸和暂停/重置；
- 面板默认开启 Gizmo，使用现有 `debug_draw_list` 显示发射器、运动方向、加速度和内置方向光，
  不新增粒子或光照公共 API；
- Smoke 模式使用固定数量、固定时间和固定参数，不依赖用户交互；
- 现有公共 `draw` 的 `instance_count` 优先复用，只有现有接口确实不足时才单独评估 API 变化。

### 10：Transparency Gallery

- 使用轨道相机展示小型固定场景，而不是复制 Model Viewer；
- 场景至少包含 Opaque、Alpha Mask、Blend 和多层交叠透明对象；
- 优先复用已有 glTF 加载、相机和资源生命周期基础设施；
- 资产必须是仓库已有且许可证明确的小型资产，缺少合适资产时使用仓库内生成的低模和确定性
  Alpha 纹理；
- 面板提供自动旋转、深度测试/写入、透明度、对象排序和模式切换，并明确显示当前限制；
- Smoke 模式固定相机、对象顺序和材质参数，验证非空画面、Resize 和多帧稳定性。

### 11：Capabilities Inspector

- 修正当前文档对 Mip、Sampler 和 Indirect 的过度描述；
- 实际创建代表性 Texture、Mip、Sampler 和 Indirect Buffer，展示成功、失败和结果码；
- 保留 Renderer limits 与格式能力表，明确区分“查询能力”和“实际创建/执行验证”；
- 不支持的格式或用法必须显示为不支持，不伪造跨 Vulkan/WebGPU 对称结果；
- 如果现有公共 API 无法表达某项探测，先记录为缺口，不为了教程临时增加后端专用入口。

## 实施顺序

1. **[x] S-98A 基础与 Smoke 契约**：确定教程共享的固定参数、截图/像素验收和浏览器导出指标；
2. **[x] S-98B Tutorial 09**：实例化 Mesh、粒子状态、面板、重置和跨后端回归；
3. **[x] S-98C Tutorial 10**：轨道相机、透明对象场景、排序控制和资产许可证审计；
4. **[x] S-98D Tutorial 11**：实际能力探测、结果展示、错误路径和文档同步；
5. **S-98E 跨平台收口**：Windows Vulkan、Linux Lavapipe、Chrome WebGPU、默认 Bind Group、
   Emscripten 页面和安装构建验收；
6. **S-98F 文档收口**：更新教程索引、能力矩阵、版本文档、验收记录和 CHANGELOG，完成发布门禁。

## 测试与验收

- 三个教程均能在 Windows Clang Debug/Release 构建并运行 Smoke；
- 09 至少验证三种形状、Storage Buffer 更新、实例数量变化、生命周期和 Alpha Blend；
- 10 至少验证 Opaque、Mask、Blend、深度边界、对象排序和轨道相机 Resize；
- 11 对每个探测项显示支持/不支持及结果码，不能只依赖预先写死的后端判断；
- Vulkan Validation Layer 无布局、同步、资源状态和越界错误；
- Chrome WebGPU 页面通过加载、连续帧、Resize、非空 Canvas 和 Validation 回归；
- Smoke 参数与交互参数分离，交互增强不得使自动测试依赖时间、随机数或用户输入；
- 不新增公共 ABI；若确需调整公共 API，必须另列 ABI、C consumer、C++ consumer 和安装 SDK 验收。

## 风险与未决问题

- **透明模型资产**：先检查现有资产和许可证；没有合适资产时采用仓库生成低模，避免外部下载和
  许可证不清；
- **实例化能力**：现有 Recorder 已有实例数量参数，需确认顶点输入和 WebGPU 路径对共享 Mesh
  的布局一致；
- **透明排序表达**：教程只演示对象级排序，不能暗示 Granit 已经解决任意透明场景排序；
- **Capabilities 覆盖范围**：若 Mip、Indirect 或某些 Format 在 WebGPU 无法可靠探测，必须在 UI
  和文档中明确“后端不支持/当前 API 不可表达”，不能用 Vulkan 结果替代。
