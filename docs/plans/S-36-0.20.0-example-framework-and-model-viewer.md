# S-36：0.20.0 示例框架与跨平台 Model Viewer 稳定化

## 状态

**实现中。** 0.20.0 聚焦示例质量、跨平台行为一致性和后续示例的可维护结构，不扩大 Granit
公共 API 或 ABI。S-36A 已完成桌面输入背压保留和拖动所有权回归，后续继续收敛帧延迟并迁移
示例结构。

## 背景与目标

当前 Model Viewer 已能在桌面 Vulkan 和浏览器 WebGPU 运行，但桌面渲染线程背压会丢弃指针
增量，ImGui 的全局鼠标捕获也会使视口拖动不稳定。与此同时，`examples/platform/web` 与根
`web/` 分担同一个 Web 示例的输入、资源加载和 Emscripten 生命周期，新增示例容易复制壳层。

本版本完成三个目标：

- 修复 Model Viewer 的旋转、缩放、焦点、窗口缩放和加载交互，使队列饱和时仍保持低延迟。
- 让浏览器 Model Viewer 与桌面版共享同一示例核心和输入语义，并形成稳定的自动化验收。
- 建立类似成熟渲染库的“框架、平台壳层、示例内容”分层，使新示例只实现自身演示逻辑。

## 非目标

- 不把示例执行器、轨道相机、glTF 加载器、文件系统或线程池提升为公共 SDK API。
- 不新增 Android、桌面 Dawn、新渲染后端或新的渲染特性。
- 不为展示数量保留可由单元测试或集成测试替代的三角形、资源创建等琐碎示例。
- 不在本版本建立统一示例启动器；示例数量形成真实需求后再评估。
- 不修改 Gneiss；本版本只修改 Granit 仓库。

## 已确认决策

- 用户级示例保留 `model_viewer` 与 `sdl3_imgui`；测试性质的程序继续归入 `tests` 或 Smoke。
- `examples/framework` 保存示例私有的生命周期、输入、资源定位、计时和平台桥接；它不安装、
  不导出，也不形成与公共 API 平行的运行时。
- `examples/samples/<name>` 保存示例自身内容、说明和最少平台无关逻辑；桌面与 Web 入口只负责
  窗口、事件循环和平台生命周期。
- 使用统一 CMake 辅助函数声明名称、支持平台、依赖组件和测试方式，两个示例可独立构建。
- Model Viewer 的相机状态在生产侧更新；背压只能跳过昂贵 Frame Packet 构造，不能丢弃输入。
- 输入捕获按一次拖动的起点确定所有权：从视口开始的拖动跨过面板后仍控制相机，从 UI 开始的
  拖动不泄漏给相机。失焦、离开窗口和按钮释放必须恢复稳定状态。
- Web 与桌面复用相同输入归一化和 Model Viewer 核心；平台差异通过窄接口表达，不使用条件编译
  污染示例内容。

## 目标目录

```text
examples/
├─ CMakeLists.txt
├─ README.md
├─ assets/
├─ framework/
│  ├─ common/
│  ├─ desktop/
│  └─ web/
└─ samples/
   ├─ model_viewer/
   └─ sdl3_imgui/
```

迁移按目标边界逐步进行，不为一次性匹配目录而混入无关重写。根 `web/` 中仍有价值的
Emscripten Shell、资源获取和浏览器测试迁入 `examples/framework/web` 或 Model Viewer 的 Web
入口，迁移完成后删除重复实现。

## 实施顺序

1. **S-36A 交互正确性**：修复背压期间指针和滚轮增量丢失、拖动所有权、失焦恢复、HiDPI 与
   Resize；增加跳帧输入回放和捕获边界测试。
2. **S-36B 帧延迟收敛**：相机在主线程持续更新，渲染线程只消费最新不可变快照；合并可替换旧帧，
   增加输入合并、跳过构造和渲染滞后统计，避免用扩大队列掩盖延迟。
3. **S-36C 示例框架分层**：建立 `framework` 与统一 CMake 声明，迁移公共生命周期、输入、资源
   定位、计时和命令行逻辑。
4. **S-36D 示例目录迁移**：迁移 `model_viewer` 与 `sdl3_imgui`，合并根 `web/` 和现有 Web 平台
   目录，清理重复壳层并保持目标名称兼容。
5. **S-36E Web 稳定化**：验证异步加载进度与取消、相对 URL、CORS 诊断、Canvas Resize、设备
   丢失诊断、输入捕获和资源回收。
6. **S-36F 示例目录与发布验收**：补齐示例索引、独立构建命令、平台/能力要求、资产许可和故障
   排查；完成桌面与浏览器矩阵后统一更新版本号、Changelog 和发布记录。

## 测试与验收

- 合成输入在连续可提交与间歇背压两种时序下得到相同相机结果；指针和滚轮累计值有界且不突跳。
- 从视口和 UI 分别开始拖动、跨窗口边界、失焦、重新聚焦和释放按钮均有确定行为。
- 桌面 Vulkan Model Viewer 连续拖动时不消费陈旧相机帧，统计能区分输入合并、跳过构造和帧替换。
- 浏览器 Chrome WebGPU 使用正式 Model Viewer 离线 Fixture 完成加载、取消、旋转、缩放、Resize、
  截图像素容差和关闭资源归零测试；三角形 Smoke 不能替代该验收。
- `model_viewer` 与 `sdl3_imgui` 可分别启用和构建；示例私有依赖不进入安装导出或下游 Consumer。
- Windows、Linux 和 Emscripten 构建通过；文档中的桌面与浏览器运行命令可直接复现。
- 发布前通过 Quick Check、Documentation、受影响平台集成和不可变 Release Candidate。

## 风险与未决问题

- 将相机更新移到生产侧时必须保持 Frame Packet 不可变，不能让渲染线程读取实时可变状态。
- 浏览器事件循环不能复用桌面阻塞线程模型；复用边界应是状态机和数据，不是线程实现。
- 示例框架只服务仓库示例。若 Gneiss 等第二个真实 Consumer 需要相同能力，再独立评估公共 API。
- 目录迁移应保留过渡目标别名或同步更新 CI、指南与脚本，避免只移动源码而遗漏发布产物路径。
