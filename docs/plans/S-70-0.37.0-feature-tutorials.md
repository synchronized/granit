# S-70：0.37.0 特性教程与 API 能力验证

## 状态

**已确认，P1。** 目标版本为 0.37.0。

## 背景与目标

0.36.0 已明确公共 API 的长期候选、观察候选和实验性边界，并公开最小渲染数学接口。继续仅从
头文件评审接口，难以判断 Granit 是否能简洁表达真实图形效果，也容易在没有使用证据时提前增加
公共抽象。

现有 `01_cube` 和 `02_pbr_assets` 分别覆盖低层资源绘制与完整 PBR 资产路径，但尚未形成类似
bgfx examples 的单项特性目录。0.37.0 将通过三个独立、可运行且跨后端的教程验证现有 API：

- `03_instancing`：用单次实例绘制展示大量重复网格和每实例数据。
- `04_raymarch`：用全屏三角形展示基于距离场的程序化渲染。
- `05_metaballs`：用动态隐式曲面展示动画参数、法线估计和光照。

本版本以教程作为 API 探针。每个实现都要记录现有接口是否足够，以及问题属于教程本地辅助、可复用
便利接口还是真正缺失的 GPU 能力，为后续版本提供有运行证据的候选清单。

## 非目标

- 不在本版本冻结 Core、Window 或 RenderPipeline，也不改变 0.x 兼容承诺。
- 不把 `examples/common` 安装到 SDK，或建立与 Granit 公共 API 平行的示例运行时。
- 不把 Shader 内部数学、距离场函数、相机控制或效果参数提前提升为公共接口。
- 不在第一阶段实现 Compute Metaballs、Marching Cubes、GPU Driven Rendering、Indirect Draw 或
  Ray Tracing。
- 不为了统一三个效果隐藏 Shader、Buffer、Pipeline、Bind Group 或命令录制过程。
- 不引入需要运行时下载的大型模型、纹理或非商业许可资产。

## 已确认决策

### 教程结构

三个教程位于 `examples/tutorials`，编号和目标保持一一对应：

```text
examples/tutorials/
├─ 03_instancing/
├─ 04_raymarch/
└─ 05_metaballs/
```

每个教程使用独立的 `main.cpp`、HLSL Shader Library 清单和 CMake 目标。可以复用
`examples/common/application` 的 Window、Renderer、Swapchain、事件与 Desktop/Web Loop，但资源
创建、Pipeline、逐帧更新和 Draw 必须留在教程中。桌面 Vulkan 与浏览器 WebGPU 编译同一主体源码。

对应说明进入 `docs/tutorials/03-instancing.md`、`04-raymarch.md` 和 `05-metaballs.md`；文档保留
理解特性所需的关键片段，完整可编译源码只维护在 `examples/`。

### 第一批效果边界

- Instancing 使用 per-instance Vertex Buffer、实例步进和一次 `draw_indexed`，实例数据至少包含
  Transform 与颜色。相机和实例布局固定，Smoke 模式使用确定性时间与实例数量。
- Raymarch 使用由 `vertex_id` 生成的全屏三角形，在 Fragment Shader 中完成射线生成、SDF、法线
  估计和简单光照；Resize 后根据真实 Framebuffer 尺寸保持纵横比。
- Metaballs 首版继续使用 Fragment Raymarch，通过固定上限的球心与半径参数生成动态隐式曲面；
  不以 Compute、3D Texture 或网格提取作为入门前置条件。
- 三个教程均通过 HLSL-first Shader Library 生成 SPIR-V 与 WGSL，不提交手工维护的后端 Shader。

### API 缺口分类

实现中发现的问题按以下规则处理：

| 分类 | 处理方式 |
|---|---|
| 单个效果的数学或数据组合 | 保留在教程内，不进入公共 API |
| 两个以上教程重复且语义稳定的便利逻辑 | 先记录证据，再单独评审是否进入公共 C++ 辅助层 |
| 现有底层能力已具备但 C++ 包装难以使用 | 在不扩大运行时状态的前提下补齐包装和契约测试 |
| 后端命令或资源能力缺失 | 建立独立计划，同时实现 Vulkan、WebGPU、C ABI、C++ 包装和测试 |
| 仅单后端可行 | 明确能力查询与降级，不伪造跨后端对称性 |

本计划不因教程需要自动批准新增公共 API。任何公共扩展必须先说明所有权、错误语义、后端共同语义
和安装 Consumer 验证方式。

## 实施顺序

1. **S-70A 基线与教程契约**：固定目标名、目录、Shader 构建方式、Smoke 参数、浏览器入口和特性
   缺口记录模板，确认 `01_cube` 不再作为复制源持续膨胀。
2. **S-70B Instancing**：实现 per-instance Transform/Color Buffer、实例 Vertex Layout、单次实例绘制、
   交互参数和确定性像素验证。
3. **S-70C Raymarch**：实现全屏三角形、相机射线、基础 SDF 场景、法线与光照，并验证 Resize、坐标
   方向和 Vulkan/WebGPU 输出一致性。
4. **S-70D Metaballs**：实现动态球参数、平滑并集、隐式曲面光照和确定性动画；复用现有应用壳，
   不与 Raymarch 教程共享隐藏的效果框架。
5. **S-70E 文档与能力报告**：为三个教程补充连续说明，汇总已满足、包装摩擦、缺失能力和暂缓特性，
   将真正需要的能力拆为后续计划。
6. **S-70F 跨平台与发布验收**：通过本地和远端矩阵、浏览器像素检查、文档检查与发布附件复验，
   更新 Changelog 并发布 0.37.0。

## 测试与验收

- 三个教程在 Windows/Linux Vulkan 和 Emscripten WebGPU 上编译同一份主体代码。
- 每个教程支持 `--smoke-test`，使用固定尺寸、时间、参数和退出帧数，不依赖人工输入。
- Instancing 的像素检查能区分不同实例位置与颜色，并证明一次 Draw 使用大于一的实例数量。
- Raymarch 与 Metaballs 使用上下或左右非对称的确定性场景，能发现 Y 轴、纵横比和后端 UV 漂移。
- Resize、最小化恢复、Swapchain 重建、Shader 加载失败和资源释放继续遵守 Example Application 契约。
- 浏览器任务分别启动三个页面，检查 Console、初始化状态和确定性像素；桌面 Smoke 纳入 CTest。
- 教程源码不包含 `src/` 私有头，不直接调用 Vulkan、WebGPU 或平台原生 API。
- 新增资产具有明确许可和固定摘要；纯程序化教程不为装饰性效果引入外部资产。
- 能力报告逐项给出“现有 API 足够、局部辅助、公共候选、后端缺口或暂缓”结论。
- Windows MSVC/Clang、Linux GCC/Clang、Emscripten、浏览器与 Documentation 矩阵通过。

## 风险与未决问题

- 三个教程若复制完整初始化和错误处理，会重新引入旧教程的样板问题；只复用应用生命周期，不抽走
  特性核心代码。
- Raymarch 和 Metaballs 都使用全屏程序化绘制，但教学目标不同；可复用极小的测试或构建声明，
  不建立难以阅读的效果基类。
- Fragment Metaballs 更适合验证现有 API，但不能代表 Compute 或网格提取性能；后续只有在测量证明
  Fragment 路径不足时再规划 Compute 版本。
- 当前 Buffer 已有 indirect usage，但 Recorder 尚未公开 Indirect Draw 命令；本版本记录该缺口，
  不在没有独立跨后端设计和测试时顺带加入。
- 浏览器软件或虚拟 GPU 的浮点结果可能存在小差异；像素验收使用容差和区域特征，不比较逐位截图。
