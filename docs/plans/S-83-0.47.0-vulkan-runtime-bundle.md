# S-83：0.47.0 Vulkan Runtime Bundle

## 状态

**已确认，待实施。** 本计划面向 v0.47.0，承接 Vulkan Loader 随应用分发、自动选择和开发期
Validation Layer 的需求。本计划不把 Vulkan SDK 变成 Granit 的运行时依赖，也不改变公共 ABI。

## 背景与目标

Granit 的 Vulkan 后端目前依赖目标平台可发现的 Vulkan Loader。Vulkan SDK 只用于开发，不能要求
普通用户安装；显卡厂商的 Vulkan ICD/驱动也不能由 Granit 通用替代。部分应用希望在目标机器缺少
Loader 时仍能直接随应用运行，因此需要提供可选的应用私有 Runtime Bundle。

本计划建立三个边界：

1. Granit SDK 继续保持 Vulkan 内部实现边界，不向使用者传播 Vulkan Headers、SDK 或驱动。
2. 应用可以下载并随自身分发对应平台的 Vulkan Loader。
3. Debug/开发环境可以选择额外的 Khronos Validation Layer Bundle，但 Release 默认不启用。

## 非目标

- 不分发 NVIDIA、AMD、Intel 等厂商驱动或 ICD；
- 不把 Vulkan Loader、Validation Layer 或 Vulkan SDK 静态合入 `granit.dll`/`libgranit.so`；
- 不修改系统目录，不替应用安装系统运行时；
- 不在 v0.47.0 承诺完整 macOS MoltenVK 运行时；
- 不新增面向普通用户的 Vulkan 类型、句柄或原生 Vulkan 公共 API；
- 不让没有 Vulkan 驱动的机器伪装成支持 Vulkan，必须返回明确错误或使用其他后端。

## 已确认决策

### 独立 Runtime Bundle

Runtime Bundle 按平台和架构独立发布，不强制进入 Granit SDK：

```text
granit-vulkan-runtime-windows-x64.zip
granit-vulkan-runtime-linux-x64.tar.zst
```

归档包含：

```text
bin/ 或 lib/
licenses/
vulkan-runtime.json
SHA256SUMS
```

清单记录 Loader 版本、平台、架构、来源、许可证、相对路径、文件大小和 SHA-256。Windows 首批
提供 `vulkan-1.dll`，Linux 首批提供 `libvulkan.so.1`。Linux 使用应用私有目录和 `$ORIGIN`
相对搜索路径，不覆盖 `/usr/lib` 等系统目录。

### `auto` Loader 选择

增加内部构建/打包策略，不新增公共 ABI：

```cmake
GRANIT_VULKAN_RUNTIME=system   # 仅使用系统 Loader
GRANIT_VULKAN_RUNTIME=bundled # 只使用应用随附 Loader
GRANIT_VULKAN_RUNTIME=auto    # 默认：system -> bundled
GRANIT_VULKAN_RUNTIME=none    # 禁止 Vulkan Loader 发现
```

`auto` 不是简单检查文件是否存在，而是：

1. 尝试加载系统 Loader；
2. 成功获取入口并完成 Vulkan Instance 枚举时使用系统 Loader；
3. 系统 Loader 缺失或不可用时尝试应用 Bundle；
4. 两者都不可用时报告包含候选路径和失败原因的后端诊断。

可提供 `GRANIT_VULKAN_LOADER_PATH` 作为开发和诊断用的显式覆盖路径。Loader 的加载、搜索和
卸载属于 `src/` 内部实现；公共头文件不出现 Vulkan 声明。

### Validation Layer Bundle

Validation Layer 与 Loader 分开打包：

```text
granit-vulkan-validation-windows-x64.zip
granit-vulkan-validation-linux-x64.tar.zst
```

归档包含 Khronos Validation Layer、layer manifest、许可证和完整性清单，但不包含显卡驱动。

```cmake
GRANIT_VULKAN_VALIDATION=off   # 强制关闭
GRANIT_VULKAN_VALIDATION=auto  # 缺失时降级为无验证层
GRANIT_VULKAN_VALIDATION=on    # 强制启用，缺失时初始化失败
```

Validation Layer 的启用必须发生在 Instance 创建前。未设置变量时保持现有公共描述的行为：
`enable_validation=false` 关闭，`true` 要求验证层可用；`auto` 允许验证层缺失时继续运行并发出
诊断。`on` 的缺失、版本不匹配和加载失败必须提供明确诊断。验证层版本、Loader 版本、Vulkan
Headers 版本和 CI 使用的 Port/驱动版本需要在 manifest 中关联记录。

## 实施顺序

1. **S-83A 来源与许可证锁定**：确认 Windows/Linux Loader 和 Validation Layer 的上游版本、
   下载来源、再分发条款、许可证文件和版本兼容矩阵。
2. **S-83B Runtime Manifest**：复用 AssetTools 工具链包的清单思路，生成文件集合、大小、
   SHA-256、组件角色和来源元数据，并加入篡改/漏文件校验。
3. **S-83C Loader 发现与 `auto`**：在 Vulkan 后端内部实现 system/bundled/explicit path 的
   加载顺序、平台路径规则和结构化失败诊断。
4. **S-83D Validation Layer Bundle**：实现 Debug `auto`、强制 `on`、Release 默认 `off`，
   覆盖 layer manifest 搜索和版本不匹配错误。
5. **S-83E CMake 与应用打包**：提供安装/打包 helper，将已审计的 Runtime Bundle 归档到应用
   目录或私有 `lib/`，不进入 Granit 的传递链接依赖。
6. **S-83F 跨平台验收**：覆盖系统 Loader、Bundle Loader、Loader 缺失、ICD 缺失、验证层缺失、
   验证层正常启用和正常 Release 关闭等场景。
7. **S-83G Release 交付**：为 Windows/Linux 生成独立 Runtime 和 Validation 归档，执行许可证、
   manifest、SHA-256、安装 Consumer 和公开下载复验。

## 测试与验收

### Loader 场景

- 系统 Loader + 系统 ICD：`system` 正常初始化；
- 系统 Loader 缺失 + Bundle Loader + 系统 ICD：`auto` 正常初始化；
- 系统 Loader 存在但不可用 + Bundle Loader：`auto` 回退成功；
- Loader 和 ICD 都缺失：返回后端不可用，不崩溃、不误报 Vulkan 可用；
- 显式 Loader 路径：只用于内部测试和诊断，路径错误时错误可定位；
- Windows DLL 搜索和 Linux `$ORIGIN` 私有目录均不修改系统安装。

### Validation Layer 场景

- Debug `auto` 找到验证层时启用；
- Debug `auto` 找不到验证层时继续运行并记录 info/warning；
- `on` 找不到验证层时返回确定错误；
- Release 默认不启用验证层；
- Vulkan 校验错误仍然通过现有诊断/测试暴露，不能通过关闭校验掩盖问题。

### 包与 ABI

- Runtime/Validation 归档的 manifest、许可证和 SHA-256 可独立复验；
- Granit SDK 安装不传播 Vulkan Headers、SDK、驱动或 Validation Layer；
- C11/C++20 Consumer、共享/静态构建和安装导出继续通过；
- 公共 ABI、公共头文件和 Vulkan 封装边界无变化。

## 风险与未决问题

- 需要确认各平台 Loader 的官方再分发方式及其许可证，不能直接复制开发机文件；
- system Loader 已被进程加载后再切换 bundled Loader 可能受动态库生命周期限制，必须在 Vulkan
  初始化最早阶段完成选择；
- Linux 发行版的 Loader、ICD JSON 和驱动搜索路径差异较大，首批只承诺受支持发行版/架构；
- macOS 的 MoltenVK 需要单独评估，不能把它当作普通 Loader 文件直接纳入本计划首批交付；
- Validation Layer 与驱动版本不匹配时应报告诊断，不能把验证层失败误判为 Vulkan 后端不可用。
