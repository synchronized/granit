# S-44：0.25.0 Window、Input 与呈现边界收敛

## 状态

**实现中。** S-44A 契约和 S-44B 源码归位已经完成。0.25.0 将当前两个相互依赖的 Window/Input
运行时合并为一个 Window component，同时保留窗口事件与输入事件各自的类型边界。Renderer
继续允许 SDL3、GLFW、Qt 和引擎平台层直接创建 Surface；使用 Granit Window 时则通过一个不
暴露原生句柄的便捷入口创建。

项目仍处于 0.x 阶段。本任务直接删除被取代的 component、头文件和函数，不保留转发头、符号别名
或运行时兼容路径。迁移方式统一记录在 0.24 到 0.25 指南中。

## 背景与目标

当前 Input 并非独立的平台输入系统：一个 `granit_input_system` 必须独占附着到一个
`granit_window_system`，Window 是平台事件的唯一读取者，Input 轮询还会反向请求 Window 泵送。
两个动态库因此需要私有 sink、附着表、销毁顺序和跨 DLL 生命周期协议，却没有形成可供外部窗口
库复用的输入能力。

Window 创建的 Surface 还需要应用查询 Win32、XCB 或 Wayland 原生值，选择
`GRANIT_SURFACE_TYPE_*`，再组装 `granit_surface_desc`。这让使用 Granit Window 的普通应用接触了
本应由组件内部确定的平台信息；Renderer 创建时的 `surface_types` 位集合也把平台选择提前泄漏到
了上层。

本任务达成以下目标：

- Window System 统一拥有窗口生命周期、平台事件泵、窗口事件队列、输入事件队列和输入状态。
- 删除独立 Input System、私有跨组件桥接和第二套句柄注册表。
- 窗口事件与键盘、文本、指针事件继续使用不同值类型和查询函数。
- Granit Window 用户可直接从 Window 创建 Renderer Surface，无需接触原生平台值。
- 外部窗口所有者继续使用 Renderer 的原生 Surface 描述，不被强制迁移到 Granit Window。
- 公共聚合入口不再带入 Win32、XCB、Wayland 等原生接入结构。
- 源码按 component 优先、平台其次组织，删除含义过宽的顶层 `src/platform`。

## 非目标

- 不把 SDL3、GLFW、Qt 或其他第三方窗口对象加入 Granit 的稳定 C ABI。
- 不把外部窗口库的输入事件转换为 Granit Window Input。
- 不增加手柄、触摸、手写笔、完整 IME、剪贴板、拖放或 Action Mapping。
- 不建立全局 Event Bus、ECS 事件层或跨线程事件调度器。
- 不改变 Surface、Swapchain 和 Window 的所有权顺序。
- 不增加公共 Provider、Adapter Registry 或平台 Context 抽象。
- 不为 0.24 的 Input component、原生查询函数或 `surface_types` 保留兼容 API。

## 已确认决策

### 合并运行时，保留领域类型

0.25.0 只安装 `granit::window` 与 `Window` component。删除 `granit::input`、`Input` 安装
component、`granit_input_system`、创建描述及创建销毁函数。Window System 直接维护每个 Window
的键盘和指针状态，以及 Window/Input 两类事件队列。

输入值类型迁至 `include/granit/window/input.h` 和 `input.hpp`，继续使用
`granit_input_event`、`granit_keyboard_state` 和 `granit_pointer_state` 等领域名称。公共函数由
Window System 提供：

```c
granit_window_system_process_events(window_system);
granit_window_poll_event(window_system, &window_event);
granit_window_poll_input_event(window_system, &input_event);
granit_window_get_keyboard_state(window_system, window, &keyboard);
granit_window_get_pointer_state(window_system, window, &pointer);
```

`process_events` 是唯一显式平台事件泵；两个 `poll` 只读取已经生成的队列，不再隐式推进另一组件。
每个队列分别保持平台分发顺序。一次事件处理结束后，状态查询反映本次已处理的全部输入；不承诺
两个独立队列之间可重建一个公共总顺序。

所有入口仍限制在 Window System 创建线程。Window 销毁同步清除其待处理输入和状态；Window
System 销毁直接回收全部窗口与输入状态，不再存在 Input 必须先销毁的额外顺序。

### Granit Window 提供 Surface 便捷入口

新增独立的 `include/granit/window/presentation.h` 与 `presentation.hpp`，由 Window 聚合头包含。
概念 C 接口为：

```c
granit_window_create_surface(window_system, window, renderer, &surface);
```

该函数校验 Window 归属和线程，在组件内部取得当前原生值并调用唯一的 Renderer Surface 创建
实现。返回的 Surface 由 Renderer 拥有，必须先于对应 Window 销毁；Window 不保存 Renderer 或
Surface 句柄，也不接管 Swapchain 生命周期。

`granit::window` 因此公开依赖 `granit::granit`。Renderer 仍不依赖 Window，关闭 Window component
不会影响离屏渲染、浏览器 Canvas 或第三方窗口路径，不形成目标循环。

### 原生 Surface 保持高级入口

外部窗口所有者仍需传入 Win32、XCB、Wayland 或 Canvas 来源。现有带标签的
`granit_surface_desc` 与 `granit_surface_create` 保持唯一原生创建模型，但迁至显式包含的
`include/granit/renderer/native_surface.h` 与 `native_surface.hpp`。

`include/granit/renderer/surface.h` 只保留 Surface 句柄、销毁和平台无关契约；Renderer 聚合头不
包含 `native_surface.h`。SDL3/GLFW integration 自己包含高级头，并继续提供各自的便捷创建函数。

Window 的 `granit_window_get_win32`、`granit_window_get_xcb` 和
`granit_window_get_wayland` 迁至显式包含的 `include/granit/window/native.h` 与 `native.hpp`，不由
Window 或 Granit 根聚合头带入。它们只服务确有原生互操作需求的应用，不参与 Window Surface
便捷路径。

### Renderer 使用平台无关的呈现开关

删除 `granit_renderer_desc::surface_types` 及平台来源位作为 Renderer 创建能力集合的用法，改为
平台无关的呈现模式。模式只包含 `DISABLED` 与 `ENABLED`，C/C++ 初始化宏默认使用
`DISABLED`，保持当前零初始化描述创建纯离屏 Renderer 的行为。

`ENABLED` 使后端启用当前构建目标可用的呈现扩展：桌面 Vulkan 启用已编译的 Win32 或
XCB/Wayland WSI，浏览器 WebGPU 启用 Canvas。具体 Surface 来源仍由创建时的带标签描述校验。
`DISABLED` 保留纯离屏设备路径，不要求 Swapchain 能力。未知模式返回
`GRANIT_ERROR_INVALID_ARGUMENT`。

该变化让 Granit Window 和第三方窗口用户只声明“需要呈现”，无需在 Renderer 创建前判断原生
窗口系统。后端仍应在 Surface 创建时返回明确的 `GRANIT_ERROR_UNSUPPORTED` 或
`GRANIT_ERROR_BACKEND_UNAVAILABLE`，不能把平台不匹配延迟成未定义行为。

### 源码和公共头按 component 组织

目标源码布局为：

```text
include/granit/window/
├─ export.h
├─ window.h/.hpp
├─ input.h/.hpp
├─ presentation.h/.hpp
└─ native.h/.hpp                 # 高级入口，不进入聚合头

src/window/
├─ CMakeLists.txt
├─ system_api.cpp
├─ window_api.cpp
├─ presentation_api.cpp
├─ event_queue.cpp/.h
├─ registry.cpp/.h
├─ input/
│  ├─ input_api.cpp
│  ├─ input_state.cpp/.h
│  └─ platform_adapter.cpp/.h
└─ platform/
   ├─ win32/window.cpp input.cpp
   ├─ xcb/window.cpp input.cpp
   └─ wayland/window.cpp input.cpp

src/core/utf8.cpp/.h             # 不依赖 Window 的 UTF-8 校验与分片
```

删除 `src/input`、`src/platform/window` 和顶层平台 Input Adapter。平台文件只实现 Window 内部
接口；通用注册表、队列、UTF-8 与状态逻辑不包含平台头。平台协议生成目标可以继续留在构建辅助
目录，但产品源码只由 `src/window/CMakeLists.txt` 管理。

公共入口调整为：

```text
<granit/window.h>                  # Window、Input 值类型与便捷呈现
<granit/window/native.h>           # 可选原生窗口互操作
<granit/renderer.h>                # 平台无关 Renderer 与 Surface
<granit/renderer/native_surface.h> # 可选外部窗口 Surface 接入
```

### 0.x 迁移策略

实现时直接删除以下入口：

- `granit_input_system`、`granit_input_system_create/destroy` 与 `<granit/input...>`；
- `granit_input_poll_event`、`granit_input_get_keyboard_state`、
  `granit_input_get_pointer_state`；
- 聚合头中的 Window 原生查询和 Renderer 原生 Surface 描述；
- `granit_renderer_desc::surface_types` 及平台 Surface 位在普通 Renderer 契约中的声明；来源标签只
  保留在显式包含的高级 Surface 头中；
- `granit::input` CMake target 和 `Input` 安装 component。

不提供弃用周期。0.25.0 的迁移指南给出逐项替换表，ABI、导出符号和安装禁止清单阻止旧入口
残留。

## 实施顺序

1. **S-44A 契约与基线（已完成）**：落地本计划，记录当前目标依赖、导出符号、ABI 布局、事件泵行为和
   Window/Surface 组合测试基线。
2. **S-44B 源码归位（已完成）**：已建立 `src/window` 的 component-first 布局，将通用 UTF-8
   辅助归入 `src/core`，并删除顶层 `src/platform` 与 `src/input` 的反向源码收集。
3. **S-44C Input 生命周期合并**：把事件队列、状态和平台解码迁入 Window System，增加显式
   `process_events` 与新查询函数，删除 Input System、私有桥和独立 target。
4. **S-44D Window 呈现入口**：增加 `granit_window_create_surface`，迁移 Window 原生查询到
   `window/native.h`，让 Window target 单向依赖 Renderer。
5. **S-44E Renderer 呈现契约**：以平台无关呈现模式取代 `surface_types`，迁移原生 Surface 描述
   到高级头，并更新 Vulkan、WebGPU、SDL3、GLFW、示例和测试。
6. **S-44F SDK 与发布验收**：更新 Reference、Concept、0.24 到 0.25 迁移指南、CMake package、
   ABI/导出快照、安装 Consumer 与发布矩阵，完成 0.25.0 候选包验证。

每个阶段形成一个聚焦提交，在同一特性分支连续开发；完整任务可评审后统一推送和创建一个 PR。

## 测试与验收

- Window 公共 C11/C++20 头可独立包含，普通聚合入口不声明平台原生来源或句柄查询。
- Window System 的一次显式事件处理可同时填充 Window/Input 队列，两个轮询函数不会再次泵送。
- 键盘、文本、指针、焦点丢失和 Window 销毁状态清理在 Win32、XCB 与 Wayland 保持通过。
- 不存在 `granit_input_system`、私有 Window/Input sink、`granit::input` 或 `Input` 安装 component。
- Granit Window 可不经过原生 getter 完成 Surface、Swapchain、Frame 和 Present。
- SDL3 与外部原生窗口仍可通过高级 Surface 入口完成相同帧闭环。
- 呈现关闭时离屏 Renderer 不要求 WSI/Swapchain；呈现开启时各后端只启用当前构建可用来源。
- Window 销毁前存在 Surface/Swapchain 时仍由既有生命周期诊断发现，便捷入口不隐式级联 GPU
  资源。
- Windows/Linux 共享与静态构建、安装后的 Core/Window Consumer、Emscripten、浏览器 Smoke、
  C ABI 布局和导出符号检查全部通过。

## 风险与未决问题

- Renderer 呈现模式默认关闭；迁移时必须找全窗口示例和 Consumer 并显式启用，避免配置成功但
  创建 Surface 时才暴露遗漏。
- Vulkan 在设备创建前无法针对实际 Surface 查询所有队列族的呈现支持。实现应保留当前可工作的
  图形队列策略，并用真实 Win32、XCB 与 Wayland Surface 测试确认；不能只验证扩展存在。
- Window target 新增 Renderer 依赖会改变 Window-only Consumer 的链接集合和安装 component
  依赖，需要同时验证共享库、静态库与 `find_package(... COMPONENTS Window)`。
- 原生头从聚合入口移出属于源码破坏性变化，安装禁止清单应防止旧声明继续被间接包含。
- 分离事件队列不提供跨类型全序；只有出现编辑器录制或确定性回放的真实需求时，才评估公共序号
  或统一事件流。
