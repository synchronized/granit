# 任务编号：S-106：0.68.0 测试依赖缓存与父项目兼容性

## 状态

规划中。

## 背景与目标

Catch2 和 Unity 当前作为仓库内置源码位于 `3rd/`，而 SDL3、ImGui、cgltf 和 stb_image 已使用
统一的源码缓存、哈希校验和获取策略。两种方式都能工作，但父项目接入时的版本判断、重复目标
复用和离线构建语义还不完全一致。

本任务将测试框架纳入同一套依赖获取模型，同时保留测试依赖不进入生产安装包的边界。

## 非目标

- 不固定父项目依赖必须等于 Granit 锁定版本；
- 不把 Catch2、Unity 导出为 Granit 的公共依赖；
- 不修改测试框架源码；
- 不新增公共 API 或 ABI。

## 已确认决策

- `system` 和 `auto` 先复用父项目 target，再尝试 `find_package`；
- `auto` 缺失时获取 Granit 锁定源码，`download` 跳过父项目并强制使用锁定源码；
- 版本判断使用“最低版本 + 主版本兼容范围”，不使用无条件精确版本锁定；
- 已有 target 但无法取得版本信息时允许继续，但必须输出可见警告；
- fallback target 使用 `granit_test_*` 私有名称，兼容 alias 只在同名外部 target 不存在时建立；
- 测试依赖不加入安装 `FILE_SET`、导出 target 或生产库链接接口。

## 实施顺序

1. 扩展依赖目录，加入 Catch2、Unity 的锁定版本、commit、URL、SHA-256 和许可证元数据。
2. 扩展依赖选项和缓存入口，加入 `GRANIT_DEPENDENCY_CATCH2` 与
   `GRANIT_DEPENDENCY_UNITY`。
3. 将 Catch2、Unity 的源码获取和 fallback target 接入统一缓存流程。
4. 增加父项目 target 的版本/能力检查，并覆盖低版本、未知版本和兼容版本三类行为。
5. 验证安装导出、独立消费者、父项目 `add_subdirectory` 和完全缓存构建。
6. 更新第三方依赖指南、版本文档、CHANGELOG 和验收记录。

## 测试与验收

- Windows/Linux shared 与 static 构建通过；
- `system`、`auto`、`download` 三种策略均有配置测试；
- 父项目预先提供 Catch2/Unity target 时不重复下载或编译；
- 不兼容版本在配置阶段失败，未知版本给出警告；
- 完全填充缓存时不访问网络；
- 安装后的 Granit Consumer 不需要 Catch2、Unity；
- CTest、文档检查和依赖许可证检查全部通过。

## 风险与未决问题

- 不同发行版的 ImGui、stb 和 Unity 包可能不提供标准版本变量，需要能力检查或兼容性警告；
- Catch2 只有部分父项目会提供完整 `Catch2::Catch2WithMain` target，需保留只补充 main 的路径；
- 将测试源码从 `3rd/` 迁移到缓存后，CI 必须明确预填缓存或允许首次联网获取；
- 若某个父项目 target 的版本和能力均无法确认，最终行为需要在实现阶段根据实际 target 属性决定。
