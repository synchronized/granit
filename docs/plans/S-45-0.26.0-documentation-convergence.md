# S-45：0.26.0 文档一致性与历史收敛

## 状态

**已完成。** S-45A～S-45F 已完成当前事实修正、Concept/Reference 职责收敛、导航压缩、长记录
历史分离和确定性自动检查。本版本只整理文档、公共头注释和项目描述元数据，不改变公共 API、
ABI、资产格式或运行时行为。验收结果见
[S-45 文档一致性基线](../records/2026-09-16-s45-documentation-baseline.md)。

## 背景与目标

仓库已经建立完整文档分类和相对链接检查，但长期连续发布后出现了内容漂移：README 的下载入口
仍指向旧版本，开发指南残留已删除的 Input component，Vulkan Concept 和资源总览描述早期能力，
路线图与计划索引重复维护大量已完成状态，Changelog 还缺少一个已发布版本。

本任务达成以下目标：

- 修正所有已确认的版本、component、能力和发布状态错误。
- 让 Concept 描述当前架构，让 Reference 只描述当前可用接口与行为。
- 每项能力只保留一个详细权威来源，其他文档使用摘要和链接。
- 路线图只保留当前状态、下一目标和长期候选，不再逐版本复制历史。
- 计划索引突出正在实施和暂缓任务，将已完成计划作为历史索引管理。
- 扩展文档检查，自动发现版本身份、Changelog、已删除组件和发布状态漂移。

## 非目标

- 不修改 C/C++ 公共接口、CMake component、安装文件或运行时实现。
- 不重新解释历史 Record、迁移指南和已发布 Plan 当时记录的事实。
- 不为减少文件数量而删除仍有追溯价值的设计和验收证据。
- 不在本任务中决定 Android、Bindless、Clustered Forward 或稳定 ABI 的产品范围。
- 不进行与文档职责无关的源码目录调整。

## 已确认决策

### 当前事实优先

README、Guide、Reference 和 Concept 必须描述 0.25.0 后的当前仓库。历史版本中的旧组件、旧能力
和旧目录只保留在迁移指南、Plan、Record 与 Changelog 中，并明确其历史语境。

### 计划与历史分离

`docs/plans/README.md` 首先列出实施中、待开始和暂缓任务。已完成计划保留原文件以避免大范围
移动和链接重写，但从“当前计划”中移入完成历史区，并按任务族或发布版本压缩索引。

Roadmap 不再为每个已发布版本保留独立章节。已发布内容由 Changelog 和 Records 负责；路线图只
保留阶段能力摘要、当前版本任务和有重新评估条件的候选方向。

### Reference 单一事实来源

`resource-types.md` 只解释跨资源共享值类型；Texture、Sampler、Render Target 等能力分别由对应
Reference 维护。Concept 不复制完整 API 枚举，Reference 不依赖已完成 Plan 才能解释当前行为。

### 自动检查只验证确定事实

文档检查新增以下确定性规则：

- 根 README 的最新版本必须与项目版本一致，Release 链接不能固定到其他版本。
- 每个稳定版本标签对应的版本必须存在 Changelog 标题；本地无 Git 元数据时使用项目声明版本
  完成最低检查。
- 当前 Guide、Reference、Concept 和根 README 不得引用已删除的独立 Input component 或目标。
- 已发布版本的当前计划状态不得继续写“等待远端验收”。

历史迁移文档、Plan 和 Record 不应用删除组件规则，因为它们需要保留当时事实。

## 实施顺序

1. **S-45A 版本与入口修正（已完成）**：修正 README Release 入口和模块表、0.17.0 Changelog、开发指南、
   S-42 状态、0.25.0 路线图收尾及迁移索引顺序。
2. **S-45B Concept 收敛（已完成）**：按当前 Vulkan/WebGPU、Window、资源、提交和生命周期实现重写过期
   Concept，并删除已经落地能力的未来时态。
3. **S-45C Reference 单一来源（已完成）**：收窄资源总览，清理 Render Target 等 Reference 的过期计划
   措辞，确保具体能力只由领域 Reference 详细定义。
4. **S-45D 导航与历史收敛（已完成）**：压缩 Roadmap、计划索引和文档中心，将已发布版本导向 Changelog
   与 Records，保留少量当前和暂缓任务入口。
5. **S-45E 长记录整理（已完成）**：拆分或压缩 H-02、H-03、H-05、H-07 中混合的计划、当前设计和逐阶段
   日志；长期事实迁入对应 Concept/Reference，历史证据继续留在 Record。
6. **S-45F 自动检查与验收（已完成）**：增加确定性一致性检查，运行 Documentation、链接、格式和文档
   结构验收，并记录 0.26.0 文档基线。

每个阶段形成一个聚焦提交，在同一分支连续实施。

## 测试与验收

- `cmake/check_documentation.cmake` 检查全部自有 Markdown 相对链接和分类索引。
- README 当前版本、Release 入口、模块表和安装示例相互一致。
- 当前 Guide、Reference 与 Concept 不再把 Input 描述为独立 component。
- Vulkan、Texture、Sampler、Mipmap、多采样和资源生命周期文档与公共头及测试一致。
- Git 发布标签与 Changelog 版本标题一致，0.17.0 历史已补齐。
- Roadmap 和计划索引各自只维护一类状态事实，不再逐版本重复大段内容。
- Windows 本地 Documentation 检查和 `git diff --check` 通过。

## 风险与未决问题

- 历史文档中的旧接口名称属于必要证据，自动检查必须限制到当前文档范围。
- Concept 重写应核对源码和测试，不能用较新的描述替换仍未实现的能力。
- 计划索引压缩不能让已有 Plan 变成孤立文档；完成历史仍需提供稳定入口。
- 长记录拆分应优先保留提交、测试和性能证据，不把历史内容误写成当前接口承诺。
