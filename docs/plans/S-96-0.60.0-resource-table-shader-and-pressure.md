# S-96：0.60.0 Resource Table Shader 集成与真实压力

## 状态

实施中。承接 v0.59.0 已完成的 Resource Table 公共契约和 Vulkan 末尾 descriptor set 绑定。
当前已完成绑定模型契约、材质归档/实例的 Resource Table 接线、在途更新保护，以及 Tutorial 12
的 Suzanne 场景和压力入口；Shader 变体实际采样、WebGPU Bind Group 回退和跨平台证据仍未完成，
因此当前不能发布为已完成版本。

## 目标

- 增加 `explicit_bindings` 与 `resource_table` Shader/Material 绑定模型变体；
- 让 HLSL 入口、SPIR-V/WGSL 产物、Material Variant Key 和 Pipeline Layout 选择保持一致；
- 以一个绑定模型选择替代每个能力一个变体维度，避免组合导致变体爆炸；
- Vulkan 使用 Descriptor Indexing；WebGPU 不具备原生能力时明确回退到 Bind Group；
- 增加 GPU 完成点保护，禁止 Resource Table 在途更新产生 descriptor 生命周期竞态；
- 用多材质、多纹理、多 Draw 对比 Bind Group 与 Resource Table 的 CPU/GPU/容量数据；
- 将 Tutorial 12 改为单一的 `12_resource_table_scene` 场景教程：使用 Suzanne/小型 glTF
  多纹理材质，同时保留程序生成纹理作为最小验证资源；不新增 Tutorial 13。

## 非目标

- 不将 Resource Table 设为默认绑定路径；
- 不把实验性 API 升级为稳定 ABI，不引入公共 Vulkan 类型；
- 不实现 SVT、纹理驻留、预算管理、虚拟地址、VFS 或自动流送；
- 不迁移 Model Viewer、Tutorial 01～11 或全部 PBR 材质到 Resource Table；
- 不把 WebGPU 的 Bind Group 回退描述为 bindless 能力。

## 已确认决策

| 项目 | 决策 |
|---|---|
| 绑定模型 | `explicit_bindings` 与 `resource_table` 作为互斥的 Pipeline/Material 选择 |
| 变体管理 | 绑定模型独立选择，不与 alpha、skinning、lighting 等功能做笛卡尔积 |
| Shader 来源 | 继续 HLSL-first，由 AssetTools 生成后端产物和布局反射信息 |
| WebGPU | 原生 Resource Table 不可用时回退到等价 Bind Group，能力查询可观察 |
| Tutorial 12 | 使用仓库内置 Suzanne/小型 glTF 和程序生成纹理，不引入外部模型下载依赖 |
| 默认路径 | Bind Group 保持默认；Resource Table 只由显式 Pipeline/Material 选择启用 |
| 公共 API | 延续实验性标记，允许在 0.x 期间调整字段、错误码和变体描述 |

## 实施顺序

1. **S-96A：Shader 绑定模型**：增加绑定模型描述和反射校验，生成两种布局一致的变体，
   并拒绝 Shader 变体与 Pipeline Layout 不一致的组合。
2. **S-96B：Material 选择与最小真实采样**：增加绑定模型选择，完成 sampled texture view
   与 sampler 的最小 PBR/Unlit 采样；Vulkan 走 Resource Table，WebGPU 走 Bind Group 回退。
3. **S-96C：Tutorial 12 场景验证**：将示例收敛为 `12_resource_table_scene`，加载 Suzanne/小型
   glTF 多纹理材质；保留确定性纹理 Quad 作为最小路径，支持槽位切换/更新，并显示 native、
   logical、fallback 和实际绑定模型。
4. **S-96D：生命周期与压力验证**：用 Frame/Fence 完成点保护在途更新和延迟回收；在同一
   Tutorial 12 增加可重复的 `--stress-test` 入口或复用其场景资源建立 8/64/512 材质对照，
   记录 CPU、descriptor 更新量、GPU 时间、容量和变体数量。
5. **S-96E：跨平台收口**：完成 Windows Vulkan、Linux Vulkan/Lavapipe、Chrome WebGPU 和
   不支持设备验证，更新 Reference、Tutorial、CHANGELOG 和验收记录。

## 测试与验收

- Shader 变体能创建 Pipeline 并完成真实纹理采样；
- Tutorial 12 能显示 Suzanne/小型 glTF 的多纹理材质和最小纹理图案，且 Resource Table 与
  Bind Group 结果一致；
- WebGPU 使用合法 Bind Group 回退，不出现未支持的 bindless 声明或能力误报；
- 在途更新、重复销毁、跨 Renderer 句柄和错误变体组合均有负向测试；
- Bind Group 默认路径和 Tutorial 01～11、Model Viewer 原有回归测试继续通过；
- 变体数量、构建时间、资产大小、CPU/GPU 数据和已知限制写入验收记录；
- 没有稳定收益时收缩或删除实验 API，不把其升级为默认路径。

## 发布门槛

- `12_resource_table_scene` 的模型材质、最小纹理切换、槽位更新、窗口缩放和 smoke test 通过；
- Windows Vulkan、Linux Vulkan/Lavapipe、Chrome WebGPU 和不支持设备均有验收证据；
- 版本文档、计划、验收记录和 CHANGELOG 完成收口后，才允许创建 tag 和 Release。

## 风险与未决问题

- WebGPU 的逻辑 Resource Table 是否值得保留，取决于真实压力数据；没有收益时只保留显式回退；
- 不同 Shader 后端的数组纹理/采样器限制可能要求缩小第一版资源类型范围；
- 若在途更新成本高于传统 Bind Group，优先保留安全语义，不为追求吞吐绕过完成点；
- 若变体数量或构建时间明显上升，必须回退到运行时绑定模型选择，而不是继续增加静态变体。
