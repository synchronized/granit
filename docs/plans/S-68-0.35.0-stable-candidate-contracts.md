# S-68：0.35.0 稳定候选契约审计

## 状态

**已完成，P1。** 已随 0.35.0 发布。

## 背景与目标

0.34.0 已为 Core、RenderPipeline、Window 和 AssetTools 保存同版本完整符号快照，并对稳定候选
component 建立跨版本符号兼容门禁。符号集合只能证明函数仍可链接，不能独立证明结构布局、错误
分类、所有权、线程约束和 C++ 包装生命周期保持一致。

0.35.0 将现有分散验证收敛成可按 component 评审的稳定候选证据：

- 为 Core、RenderPipeline 与 Window 建立带版本和平台身份的结构布局快照。
- 补齐错误结构尺寸、保留字段、错误资源类型、跨 Renderer、失效句柄和重复销毁等负向行为。
- 让安装 SDK Consumer 覆盖三类稳定候选 component 的 C11 与 C++20 典型生命周期。
- 汇总所有权、线程安全、错误语义和 component 依赖，给出逐 component 的稳定准备结论。

## 非目标

- 不在 0.35.0 宣布稳定 ABI，也不发布 1.0。
- 不冻结 AssetTools 或第三方 Integration；它们继续保持实验性。
- 不新增 Android、Bindless、透明 PBR、Clustered Forward 或公共执行器。
- 不改变 Shader、Material、Texture Asset 或 Environment 的持久化格式。

## 已确认决策

- 符号兼容、结构布局、运行时行为和安装 Consumer 是四类互补证据，不能互相替代。
- 布局快照按 component 维护，并记录版本、平台、架构和编译器范围；当前只覆盖受支持的 64 位
  Windows 与 Linux 工具链。
- 负向行为优先通过不需要真实 GPU 或窗口的入口验证；需要设备的行为继续允许明确跳过不可用环境。
- C++ 包装只承诺源码接口和 C ABI 转发语义，不建立 C++ 二进制 ABI 快照。
- 稳定准备结论分别评估 Core、RenderPipeline 与 Window，不从统一包版本推导统一稳定等级。

## 实施顺序

1. **S-68A 结构布局基线**：按 component 拆分布局契约，绑定 0.35.0 身份并保留公共常量检查。
2. **S-68B 负向行为契约**：补齐结构扩展、保留字段、句柄归属、类型和生命周期边界测试。
3. **S-68C 安装 Consumer**：扩展 Core、RenderPipeline 与 Window 的 C11/C++20 安装后生命周期。
4. **S-68D 契约参考与报告**：统一稳定候选证据入口并记录逐 component 的剩余风险。
5. **S-68E 发布验收**：通过本地与远端矩阵，更新版本和 Changelog，发布 0.35.0。

## 测试与验收

- Windows MSVC/Clang 与 Linux GCC/Clang 能编译对应布局快照，结构漂移会在编译期失败。
- Core、RenderPipeline 与 Window 的代表性无效参数、句柄和生命周期行为由自动测试固定。
- shared SDK 安装 Consumer 同时构建并运行三类 component 的 C11 与 C++20 路径。
- Emscripten 继续构建公共头、Window 契约和浏览器工作流，不引入桌面原生类型。
- 文档检查、`git diff --check`、发布版本检查和公开附件摘要复验通过。

## 完成结果

- Core、RenderPipeline 与 Window 已建立绑定 0.35.0、平台和架构身份的结构布局快照；稳定候选
  component 同时保留精确符号集合与跨版本兼容检查。
- C11 行为测试已固定无效描述、无效所属对象和创建失败时清零输出句柄等负向契约。
- 安装 SDK Consumer 已覆盖 Window C++20 生命周期，三类候选 component 均有 C11/C++20
  安装后验证入口。
- [稳定候选证据参考](../reference/stable-candidate-evidence.md)统一说明证据边界、所有权、线程安全、
  错误语义和剩余风险；本次结果仍不构成稳定 ABI 宣告。
- 本地 Windows Clang shared/static、MSVC shared、Emscripten 与安装 SDK Consumer，以及远端
  Windows、Linux、Emscripten、浏览器和文档矩阵全部通过；`v0.35.0` 已完成公开附件复验。

## 风险与未决问题

- 当前布局快照只覆盖受支持的 64 位平台；未来支持 32 位或新架构时必须新增独立快照身份。
- GPU 与宿主窗口不可用时，部分运行时契约只能在远端对应平台验证，跳过原因必须可见。
- 即使三个候选 component 全部通过，本版本也只形成是否进入稳定规划的证据，不自动产生兼容承诺。
