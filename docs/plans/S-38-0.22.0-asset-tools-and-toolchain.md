# S-38：0.22.0 AssetTools SDK 与工具链交付

## 状态

**实施中。** S-38A～S-38D 已建立 AssetTools 交付骨架并完成 Shader、Material、Texture 领域迁移；
C API、C++ 命名空间、CLI 和 Toolchain 根目录现已使用统一契约。0.22.0 将继续迁移 Environment 的
离线构建能力，并补齐 DXC/Tint 获取方式。各类运行时资产继续保持独立格式，不合并为一个大归档。

## 背景与目标

0.21.0 已将 Shader 作者入口收敛为 HLSL-first，并形成 `.grshlib`、逻辑索引与 `.grmat` 的构建
关系。当前离线资产能力仍分散在不同组件：

- `.grshlib` 由可安装的 ShaderTools SDK 和 `granit_shader_tool` 构建，但分别传递 DXC/Tint；
- `.grmat` 由没有正式安装契约的 `granit_material_tool` 构建，并直接复用 Material 私有源码；
- Texture Asset 的确定性编码位于 Renderer 公共 API，没有对应的离线 Builder 或 CLI；
- `.grenv` 的解析和编码位于 RenderPipeline 私有实现，仓库只分发外部预处理后的资产快照；
- 文件读写、原子替换、诊断、内容摘要和清单解析在不同工具中重复实现。

本任务建立清晰的双向边界：Runtime 只检查、选择、上传和消费最终资产；AssetTools 负责构建、
检查和调试导出。Shader、Material、Texture 与 Environment 共用交付方式和基础设施，但保留各自
的数据模型、依赖和失败语义。

## 非目标

- 不把 DXC、Tint、图片解码器或纹理压缩器链接进 Core、Renderer 或 RenderPipeline。
- 不把 DXC/Tint 二进制重复放入每个 Granit SDK 或应用运行时包。
- 不把 `.grshlib`、`.grmat`、Texture Asset 和 `.grenv` 合并为一个通用容器。
- 不在运行时下载、编译或转换资产；网络访问只属于明确启用的离线构建。
- 不恢复 WGSL、SPIR-V 或 GLSL 作者入口，也不增加新的 Shader 作者语言。
- 不在首版内置 PNG、JPEG、HDR、EXR、KTX2 或 DDS 解码及 BC、ASTC、ETC2 压缩。
- 不在首版实现 HDR 到 Irradiance、Prefiltered Cube 和 BRDF LUT 的卷积算法；Environment Builder
  接收上游已经预处理的像素输入。
- 不为 0.21.0 的 ShaderTools 名称、ABI、CLI 参数或 Texture 编码入口保留弃用层。
- 不在本任务增加 macOS、Windows ARM64 或 Linux ARM64 工具链包。

## 已确认决策

### 一个 AssetTools component

0.22.0 使用以下正式交付名称：

```text
CMake component: AssetTools
CMake target:    granit::asset_tools
Library:         granit_asset_tools
CLI:             granit_asset_tool
Build option:    GRANIT_BUILD_ASSET_TOOLS
```

`ShaderTools` component、`granit::shader_tools`、`granit_shader_tools`、`granit_shader_tool`、
`granit_material_tool` 和 `GRANIT_BUILD_SHADER_TOOLS` 直接退出公共交付。项目仍处于 0.x 阶段，
本次同步更新 C/C++ Consumer、CMake、文档与导出快照，不建立名称兼容层。

公共头按领域组织：

```text
include/granit/tools/
├─ asset_tools.h/.hpp
├─ shader_compiler.h/.hpp
├─ shader_library_builder.h/.hpp
├─ material_builder.h/.hpp
├─ texture_builder.h/.hpp
└─ environment_builder.h/.hpp
```

AssetTools C API 保持 C11 可独立包含，使用调用方提供的输入字节、输出缓冲区和显式长度。C++20
包装只提供值类型、移动语义和 RAII，不建立平行运行时状态。

### 一个 CLI，按资产领域分派

标准命令收敛为：

```text
granit_asset_tool shader compile ...
granit_asset_tool shader build-library ...
granit_asset_tool shader inspect ...
granit_asset_tool material build ...
granit_asset_tool material inspect ...
granit_asset_tool texture build ...
granit_asset_tool texture inspect ...
granit_asset_tool environment build ...
granit_asset_tool environment inspect ...
```

CLI 只负责参数、文件 I/O、原子写入和退出码映射。格式编码、严格校验、缓存身份、逻辑引用解析和
诊断内容来自 AssetTools SDK；CMake 资产目标调用同一 CLI，不复制格式算法。

### 私有格式层由 Runtime 与 AssetTools 共用

二进制格式编解码从 GPU 对象和 CLI 中拆到 `src/assets/formats` 私有实现，按 Shader Library、
Material、Texture 和 Environment 分文件。Runtime 与 AssetTools 可以在构建时复用这些实现，
但安装包不导出私有 C++ 类型，也不让 AssetTools 链接 Renderer 或 RenderPipeline 的运行时状态。

Runtime 保留：

- Shader Library 的严格检查、后端选择和 GPU Shader 创建；
- Material 归档验证、参数状态、Pipeline 与 Bind Group 创建；
- Texture Asset 检查、设备变体选择和逐 mip 上传；
- GRENV 检查、Texture 创建、上传和逐帧 Environment View。

AssetTools 拥有所有确定性编码、源描述解析、索引生成、调试导出和构建缓存。只用于运行时选择的
接口继续留在对应 Runtime component。

### 各领域保持独立依赖

Shader Builder 接收 HLSL 与 Library 源清单，输出 `.grshlib` 和 `.grshidx.json`。只有 Shader
Compiler 需要外部 DXC/Tint。Material Builder 接收 `.grmat.json` 和一个或多个 Shader Library
索引，构建时将逻辑名称解析为内容 ID，最终 `.grmat` 不保存索引路径。

Texture Builder 接收已经编码为目标 GPU 格式的变体负载及布局，生成确定性 Manifest、内容 ID
和负载摘要。图片解码与 GPU 格式压缩由上游资产管线负责；Runtime 中的
`granit_texture_asset_encode` 迁入 AssetTools，检查、选择和上传接口不变。

Environment Builder 接收已经预处理的 RGBA16F Irradiance Cube、完整 mip 链 Prefiltered Cube、
BRDF LUT 和推荐光照参数，生成确定性的 `.grenv`。现有 Studio 环境继续作为经过摘要验证的快照；
完整 HDR 预处理器需要独立评估算法、第三方依赖和可复现性，不能与 GRENV 格式编码耦合。

### Shader Toolchain 使用一个根目录

AssetTools 的 Shader Compiler 描述只接收 `toolchain_root`，内部从固定布局解析并验证 DXC、Tint、
运行库、许可证目录和 `shader-toolchain.json`。CLI 使用 `--toolchain <root>`，删除 `--dxc` 与
`--tint`。Material、Texture 和 Environment 命令不解析或下载 Shader Toolchain。

Shader Toolchain 继续使用不可变的独立 Release 标签，普通 Granit Release 只记录锁定身份和摘要，
不复制工具链归档。同一经过验证的工具链可以由多个 Granit 版本复用。

### 工具链获取由使用者显式选择

CMake 增加 `GRANIT_SHADER_TOOLCHAIN_MODE`：

| 模式 | 行为 |
|---|---|
| `off` | 禁用 HLSL 资产生成，其他 AssetTools 领域仍可使用 |
| `system` | 默认值；只查找显式根目录、Vulkan SDK 和 `PATH`，不访问网络 |
| `auto` | 先查找完整本机工具链，找不到或不兼容时下载锁定包 |
| `download` | 不采用本机偶然版本，下载或复用缓存中的锁定包 |

显式 `GRANIT_SHADER_TOOLCHAIN_ROOT` 优先级最高。新增可安装的
`GranitShaderToolchain.cmake`，让内部构建、`add_subdirectory`、FetchContent 与安装 Consumer
共用查找、下载、校验和能力探测逻辑。

下载使用构建树内的版本化缓存，并实施归档 SHA-256、包内文件清单、真实编译能力、并发锁、临时
解压和成功后的原子重命名。已有缓存复用前重新验证；失败不静默回退。锁定版本、Release 标签、
平台归档名和摘要只有一个机器可读来源。

### 错误与输出事务统一

- 描述结构、字符串、模式或布局非法：`GRANIT_ERROR_INVALID_ARGUMENT`；
- 外部工具、输入依赖或工具链尚未准备：`GRANIT_ERROR_NOT_READY`；
- 当前目标、格式或能力无法支持：`GRANIT_ERROR_UNSUPPORTED`；
- 工具无法执行、格式损坏、摘要不一致或构建过程失败：映射到现有明确结果并提供诊断；若现有
  结果不足，只在统一评估全部资产领域后增加一个通用错误；
- Builder 失败时不替换既有输出，并删除本次产生的不完整临时文件。

公共 Builder 统一提供稳定诊断读取方式。CLI 将诊断输出到标准错误；CMake 保留完整子进程输出，
不把所有失败压缩成“生成失败”。

## 实施顺序

1. **S-38A AssetTools 骨架（已完成）**：已建立 component、共享/静态库、公共 C/C++ 聚合头、
   按领域分派的统一 CLI 及安装导出；已确认 AssetTools 默认进入完整 SDK，并验证单 component
   安装会携带 Core 头和运行库。CLI 文件读取与原子输出已在 Material 成为第二个调用方后收敛为
   共用的私有实现。
2. **S-38B Shader 迁移（已完成）**：Shader API、Builder、Reflection 和 CLI 已迁入 AssetTools；
   C ABI 使用 `granit_asset_tools_shader_*`，C++ 使用 `granit::asset_tools::shader`。Compiler 与
   Library Builder 只接收 Toolchain 根目录，旧 target、component、选项、字段和命令名称已删除。
3. **S-38C Material 迁移（已完成）**：已公开 Material Builder 与检查接口，迁移源 JSON、Shader
   索引解析和调试导出；统一 CLI 直接调用 SDK，并删除独立 `granit_material_tool` 及其对运行时
   Material target 的依赖。共享/静态库、C11/C++20 API、导出快照和安装 Consumer 均已验证。
4. **S-38D Texture 迁移（已完成）**：已增加 Texture Builder、Inspector 和统一 CLI；Builder
   根据已编码格式变体及布局生成内容 ID、负载摘要、Manifest 与合并负载。旧确定性编码符号已从
   Renderer 公共 API 删除；Runtime 继续保留检查、选择、摘要验证和上传。
5. **S-38E Environment 迁移**：拆出 GRENV 私有格式层，增加接受预处理像素输入的 Builder、检查和
   CLI；让内建快照校验与安装 Consumer 使用同一实现。
6. **S-38F Toolchain 获取与发布**：安装统一解析模块，完成四种模式、安全下载缓存和独立
   Windows/Linux Toolchain Release；普通 SDK 记录锁定工具链身份。
7. **S-38G 集成与发布验收**：统一 CMake 资产目标，更新 ABI/导出快照、安装清单、Reference、
   构建 Guide 和 0.21 到 0.22 迁移说明，完成跨平台 Release Candidate。

每个子阶段形成一个聚焦提交，全部阶段在当前 0.22.0 特性分支和一个 Pull Request 中连续完成。

## 测试与验收

- C11 与 C++20 安装 Consumer 可以分别构建和检查 Shader、Material、Texture 与 Environment 资产。
- AssetTools 共享/静态安装不传播 Renderer、RenderPipeline、Vulkan SDK、DXC 或 Tint 链接依赖。
- Shader Library 与 Material 的逻辑索引关系在 SDK、CLI 和 CMake 路径产生相同内容 ID。
- Texture Builder 对多格式、多 mip、数组层、行布局、摘要和确定性编码完成正反向测试。
- Environment Builder 对 Cube 面、mip 链、RGBA16F 尺寸、推荐参数和摘要完成严格测试。
- `off` 和缺少本机工具的 `system` 不访问网络，Material、Texture 与 Environment 工具仍然可用。
- `auto` 仅在缺失完整 Shader Toolchain 时下载；`download` 始终使用锁定缓存。
- 损坏归档、错误摘要、缺失或额外文件、能力探针失败及并发配置均不会留下有效缓存假象。
- Runtime-only、Emscripten 和禁用 AssetTools 的构建不下载、不安装且不依赖离线工具。
- Windows/Linux 共享与静态构建、安装 Consumer、HLSL 双后端编译及内建资产确定性比较通过。
- Release Candidate 可以从公开工具链标签获取依赖，并复现 Shader、Material 和格式快照。

## 风险与未决问题

- AssetTools 是新的正式 component，S-38A 必须先确认它是否默认进入完整 SDK 归档，以及单 component
  安装时对 Core 类型头和运行库的最小依赖。
- Material 和 Environment 格式代码当前靠近运行时状态；拆分时必须保持一份编解码规则，避免工具
  与 Runtime 对同一字节产生不同解释。
- Texture 源图解码、压缩和 Environment IBL 卷积需要额外第三方依赖或上游处理器，首版必须用
  清楚的预处理输入契约留出扩展点，不能以临时私有格式代替。
- Linux DXC 运行库加载不能依赖开发机全局路径；安装 Consumer 必须从工具链根目录独立运行。
- GitHub API 限流和离线环境必须给出可操作诊断；预下载后设置 Toolchain 根目录始终可用。
- 新宿主平台的工具链包必须分别确认可执行产物、运行库布局、许可证和真实双后端能力。
