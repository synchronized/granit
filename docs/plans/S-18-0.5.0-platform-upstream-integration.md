# S-18：0.5.0 平台扩展与上游集成

## 状态

- 目标版本：0.5.0
- 优先级：P1
- 实现状态：已完成；S-18A、S-18B1、S-18C、S-18E 均已验收

## 背景与目标

0.4.0 已完成桌面 Vulkan、浏览器 WebGPU、私有 HAL 和模型查看器闭环。0.5.0 不再横向增加图形
后端，而是让游戏编辑器、工具和其他宿主程序更容易正确嵌入 Granit。

本阶段以 Gneiss 等真实 Consumer 的接入问题为需求来源，完善已有平台的 Surface、窗口、输入、
生命周期、资源所有权和诊断契约。进入 Granit 的能力必须后端无关且可由独立 Consumer 复现，不能
把上游的 ECS、场景、资产格式或业务类型引入公共 SDK。

## 非目标

- 不在 0.5.0 接入 Android NDK、`ANativeWindow`、Gradle、Prefab 或 AAR。
- 不恢复桌面 Dawn WebGPU，也不增加新的桌面图形后端。
- 不把示例私有 glTF 加载器提升为公共 SDK；S-14 仍遵守双 Consumer 门槛。
- 不接管上游的 Mesh、材质、场景、RID、缓存、Camera 或 Transform 数据模型。
- 不以版本填充为理由启动透明 PBR、CSM、Clustered Forward 或 Bindless。
- 不在 0.5.0 宣布稳定 ABI；破坏性调整仍须集中记录并提供迁移说明。

## 已确认决策

- 公共能力继续采用 C11 ABI 与轻量 C++20 RAII 包装，不为单个上游建立专用 API。
- 上游问题先收敛为最小复现、所有权契约和预期失败语义，再决定是否修改公共接口。
- 平台扩展聚焦已有 Win32、XCB、Wayland、SDL3 和浏览器宿主路径，不新增平台实现。
- Granit 可以提供 GPU 资源、提交、呈现和可选参考管线；宿主仍拥有应用循环和业务世界。
- 高频操作优先使用现有批量入口，新增调用前必须检查动态库边界成本和生命周期风险。
- 每项公共变更同步覆盖 C API、C++ 包装、安装 Consumer、参考文档和 `CHANGELOG.md`。

## 实施顺序

1. **S-18A 上游接入基线（已完成）**：Gneiss 已覆盖完整渲染与关闭路径；审查结果见
   [Gneiss 接入基线](../records/2026-09-04-s18a-gneiss-integration-baseline.md)。
2. **S-18B 嵌入边界补齐（S-18B1 已完成）**：已增加窗口当前状态查询，使宿主在首个事件前
   取得逻辑尺寸、Framebuffer 尺寸与内容缩放；后续没有复现场景时不新增接口。
3. **S-18C 资源与提交契约（已完成）**：Gneiss 已验证动态 Uniform Arena、Upload Batch、资源
   统计、延迟回收和逆序关闭；本轮没有发现需要新增公共 API 的后端无关缺口。
4. **S-18D 诊断与可观测性（需求门控）**：现有结果码、诊断回调和资源统计已覆盖当前 Consumer；
   仅在无效句柄、跨 Renderer、Device Lost、资源泄漏或错误线程出现可复现缺口时继续扩展。
5. **S-18E SDK 验收（已完成）**：Windows 共享/静态安装 Consumer、Emscripten Debug/Release
   浏览器 WebGPU，以及 Linux Clang/GCC 共享/静态与 X11/Wayland Integration 均已通过。结果见
   [S-18E SDK 验收](../records/2026-09-04-s18e-local-sdk-acceptance.md)。

各子阶段可以形成聚焦提交，但在 0.5.0 范围可评审前保持同一特性分支和 Pull Request。任何新增
公共 API 都必须绑定真实问题、最小测试和明确所有权；仅有便利性设想时先保留在计划中。

## 测试与验收

- 至少一个真实上游完成从安装 SDK 创建 Renderer、运行帧循环并无泄漏关闭的闭环。
- 仓库内独立 Consumer 能复现已修复的通用问题，不依赖上游源码或私有资产。
- Windows 与 Linux 的共享/静态 SDK、C11/C++20 Consumer 和安装导出检查全部通过。
- Emscripten Debug/Release 构建、浏览器 WebGPU Fixture、输入和资源归零检查通过。
- 公共 API 不暴露 Vulkan、WebGPU 或平台原生实现类型；可选组件依赖不传递到 Core Consumer。
- 0.4.0 到 0.5.0 的破坏性变化、替代写法和重新编译要求均记录在迁移指南与变更记录中。

## 风险与未决问题

- 当前只有 Gneiss 被明确为真实上游，需求不能自动证明适合公共 SDK；每项能力仍需通用性审查。
- “平台扩展”容易被误解为新增操作系统，本计划只完善现有平台的宿主集成边界。
- 若接入问题实际属于上游资产或场景系统，应在 Gneiss 侧解决，不扩大 Granit 职责。
- Android 保留为独立 S-11，待产生明确产品需求、设备与维护资源后重新排期。
- 0.5.0 的功能截止日期和首个稳定 component 尚未确定，不在本计划中承诺。
