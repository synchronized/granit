# S-54：0.30.0 特性教程与 Example Application

## 状态

**实施中，P1。** 目标版本为 0.30.0。本计划把重复的线性教程收敛为编号特性示例，并建立仅供
仓库示例使用的跨平台 Application 框架。公共 API、ABI 和安装内容不受影响。

## 背景与目标

现有十章教程通过复制上一章完整应用形成线性路径。Window、Renderer 异步初始化、Surface、
Swapchain、事件、Resize、Acquire、Present 和错误恢复在多个 `main.cpp` 中重复，新增一个特性示例
需要再次维护相同样板。Model Loading 与 Model Viewer 又属于完整应用，放在教程编号中会让后续
Compute、Instancing 等独立特性无法形成清晰目录。

0.30.0 完成以下整理：

- 建立 `examples/common/application`，以类似 bgfx `entry::AppI` 的仓库私有接口统一桌面与浏览器
  应用生命周期。
- 将原 01～05 与 ImGui 教程合并为 `01_cube`，展示带控制面板的纹理立方体和低层 Renderer 路径。
- 将原 Material/Lighting 与 Render Pipeline 教程合并为 `02_pbr_assets`，展示 HLSL-first 资产、
  PBR、Scene、阴影、HDR 与后处理。
- 将 Model Loading 和 Model Viewer 移回 `examples/samples`，与编号特性教程分离。
- 为后续 `03_compute`、`04_instancing` 等单项能力保留稳定的编号空间和公共应用基础设施。

## 非目标

- 不把 Example Application 安装到 SDK、加入公共头文件或承诺兼容性。
- 不让公共框架依赖 ImGui、Render Pipeline、glTF 或具体教程资源。
- 不把 Texture、Shader、Pipeline、Material 等教程主体隐藏到公共框架中。
- 不删除底层 Window、Triangle、Texture 和 Frame 行为测试；重复的用户教程目标可以删除。
- 不直接分发带非商业限制的 LearnOpenGL 纹理或 Stanford Bunny。

## 已确认决策

### Example Application 边界

新增私有静态目标 `granit_example_application`，负责：

- Window System、Window、Renderer、Surface 与 Swapchain 生命周期；
- Renderer 异步 Ready、统一 Window Loop、关闭、Escape、Resize 与最小化；
- Acquire、Backbuffer、Present、失败 Cancel 和 `out_of_date` 恢复；
- Window/Input 事件转发、帧尺寸、时间和 Smoke Test 退出条件。

派生应用通过 `initialize`、`render`、`swapchain_changed`、事件与 `shutdown` hook 实现内容。
Application 不自动创建 `frame_context`：`01_cube` 在低层录制路径中自行持有它，`02_pbr_assets`
直接把 acquired Frame 交给 Render Pipeline。公共层统一 Present，但不猜测内容如何提交 GPU 工作。

### 教程与 Sample

```text
examples/
├─ common/application/
├─ tutorials/
│  ├─ 01_cube/
│  └─ 02_pbr_assets/
└─ samples/
   ├─ model_loading/
   ├─ model_viewer/
   └─ imgui/
```

`01_cube` 是后续特性示例的基础模板，但自身仍使用 Granit 公共 API 显式创建 Shader、Texture、Mesh、
Pipeline、Frame Context、ImGui 与 Canvas。`02_pbr_assets` 只复用应用生命周期，显式展示 AssetTools
产物、Material、Scene Snapshot、Draw Binding 和 Render Pipeline。

Model Loading 保留最小同步 glTF 示例；Model Viewer 保留完整异步、IBL、轨道相机、检查器和跨后端
入口。二者继续复用 `examples/common/gltf` 与 `examples/common/model_viewer`。

### 示例资产

- 木箱纹理选择允许商业使用和再分发的 CC0 来源，保存来源、许可、校验值和离线转换说明；早期教程
  上传预处理 RGBA，不引入运行时图片解码依赖。
- 曲面 PBR 或模型加载资产优先使用 Khronos glTF Sample Assets 中明确标记 CC0 的 Suzanne 等模型。
- Flight Helmet 与现有 CC0 环境资源继续服务 Model Viewer，不重复进入基础教程。

## 实施顺序

1. **S-54A 计划与基线**：登记目录、生命周期边界、目标名、资产许可与验证矩阵。
2. **S-54B Application 框架**：实现公共描述、Frame 视图、hook、事件转发、Swapchain 恢复和桌面/
   Emscripten Loop，先迁移一个现有目标验证边界。
3. **S-54C 01 Cube**：以最终立方体代码合并 Window、Triangle、Texture、Depth、Camera、Mesh 与 ImGui，
   增加 CC0 木箱纹理并保留 Vulkan/WebGPU 行为测试。
4. **S-54D 02 PBR Assets**：合并 Material/Lighting 与 Render Pipeline，使用更适合 PBR 的曲面模型，
   保留空场景、阴影、Resize 和生命周期验证。
5. **S-54E Samples 迁移**：移动 Model Loading/Viewer，更新目标、资产脚本、浏览器产物和测试路径；
   删除过时教程目录和重复内容。
6. **S-54F 文档与验收**：教程文档压缩为两个特性入口，Guide 接管 Samples；运行桌面、Emscripten、
   浏览器、Documentation 与安装边界检查。

## 测试与验收

- Example Application 不进入安装导出，且不传播 ImGui、glTF 或 Render Pipeline 依赖。
- `01_cube` 和 `02_pbr_assets` 在 Windows/Linux Vulkan 下构建并运行；`01_cube` 在浏览器 WebGPU
  下覆盖多帧、输入、Resize、Canvas 和显式释放。
- Model Loading/Viewer 的桌面、离屏与浏览器测试迁移后保持通过。
- Window、Triangle、Texture、Frame Context 与空场景底层测试继续提供独立回归覆盖。
- 教程索引只列两个当前特性教程；Sample 指南准确列出完整应用。
- 第三方资产具有固定来源、许可与 SHA-256，不依赖开发机临时下载结果。
- Documentation、`actionlint`、`git diff --check` 以及 Windows/Emscripten 相关构建通过。

## 风险与未决问题

- Application 抽象过厚会隐藏 Granit API；只收敛应用壳和呈现恢复，内容资源保持在教程内。
- Low-level 与 Render Pipeline 的提交方式不同；公共 Frame 只借用 acquired Frame 和 Backbuffer，
  不强制统一命令录制策略。
- 目录和目标改名会影响 CI 脚本与文档；同一阶段搜索旧路径和目标名并一次迁移，不保留过时别名。
- 示例资产可能扩大仓库；优先选择小型 CC0 数据和确定性离线转换，不提交大型原始制作文件。
