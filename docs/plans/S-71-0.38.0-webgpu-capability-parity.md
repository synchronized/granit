# S-71：0.38.0 跨后端能力契约与 WebGPU 补齐

## 状态

**已完成，P1。** S-71A～S-71F 已完成，相关功能已随 `v0.38.0` 发布。

## 背景与目标

两个正式后端已经共享 Renderer Registry、资源句柄、Graphics/Compute、传输、异步操作和呈现
接口，但 WebGPU 实现仍保留早期 MVP 限制。部分限制是实现尚未接通，例如 Primitive Topology、
多颜色附件和已经被格式能力声明支持的颜色格式；另一些来自 WebGPU 固有限制，不能通过模拟获得
相同语义。

本版本完成以下目标：

1. 建立当前行为的正式 [Renderer 后端能力矩阵](../reference/backend-capabilities.md)。
2. 让能力查询、文档、Registry 校验和后端实际行为一致。
3. 补齐 WebGPU 全部公共 Primitive Topology 和多颜色附件路径。
4. 补齐 WebGPU 可准确映射的颜色、深度格式，以及 Storage Texture Binding。
5. 为真实浏览器 WebGPU 增加正向像素验证和稳定的负向契约测试。
6. 明确保留的后端差异，不用静默降级或近似模拟换取表面对称。

## 非目标

- 不恢复桌面 WebGPU、Dawn Provider、动态插件或第二套 Registry。
- 不为 WebGPU 模拟 Pipeline Cache、Sampler LOD Bias 或非实心 Polygon Mode。
- 不公开 Vulkan Barrier、WebGPU 原生对象或任何后端专用同步 API。
- 不在本版本实现 Binding 资源数组、Bindless、Indirect Draw/Dispatch 或分层 Rendering。
- 不把 WebGPU `Depth24Plus` 冒充精确的 `D24_UNORM`。
- 不改变 HLSL-first、SPIR-V/WGSL 双载荷和 Shader Library 逻辑名称流程。

## 已确认决策

### 能力矩阵与失败语义

- Reference 矩阵只记录已经实现并验证的事实；本计划记录未来工作。
- 能力可以提前查询时，调用方先查询；设备或格式不支持时返回
  `GRANIT_ERROR_UNSUPPORTED`。
- 参数非法、句柄错误和能力不支持继续使用不同结果码，不把所有失败归并为不支持。
- 后端不得静默替换 Texture 格式、采样数、Load Operation 或 Primitive 状态。

### 无需扩展公共描述即可补齐的能力

- WebGPU 接通 Point List、Line List、Line Strip、Triangle List 和 Triangle Strip。WebGPU 的
  Indexed Strip 要求 Pipeline 提前固定 Index Format，而 Granit 的长期候选契约在录制时才选择
  Index Type；0.38.0 明确拒绝 Indexed Strip，不为这一项破坏现有 Pipeline ABI。
- Graphics Pipeline、Render Pass 和私有设备描述改为颜色附件数组，支持每个附件独立格式、Blend
  和 Write Mask。
- `renderer_limits` 在尾部追加 `max_color_attachments`；Vulkan 和 WebGPU 都报告设备实际限制，
  Registry 在进入后端前统一校验。
- 修正 WebGPU Texture 格式能力与 Pipeline 格式映射不一致。优先接通已经声明可渲染的
  `R8_UNORM`、`RG8_UNORM`、`RGBA8_SRGB`、`BGRA8_SRGB` 与 `D16_UNORM`。

### Storage Texture 契约

WebGPU 创建 Storage Texture Layout 时必须知道格式、访问模式和 View Dimension，现有
`granit_bind_group_layout_entry` 无法表达这些字段。项目尚处于 API 快速迭代期，本版本直接扩展
该条目，仅维护最新结构，不保留尚未稳定的旧布局兼容分支。条目增加：

- Texture 格式；
- Read、Write 或 Read-Write 访问模式；
- View Dimension；0.38.0 的跨后端基线只承诺 2D Storage Texture。

Vulkan 与 WebGPU 消费同一描述。格式必须通过 Texture 格式能力查询支持 Storage Usage；缺少后端
或设备能力时返回不支持。C++ 包装提供强类型描述，不要求普通用户填写原始枚举值。

### 明确保留的不支持项

以下项目在 0.38.0 继续返回 `GRANIT_ERROR_UNSUPPORTED`：

- WebGPU Binding 资源数组：依赖浏览器可选 Feature 和额外数量限制，等待真实用例后独立规划。
- WebGPU Line/Point Polygon Mode、Front And Back Cull、Sampler LOD Bias：WebGPU 没有同等状态。
- WebGPU Pipeline Cache：浏览器没有可持久化、可导入导出的同等数据契约。
- 浏览器 Timestamp Query：当前公共契约要求任意命令位置写入，浏览器能力不能稳定满足。
- WebGPU 分层 Rendering 和 Attachment Load Discard：当前实现不提供同等语义。
- `D24_UNORM_S8_UINT` 与 `D32_FLOAT_S8_UINT`：前者没有精确格式映射，后者依赖尚未公开的可选
  Feature；保持不支持直到格式契约单独扩展。
- Vulkan Canvas Surface 与浏览器 WebGPU 桌面原生 Surface：属于运行平台差异。

## 实施顺序

1. **S-71A 文档与现状基线**：加入能力矩阵，修正 Shader、Surface 和 Pipeline Reference，增加
   文档链接检查与当前 `UNSUPPORTED` 行为清单。
2. **S-71B Pipeline 能力快照（已完成）**：追加最大颜色附件限制，统一 Vulkan/WebGPU 报告、
   Registry 校验和 C/C++ 包装。
3. **S-71C Primitive Topology（已完成）**：扩展 WebGPU 私有枚举、映射与原生命令；全部非索引
   拓扑和索引 List 已接通，Indexed Strip 因索引格式属于不可变 Pipeline 状态而明确返回不支持。
4. **S-71D MRT 与格式一致性（已完成）**：WebGPU Pipeline/Render Pass 已改为附件数组，接通
   独立 Blend，并修复 R8、RG8、RGBA8 sRGB、BGRA8 sRGB 与 D16 UNORM 格式映射。
5. **S-71E Storage Texture（已完成）**：Layout Entry 直接携带格式与访问元数据，WebGPU 接通
   Write-Only RGBA8/RGBA16F；Read-Only/Read-Write 明确返回不支持。
6. **S-71F 双后端验收（已完成）**：Windows Vulkan Debug/Release、Emscripten Debug/Release
   及真实 Chrome 的 MRT、Storage Texture 与异步 Readback 像素测试已通过。Linux CI 软件
   WebGPU 在异步 Pipeline 回退后会使外部 Instance 失效，因此该路径只验收同步 Pipeline 与
   生命周期，不继续执行同实例异步像素读回；远端 Linux、Windows、安装 Consumer、文档和发布
   工作流均已通过。

## 最终结果

- 公共能力查询新增 `max_color_attachments`，Vulkan 与 WebGPU 的限制、Registry 校验和文档一致。
- WebGPU 已接通非索引 Point/Line/Triangle 拓扑、MRT、独立 Blend/Write Mask、可准确映射的新增
  格式，以及 Write-Only RGBA8/RGBA16F Storage Texture。
- Indexed Strip、资源数组、非实心 Polygon Mode、Front And Back Cull、Sampler LOD Bias、
  Pipeline Cache、浏览器同步 Timestamp、分层 Rendering、Load Discard 和不能准确映射的深度
  模板格式继续明确返回不支持，未增加语义不可靠的模拟层。
- 功能 PR [#109](https://github.com/synchronized/granit/pull/109) 与版本 PR
  [#110](https://github.com/synchronized/granit/pull/110) 已合并；发布证据见
  [0.38.0 发布验收](../records/2026-09-28-v0.38.0-release-acceptance.md)。

每个阶段形成聚焦提交；同一特性分支持续开发，完成全部本地与浏览器验收后统一创建 Pull Request。

## 测试与验收

- 公共 C 头由 C11 Consumer 编译；C++20 包装覆盖新增 Limits 和 Storage Texture 描述。
- ABI/Layout 快照验证当前公共结构布局；项目处于 API 快速迭代期，不保留尚未稳定的历史结构。
- 后端 Contract Test 覆盖五种非索引 Primitive Topology、索引 List、MRT、独立 Blend 与 Storage
  Texture Compute 写入；Indexed Strip 覆盖明确的不支持结果。
- WebGPU 格式表逐项验证 Texture 创建、View、Pipeline 和 Render Pass，不能只测试内部映射函数。
- 浏览器像素测试至少使用两个颜色附件并读回可区分结果；Storage Texture 测试写入后复制回读。
- 负向测试覆盖资源数组、LOD Bias、非实心 Polygon Mode、不兼容深度模板格式和 Pipeline Cache。
- Windows Clang/Vulkan、Linux Clang 或 GCC/Vulkan、Emscripten Debug/Release、安装 SDK C/C++
  Consumer 和文档检查全部通过。
- 最终能力矩阵、Renderer、Shader、Pipeline、Surface、Texture 与迁移文档和实际结果一致。

## 风险与未决问题

- WebGPU MRT 会扩大私有设备描述和异步 Pipeline Warmup 捕获数据，必须保证数组生命周期持续到原生
  调用完成。
- Indexed Strip 若出现真实 Consumer 需求，应另行设计兼容扩展或内部 Pipeline 变体；不能按首次
  绑定动态修改不可变 Pipeline，也不能固定假定 UInt16 或 UInt32。
- Storage Texture Read-Write 支持可能受浏览器 Feature 限制；若基线只保证 Write-Only，则能力查询
  和 Shader 资产必须精确区分访问模式。
- `max_color_attachments` 之外还可能需要每阶段资源数量限制。本版本只公开真实 Consumer 已需要的
  最小限制，后续按证据追加，不复制整套 Vulkan/WebGPU Limits。
