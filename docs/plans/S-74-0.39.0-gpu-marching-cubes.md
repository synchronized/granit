# S-74：0.39.0 GPU Marching Cubes 与动态几何

## 状态

**实施中，P1；S-74A～F 已完成，正在执行跨平台发布验收。** 本任务新增
`06_marching_cubes`，用 GPU Compute 生成动态三角形，通过帧级
Transient Buffer 保存临时密度场、顶点和间接参数，并使用 Indirect Draw 绘制。它将作为 Compute、
动态几何、Transient Buffer、跨阶段同步和间接绘制的端到端能力探针，版本目标为 `v0.39.0`。

## 背景与目标

现有 `05_metaballs` 使用 Fragment SDF Raymarch，不生成真实网格。它已经验证全屏三角形、Shader
循环、隐式距离场和程序化法线，但没有覆盖 GPU 动态几何生产链。

当前 Vulkan 与 WebGPU 已支持 Compute Pipeline、Storage Buffer 和直接 Dispatch，Buffer Usage 也
已经包含 Indirect；缺口是公共 Indirect 命令和可供一帧内 Compute/Graphics 共用的 Transient Buffer
分配。S-74 不再使用 CPU 网格提取绕过这些缺口，而是先补齐共同能力，再以 GPU Marching Cubes 验证：

- Compute 更新三维密度场和梯度；
- Compute 查表并向有界顶点 Buffer 追加三角形；
- GPU 生成 Draw Indirect 参数，运行时不回读顶点数量；
- Transient Buffer 随真实 Frame Slot 复用，调用方不手工管理在途帧资源；
- Recorder 自动处理 Transfer → Compute、Compute → Compute、Compute → Vertex/Indirect 的依赖；
- Desktop Vulkan 与浏览器 WebGPU 编译同一 C++ 主体和 HLSL-first Shader Library；
- 复用 S-73 的统一 ImGui、帧指标与 Orbit Camera。

## 非目标

- 不删除或改写 `05_metaballs`；两章分别展示像素求交和显式网格生成；
- 不在首版实现 Async Compute、多 Queue、Mesh Shader 或 GPU Driven 场景系统；
- 不提供多 Draw、Count Buffer 或后端专有 Indirect 扩展；
- 不通过每帧同步 GPU 回读决定 Draw 数量；
- 不把 Tutorial 的 Marching Cubes 算法提升为通用 Geometry SDK；
- 不为尚未稳定的旧 API 保留兼容入口。

## 已确认设计

### 公共 Indirect 命令

在 C API 和 C++ 包装中增加单命令跨后端入口：

```c
granit_command_recorder_draw_indirect(renderer, recorder, buffer, offset);
granit_command_recorder_draw_indexed_indirect(renderer, recorder, buffer, offset);
granit_command_recorder_dispatch_indirect(renderer, recorder, buffer, offset);
```

每次调用只消费一个参数结构，保持 Vulkan 与 WebGPU 的共同能力。公开定宽参数布局，方便 CPU、Copy
或 Compute 生成：

```c
typedef struct granit_draw_indirect_args {
  uint32_t vertex_count;
  uint32_t instance_count;
  uint32_t first_vertex;
  uint32_t first_instance;
} granit_draw_indirect_args;
```

Indexed Draw 与 Dispatch 使用各自对应结构，其中 `vertex_offset` 为 `int32_t`。Recorder 校验 Buffer
所属 Renderer、Indirect Usage、4 字节 Offset 对齐、参数范围以及 Graphics/Compute Pass 状态。

两个后端分别映射 `vkCmdDrawIndirect`、`vkCmdDrawIndexedIndirect`、`vkCmdDispatchIndirect` 与 WebGPU
对应命令。Storage 写入后的 Buffer 在 Indirect 读取前必须建立正确执行与内存依赖。

### 帧级 Transient Buffer

为 `frame_context` 增加帧录制期临时 Buffer Slice：

```cpp
transient_buffer_slice density;
transient_buffer_slice vertices;
transient_buffer_slice draw_args;

recording.allocate_transient_buffer(desc, density);
```

Slice 是借用值，只包含 `buffer_ref`、Offset、Size 和 Usage，不拥有也不能销毁底层 Buffer。有效期从
分配成功开始，到该 Frame Recording 提交或放弃为止；已录制命令引用的底层资源由 Frame Context
保活至对应 Frame Slot 再次可用。

Frame Context 按真实在途槽维护 Arena/Page。首版允许按 Usage 兼容组复用页面，不要求跨资源内存
别名；必须保证：

- 分配大小与对齐使用 64 位溢出检查；
- Slice 不跨页面边界且满足 Uniform/Storage/Vertex/Index/Indirect 对齐；
- 同一槽位在 GPU 完成前不会被覆盖；
- Abort 回收尚未提交的分配；
- Context 销毁等待并释放全部页面；
- 旧 Slice 不能作为可持久化身份或跨帧缓存。

Transient Buffer 支持 Storage、Vertex、Index、Indirect 和 Transfer Usage 的必要组合。CPU 上传仍用
现有 Buffer Write/Copy 路径；本任务不公开长期映射指针，避免 WebGPU 映射状态差异进入 API。

### GPU Marching Cubes 数据流

```text
Transient Field Buffer
  ← Density/Gradient Compute
             ↓
Transient Vertex Buffer + Counter
  ← Polygonize Compute + Atomic Append
             ↓
Transient Draw Args
  ← Finalize Compute（容量钳制、写 Draw 参数）
             ↓
Vertex Bind + Draw Indirect
```

Density Pass 为每个 Grid Sample 写密度与梯度。Polygonize Pass 每个 invocation 处理一个 Cell，通过
Edge/Triangle Table 生成非索引三角形，并用 Atomic Counter 预留输出范围。越过容量的 Cell 只记录
Overflow，不写越界数据。

Finalize Pass 把成功写入的 Vertex Count 钳制到容量，写入单个 Draw Indirect 参数，并保留 Overflow
诊断。Graphics Pass 将同一 Slice 绑定为 Vertex Buffer，随后执行 Draw Indirect。运行时不等待或回读
计数。

Recorder 必须在连续 Dispatch 之间识别 Storage 写后读/写依赖，也必须在 Begin Rendering 前处理
Storage → Vertex 和 Storage → Indirect 依赖。不能依赖 Vulkan 隐式行为或 WebGPU 实现偶然顺序。

### 异步统计

UI 显示 Grid Size、理论容量、GPU Timestamp 和最近一次已完成的 Triangle/Vertex/Overflow 数据。
统计通过低频、延迟一帧以上的异步 Readback 获取；如果结果尚未完成则继续显示旧值，不阻塞当前帧。
绘制本身始终由 Indirect 参数驱动，Readback 只用于诊断。

### 面板参数

- `ISO`：等值面阈值；
- `Grid Size`：每轴采样数量，首版范围 8～32；
- `Ball Count`、`Radius` 和场强；
- `Animation` 与 `Animation Speed`；
- `Wireframe`：仅在能力矩阵支持 Line Polygon Mode 时启用；
- Vertex Capacity、最近完成的 Vertex/Triangle 数量和 Overflow；
- Density、Polygonize、Finalize 与 Draw GPU 时间。

相机复用 Common Orbit Camera，根据密度场范围设置 Focus，支持 Reset 与 Auto Orbit。Smoke 固定所有
参数和时间，不依赖真实输入。

### 查表与 Shader 工具链

Edge/Triangle Table 作为只读 Storage/Uniform 数据上传，或在构建时生成适合 Shader 的常量数据。
来源必须具备兼容许可证并记录固定版本，或者提交生成器和确定性结果测试；不能复制来源不明的表格。

Compute、Vertex 和 Fragment 入口位于同一 HLSL-first Library，由现有工具链生成 SPIR-V 与 WGSL。
Shader Reflection 必须验证 Storage、Atomic、Workgroup Size、Vertex 输入和 Fragment 输出契约。

## 测试与验收

- 三种 Indirect 命令在两个后端正确执行，并拒绝错误 Usage、Offset、范围、Pass 状态与跨 Renderer；
- Compute 写 Draw Args 后无需 CPU 回读即可驱动 Graphics Draw；
- Transient Slice 在每个 Frame Slot 保持独立，Submit/Abort/Resize/Context Destroy 不泄漏或提前复用；
- Density → Polygonize → Finalize → Draw 的跨阶段依赖通过 Vulkan Validation 与 WebGPU Validation；
- Atomic Append 永不越界，容量不足时设置 Overflow 并绘制钳制后的完整三角形；
- 固定 Grid、球参数、ISO 和时间产生确定的非零几何摘要；
- UI Readback 未完成时不阻塞，显示最后完成结果；
- WebGPU Wireframe 控件明确禁用，其他核心功能与 Vulkan 一致；
- Resize、最小化恢复、Swapchain 重建和资源释放继续遵守 Frame Context 契约；
- C11 头、C++20 包装、shared/static Consumer 和安装 File Set 同步更新；
- Windows/Linux、Emscripten 编译、Chrome 行为、文档检查和 `git diff --check` 通过。

## 风险与限制

- WebGPU 没有 Vulkan 风格通用 Pipeline Barrier；公共状态跟踪必须表达资源用途和 Pass 边界，不能把
  原生同步参数暴露给调用方。
- Atomic Append 的输出顺序可能因执行调度不同而变化；验收比较几何计数、范围和图像特征，不比较
  顶点逐字节顺序。
- 最大 Grid 的理论输出较大；默认值以浏览器软件实现也能交互为准，面板明确显示容量和 Overflow。
- Transient Arena 首版以正确复用和生命周期为目标；页面别名、碎片整理和跨 Pass 自动生命周期分析
  留给 Render Graph，不混入本任务。
