# S-25：0.10.0 环境资源与帧构造背压

## 状态

- 路线图任务：S-25
- 目标版本：0.10.0
- 优先级：P1
- 状态：实施中；S-25A 至 S-25D 已完成
- 前置依赖：S-13H、S-19、S-24

## 背景与目标

0.9.0 已将 Model Viewer 的 PBR Shader 收敛为公共资产，但环境包解析、IBL 纹理所有权仍位于
示例内部。桌面渲染线程也会先构造完整 Frame Packet，再由有界队列替换过期帧；渲染落后时，
主线程仍会复制 Scene Snapshot、Draw Binding 和 ImGui 数据。

0.10.0 只处理这两个已经由真实模型验证的问题：把环境贴图变成 RenderPipeline component 的
公共资源，并让 Model Viewer 在昂贵帧数据构造前实施背压。版本不引入通用任务系统或场景系统。

## 非目标

- 不公开 Model Viewer 的执行器、Frame Packet、轨道相机、界面状态或性能历史。
- 不让 Granit 接管文件 I/O、资产数据库、异步加载、缓存或应用主循环。
- 不把示例 glTF Loader 提升为公共 SDK，也不引入 Android。
- 不加入 TAA、透明 PBR、CSM、Clustered Forward、Bindless 或新的 PBR 变体。
- 不承诺 1.0 ABI 稳定性；版本收尾前统一提升版本号。

## 已确认决策

### Model Viewer 构造前背压

- 桌面执行器提供只读容量查询；它是单生产者场景下的瞬时提示，不替代 `submit()` 的最终检查。
- 主线程在 `application_core::tick()` 前检查容量。满载时继续处理 SDL 事件、窗口状态、退出、
  Resize 和不可丢弃控制命令，但跳过 Scene Snapshot、Draw Binding、ImGui Capture 与 Frame Packet。
- 分别统计构造前跳过的 `skipped_frame_builds` 和构造后被替换的 `replaced_frames`，避免混淆成本。
- 该机制先保持示例私有；只有第二个非示例 Consumer 提出相同需求后才重新评估公共执行器 API。
- 浏览器保持同步执行，不为 Emscripten 引入线程依赖。

### 公共 Environment Map

- Environment Map 属于 RenderPipeline component，不进入 Core Renderer，也不暴露后端原生类型。
- C API 使用 64 位非零句柄表达所有权，C++20 包装提供移动语义和 RAII。
- 对象拥有 Irradiance Cube、Prefiltered Environment Cube、BRDF LUT 及对应 View；Render Pipeline
  仍通过现有 `granit_render_pipeline_environment` 借用渲染描述，不复制纹理所有权。
- 创建入口接收调用方提供的环境资产内存字节；文件读取、调度与缓存仍由调用方负责。
- 环境对象必须校验所属 Renderer、重复销毁、无效句柄和父 Renderer 失效；资源统计覆盖其子资源。
- 提供无需外部文件的中性默认环境，作为缺失资产时的确定性降级路径。

### 正式环境资产

- 将示例 GRENV v2 的有效能力收敛为正式、版本化的 RenderPipeline 环境资产；发布前确定稳定扩展名
  和魔数，示例私有格式不与正式格式长期并存。
- 格式固定颜色/像素格式、Cube 面顺序、Mip 布局、尺寸上限、推荐曝光与强度，并校验区段长度和
  SHA-256；未知版本、截断、溢出和不支持格式必须明确失败。
- 离线环境工具负责生成资产并随工具 component 发布；运行时不进行耗时的环境卷积。
- Vulkan 与浏览器 WebGPU 消费同一资产字节，后端差异仅存在于内部纹理创建和上传。

## 实施顺序

1. **S-25A Model Viewer 背压（已完成）**：增加容量查询、构造前跳过、统计与满载恢复测试，并记录 Packet
   构造次数和主线程成本变化。
2. **S-25B Environment Map API（已完成）**：确定 C ABI、C++ RAII、句柄所有权、默认环境和现有渲染描述
   的借用关系，补齐生命周期与资源统计测试。
3. **S-25C 环境资产与工具（已完成）**：固定 GRENV v3，迁移解析、编码和离线工具，增加确定性、摘要、损坏
   输入与资源上限测试。
4. **S-25D Consumer 迁移（已完成）**：让 Model Viewer 删除私有环境包和资源类，桌面 Vulkan、浏览器
   WebGPU 统一使用公共 Environment Map，并保持环境强度、旋转和曝光控制。
5. **S-25E 版本收尾**：完成安装资产、独立 C/C++ Consumer、Reference、迁移指南、变更记录、
   跨平台矩阵及 0.10.0 发布验收。

## 测试与验收

- 队列满载时不调用昂贵帧构造路径；容量恢复后可继续提交，Resize、退出和控制命令不会饥饿。
- `skipped_frame_builds`、`replaced_frames` 与队列高水位分别准确，压力测试不出现死锁或数据竞争。
- Environment Map 覆盖成功创建、销毁、重复销毁、无效句柄、跨 Renderer、父资源失效和部分失败
  回滚，销毁后其 Buffer、Texture、View 与 Sampler 统计归零。
- 正式环境资产覆盖确定性往返、摘要、截断、越界尺寸、未知版本和不支持像素格式。
- Model Viewer 不再编译示例私有环境解析/资源实现，真实 Flight Helmet 的 IBL 表现保持一致。
- Vulkan 与浏览器 WebGPU 使用同一环境资产，并通过图像容差和资源释放验收。
- Windows/Linux 共享与静态安装 Consumer、Emscripten、文档及 Release 候选工作流全部通过。

## 风险与未决问题

- `can_submit_frame()` 是提示而非容量预留；若未来出现多个生产者，需要改为令牌式预留，不能依赖
  检查与提交之间的原子性。
- 正式环境资产继续使用 `.grenv`，当前格式版本为 GRENV v3；离线生成器当前作为仓库工具构建，
  运行库和安装包只发布确定性资产。后续格式变化必须使用独立版本并提供迁移说明。
- 公共 Environment Map 是高层资源聚合，不能成为与调用方纹理组合路径含义重叠的第二套环境状态；
  现有 `granit_render_pipeline_environment` 继续作为唯一逐帧借用描述。
