# S-78：0.42.0 Model Viewer Linux 与 Emscripten 可靠性

## 状态

- 文档状态：已确认
- 实现状态：未开始
- 目标版本：v0.42.0
- 前置任务：[S-77 Model Viewer 架构收敛](S-77-0.42.0-model-viewer-convergence.md)
- 遗留证据：[S-76 验收记录](../records/2026-09-29-s76-pbr-material-correctness-acceptance.md)

## 已确认问题

v0.41.0 的 Emscripten 浏览器矩阵在 Linux 托管 Runner 上偶发报告 Dawn 外部 Instance 不再有效，
串行执行浏览器矩阵只能降低波动，没有证明或修复根因。该问题属于 Linux 主机上的 Emscripten/
Chrome WebGPU 路径，当前没有证据表明原生 Linux Vulkan Model Viewer 存在同一缺陷。

浏览器 Model Viewer 还保留可见 DOM 加载层，并从控制台文本重建状态。共享 C++ Application 已有
ImGui 加载窗口，但同步解析、上传和 Pipeline 准备期间不能稳定产生中间帧，形成两套用户界面和
两套状态传播。

本任务在 S-77 的共享结构上修复这些问题，并补齐原生 Linux XCB/Wayland 与 Emscripten 浏览器的
独立验收证据。

## 非目标

- 不把 Linux 托管 Runner 的 Dawn 症状直接归因于 Granit、Chromium 或 CI 并提前固定方案。
- 不用无限重试、吞掉设备丢失、降低 Validation 或跳过 Model Viewer 作为稳定性修复。
- 不建立 JavaScript 业务状态机或可见 DOM 备用 UI。
- 不要求原生 Linux 和浏览器呈现路径使用相同底层 Surface 实现。

## 统一加载界面

- Desktop 与 Web 使用同一个 ImGui 加载面板、主题、阶段说明、进度和取消入口。
- 浏览器在 Renderer/Surface/Swapchain/Font 尚未建立时只显示 Canvas 背景；首个可渲染帧开始显示
  ImGui，不承诺在 GPU 呈现可用前绘制 UI。
- HTML Shell 删除可见标题、进度条、状态文本和取消按钮，只保留 Canvas、启动胶水及不可见测试
  状态。
- 正常、取消和失败均由共享 `model_load_operation` 快照驱动；控制台消息只用于诊断。

## 浏览器 WebGPU 生命周期审计

按所有权链检查 Instance、Adapter、Device、Queue、Surface、Swapchain 和异步回调：

1. 记录每个对象的创建、异步完成、设备丢失、关闭和销毁顺序。
2. 确保回调捕获的状态存活期不超过其 Renderer/Instance，并在 Shutdown 后拒绝发布完成事件。
3. 检查页面关闭、加载取消、初始化失败、重复 Shutdown 和测试创建多个 Page 时的清理。
4. 区分应用资源泄漏、浏览器进程级 WebGPU 状态以及测试服务器/页面复用影响。
5. 根因明确后再决定是否保留矩阵串行；串行不能作为唯一修复。

浏览器正式 Sample 和测试构建必须使用相同生命周期实现。测试专用控制与 Pipeline Validation 放入
独立测试目标，不能改变正式应用的对象所有权。

## Linux 原生验收

原生 Linux 分别验证 XCB 和 Wayland：

- Window、Surface、Swapchain 创建和 Resize；
- Model Viewer 资产加载、GPU 上传、PBR/环境、ImGui 和输入；
- Dedicated Render Dispatcher 的线程亲和性、Flush 和 Shutdown；
- Headless/Xvfb/Weston 环境无法验证真实合成像素时，使用离屏像素回归承担颜色门禁，并明确记录
  窗口测试只验证生命周期与事件。

该矩阵用于确认 S-77 重构没有破坏 Linux，不把未复现的平台缺陷写成已修复问题。

## 浏览器自动化边界

Web Shell 可以通过隐藏状态或显式测试 API 暴露阶段、结果和诊断。自动化不得依赖可见 DOM 文本，
也不得通过解析 Console 推断业务状态。验收至少区分：

- 启动但尚未具备呈现能力；
- ImGui 加载帧已经提交；
- Viewer Ready 且模型帧已经提交；
- 用户取消；
- 外部 Buffer/资源失败；
- Device Lost 或初始化失败；
- Shutdown 完成且活动及待退休资源归零。

## 实施顺序

1. 在现有失败路径增加临时生命周期诊断，保存可复现的创建/销毁时间线。
2. 将 Web 自动化从可见 DOM/Console 迁移到隐藏结构化状态，并保持现有失败场景覆盖。
3. 删除可见 DOM 加载层，让共享 ImGui 加载面板覆盖所有可绘制阶段。
4. 基于 S-77 的协作式加载，让解析、上传和 Pipeline 准备期间持续绘制并响应取消。
5. 修复由证据确认的 Instance/Device/回调所有权问题，增加连续启动、退出和多 Page 回归。
6. 运行 Linux XCB/Wayland Model Viewer 验收，修正重构暴露的平台执行或关闭问题。
7. 清理临时诊断，保留结构化错误和必要生命周期测试，完成远端矩阵。

## 测试与验收

- Web Shell 没有可见加载控件，加载期间至少提交一个 ImGui 帧。
- Fetch、解析、GPU 上传和 Pipeline 准备进度单调，长阶段不会冻结页面主循环。
- 取消、资源失败、Device Lost 和重复 Shutdown 返回稳定结果且资源计数归零。
- 同一浏览器进程连续运行正式/测试 Model Viewer，不出现悬空回调或失效 Instance。
- 浏览器测试首次执行通过；允许测试框架报告诊断，不允许自动重跑转为成功。
- Linux XCB 和 Wayland 的加载、渲染、Resize、输入及退出通过。
- Windows Desktop 回归通过，证明共享状态机没有引入平台分叉。
- Emscripten Node、Chrome WebGPU、Linux、Windows 和文档工作流通过。

## 完成条件

只有根因和回归证据都明确后，才能关闭 v0.41.0 遗留项。若确认故障来自锁定 Chromium/Dawn 的
外部缺陷，必须记录最小复现、受影响版本、可靠探测方式和有限规避；不能只记录“偶发”或保留无界
重试。
