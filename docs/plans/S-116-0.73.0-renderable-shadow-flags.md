# S-116：Renderable 阴影投射与接收控制

## 状态

**本地实现完成，待 v0.73.0 发布候选验收，2026-11-20。** 本任务为 RenderPipeline 的每个 Renderable 实例增加
独立的阴影投射和阴影接收控制，同时保持未设置开关时的现有行为。

## 背景与目标

当前方向光 Shadow Pass 会从场景可见 Renderable 中收集投射者，PBR 主视图则统一使用阴影资源。
Renderable 没有表达“只参与主视图、不投射阴影”或“显示物体但不接收阴影”的能力。

目标语义：

- 默认实例继续投射并接收阴影；
- 关闭投射只影响 Shadow Caster 集合，不影响主视图可见性、材质或其他光照；
- 关闭接收只关闭该实例的阴影采样，不影响其漫反射、镜面、IBL、透明度和主视图提交；
- 两个开关相互独立，可组合使用；
- 多 View 下开关属于实例，默认对该实例的所有 View 生效。

## 公共 API 设计

在 `granit_scene_renderable` 当前 `reserved` 字段位置收敛为 `shadow_flags`，不扩大 Renderable
元素布局，保持旧的零值输入能够继续表示默认行为：

```c
#define GRANIT_SCENE_RENDERABLE_SHADOW_DISABLE_CAST UINT32_C(1)
#define GRANIT_SCENE_RENDERABLE_SHADOW_DISABLE_RECEIVE UINT32_C(2)
```

约定：

- `shadow_flags == 0`：投射和接收均开启；
- 设置 `DISABLE_CAST`：不进入方向光 Shadow Caster 集合；
- 设置 `DISABLE_RECEIVE`：主视图不采样阴影；
- 未知标志位返回 `GRANIT_ERROR_INVALID_ARGUMENT`，避免静默改变渲染语义；
- 同步更新 C++ 内部 `renderable_input`、公共注释、C/C++ Consumer 和契约测试。

选择保留现有字段位置，是为了避免在数组元素中追加字段后，让旧调用方按旧元素步长传入数据时
产生越界读取。0.x 阶段允许字段命名和语义收敛，但必须同步更新公共头、安装头和测试。

## 实施分解

1. **Scene 数据与校验**
   - 将公共 `reserved` 收敛为 `shadow_flags`；
   - 在 Scene Snapshot 创建时复制并校验标志；
   - 将标志传递到内部可见列表和 RenderPipeline 提交数据。
2. **阴影投射路径**
   - 在方向光阴影可见性/收集阶段过滤 `DISABLE_CAST`；
   - 保留主视图可见性判断，不把投射过滤误用于普通绘制；
   - 空投射者时继续使用现有 Shadow Pass 清除和无 caster 语义。
3. **阴影接收路径**
   - 扩展 PBR Object 常量中已有保留字段，表达接收阴影开关；
   - 在 PBR Shader 中按实例跳过阴影采样，保留其他光照计算；
   - 确认自动材质、无纹理材质、透明材质和 MSAA 路径的布局一致性。
4. **公共契约与文档**
   - 更新 C/C++ 头文件、Doxygen、迁移说明和安装 Consumer；
   - 更新 ABI/布局快照及版本说明；
   - 不新增 Vulkan 类型或 Renderer 公共依赖。
5. **测试与示例**
   - 增加默认、仅禁用投射、仅禁用接收、同时禁用四种组合；
   - 使用可读回的离屏目标验证主视图仍有输出；
   - 使用 Shadow Pass 录制统计或诊断数据验证禁用投射实例未进入 caster 集合；
   - 增加 C API 和 C++ 包装层的字段/默认值测试。

## 不在范围内

- 每个灯光单独配置投射/接收；
- 阴影质量、分辨率、级联、过滤算法或阴影图格式调整；
- 材质级阴影策略和全局阴影开关；
- Spot/Point Light 阴影实现；
- 公共 Render Graph API 的改造。

## 风险与决策点

- 接收开关需要 Shader 变体或 object 常量分支，必须确认现有 PBR Shader 的布局和缓存键不会冲突；
- Shadow Caster 过滤应在阴影可见性阶段完成，不能只在录制阶段跳过，否则会留下错误的排序、计数或
  诊断信息；
- 若未来需要每灯光策略，应在当前实例级标志稳定后另行设计，不在本任务中预留含义不清的位。
