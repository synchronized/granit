# S-32：0.17.0 WebGPU 原生异步 Pipeline 预热

## 状态

- 路线图任务：S-32
- 目标版本：0.17.0
- 优先级：P1
- 状态：已确认
- 前置依赖：S-28～S-31

## 背景与目标

0.16.0 已让 Vulkan Pipeline 冷创建进入私有后台任务，并为异步传输建立可重试背压；浏览器
WebGPU 仍在事件推进中同步创建单条 Pipeline，因此不能报告严格非阻塞预热能力。0.17.0 要接入
WebGPU 原生异步 Render/Compute Pipeline 创建，并把两种后端的实现收敛到同一私有 HAL 契约。

本版本还要让 Web Model Viewer 在加载阶段消费严格非阻塞预热，展示真实进度和失败详情，使
Pipeline 冷创建不再造成浏览器交互停顿。

## 非目标

- 不公开线程池、Future、WebGPU 回调、Vulkan Queue 或后端原生句柄。
- 不改变普通同步 Pipeline 创建接口及其错误语义。
- 不承诺撤销已经交给驱动的 Pipeline 创建，只保证取消后的状态和资源回收。
- 不加入桌面 Dawn、Android、新渲染后端、公共 glTF SDK、场景管理或通用任务系统。
- 不在本版本引入 TAA、Bindless、光线追踪等新的渲染特性。

## 已确认决策

- 新增私有 HAL 异步 Pipeline 预热接口和完成对象，Registry 不直接依赖 WebGPU 或 Vulkan 类型。
- WebGPU 使用原生异步 Render/Compute Pipeline 创建回调；提交和单次事件推进不得执行同步冷编译。
- Vulkan 迁移到同一 HAL 契约，继续使用私有后台任务，不向公共层暴露线程所有权。
- 只有完整满足严格语义的后端才报告 `NON_BLOCKING_PIPELINE_WARMUP`；否则保留现有分步降级路径。
- 异步操作保留 Pipeline Layout、Shader 和描述数组，直至回调结束或后端确认安全释放。
- Device Lost、取消和 Renderer 销毁都通过现有异步状态机收敛，不新增平行 Future API。

## 实施顺序

1. **S-32A HAL 契约**：定义异步图形/计算 Pipeline 预热及完成轮询接口，整理描述和资源保活。
2. **S-32B WebGPU 原生异步创建**：扩展私有 Provider，接入创建回调、事件推进和错误映射。
3. **S-32C Vulkan 迁移**：把 0.16.0 私有后台任务移入 HAL 实现，Registry 只编排公共状态机。
4. **S-32D 生命周期与一致性**：覆盖取消、Device Lost、关闭、缓存命中及跨后端结果码。
5. **S-32E Web Consumer**：让 Web Model Viewer 预热标准 PBR 变体并显示真实进度与错误阶段。
6. **S-32F 发布验收**：完成共享/静态、Vulkan/WebGPU、安装 Consumer、文档和 Release 矩阵。

## 测试与验收

- WebGPU 图形与计算 Pipeline 的首次冷创建通过原生异步回调完成。
- 报告严格能力的后端在提交和单次事件推进中均不执行同步冷编译。
- 同一批次在 Vulkan/WebGPU 上具有一致的逐项结果、稳定键、缓存命中和取消终态。
- Device Lost 或 Renderer 销毁期间不回调已释放对象，不泄漏 Pipeline、Shader、Layout 或操作记录。
- Web Model Viewer 加载期间页面持续处理事件，预热进度单调推进，并能展示逐项失败原因。
- Windows、Linux、Emscripten、共享/静态、C/C++ Consumer、文档和 Release 预验证全部通过。

## 风险与未决问题

- Emscripten WebGPU 回调模式和浏览器事件循环存在实现差异，需要以当前锁定工具链验证。
- 取消只能停止尚未提交的条目；已进入驱动的创建必须等待回调后再释放结果。
- Model Viewer 只消费标准 PBR 变体，不把示例加载器或线程模型提升为公共 API。
