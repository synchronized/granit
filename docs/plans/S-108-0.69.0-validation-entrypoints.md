# 任务编号：S-108：0.69.0 验证入口与报告

## 状态

**已完成，P1。** 属于 [v0.69.0](../versions/v0.69.0.md)。

## 目标与职责

CTest 负责测试注册、选择、超时、返回码和结果；测试程序负责正确性断言。
脚本负责环境准备、配置构建、运行选择与归档；Actions 负责机器和工具链调度。
本地与 CI 复用测试入口，不在 YAML 或 Shell 中复制功能断言。

## 实施步骤

1. 审计现有 CTest 标签、测试环境和默认注册集合，补齐标签说明，保留已有 preset 名称。
2. 扩展 `scripts/dev.ps1`、`scripts/dev.sh` 的本地运行范围与归档能力；
   `scripts/ci.ps1`、`scripts/ci.sh` 继续只负责远端 workflow 调度，增加 ref 和验收范围参数。
   平台脚本保持薄层，跨平台通用逻辑优先使用 CMake 脚本，避免再建一套构建系统。
3. 设计默认关闭的 `GRANIT_ENABLE_STRESS_TESTS`；新增 `stress` 标签，
   普通配置不注册长测，启用后仍需显式选择长测范围。
4. 确定报告格式：运行编号、提交号及工作区是否干净、命令、preset、系统/架构、编译器完整版本、
   配置、链接方式、依赖身份，以及 GPU、驱动、后端、时长、种子和通过/失败/跳过状态。
5. 更新现有 `docs/guides/ci.md` 与 `tests/README.md`，避免另建重复的操作指南。

## 目录约定

- 测试源码仍按组件归属；跨模块与 GPU 用例进入所属组件 `integration/`。
- `tests/support/` 只放共用测试辅助；`tests/fixtures/` 放受审查输入数据。
- 公共测试配置继续放 `cmake/`；跨目录检查脚本继续放 `tests/cmake/`。
- 产物放忽略目录 `build/validation/<运行编号>/`，包含 `environment.json`、
  `summary.json`、`junit.xml` 和 `logs/`，避免不同运行互相覆盖。
- 失败时仍归档报告，外层脚本保持原始失败退出码；汇总记录实际测试数量，零测试不能算通过。
- 机器日志不提交；关键版本摘要和制品链接进入 `docs/records/`。
