# S-91：0.55.0 Bindless 真实压力与边界复评

## 状态

**实施中。** S-91A 已完成首轮 Descriptor/CPU 压力基线，S-91C 已补充单 dispatch GPU 时间戳基线，S-91B 与 S-91D 待完成。本计划承接 S-90，先补齐真实负载和跨平台证据，再决定是否有理由设计公共后端无关
Bindless API。0.55.0 不预设公共 ABI 必须落地。

## 背景与目标

S-90 已验证 Vulkan sampled texture/sampler Descriptor Indexing、显式 Shader/Pipeline 变体和
GPU 安全回收，但现有 A/B 只有微型 descriptor 更新负载，不能代表多材质场景。0.55.0 的目标
是建立可重复的真实对照，并用结果决定 Bindless 的下一步边界。

目标：

1. 使用同一批材质、纹理、采样器和 Draw 输入，对比传统 Bind Group 与内部 Bindless 变体；
2. 覆盖 Windows Vulkan 硬件、Linux Vulkan/Lavapipe 和不支持设备的回退行为；
3. 记录绑定切换、CPU 命令录制、GPU 时间、Descriptor/显存占用和容量耗尽行为；
4. 验证 Shader/Pipeline 缓存键、资源索引 generation、GPU 延迟回收和线程边界在压力下仍成立；
5. 在没有稳定收益时明确继续使用 Bind Group，不创建只为“支持 Bindless”而存在的公共接口。

## 非目标

- 不冻结公共 Bindless ABI、Vulkan descriptor 规则或可持久化资源索引；
- 不改变 WebGPU/Emscripten 的 Bind Group 模型和回退路径；
- 不实现 Descriptor Buffer、SVT/纹理驻留、虚拟文件系统、Mesh Shader 或 Ray Tracing；
- 不让 Bindless 成为 Renderer、Material、Pipeline 或资产包的默认依赖；
- 不用理论容量或单一设备结果替代真实 A/B 数据。

## 实施顺序

### S-91A：真实多资源对照负载

- 扩展现有 PBR textured 压力场景，使传统和 Bindless 使用完全相同的材质/纹理输入；
- 覆盖 8、64、512 组材质以及多纹理采样、材质切换和批次录制；
- 将结果输出为稳定 CSV/记录，区分预热、CPU 录制和提交阶段。

首轮已完成 8/64/512 个逻辑槽位的 Descriptor 更新和 Resource Table 回收对照。当前负载使用
相同底层 1×1 纹理/采样器填充不同逻辑槽位，证明绑定压力和索引回收契约，但不代表真实材质
内容差异或端到端 GPU 收益；证据见 [S-91A 记录](../records/2026-10-08-s91a-bindless-pressure-baseline.md)。

### S-91B：跨平台与能力矩阵

- 在 Windows Vulkan 硬件上测量实验路径和传统路径；
- 在 Linux Vulkan/Lavapipe 上重复运行，并记录驱动能力组合、跳过原因和性能结果；
- 在不支持 Descriptor Indexing 的设备上确认传统路径完整可用，不创建实验资源。

### S-91C：GPU 与资源占用

- 使用 Timestamp 查询或等价后端测量 GPU 工作时间；
- 记录 descriptor pool/array 容量、资源表占用、内存统计和容量耗尽错误；
- 验证多帧在途资源释放、generation 失效、重复销毁和跨 Renderer 混用。

首轮已在 Windows Vulkan 硬件 + Validation 上完成 Bindless/传统各一次真实 dispatch 的 GPU 时间戳
对照；结果处于相同数量级，且当前输入仍是单个 1×1 纹理和单 workgroup，不构成稳定收益结论。证据见
[S-91C 记录](../records/2026-10-08-s91c-bindless-gpu-timing.md)。

### S-91D：准入结论

- 若收益在目标平台和目标规模上可重复，提出下一版本的后端无关设计草案，不立即承诺 ABI；
- 若收益不稳定、覆盖率不足或复杂度不抵消收益，关闭公共 Bindless 候选并保持内部实验；
- 将结论写入独立 Record，版本文档只保留范围和出口，不复制测量日志。

## 验收门槛

- 传统 Bind Group 和 Bindless 对照使用同一输入和同一计量口径；
- Windows 与 Linux/Lavapipe 结果可复现，设备不支持时明确回退；
- Vulkan Validation 无 descriptor、pipeline layout、同步或生命周期错误；
- CPU、GPU、Descriptor/显存数据和容量耗尽行为均有记录；
- 公共头文件、C ABI、WebGPU 回退和现有消费者不发生 Bindless 泄漏；
- 版本结论明确是“继续内部实验”或“进入后续 API 设计”，不得把实验结果写成稳定能力。

## 发布出口

0.55.0 默认出口是“完成真实压力复评并保留传统 Bind Group 默认路径”。只有 S-91D 的数据同时
满足收益、覆盖率和生命周期门槛，才允许在后续版本单独规划公共 API；否则将 Bindless 继续留在
Vulkan 内部实验范围。
