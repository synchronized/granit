# S-65：0.32.0 安装 SDK 图形工作流

## 状态

**已完成，P1。** 0.32.0 已补齐安装后 SDK 从源码 Shader 到首个 Draw 的独立消费闭环，并完成
版本准备与发布验收。

## 背景与目标

0.31.0 已提供只依赖安装包的 Window 清屏示例，但尚未证明普通使用者能仅凭发布 SDK 构建 Shader
Library、创建 Graphics Pipeline 并提交绘制。版本准备脚本还会全局替换 README 中的旧版本号，可能
篡改历史说明。

0.32.0 完成以下工作：

- 版本准备只更新唯一工程版本、README 当前发布入口和 Changelog，不修改历史版本文本。
- 增加只依赖安装后 SDK 的 Triangle 示例，覆盖 Shader Library、Graphics Pipeline、顶点数据与 Draw。
- 明确发布包中的 Shader Tools 消费方式，让同一份 HLSL 清单生成跨 Vulkan/WebGPU 的 `.grshlib`。
- 将独立图形示例接入 Windows/Linux shared SDK 和可用的浏览器验收。

## 非目标

- 不新增渲染特性、公共 VFS、模型加载或材质系统接口。
- 不改变 `.grshlib` 格式、Renderer ABI 或后端坐标约定。
- 不把仓库私有 Example Common 安装为公共 SDK。
- 不恢复预构建静态库发布产物。

## 已确认决策

- PowerShell 与 Bash 发布入口复用同一个确定性版本文件变更器。
- 版本变更器使用唯一锚点并在缺失或重复时失败，测试必须保留历史版本文本。
- 安装 SDK 示例是独立 CMake 工程，只链接导出的 Granit target，不依赖源码树私有 target。
- Shader 源码以 HLSL-first 清单为入口，运行时只消费生成的 `.grshlib` 和逻辑 Shader 名称。
- 无 GPU 或显示环境可以返回约定的跳过码；编译、资产和生命周期错误必须失败。

## 实施顺序

1. **S-65A 发布准备加固**：统一两个发布脚本的精确版本变更逻辑并增加回归测试。
2. **S-65B Shader Tools 安装消费契约**：审计发布包内容、工具链发现与独立构建命令，补齐缺口。
3. **S-65C 安装 SDK Triangle**：增加独立源码、Shader 清单、构建与运行说明。
4. **S-65D 发布矩阵**：接入 Windows/Linux shared SDK；浏览器侧验证同一 Shader 逻辑入口。
5. **S-65E 0.32.0 收口**：完成文档、Changelog、本地与远端矩阵并正式发布。

## 测试与验收

- 发布准备测试证明当前发布入口会更新，README 历史版本文本保持不变。
- PowerShell 与 Bash 入口调用同一个变更器，失败不会产生部分版本文件改动。
- 独立 Triangle 在安装目录之外通过 `find_package(granit CONFIG REQUIRED ...)` 配置和构建。
- Shader Library 从 HLSL 与清单生成，Desktop 与 WebGPU 使用相同逻辑 Shader 名称。
- Windows/Linux shared SDK、源码 static、Emscripten、Documentation 与 `git diff --check` 通过。

## 风险与未决问题

- DXC、Tint 的体积与平台分发可能不适合并入基础运行时 SDK；先以独立 Shader Tools 包或明确的
  外部工具链根目录完成闭环，再依据产物审计决定发布形式。
- 无头环境不能证明屏幕可见结果，Triangle 需要确定性像素检查或明确跳过，不能只验证进程退出码。

## 完成结果

- PowerShell 与 Bash 发布入口已复用确定性版本变更器，并用回归测试保护 README 历史版本文本。
- 安装 SDK Triangle 已覆盖预构建 `.grshlib` 和从 HLSL 重建两种路径；Linux 软件 Vulkan 环境执行
  窗口与确定性像素验证，Windows 验证安装后编译。
- 官方 shared SDK 已安装实验性 AssetTools/CLI；DXC/Tint 继续作为独立锁定工具链按需获取。
- Windows、Linux、Emscripten、浏览器与公开 Release 复验均通过，`v0.32.0` 已发布。
