# S-101：0.65.0 示例第三方依赖缓存收敛

## 状态

**实施中。**

## 背景与目标

SDL3 和 ImGui 已经使用仓库级 `vendor/cache` 共享源码缓存，但示例 glTF 支持仍由
`FetchContent` 在当前构建目录获取 cgltf 和 stb_image。全新静态构建因此可能在无缓存或网络受限时
失败，也无法复用其他 preset 已下载的源码。

本任务将两项示例依赖接入现有缓存机制，统一下载、校验、解压和跨 preset 复用行为。

## 非目标

- 不把示例依赖安装到 Granit SDK；
- 不把 cgltf 或 stb_image 暴露到公共头文件、C ABI 或运行时库；
- 不缓存 Vulkan SDK、编译器、系统线程库和窗口系统开发包；
- 不引入新的包管理器或修改第三方源码。

## 已确认决策

- 继续使用 `GRANIT_DEPENDENCY_POLICY` 及对应的 `GRANIT_DEPENDENCY_CGLTF/STB` 覆盖；
- `system` 只查找现有 CMake target，`auto` 先查找系统 target、缺失时使用共享源码缓存，
  `download` 直接使用锁定版本共享缓存；
- 归档和源码分别位于 `vendor/cache/archives/<name>-<commit>.tar.gz` 与
  `vendor/cache/sources/<name>/<commit>/`；
- 缓存使用锁定 commit、SHA-256 和根文件标记校验，编译产物仍位于当前 build 目录。

## 实施顺序

1. 将 cgltf 与 stb_image 从示例私有 `FetchContent` 迁移到现有源码缓存辅助函数；
2. 保持父项目 target 和 `find_package` 优先级，补齐缺失依赖的离线诊断；
3. 更新构建指南、CMake 文件说明、第三方通知和版本索引；
4. 验证缓存命中、system 策略、共享/静态配置和 glTF 支持测试；
5. 记录验证结果并完成 v0.65.0 发布收口。

## 测试与验收

- CMake 配置确认已有缓存时不触发网络下载；
- `GRANIT_DEPENDENCY_CGLTF=system` 或 `GRANIT_DEPENDENCY_STB=system` 缺少 target 时失败信息明确；
- Model Viewer/glTF 支持目标能够编译，相关测试能够注册并运行；
- `git diff --check`、文档检查和受影响 preset 构建通过；
- 至少验证 Windows 共享与静态配置；若网络或系统包缺失，记录未验证项及原因。

## 风险与未决问题

- 当前环境可能没有 cgltf/stb 的系统包，首次填充缓存仍需要网络或预置归档；
- 示例 glTF 支持是仓库私有目标，缓存迁移不改变下游安装包的依赖解析。
