# 任务编号：S-109：0.69.0 手动兼容矩阵

## 状态与依赖

**已确认，待实施，P1。** 依赖 [S-108](S-108-0.69.0-validation-entrypoints.md)，
属于 [v0.69.0](../versions/v0.69.0.md)。

## 目标

关键版本手动运行跨系统、跨工具链版本的验收；PR 只承担快速反馈。
验收结果描述已测试的具体环境，不推导未测试系统或驱动的支持承诺。

## 实施步骤

1. 首先核查 C++20、标准库与锁定依赖的要求，以及 Runner 可安装的工具链；确定各工具链
   最低支持版本和当前验证版本。将确切版本集中在 `.github/ci/compatibility-matrix.json`，
   工作流读取此清单，报告记录实际版本并核对是否匹配。此步骤通过前不宣称最低版本支持。
2. 新建 `.github/workflows/compatibility.yml`，只提供 `workflow_dispatch`，
   可选择 `native`、`sanitizers` 或 `all`。手动执行时选择候选 ref，全部任务绑定同一提交。
   Web 回归复用现有 Emscripten 手动入口，汇总时校验提交一致。
3. 主组合采用 Windows x64 MSVC、Windows x64 Clang、Linux x64 GCC/Clang，
   Release 共享/静态，运行适用行为测试、公共头/ABI、安装审计与独立 C11/C++20 Consumer。
4. 每种工具链增加另一个版本边界组合，先覆盖公共头、核心行为及安装 Consumer；
   Windows MSVC 与 Linux Clang 各选一个主版本补充 Debug，共享模式即可。
   所有组合隔离构建目录与缓存，显式选择编译器和匹配的 C/C++ 驱动及运行库。
5. Linux Clang 增加 ASan+UBSan；TSan 使用独立构建，仅运行适用的 CPU 并发测试。
   插桩选项限定 Granit 自有测试目标与被测实现，不传播到安装导出或下游。
   不通过关闭诊断掩盖失败；外部依赖诊断需单独记录范围和依据。
6. 从 Windows/Linux/Emscripten 工作流移除 PR 触发，保留手动入口；
   Quick Check 和文档检查保留 PR 反馈，审计其他调用路径，避免间接启动完整矩阵。
7. 更新 CI 指南、手动触发脚本和关键版本验收流程；不改变 Release、依赖与镜像工作流的触发策略。

## 环境与证据边界

Linux 软件 Vulkan、窗口虚拟环境与真实 GPU 分别记录。Windows 云端缺少 ICD 时明确报告
GPU/平台测试未执行，由 S-110 的真实硬件验收补足，不把过滤测试写成全量通过。
软件驱动的 Sanitizer 结果不代表第三方真实 GPU 驱动已受插桩验证。

macOS、ARM64、多发行版、多浏览器不进入本次矩阵。工具链安装源和版本升级应显式评审，
不新增生产库依赖，也不改变 Vulkan-Headers/Volk 的配对锁定。

## 验收门槛

- [ ] 工具链确切版本清单及最低版本判断依据已确认，实际环境可复现。
- [ ] PR 不触发完整平台矩阵；新增矩阵无 push、tag、定时触发。
- [ ] 主组合、额外版本边界、Debug、Sanitizer 和同提交 Web 回归通过。
- [ ] 安装导出不包含插桩或测试依赖；现有共享/静态与 C/C++ Consumer 通过。
- [ ] 所有组合上传环境、测试数量和失败诊断，缺少环境不被标为通过。
- [ ] 首次手动验收保存 Actions 链接和对应提交号。
