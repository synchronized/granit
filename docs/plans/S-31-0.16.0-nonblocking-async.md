# S-31：0.16.0 严格非阻塞异步调度

## 状态

- 路线图任务：S-31
- 目标版本：0.16.0
- 优先级：P1
- 状态：实现中
- 前置依赖：S-28～S-30

## 背景与目标

0.15.0 已统一异步上传、回读和 Pipeline 预热，但 Vulkan 后端槽位耗尽时仍可能在提交调用中等待，
Pipeline 预热也只保证条目间让出执行权。0.16.0 要让标记为异步的提交入口具有可验证的非阻塞
语义，并让调用方通过背压结果和能力位安排重试或降级。

## 非目标

- 不向公共 API 暴露线程池、Vulkan Queue 或 WebGPU 回调对象。
- 不改变同步上传和普通 Pipeline 创建的同步语义。
- 不保证取消已经进入驱动或 GPU 的工作。
- 不加入 Android、桌面 Dawn、新后端或公共资产任务系统。

## 已确认决策

- 异步上传和回读在后端槽位不足时立即返回 `NOT_READY`，批次内容保持可重试状态。
- `NOT_READY` 不把批次标记为永久失败，也不遗留公开或内部异步操作记录。
- Vulkan 严格非阻塞 Pipeline 预热优先使用驱动的“编译必需”探测；需要编译时移交私有后台工作，
  不把执行器或线程所有权暴露给上游。
- WebGPU 使用异步 Pipeline 创建回调；不具备可靠异步入口时不报告严格非阻塞能力。
- 同一异步状态机继续表达完成、失败和取消，避免新增平行 Future 类型。

## 实施顺序

1. **S-31A 传输背压**：移除 Vulkan 异步槽位等待，修正 `NOT_READY` 重试和资源生命周期。
2. **S-31B 可观测性**：补充容量/饱和测试、诊断与调用指南。
3. **S-31C Pipeline 非阻塞化**：实现受能力门控的 Vulkan/WebGPU 异步创建路径。
4. **S-31D Consumer 验收**：让 Model Viewer 加载调度使用背压与严格能力查询。
5. **S-31E 发布验收**：完成共享/静态、双后端、安装 Consumer、文档和 Release 矩阵。

## 测试与验收

- 人为占满所有上传或回读槽后，异步提交在调用线程立即返回 `NOT_READY`，推进事件后可重试成功。
- 背压失败不丢失批次内容、不泄漏异步操作，并保持源/目标资源生命周期正确。
- 报告严格非阻塞预热能力的后端不得在提交或单次事件推进中执行同步冷编译。
- 不支持严格非阻塞预热的设备继续支持 0.15.0 分批预热，并准确报告能力差异。
- Windows、Linux、Emscripten、共享/静态、C/C++ Consumer、文档和 Release 预验证全部通过。

## 风险与未决问题

- Vulkan 驱动对 Pipeline Cache 与编译必需探测的支持不同，必须保留明确的能力降级。
- WebGPU 异步回调生命周期必须覆盖 Device Lost、取消和 Renderer 销毁。
