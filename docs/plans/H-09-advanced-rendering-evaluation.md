# H-09：高级渲染能力真实负载评估

## 状态

- 设计状态：已确认
- 实现状态：H-09A～H-09D 已完成；Clustered Forward 暂缓，下一项为 H-09E 绑定压力
- 路线图任务：H-09
- 优先级：P2
- 前置依赖：H-03、H-05、H-07、D-09B

## 背景与目标

当前 Forward PBR、单方向光阴影、IBL、Tone Mapping 与传统 Bind Group 路径已经完成。已有基准
覆盖单对象阶段 GPU 时间、点光打包、Scene 可见性和材质缓存命中，但没有同时包含真实数量的
Draw、材质、纹理、透明重叠与光源，因此不足以证明透明 PBR、CSM、Clustered Forward 或
Bindless 的收益。

H-09 只建立可复现负载、测量现有路径并形成独立决策依据。每项高级能力必须单独证明需求，不能
因为其中一项达到触发条件就捆绑实现其他能力。

## 非目标

- 本阶段不新增公共 API、C ABI、材质绑定模型或 Vulkan 后端能力。
- 不把微基准结果外推为跨设备性能承诺。
- 不用合成场景替代最终产品负载；合成场景只负责稳定复现规模与状态分布。
- 不预先认定 Forward、Clustered、Bind Group 或 Bindless 中任何路径必然更优。
- 不在同一原型中捆绑 Deferred、Descriptor Buffer、Mesh Shader 或 Ray Tracing。

## 已确认决策

### 基准层级

测量分为三层，结果不得混写：

1. CPU 准备层：Scene 快照、可见性、稳定排序、材质更新、Bind Group 创建与缓存命中。
2. CPU 帧层：Graph 构建、资源准备、命令录制、提交和完成等待。
3. GPU 阶段层：Shadow、Opaque、Transparent、Tone Mapping 与整帧 timestamp。

CPU 和 GPU 结果分别报告 P50、P95、P99。每份结果记录提交、编译器、链接模式、CPU、GPU、驱动、
分辨率、样本数、预热次数和 Validation 状态。

### 负载维度

首轮使用固定种子的合成场景，至少覆盖：

| 维度 | 档位 | 目的 |
|---|---|---|
| 可见 Draw | 100、1,000、10,000 | 观察提交、排序和录制扩展曲线 |
| 唯一材质 | 8、64、512 | 观察 Pipeline/Bind Group 缓存与切换成本 |
| 唯一纹理组 | 8、64、512 | 隔离传统绑定与批次破碎成本 |
| 点光 | 1、16、64、128 | 观察当前 Forward 逐光成本曲线 |
| 透明覆盖层 | 0、2、8、32 | 观察稳定排序、混合和 overdraw 成本 |
| 阴影视锥跨度 | 近景、中景、远景 | 记录单阴影图的覆盖与质量限制 |

10,000 Draw 与 512 纹理组属于压力档，不代表默认场景预算。超出当前固定光源容量的输入不在首轮
通过绕过校验实现，而是记录为能力上限。

### 对照原则

- Clustered Forward 与当前 Forward 使用相同可见对象、材质、光源、分辨率和 Shader 质量。
- Bindless 与传统 Bind Group 使用相同纹理、Sampler、Draw 顺序和材质变体。
- CSM 与单阴影图使用相同主方向光、总阴影像素预算，并分别报告质量差异与 GPU 成本。
- 透明 PBR 先验证排序、混合、深度和材质语义；不得只用不透明 Shader 加混合状态作为结论。
- 任何原型均保留现有路径作为回退，且不得修改默认行为。

## 实施顺序

1. **H-09A：现有路径负载生成器**——扩展 Render Pipeline benchmark，生成固定种子的多对象、
   多材质、纹理组和点光场景，输出实际可见 Draw、材质切换、纹理组切换和光源计数。
2. **H-09B：透明基线**——先以现有 Unlit 透明路径测量排序、批次和 overdraw，再为透明 PBR 建立
   [独立正确性草案](H-09B-transparent-pbr-correctness.md)；当前没有明确材质需求，不进入原型。
3. **H-09C：阴影覆盖评估**——记录近、中、远景下单阴影图的有效 texel 密度与 GPU 时间；只有
   质量不足且目标预算允许时，建立 CSM 原型 Plan。
4. **H-09D：多光源曲线**——在 1、16、64、128 点光下测量 Opaque GPU 时间和整帧时间；只有
   当前逐光路径成为主要瓶颈时，建立 Clustered Forward 原型 Plan。
5. **H-09E：绑定压力**——测量 8、64、512 纹理组下 Bind Group 创建、更新、切换、缓存占用和
   Draw 批次；满足 D-09 条件后才进入纯 CPU Resource Table 原型。
6. **H-09F：决策记录**——为四项能力分别给出“继续原路径、建立原型或暂缓”的结论，不输出一个
   打包式总决策。

## 测试与验收

- 相同种子生成完全一致的对象、材质、纹理、光源和透明顺序。
- 参数校验拒绝零值、溢出、超过当前能力上限和不可比较的组合。
- 基准输出包含工作负载实际计数，避免仅按请求值解释结果。
- GPU timestamp 不包含 CPU 等待；端到端 CPU 指标单独报告等待成本。
- 至少在一个硬件 Vulkan 驱动和一个软件 Vulkan 驱动完成可复现性检查。
- Validation 开启的正确性运行无 warning/error；正式性能采样关闭 Validation 并明确记录。
- 原始结果进入 `benchmarks/results/`，摘要只链接结果，不复制整份数据。

## 进入原型的条件

四项能力分别满足以下条件后才能建立实现 Plan：

- 目标负载和目标设备可稳定复现问题，而不是单次异常值。
- 问题在 P50 与 P95 均存在，并能归因到对应阶段、绑定或质量限制。
- 已记录现有路径可采取的更小优化，并说明为何不足。
- 已定义回退路径、像素正确性检查、生命周期边界和可接受的内存成本。
- 产品需求或明确场景需要该能力；纯理论上限不构成实现依据。

## 风险与未决问题

- 当前缺少由真实项目导出的材质和光源分布；首轮固定种子只能建立基础曲线。
- 不同 GPU 的光照、带宽、Descriptor 与 overdraw 特征差异显著，单设备结果只能用于该设备决策。
- 透明排序与阴影质量包含视觉判断，需要同时保留截图或数值图像指标，不能只看耗时。
- 若后续进入 CSM 原型，需沿用 H-09C 固定的摄像机路径、分辨率和总阴影像素预算。
