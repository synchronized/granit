# S-99：0.63.0 Vertex Streams 与 PBR 顶点属性验证

## 状态

**实施中。** 本版本从 bgfx 的 `34-mvs` 和 `06-bump` 提取验证目标，分别覆盖多 Vertex Buffer
绑定和完整标准 PBR 顶点属性；不复制 bgfx 示例代码或未审计资源，不新增公共 ABI。

## 背景与目标

当前 Granit 已支持多个 Vertex Buffer、实例步进、标准 PBR 纹理变体、UV0、UV1、Tangent 和
顶点颜色，但这些能力分散在 Mesh、glTF 上传和 PBR 布局校验中，缺少一个可视化的最小验证闭环。

本版本建立两个独立教程或示例场景：

- **34-mvs：Multiple Vertex Streams**：用同一几何体对照交错顶点布局和多个 Vertex Buffer，
  验证布局、步长、Attribute location、Index Buffer 及绑定顺序；
- **06-bump：PBR Vertex Attributes**：用同一模型逐步启用纯色 PBR、Base Color/Metallic-Roughness
  纹理和 Normal Map，验证位置、法线、UV0、Tangent 及可选顶点属性的组合规则。

## 非目标

- 不在 Rendering 作用域内放开 Vertex/Index Buffer 切换；当前跨后端契约仍要求在
  `begin_rendering` 前绑定；
- 不新增 Mesh、Vertex Buffer、PBR Material 或 Texture 公共 API；
- 不实现 bgfx 的 Multi-Draw Indirect、GPU Driven、Tessellation、OIT 或 SVT；
- 不直接复制 bgfx 源码、Shader、TGA 图片或运行时框架；
- 不把 `1x1` 纯色纹理作为纯色 PBR 的强制路径。

## 已确认决策

### S-99A：34-mvs Multiple Vertex Streams

- 复用 `examples/common/geometry/primitives.hpp` 的立方体或球体；
- 提供交错布局基线：Position、Normal、可选 UV 在一个 Vertex Buffer 中；
- 提供拆分布局：Position/Normal 与 UV/辅助属性放入不同 Vertex Buffer；
- 两条路径使用相同 Index Buffer、Pipeline、相机和材质，默认输出应逐像素一致；
- 面板显示当前拆分/交错布局、属性数量和 Index Buffer 信息；
- 独立 Instance Vertex Buffer 对照仍是后续补充项，不把本阶段的两个 Vertex Stream 误称为实例流；
- Mesh 在 Rendering 前统一 `bind`，Rendering 内只切换 Pipeline/Bind Group，不切换 Vertex Buffer；
- Smoke 固定使用拆分布局，验证非空画面、Resize、多帧稳定和资源销毁无泄漏。

### S-99B：06-bump PBR Vertex Attributes

- 复用现有 `02_pbr_assets` 的 Suzanne glTF；该模型已经包含 Position、Normal、Tangent 和
  `TEXCOORD_0`；
- 复用仓库内已审计的 Base Color 与 Metallic/Roughness 纹理；
- 运行时生成确定性的低分辨率 Normal Map，不新增外部二进制资产（当前阶段先复用标准默认法线纹理）；
- 目标验证以下材质变体：
  - 纯色 PBR：Position + Normal，无 UV、无纹理采样；
  - Base Color + Metallic/Roughness：需要 UV0；
  - Base Color + Metallic/Roughness + Normal Map：需要 UV0 + Tangent；
  - 带顶点颜色或 UV1 的非法/合法布局校验路径；
- 当前阶段面板先显示实际顶点属性；texture flags、Variant Key 和缺失属性错误码属于下一步矩阵验证；
- Smoke 固定执行纯色、纹理和 Normal Map 三个变体，验证 PBR、Resize、浏览器连续帧和
  资源回收；
- 纯色变体优先使用 Material 常量，不创建 1x1 纹理，以验证无 UV 的 untextured PBR 路径。

## 资源方案

| 场景 | 资源 | 结论 |
|---|---|---|
| 34-mvs | `examples/common/geometry/primitives.hpp` 的程序化几何 | 不需要新增资源 |
| 06-bump 模型 | 现有 Suzanne glTF/BIN | 复用，来源为已固定提交的 CC0 资产 |
| 06-bump Base Color/MR | 现有两张 PNG | 复用，不重新下载 |
| 06-bump Normal Map | 运行时生成 4×4 或 8×8 确定性纹理 | 不新增外部资源 |
| PBR 环境与阴影 | 复用现有 Render Pipeline/教程资产路径 | 先不引入新 HDR 或环境图 |

如果运行时 Normal Map 无法通过当前纹理上传路径稳定表达，才考虑加入一张极小、可审计并带来源
说明的 PNG；在此之前不下载 bgfx 的 `fieldstone-n.tga` 或其他示例资产。

## 实施顺序

1. **S-99A1 公共示例几何**：确认 primitives 的 Position/Normal/UV/Tangent 数据布局和绕序；
2. **S-99A2 多流 Mesh 对照**：完成交错/拆分 Vertex Buffer、实例流和 UI 统计；
3. **S-99A3 多流 Smoke**：补充像素/非空画面、Resize 和资源生命周期验收；
4. **S-99B1 PBR 属性矩阵**：接入现有 PBR 校验和 Variant Key，固定合法/非法组合；
5. **S-99B2 Normal Map 变体**：生成确定性 Normal Map，验证 Tangent 和法线视觉结果；
6. **S-99B3 跨后端收口**：Windows Vulkan、Linux Lavapipe、Chrome WebGPU、安装 Consumer；
7. **S-99C 文档收口**：更新教程索引、能力矩阵、版本文档、验收记录和 CHANGELOG。

## 测试与验收

- 交错与拆分 Vertex Buffer 使用同一相机和材质时画面一致；
- 多流 Mesh 覆盖至少两个 Vertex Buffer、一个 Index Buffer 和一个 Instance Buffer；
- Rendering 内不重新绑定 Vertex/Index Buffer，且示例文档明确该限制；
- PBR 变体正确区分无纹理、UV0 纹理和 UV0 + Tangent Normal Map；
- 非法布局返回明确的 `missing_uv0`、`missing_tangent`、`missing_uv1` 或 `missing_color`；
- Windows Clang Release、Linux GCC/Clang、Emscripten/Chrome WebGPU 均通过 Smoke；
- 安装 SDK Consumer、`git diff --check`、文档链接和 Vulkan/WebGPU Validation 通过；
- 不新增公共 ABI；若实现中发现 API 不足，单独记录为后续候选，不在本版本临时扩展。
