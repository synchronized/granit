# S-09：0.3.0 公共 SDK 易用性与集成体验

## 状态

- 实现状态：已确认，待开始
- 目标版本：0.3.0
- 基线版本：v0.2.0
- 路线图任务：S-09
- 优先级：P1

## 背景与目标

0.2.0 已交付 Core、RenderPipeline、Window 和 Input 的公开安装包，并完成 Windows/Linux、共享库、
静态库及独立 C/C++ Consumer 验证。下一阶段先验证现有 SDK 是否容易正确使用，再决定是否扩大
公共 ABI。

0.3.0 的主题是“公共接口易用性与集成体验”，目标包括：

- 用核心 C、核心 C++、Window/Input 和 RenderPipeline 四条代表性用户路径审计样板代码与失败行为。
- 统一现有 C/C++ 接口的错误、空句柄、重复销毁、移动后状态、`struct_size` 和所有权表达。
- 让公开安装包、最小示例、文档命令和独立 Consumer 保持可复制、可运行和相互一致。
- 对发现的缺口先形成证据和独立设计，再决定内部修复、包装层改进或公共 ABI 扩展。

## 非目标

- 不公开内部 Render Graph、Material、PBR、Lighting 或 Vulkan 类型。
- 不因版本规划直接加入 Bindless、透明 PBR、CSM、Clustered Forward 或 Deferred Renderer。
- 不预先承诺异步 Readback、多区域传输、原生 Vulkan 互操作或通用线程池。
- 不把 SDL3、ImGui 或其他第三方对象类型加入稳定 C ABI。
- 不在 0.3.0 宣布 1.0 级 ABI 稳定。

## 已确认决策

### 必须完成

1. **S-09A 使用路径基线**：从已安装包构建四条代表性程序，记录必要初始化、资源清理、错误分支、
   动态库调用次数和平台差异；结论进入独立 Record，不把测量日志堆入本计划。
2. **S-09B 契约一致性审计**：逐项比较 `.h`、`.hpp`、Reference 和测试，修复现有接口在结果码、
   空值、重复调用、移动语义、线程安全与父资源失效方面的不一致。
3. **S-09C 安装与文档闭环**：保持公开 Release 产物、CMake component、README 快速开始、示例和
   Consumer 使用同一组安装入口；关键文档命令进入自动化验证。
4. **S-09D 诊断可执行性**：代表性失败路径必须返回可区分的结果码，并通过诊断回调提供足以定位
   参数、句柄类型或生命周期问题的信息；不依赖解析英文消息实现程序逻辑。
5. **S-09E 0.3.0 验收**：比较 0.1.0 ABI 基线和 0.2.0 已发布接口，列出兼容新增、破坏性变化与
   迁移步骤，完成 Windows/Linux 共享、静态、安装 Consumer 和 Release 预验证。

### 有证据后再进入独立设计

以下候选来自当前 Reference 的明确限制，但尚无足够依据直接加入 0.3.0：

- RenderPipeline 外部环境资源切换。
- Box、Sphere、Axes、Frustum 等 Debug Gizmo 便捷生成。
- XCB 键盘布局相关文本输入。
- 同一 Texture 内复制、异步 Readback 和多区域传输。

候选只有在代表性用户路径出现重复样板、无法绕过的功能缺口或可复现性能问题后，才建立独立 Plan；
涉及 C ABI 时必须同步定义结构尺寸、所有权、错误语义和回归快照。

## 实施顺序

1. 完成 S-09A，冻结审计程序、指标和当前结果。
2. 按风险从文档或包装层不一致、内部行为缺陷、公共 C ABI 变化依次处理 S-09B。
3. 同步完成 S-09C；所有文档示例只描述仓库当前实际能力。
4. 用 S-09A 的失败路径验收 S-09D，不为没有调用方的诊断信息扩大接口。
5. 对满足门槛的候选分别提案；未满足者保留为限制，不阻塞 S-09E。
6. 完成 ABI、包、迁移和发布矩阵后执行 S-09E。

## 测试与验收

- 公共 `.h` 继续由 C11 编译器独立包含，`.hpp` 由 C++20 Consumer 验证。
- 四条代表性用户路径同时覆盖成功、失败、重复清理和父资源提前失效。
- README 与 Guide 中的关键构建命令能在干净安装包上执行。
- Core、RenderPipeline、Window 和 Input 的共享库不得出现未登记公共或私有导出。
- Windows/Linux 的共享与静态矩阵、安装审计、独立 Consumer 和 Release 预验证全部通过。
- 任何 0.x 破坏性变化都必须有变更记录、迁移步骤和对应 ABI 快照调整。

## 风险与未决问题

- 当前没有 0.2.0 外部使用反馈；S-09A 只能建立仓库内代表性基线，不能代替真实用户需求。
- 易用性改进可能只需要 C++ 包装或文档，不应为追求接口对称而增加 C ABI。
- 若候选功能缺少重复场景、性能数据或明确调用方，应继续暂缓，不以填满版本范围为目标。
