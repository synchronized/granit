# S-53：0.30.0 文档、教程与发布面收敛

## 状态

**实施中，P1。** 目标版本为 0.30.0。本计划整理现有公共能力的学习路径和发布方式，不改变
Renderer、Window、RenderPipeline 或资产格式的公共 API/ABI。

## 背景与目标

Granit 已有分类完整的文档中心和十章线性教程，但 Frame Context 与 Command Recorder 的层次关系
主要依赖读者交叉阅读两份 Reference；教程索引仍引用已经完成的实施计划，并在多个入口重复维护完整
章节清单；正式 Release 同时发布 shared/static 四套 SDK，而项目推荐普通使用者采用共享库。

0.30.0 完成以下收敛：

- 建立 Frame、Frame Context、Frame Recording、Command Recorder、Swapchain 与 Render Pipeline 的
  单一概念说明，明确拥有关系和适用场景。
- 审计文档中心、Concept、Reference、Guide 与历史计划的职责和链接，移除当前文档对历史验收记录
  的理解依赖。
- 统一十章教程的章节结构、前后依赖、构建运行入口和结果验证，让教程正文只维护关键增量，完整代码
  继续由 `examples/tutorials` 提供。
- 正式 Release 只发布 Windows/Linux x64 shared SDK 和 `SHA256SUMS`；静态构建能力与 CI 验证继续
  保留，供源码集成和高级使用者选择。

## 非目标

- 不删除静态库 preset、`BUILD_SHARED_LIBS=OFF`、安装导出或静态 Consumer 测试。
- 不把教程改成完整 API Reference，也不在 Markdown 中复制每章完整源码。
- 不改变现有十章的功能顺序，不在本版本增加新的渲染能力。
- 不修改已经发布版本的 Release 附件和历史 Record。
- 不为纯文档整理制造兼容别名或新的公共接口。

## 已确认决策

### Frame 与命令录制文档

- Concept 解释分层与选择：`command_recorder` 是通用 GPU 命令录制原语，`frame_context` 是面向
  acquired Frame 的槽位和 Recorder 复用管理，Render Graph/Render Pipeline 位于两者之上。
- Frame Context Reference 只定义 begin/submit/abort、借用 Recorder、frame slot 与错误语义。
- Command Recorder Reference 只定义录制、提交、资源保持和线程契约，并链接 Concept 解释何时选择
  Frame Context。

### 教程组织

- `docs/tutorials/README.md` 是唯一学习路线清单；文档中心只给出系列入口和推荐起点，不复制十章
  完整列表。
- 每章至少明确目标、相对上一章的新增内容、配套源码、构建运行方式、预期结果、关键生命周期和下一章。
- 教程只展示理解当前增量所需的代码，完整可运行实现以对应 `examples/tutorials/<step>` 为准。
- 当前教程不再链接已完成 Plan 作为状态依据；历史实施与验收继续留在 Plan/Record。

### 发布包策略

- 官方 Release 只包含：
  `granit-X.Y.Z-windows-x64-shared.zip`、
  `granit-X.Y.Z-linux-x64-shared.tar.gz` 和 `SHA256SUMS`。
- Release 工作流只为 shared SDK 构建、测试、审计和打包；PR 的 Windows/Linux CI 继续验证 shared 和
  static，防止静态构建退化。
- README、发布 Guide、路线图当前边界和发布后公开复验必须同步为两套 SDK。
- 0.30.0 Changelog 明确静态库不再作为预编译附件，但仍可从源码构建。

## 实施顺序

1. **S-53A 计划与文档审计**：登记 0.30.0 范围，检查入口重复、历史链接、章节结构和发布包事实。
2. **S-53B Frame 生命周期 Concept**：新增分层说明，压缩 Frame Context 与 Command Recorder Reference
   中的解释性重复，并更新文档中心阅读路径。
3. **S-53C 教程入口与章节模板**：让教程 README 成为唯一路线清单，逐章统一元信息、源码链接、运行
   命令、预期结果与下一步，修复失效或重复内容。
4. **S-53D shared-only Release**：收窄正式打包矩阵、校验和与公开下载复验，更新 README 和发布指南；
   静态 CI 保持不变。
5. **S-53E 验收与版本收口**：运行文档检查、桌面教程相关构建、Emscripten 浏览器教程验证和 Release
   工作流语法/包名测试，记录最终差异后准备 0.30.0。

## 测试与验收

- Documentation workflow、相对链接和 `git diff --check` 通过。
- 文档中心只维护教程系列入口，十章顺序只在教程 README 中定义。
- Concept 和两份 Reference 能分别回答“如何选择”和“接口如何工作”，不存在相互复制的大段流程。
- 十个教程文档均能链接到真实配套源码，并提供可执行的构建或运行入口和可观察结果。
- Windows/Linux PR CI 仍覆盖 shared/static；静态安装 Consumer 保持通过。
- Release 工作流只生成两个 shared SDK，`SHA256SUMS` 精确覆盖这两个归档，公开下载复验检查相同集合。
- README 和发布 Guide 不再宣称正式 Release 提供预编译静态 SDK。

## 风险与未决问题

- 缩减 Release 附件可能影响直接下载静态包的使用者；通过 Changelog 和构建 Guide 明确源码静态构建
  路径，不删除能力。
- 教程结构整理容易造成大范围无意义改写；只修复职责、入口和可执行性问题，不统一措辞风格。
- Release 工作流与文档中的精确文件名必须同提交修改，否则公开复验会在发布后失败。
