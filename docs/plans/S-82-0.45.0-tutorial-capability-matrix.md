# S-82：0.45.0 教程能力矩阵与图形特性探针

## 状态

**已完成，待发布。** 本计划参考 [bgfx Examples](https://github.com/bkaradzic/bgfx/tree/master/examples)
的单项特性组织方式，但只选择能验证 Granit 公共契约的教程，不追求示例数量对齐。

## 背景与目标

v0.44.0 已完成 Gneiss 所需的纹理变体上传。Granit 现有八个 Tutorial 已覆盖基础资源、PBR、
实例化、程序化 Fragment、Compute/Atomic/Indirect、Deferred 和外部 ImGui 集成，但覆盖矩阵仍
主要由既有功能驱动，缺少一轮面向“现有 API 是否足够”的系统探针。

本版本通过少量独立、可运行、可跨后端验证的教程，回答两个问题：

1. 现有 C API/C++ 包装能否表达常见实时渲染工作流；
2. 不能表达时，缺口是教程本地组合、公共包装摩擦、跨后端能力缺失，还是应明确保持不支持。

## 现有覆盖与不重复范围

| bgfx 特性方向 | Granit 当前证据 | v0.45 决定 |
|---|---|---|
| Cubes、Mesh、Instancing、Raymarch、Metaballs | `01`～`05` Tutorial、Model Viewer | 不重复新增 |
| HDR、Shadow Maps、IBL、PBR 法线/遮挡纹理 | `02_pbr_assets`、Render Pipeline、Model Viewer | 增加矩阵检查，不复制效果教程 |
| Deferred、Compute、Atomic、Indirect | `06_marching_cubes`、`07_deferred` | 不重复新增 |
| ImGui/外部宿主与资源上传 | `08_sdl_imgui`、基础教程 | 作为公共边界基线 |
| 动态几何与粒子 | 尚无独立教程 | 新增 `09_particles` 探针 |
| Blend、Mask、透明对象排序 | PBR 内部已有，缺少独立最小验证 | 新增 `10_transparency` 探针 |
| 格式、Sampler、Mip 和能力查询 | Reference 与多个教程分散覆盖 | 新增 `11_capabilities` 探针 |
| Stencil、OIT、GPU-driven 多批次、SVT | 当前没有完整公共契约 | 只做缺口记录，不在本版顺带实现 |

## 固定范围

### 1. `09_particles`

使用动态 Vertex/Storage 数据和透明混合绘制确定性粒子，验证 Buffer 更新、容量变化、深度测试、
对象级排序、Frame 生命周期和跨后端资源状态。第一版不引入专用 Particle API、GPU simulation 或
第二套效果框架。

### 2. `10_transparency`

用最小场景并列验证 Opaque、Mask、Blend、双面和对象级远近排序，覆盖深度写入、预乘/非预乘混合、
纹理 Alpha 和 UI 合成。教程必须明确记录：逐三角形排序、透明阴影、OIT、折射不属于当前能力。

### 3. `11_capabilities`

以可视化矩阵和 Smoke 断言验证 Texture Format/Usage、Sampler、Mip、Indirect、Render Target 和
后端能力查询。不可用组合必须返回明确的 `unsupported` 或能力结果，不允许教程绕过公共查询直接猜测
后端类型。

## 非目标

- 不复制 bgfx 的全部示例，不为了数量新增没有独立教学目标的 Demo；
- 不因单个教程方便而增加 Render Graph、Particle、OIT、Bindless 或 GPU-driven 专用公共 API；
- 不在本版本实现 Stencil State、OIT、透明阴影、SVT/虚拟纹理或多批次 GPU-driven；
- 不把 `examples/common` 变成与 Granit 公共 API 平行的运行时；
- 不引入新的第三方依赖或运行时下载资产；程序化资产优先，外部资产必须有许可证和摘要。

## 实施顺序

1. **S-82A 矩阵基线**：固定 bgfx 对照表、Tutorial 目标命名、Smoke/浏览器验收协议和缺口分类。
2. **S-82B 粒子探针**：完成 `09_particles`，确认现有动态资源和混合路径是否足够。
3. **S-82C 透明探针**：完成 `10_transparency`，确认 PBR Blend/Mask 的独立可观察行为和限制。
4. **S-82D 能力探针**：完成 `11_capabilities`，统一格式、Usage、Sampler、Mip 和 Indirect 的
   正向/负向验证。
5. **S-82E 缺口报告**：按“教程本地、C++ 包装、公共 ABI、后端能力、明确不支持”分类，不在计划
   内临时扩大 API。
6. **S-82F 跨平台验收**：Windows/Linux Vulkan、Emscripten WebGPU、安装 Consumer、文档检查和
   浏览器 Smoke 通过后，再决定是否形成 v0.46 的公共能力计划。

## 验收要求

- 三个新教程使用同一份 C++ 主体在 Vulkan 和 WebGPU 编译；
- 每个教程支持固定尺寸、固定时间、固定参数和有限帧数的 Smoke 模式；
- 桌面 CTest、浏览器测试和 Resize/最小化恢复路径通过；
- 正向和负向能力结果均有断言，不能用跳过测试掩盖后端差异；
- 教程不包含 Vulkan/WebGPU 类型，不依赖 `src/` 私有头；
- 最终记录明确列出已有能力、包装摩擦、真正缺口及暂不支持项；
- 只有缺口同时满足跨后端语义稳定、所有权清晰和独立复现时，才进入后续公共 API 计划。

## 设计边界

教程是 API 探针，不是公共功能的需求生成器。粒子积分、透明场景布局、能力矩阵展示和像素阈值
留在教程或测试中；重复出现且语义稳定的资源/命令模式先记录证据，再单独评审公共接口。这样可以
保持 Granit 的公共层高内聚、低耦合，并避免把 Gneiss 或单个示例的运行时状态下沉到 Granit。
