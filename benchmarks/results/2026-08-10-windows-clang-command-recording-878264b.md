# Windows Clang 命令记录基线

## 环境

- Granit：`878264b`
- 构建：Windows Clang 22.1.8、Release、共享库
- 系统：Windows AMD64
- CPU：Intel Core i5-8600K，6 个逻辑处理器
- Buffer 大小：4,096 字节
- 重复：每个线程和命令数档位完整运行 3 次

每线程每样本执行 500 次，每次运行包含 2 次预热和 10 个正式样本。所有记录用例均不包含队列
提交；`buffer_record` 的一次操作包含 begin、指定数量的 fill buffer 命令、end 和 reset。

## 观察与边界

- 空记录约为 1.1～1.2 微秒，各线程档位接近；它反映当前 begin/end/reset 路径的固定成本，
  不能直接解释为单一锁或 Vulkan 调用的成本。
- 单线程从 10 条增加到 100 条命令时耗时近似线性增长。扣除空记录后，当前样本中的每条 fill
  buffer 命令约处于 0.56～0.64 微秒量级；该换算仅用于识别趋势，不作为 API 性能承诺。
- 10 条命令从 1 线程提升到 2 线程后总吞吐提高，4 线程没有继续增长，后续 profiler 测量应区分
  Registry、Recorder 内部状态、驱动调用与线程调度的影响。
- Recorder 创建/销毁在 2 线程较快、4 线程回落；该用例包含句柄注册、Vulkan command pool 与
  command buffer 生命周期成本，不应仅凭本数据调整锁结构。
- 本阶段没有测量队列提交和 GPU 完成等待；这些属于 P-02D。
- 本阶段只覆盖 Transfer 风格的 buffer 命令；Graphics/Compute 混合流水线记录仍属于 P-02C2。
